# M5.2 — RHI Frame-Data Path and Public Surface — Design Spec

**Date**: 2026-08-12
**Status**: Implemented
**Boundary authority**: `docs/roadmap.md` M5.2 owns the outcome, deliverables, exit gate, and
deferrals. This spec decomposes that boundary without expanding it; where wording differs, the
roadmap wins. ADR 0010 owns the production direction: adopt an address-first per-frame data path
while retaining the object-shaped resource, pass, barrier, residency, and pipeline model and the
render graph's logical ownership.

## 1. Purpose

M5.2 implements the bounded production reshape selected by M5.1. It replaces the fixed-capacity
`setUniforms` path with one typed operation that suballocates frame-owned CPU-visible memory,
copies the caller's block, binds its GPU address, and returns that address. The same milestone
splits the monolithic public `RHI.h` into self-contained concept headers without changing the
retained RHI model.

The goal is not to make production resemble the whole NoApi prototype. It is to remove the
measured per-draw allocation cliff, keep static data reusable, make the adopted address visible to
callers that need to compose current-frame data, and improve API readability without importing
M5.1's API-surface, static-binding, or barrier regressions.

## 2. Adopted boundary

- **Change one contract area.** Only per-frame CPU-to-GPU data delivery and the organization of
  existing public declarations change. Resource ownership, texture and sampler binding, pass
  scopes, pipelines, barriers, residency, submission, presentation, and graph scheduling retain
  their current semantics.
- **One production API.** `bindFrameData` replaces `setUniforms`; the old name is removed after all
  callers migrate. There is no deprecated alias, backend-only compatibility path, or second public
  allocator API.
- **Static reuse stays static.** `bindBuffer` remains the path for immutable or caller-owned data
  that can be created once and reused. M5.2 never copies such data into the frame arena merely to
  make it address-first.
- **The experiment remains evidence.** The NoApi prototype is not modified, promoted, or treated
  as a post-migration compatibility target. Its final source is archived at immutable tag
  `m5.1-noapi-evidence`; production benchmarks live on `main` and do not import it.
- **Backend honesty.** Metal 4 is implemented and measured. The affected contract is designed
  against its native D3D12 mapping; no D3D12 backend is built in this milestone.

## 3. Public frame-data contract

The public surface adds an API-neutral `GpuAddress` value and replaces `CommandList::setUniforms`
with these overloads, shown here as the normative shape rather than exact formatting:

```cpp
struct GpuAddress {
    uint64_t value = 0;
};

inline constexpr uint64_t kFrameDataAlignment = 256;

virtual GpuAddress bindFrameData(uint32_t slot, const void* data, uint64_t size,
                                 uint64_t alignment) = 0;

GpuAddress bindFrameData(uint32_t slot, const void* data, uint64_t size);

template <typename T>
GpuAddress bindFrameData(uint32_t slot, const T& value);
```

- `GpuAddress` is a standard-layout, trivially copyable value containing no backend handle. Zero
  is the null address. Equality and an explicit validity test are permitted; general address
  arithmetic is not added until a real caller requires it.
- The untyped overload requires non-null, non-empty input. `alignment` must be a power of two and
  at least 256 bytes, preserving the D3D12 root-CBV placement contract as well as Metal's needs.
- The default alignment is supplied by the non-virtual convenience overload and the typed wrapper,
  never by a defaulted parameter on the virtual operation, so the default cannot vary with the
  caller's static type or drift between backends.
- The typed overload rejects top-level pointers, accepts only trivially copyable `T`, copies exactly
  `sizeof(T)` bytes, and requests `max(kFrameDataAlignment, alignof(T))`. C++ cannot inspect an
  aggregate's members, so the caller remains responsible for ensuring the block contains values and
  `GpuAddress` fields rather than live CPU pointers or ownership-bearing objects.
- One call performs allocation, immediate CPU copy, and at most one backend address bind to the
  requested buffer slot. The caller may reuse or destroy its source bytes immediately.
- The returned address names the copied block. It may be embedded into another block uploaded
  later in the same open frame, but it must not be cached into a later frame or used after the
  owning frame slot becomes reusable.
- The operation is valid inside render and compute passes, uses the existing buffer-slot namespace,
  and preserves current slot validation. Copy passes carry no shader bindings and reject it.
- M5.2 adds no allocation-only sibling such as `pushRoot`, no general `bindAddress`, and no public
  mapped-buffer write API. Those would enlarge the adopted contract beyond demonstrated demand.

## 4. Frame arena and lifetime

Each of the three frames-in-flight slots owns a growable arena made of persistent mapped pages.
The command allocator, argument table, timestamps, and every page for one slot share the existing
shared-event retirement proof.

- A normal page is 256 KiB, retaining the incumbent ring's useful initial footprint without
  retaining its hard capacity limit. Device creation allocates one normal page per slot; failure
  is reported by `createDevice` through `Result`.
- Allocation is bump-only within a frame. Each block begins at its requested alignment; padding is
  not copied or exposed as part of the block.
- When no existing page in the active slot can fit a request, the backend lazily adds a page. Its
  capacity reserves the request plus worst-case leading alignment padding, rounded up to the
  256 KiB page quantum. Growth is by pages, never by one GPU buffer per draw.
- Pages remain owned, mapped, labeled, and resident until device destruction. Once a slot retires,
  its page cursors reset and its prior high-water capacity is reused. A transient peak therefore
  grows retained capacity but cannot cause repeated allocation churn on later frames of the same
  size.
- `beginFrame` asserts that the shared event has retired the previous owner before resetting any
  cursor. The diagnostic names the slot, prior frame, bytes used, pages used, and retired frame.
- Failure of a lazy internal page allocation aborts recording with a diagnostic containing the
  requested block size and existing per-slot capacity. It is a fatal device-resource exhaustion,
  not caller misuse; command recording has no fallible partial-frame contract to recover through.
- Recording and allocation remain single-threaded per `CommandList`. Multi-threaded or secondary
  command recording is outside the milestone.

## 5. Backend mapping and shader contract

### Metal 4

Each page is one shared `MTL::Buffer` under the default CPU cache mode. A write-combined hint is
deliberately not used: `bindFrameData` writes small blocks scattered across caller-chosen
alignment strides rather than one streaming run, and on Apple silicon the hint maps the range
non-cacheable, which measured as the whole of a −32% fitting-workload regression (42.6 ns per
call, M3 Max) before it was removed; shared storage is coherent either way. The backend caches
the mapped CPU base, GPU base address, and capacity when the page is created, adds it to the
existing residency set once, and labels it with its frame slot and page index. `bindFrameData` copies to `cpuBase + offset` and
publishes `gpuBase + offset` through the frame's argument table. The hot path performs no native
resource creation, label lookup, or address query after a page exists.

### D3D12

The same public contract maps to a persistently mapped upload resource, or GPU-upload resource when
the adapter supports it, plus `GetGPUVirtualAddress`. A graphics or compute root CBV publishes the
aligned address through the backend's root-signature mapping. Ordinary upload memory is the
required portable floor; GPU-upload memory is an optimization, not a semantic requirement.

### Shared shader contract

M5.2 keeps the current buffer register indices and `ConstantBuffer<T>`-shaped Slang declarations.
It does not adopt the prototype's shader-pointer frontend, per-stage draw signature, bindless
table, specialization struct, or root-slot naming. The different backends may publish the address
through different native state, but shaders see the same typed block at the same RHI slot.

## 6. Static and persistent data

`bindBuffer` remains behaviorally unchanged. Mesh data, static pass data, prebuilt draw data, and
other resources whose contents survive frame boundaries remain ordinary `Buffer` objects and
incur no frame-arena allocation or copy. A renderer chooses between two non-overlapping intents:

- `bindBuffer(slot, buffer)` — bind already-owned reusable storage;
- `bindFrameData(slot, value)` — capture one temporary block for the open frame.

M5.2 does not infer static reuse by hashing uploaded bytes or deduplicate equal frame blocks. Such
work would add unpredictable CPU cost and obscure ownership; the caller already knows which data
is static.

## 7. Public header organization

The exported component is split by owner concept while preserving `RHI/RHI.h` as a convenience
umbrella. The intended leaf set is:

- `GpuAddress.h`, `Format.h`, `Buffer.h`, `Texture.h`, `Heap.h`, and `Sampler.h`;
- `ShaderLibrary.h`, `GraphicsPipeline.h`, and `ComputePipeline.h`;
- `Indirect.h`, `RenderPass.h`, `CommandList.h`, `Swapchain.h`, and `Device.h`;
- the existing focused `Result.h`, `Validate.h`, `CaptureSchema.h`, and Metal extension headers.

Closely coupled descriptors, enums, constants, and ranges live with their owning primary concept;
there is no catch-all `Types.h`. Leaf headers include only what their own declarations require and
use forward declarations where ownership permits. `Device.h` may depend on the creation
descriptors it accepts; `CommandList.h` may depend on the command vocabularies it records. The
umbrella contains includes only and declares no parallel surface.

Every leaf header compiles in isolation as both the first project include and the only RHI include.
Backend headers consume the narrowest practical leaf set, and public headers expose no Metal,
D3D12, or ImGui type. Existing callers may keep including `RHI/RHI.h`; changing every consumer to
leaf includes is not a condition of API correctness, though component and test code use narrow
includes where doing so proves the boundary.

## 8. Documentation policy for the split API

The existing public-API documentation convention remains binding. Each public type and operation
keeps a concise symbol-level `///` contract so IDE help and the Clang documentation checks remain
useful. Shared ownership, lifetime, slot, and failure rules live once on the owning class or type;
simple overrides use `@copydoc` or inherited documentation rather than repeating paragraphs.

The split does not introduce decorated section rulers. The `-` ruler remains exclusive to file
envelopes and the `=` ruler to implementation function boundaries. Longer rationale moves into
this spec or current architecture documentation; headers state the contract a caller must honor.

## 9. Migration and compatibility

All production renderer, app, engine, test-support, mock-device, and GPU-test call sites migrate in
one milestone. Untyped calls become typed calls wherever a concrete block type exists; raw byte
spans remain on the untyped overload. Static data stays on `bindBuffer` rather than being
mechanically converted.

`setUniforms` is removed from `CommandList`, the Metal backend, mocks, and tests before the exit
gate. No source-compatible wrapper remains. The frozen NoApi comparison host is archived at tag
`m5.1-noapi-evidence`; its last verified environment and evidence remain the M5.1 record rather
than a claim that the historical experiment is a supported rolling target.

## 10. Diagnostics and capture

- Every page has a stable label containing device, frame slot, and page index. Capture metadata
  records the page label, slot binding, offset, size, alignment, and returned GPU address for every
  `bindFrameData` call.
- Validation asserts pass scope, slot bounds, null or empty input, invalid alignment, allocation
  overflow, and frame-slot reuse before native calls execute.
- Backend test instrumentation counts page creations, pages and bytes used per slot, frame-data
  calls and bytes, and native address binds. These counters are test and capture evidence, not a
  permanent public performance-query API.
- Xcode captures must retain the same pass and resource readability as M5.1 and make every uploaded
  address traceable back to one labeled page range.

## 11. Performance evidence

The baseline is the maintained M5.1 production RHI at the accepted M5.2 implementation branch's
fork from `main`. Baseline and candidate executables use the same shaders, resources, draw order,
output oracle, compiler configuration, and timed region. The new harness is production-owned and
does not import implementation from the NoApi evidence tag.

The frozen workload set is:

| Case | Per-frame work | Purpose |
|------|----------------|---------|
| `F-FIT-512` | 512 draws, one changing 64-byte block per draw | incumbent ring fits; guards the normal hot path |
| `F-DYNAMIC-1024` | 1,024 draws, one changing 304-byte block per draw | reproduces the measured 512 KiB overflow shape |
| `F-DYNAMIC-4096` | 4,096 draws, one changing 64-byte block per draw | proves growth scales without per-draw objects |
| `F-STATIC-1024` / `F-STATIC-4096` | prebuilt reusable buffers, one bind and draw per item | guards M5.1's static-reuse finding |

Every case renders disjoint deterministic quads and verifies byte-identical baseline/candidate
readback. Dynamic blocks change as a deterministic function of frame and draw index so their work
cannot be hoisted out of the timed region. Static resources are created before timing and write
zero frame-data bytes.

Performance runs use release builds with validation and capture off. One repetition launches fresh
baseline and candidate processes back to back from one driver; order alternates AB/BA. There are 12
paired repetitions, each side running 16 warm-up and 256 measured frames. The statistic is each
side's median frame time and a two-sided 95% paired bootstrap interval over percentage deltas,
using M5.1's fixed-resample method. The timed region starts after the pacing wait and includes
arena reset, allocation, copy, binding, command encoding, and submit.

The acceptance thresholds are intentionally asymmetric:

- `F-DYNAMIC-1024` and `F-DYNAMIC-4096` each show at least a 25% CPU encoding win with the
  confidence interval excluding zero.
- The candidate's upper 95% confidence bound is no more than +5% on `F-FIT-512` and both static
  cases. Inconclusive data above that bound is rerun or investigated; it is not called a pass.
- After all three frame slots reach a workload's high water, measured frames create zero new arena
  pages or per-draw GPU buffers. Total page creation is bounded by retained high water per slot,
  not by draw count times frame count.
- One `bindFrameData` produces one public call, one copy, and no more than one native address bind.
  Static cases produce zero frame-data calls and bytes.

The milestone record publishes the environment, exact paired results, confidence bounds, binding
and allocation counts, and any deviation. M5.1's −96.2% graph result is historical motivation, not
a performance promise for this cleaner production workload.

## 12. Testing

- ADR 0009's `[checkpoint-a]` cases, tags, assertions, and tolerances remain unchanged and pass
  under `MTL_DEBUG_LAYER=1`.
- Header-isolation tests cover every new leaf and the umbrella. Include-policy checks verify that
  no backend or ImGui type leaks through the public surface.
- CPU tests cover typed and untyped validation, alignment arithmetic across page boundaries,
  oversized pages, exact cursor reset, and deterministic page reuse.
- GPU tests upload distinguishable blocks across multiple pages and at least twelve overlapping
  frames, then verify exact results and that no slot resets before retirement.
- Capture tests verify the range schema and stable labels. Existing renderer, graph, scene, copy,
  compute, indirect, transient, exposure, and bloom tests remain green.
- The full renderer runs under Metal validation in Sponza, Damaged Helmet, and MaterialLab, with
  manual/automatic exposure and bloom on/off paths represented.

## 13. Delivery stages

The later active implementation plan may decompose these further but must preserve this order and
the no-parallel-API exit:

| # | Stage | Delivers |
|---|-------|----------|
| 1 | Baseline and header boundary | Frozen production benchmark baseline; self-contained modular public headers with unchanged runtime behavior |
| 2 | Frame-data primitive | `GpuAddress`, paged three-slot arena, Metal binding, validation, capture metadata, and focused CPU/GPU tests |
| 3 | Atomic migration | Typed production call sites and mocks migrated; `setUniforms` and temporary compatibility removed |
| 4 | Evidence and conformance | Paired performance collection, allocation/binding counts, checkpoint A, full tests, policy, and validation runs |
| 5 | Current-state record | Architecture/frame documentation, milestone record, roadmap baseline, and active-plan closure |

## 14. Non-goals

Per the roadmap's M5.2 deferrals: bindless-resource migration; shader-pointer, root-signature,
resource, barrier, residency, or pipeline redesign; a general mapped-buffer or allocation API;
per-mip raster attachments; generation-checked handles; resident-size queries; a D3D12 backend;
and later rendering features.

Also out of scope: changing the NoApi evidence archived at `m5.1-noapi-evidence`, re-running or rewriting M5.1 evidence,
multi-threaded recording, arena shrinking, memory-budget eviction, cross-frame frame-data reuse,
automatic content deduplication, GPU-generated root blocks, and expanding `GpuAddress` into a
general replacement for `Buffer`.

## 15. Exit gate

The roadmap's M5.2 exit gate applies verbatim: checkpoint A passes unchanged; every public header
compiles alone and leaks no native types; all production callers use the new path; frame-data
growth creates no per-frame backing allocations after the three slots reach high water; static
bindings write no frame-data bytes; overflow workloads materially beat the old allocation path
while fitting and static workloads regress by no more than 5%; captures identify every uploaded
range; and three-frame reuse is clean under Metal validation.
