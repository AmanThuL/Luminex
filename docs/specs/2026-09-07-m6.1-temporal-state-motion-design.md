# M6.1 — Temporal State and Motion — Design Spec

**Date**: 2026-09-07
**Status**: Accepted
**Boundary authority**: `docs/roadmap.md` M6.1 and the M6 shared rules own the outcome,
deliverables, exit gate, and deferrals. This spec decomposes that boundary without expanding it;
where wording differs, the roadmap wins. M6.1 adds engine-owned temporal inputs and one diagnostic
history. It does not accumulate, upscale, or evaluate a display path; those are M6.2–M6.5.

## 1. Purpose

Nothing in the shipped frame remembers the previous one. The camera holds no previous pose, a
`DrawItem` carries one model matrix and no identity, and the only cross-frame GPU value is the
exposure feedback buffer. M6.1 gives the frame trustworthy motion: current and previous camera and
rigid-object transforms, jittered and unjittered matrices, a motion-vector target with a declared
convention, render and output extents, and one persistent history whose ownership and reset
reasons are explicit. A code-generated TemporalLab and a small fetched rigid-animation sample make
every claim reproducible. With temporal inputs off, the frame is declared exactly as M5.5 declared
it, so fixed-camera output stays byte-identical.

## 2. Adopted boundary and reference model

- **Opt-in in this slice.** A `SceneView::temporal.enabled` flag selects the temporal path. Off is
  the default for the editor and `--screenshot`; TemporalLab turns it on when selected. M6.2 flips
  the default when TAA ships.
- **Engine owns identity and previous transforms; Render owns camera history and GPU history.**
  `Scene` keeps each object's committed previous model matrix; `Renderer` keeps the previous
  camera state and the history texture. Nothing persists on the GPU that the Renderer does not own
  and import.
- **Previous means the previous declared frame.** The Renderer advances its temporal state at the
  end of `declarePasses`, so a frame skipped before declaration never becomes "previous". Scene
  objects advance when the App calls `Scene::commitFrame()` after a declared frame.
- **Unsupported deformation is invalid, never zero.** Skins and morph targets fail the glTF load
  with `Unsupported`; a `MotionClass::Invalid` draw writes the motion sentinel.
- **Additive RHI growth.** Multiple colour attachments are added as new fields; every existing
  caller and every `[checkpoint-a]` test source compiles unchanged.
- **Nothing encodes sRGB upstream of the display transform.** The temporal debug view runs after
  the display pass and writes display-domain pixels into the display target.

## 3. Temporal contract (`Source/Render/Temporal.h`)

Pure data and free functions, device-free, unit-tested.

```cpp
struct FrameExtents { uint32_t renderWidth, renderHeight, outputWidth, outputHeight; };
constexpr uint32_t kJitterSequenceLength = 16;
glm::vec2 haltonJitterPixels(uint32_t index);   // Halton(2,3) − 0.5, each axis in [−0.5, 0.5)
struct CameraFrameState {
    glm::mat4 view, projection, projectionJittered, viewProjection, viewProjectionJittered,
        inverseViewProjection;
    glm::vec2 jitterPixels; glm::vec3 position; float fovY, nearZ;
};
CameraFrameState buildCameraFrameState(const Camera&, const FrameExtents&, glm::vec2 jitterPixels);
enum class MotionClass : uint8_t { Rigid, Invalid };
constexpr rhi::Format kMotionFormat = rhi::Format::RG16Float;
```

- **Extents.** Render and output extents are equal in M6.1 and declared separately so M6.3 can
  diverge them without changing consumers. Motion UVs are relative to the render extent.
- **Jitter.** The jittered projection is `translate(2·jx/W, 2·jy/H, 0) · projection` in NDC with
  `(jx, jy)` from the Halton sequence in pixels, indexed by the Renderer's temporal frame counter
  modulo the sequence length. `temporal.jitterEnabled` false uses `(0, 0)`, and the jittered and
  unjittered matrices are then identical. No shipped pass consumes jitter in M6.1 beyond the scene
  and sky rasterisation; it exists so the motion convention can be verified to exclude it.
  *Amended 2026-09-07*: the sequence is 1-based (radical inverses at `index % 16 + 1`), and each
  axis falls strictly inside `(-0.5, 0.5)` rather than `[-0.5, 0.5)` — the corner sample at index 0
  would otherwise be the worst jitter in the set. See `docs/milestones/m6.1.md`.
- **Motion convention** (documented here and in `Shaders/Motion.slang`): the target
  `lmx.render.motion` holds `uvCurrent − uvPrevious`, both from *unjittered* clip positions, with
  `uv = ndc.xy · (0.5, −0.5) + 0.5` over the render extent (+y down, texture space). A consumer
  fetches history at `uv − motion`. The sentinel `kMotionInvalid = (+inf, +inf)` marks invalid
  motion; consumers test `isinf`, never compare against zero.
- **Motion class.** `DrawItem` gains `glm::mat4 previousModel` and `MotionClass motionClass`. A
  `Rigid` item reprojects through `previousModel`; an `Invalid` item writes the sentinel through
  a bit in `ObjectUniforms.flags`.

## 4. History ownership and reset (`Source/Render/TemporalHistory.h`)

```cpp
enum class HistoryResetReason : uint8_t {
    None, FirstFrame, TemporalEnabled, SceneChanged, ExtentChanged, ProjectionChanged, CameraCut };
struct FrameSignature { uint64_t sceneGeneration; FrameExtents extents; float fovY, nearZ;
                        bool temporalEnabled; };
HistoryResetReason deriveHistoryReset(const std::optional<FrameSignature>& previous,
                                      const FrameSignature& current, bool cameraCut);
```

- **Derivation** is pure and ordered: no previous → `FirstFrame`; previous had temporal off and
  current on → `TemporalEnabled`; then scene generation, extents, projection (`fovY`, `nearZ`),
  then the explicit cut; otherwise `None`. The Renderer records a signature every declared frame,
  temporal on or off, so re-enabling is distinguishable from the first frame.
- **Camera cuts are explicit events.** `SceneView::temporal.cameraCut` is raised by the Inspector
  button and consumed for one frame. Scene switches already change the generation. No motion
  heuristic guesses a cut.
- **The M6.1 history** is `lmx.render.historyColor`: one `RGBA16Float` texture at the render
  extent, Renderer-owned, created the first frame temporal is enabled and recreated by `resize()`
  under the caller's idle guarantee. Disabling temporal keeps the allocation (reported by
  `temporalStatus()`) rather than freeing under in-flight frames.
  *Amended 2026-09-07*: the history and motion targets are created with the scene targets, in
  `resize()` and so in `create()`, rather than on the first frame that enables temporal. The
  allocation is therefore permanent for the renderer's life and is reported by
  `TemporalStatus::historyBytes` whether or not any frame enables temporal; both functions already
  return a `Result`, so an allocation failure is reported rather than asserted inside
  `declarePasses`.
  Each temporal frame imports it
  with `previousUse = ShaderRead`, reads it in the reprojection diagnostic when the reset reason is
  `None`, and then overwrites it from scene colour with a copy pass, the same read-previous /
  write-current version chain the exposure buffer uses. After any non-`None` reason the read is
  skipped and the copy still runs, so the next frame is valid again.
  *Amended 2026-09-07*: `previousUse = CopyDestination`, not `ShaderRead`. The previous temporal
  frame's actual terminal access to the history is the commit copy that overwrote it; declaring a
  prior read would leave the cross-frame read-after-write unbarriered, since a prior read only
  orders ahead of this frame's first write, not its first read. See ADR 0013 and
  `docs/milestones/m6.1.md`.
- **Exposure keeps its policy.** Spec 9's feedback buffer already clears on scene change, extent
  change and enable, and ignores camera cuts and projection changes. That is the roadmap's "each
  history chooses" rule applied; M6.1 documents the mapping in `frame-pipeline.md` and leaves
  `App/ExposureReset.h` untouched. Driving both from one event is M6.2's job, where TAA needs
  exposure correction.
- **Status** is published as `Renderer::temporalStatus()`: last reset reason and the frame it
  applied to, the jitter index, whether history is valid, and history bytes.

## 5. RHI and render-graph growth

- **RHI** (`RenderPass.h`, `GraphicsPipeline.h`): `RenderPassDesc` keeps `colorTarget` as
  attachment 0 and gains `ExtraColorTarget extraColor[kMaxExtraColorTargets]` (target, clear
  colour, clear flag) with `extraColorCount`; `GraphicsPipelineDesc` gains matching
  `extraColorFormats` and count. `kMaxExtraColorTargets = 3`. Validation: extras require a primary
  colour target, colour-renderable formats, equal extents, and count within the limit; misuse is
  `LMX_ASSERT`, creation failure is `Result`. The Metal 4 backend maps index *i*+1 to
  `colorAttachments[i+1]`. `Validate::bytesPerPixel(RG16Float)` becomes 4 so tests can read motion
  back. A new `[gpu]` MRT smoke renders two attachments with distinct clears and fragment writes.
- **Graph** (`RenderGraph.h`): `PassDesc` keeps `color` and gains
  `std::vector<ColorAttachment> extraColor`, each producing its own next version; compile checks
  format and extent agreement and the limit; `GraphDump` prints extras in declaration order; the
  compiled record lists them as attachment uses. Existing goldens are unchanged because the
  temporal-off frame declares no extras.
  *Amended 2026-09-07*: `GraphDump` prints an extra as `color attachment[1]` (matching the existing
  `color attachment` vocabulary the primary already uses), not `color[1]`. See
  `docs/milestones/m6.1.md`.
- **Shaders.** `ScenePass`, `ScenePassAuto`, `Sky` and `SkyAuto` gain `vertexMainMotion` /
  `fragmentMainMotion` entry points in the same files, sharing a new `Motion.slang` module
  (`motionFromClip`, `kMotionInvalid`). The vertex stage carries unjittered current and previous
  clip positions; the fragment stage derives the motion and writes `SV_Target1`. Uniform blocks
  grow append-only: `PassUniforms` adds `viewProjUnjittered` and `previousViewProjUnjittered`;
  `ObjectUniforms` adds `previousModel`; `SkyUniforms` adds `previousViewProj` and
  `previousEyePos`. Static asserts and `registerUniformLayoutsForCapture` follow. Temporal-off
  pipelines keep the original entry points; SHA-256 screenshot parity is the check that the shared
  file did not disturb them, and twin files (the `ScenePassAuto` precedent) are the fallback if it
  did.

## 6. Passes

With temporal off, `declarePasses` is the M5.5 declaration. With it on:

| Pass | Kind | Declares |
|---|---|---|
| `lmx.pass.scene` | raster | colour + `lmx.render.motion` (extra attachment, cleared to 0); sky draws motion from the previous eye, rotation only |
| `lmx.pass.temporal.reproject` | compute | reads history, scene colour, motion; writes transient `lmx.render.temporalDiagnostic` (RGBA16Float: abs difference, alpha 0 when the history UV leaves the extent or motion is invalid). Declared only when history is valid; culled when no debug view sinks it |
| `lmx.pass.temporal.debugView` | raster (amended 2026-09-07, see below) | after `lmx.pass.display`; overwrites the display target with the Motion view (R,G = 0.5 + motion × 8, B = 0.5, invalid magenta) or the Reprojection view (grey = min(1, 4 × luminance of the difference), out-of-extent blue). Declared only when a view is selected |
| `lmx.pass.temporal.commitHistory` | copy | scene colour → history |

The shadow, exposure, bloom and display passes are untouched. Frame order is shadow, scene,
reproject, exposure, bloom, display, debug view, commit; the graph derives the barriers.

*Amended 2026-09-07*: `lmx.pass.temporal.debugView` is a raster pass, not compute. The display
target's `BGRA8Unorm` format carries no storage-write usage under this RHI's `isStorageFormat`, so
a compute pass cannot write it; a fullscreen triangle overwrites every texel identically and lands
the same encodings, since the display target is not an sRGB view. See ADR 0013 and
`docs/milestones/m6.1.md`.

## 7. Engine: identity, previous transforms, rigid animation, assets

- **Previous transforms.** `SceneObject` gains `glm::mat4 previousModel` and
  `render::MotionClass motionClass`. `Scene::resetMotion()` sets every previous model to the
  current one (called on activation); `Scene::commitFrame()` does the same after a declared frame.
  `Scene::view()` fills both into each `DrawItem`, so Inspector drags produce correct motion.
- **Rigid tracks.** `Scene` gains `SceneAnimation { std::vector<RigidTrack> tracks; double
  duration; bool loop; }` where a `RigidTrack` names an object index and holds time-sorted keys of
  world-space translation, rotation quaternion and scale. `Scene::animate(double seconds)` samples
  each track (linear translation and scale, slerp rotation, clamped at the ends, step keys held)
  and writes the object's transform through `decomposeTransform`. `Scene::advanceAnimation(dt)`
  advances `animationTime` with wrap when looping.
- **glTF animation.** The loader evaluates node TRS channels with LINEAR and STEP samplers through
  the existing flattened hierarchy by baking each animated object's *world* transform at 60 Hz over
  the clip's duration into a `RigidTrack`. CUBICSPLINE samplers, skins, morph targets, and
  non-decomposable animated transforms fail the load with `Unsupported`. Only the first animation
  is used.
- **Clock.** A fixed step of 1/60 s per declared frame while playing, never wall time, so
  captures and tests are deterministic. The App owns play state.
- **Camera track.** `Scene::cameraTrack` is an optional list of keys (time, position, yaw, pitch)
  sampled like a rigid track; the App follows it when enabled and the scene has one.
- **Assets.** `xmake setup` fetches, from the Khronos commit already pinned as `helmet_pin`,
  `Models/CesiumMilkTruck/glTF-Binary/CesiumMilkTruck.glb` (369,980 bytes, SHA-256
  `09371b34608116de5842d23abe260bf11acf3e1554daf334a647eb566eee5c49`, CC BY 4.0) with its
  `LICENSE.md` and `metadata.json` into `Assets/Fetched/CesiumMilkTruck/`, baking its textures like
  the Helmet, and `Models/InterpolationTest/glTF-Binary/InterpolationTest.glb` (7,952 bytes,
  SHA-256 `a86eb331b4a083715e75fe19a1f747eac5692d5b9ff120f1eaa457c23ba72bca`, CC0) with its
  license and metadata into `Assets/Fetched/InterpolationTest/` as a sampler-conformance fixture.
  Both keep the `.part` download and file-hash pattern. The truck registers as scene `milk-truck`
  (Sample role); InterpolationTest is test-only.

## 8. TemporalLab (`Source/Engine/TemporalLab.cpp`)

Deterministic and always available, scene id `temporal-lab`, Diagnostic role: a checkerboard
floor, a rotating cube, a sphere orbiting a static reference cube, a row of thin oscillating poles,
and one static object flagged `Invalid`. Every motion is authored as a looping `RigidTrack`; a
looping camera track dollies and pans slowly. Placement is specified numerically in the file
header, and `Tests/EngineSceneTests.cpp` verifies the geometric claims the way it does for
MaterialLab. Selecting it in the editor enables temporal inputs and the Motion view once.

## 9. App, Inspector, screenshot

- `EditorRenderSettings` gains `temporalEnabled`, `jitterEnabled`, `temporalDebugView`,
  `animationPlaying`, and `followCameraTrack`; `EditorShell::sceneView()` forwards them. The
  Rendering section gains a Temporal block: the toggles, the view combo, Play/Pause/Step/Reset
  time, a Camera cut button, and read-only status (last reset reason and frame, jitter index,
  history validity and bytes, the motion convention in one line).
- The frame loop calls `scene.advanceAnimation`, `scene.animate`, and the camera-track sampler
  before `declarePasses`, and `scene.commitFrame()` after it. A frame skipped for a missing
  drawable does neither.
- `--screenshot` gains `--frames N` (renders N frames, advancing the clock, writes the last),
  `--temporal` (enables temporal inputs), and `--temporal-view off|motion|reprojection`. These are
  how the roadmap's declared warmup and intermediate captures are produced.

## 10. Testing and evidence

- **Unit** (`[render]`, `[engine]`, `[app]`): Halton sequence values, bounds and period; jittered
  and unjittered matrices differ by exactly the NDC jitter and agree when disabled; the inverse
  round-trips; the reset derivation table including priority; previous-frame commit ignores skipped
  frames; a CPU motion oracle over a moved camera and a moved object; track sampling for linear,
  slerp, step, clamp and wrap; the loader rejects skins, morph targets and cubic samplers and
  bakes InterpolationTest's linear and step clips within tolerance; TemporalLab geometry claims;
  option parsing for the new flags.
- **Graph (FakeDevice)**: extra attachments validate, version and dump; a history import carries
  its previous use; the reprojection pass is culled without a sink; a new `frame-temporal.txt`
  golden alongside the unchanged existing goldens.
- **GPU** (`[gpu]`, Metal validation on): the MRT smoke; motion readback against the CPU oracle
  for camera motion, rigid motion, jitter on with a static scene (motion unchanged), and the invalid
  sentinel; a history lifetime stress that enables, disables, resizes and re-enables across more
  than three frames validation-clean; the `[checkpoint-a]` filter unchanged and green.
- **Runtime evidence** on Metal 4 Apple Silicon: `MTL_DEBUG_LAYER=1 xmake test Tests/gpu`; a
  240-frame validation-clean editor run in TemporalLab with the Motion view, a camera cut and a
  resize; TemporalLab and truck captures of raw, motion and reprojection views with the frame count
  declared; a GPU capture dumped to show the motion attachment and the history import.
- **Parity.** Fixed-camera 1280×720 screenshots of Sponza, Helmet and MaterialLab stay
  byte-identical to the M5.5 tip with temporal off.
- **Manual QA** (owner): the truck's wheels show motion in the Motion view and the body none while
  the camera is still; moving the camera colours the floor; a camera cut blanks the Reprojection
  view for one frame; dragging an object in the Inspector shows motion for that object only.

## 13. Non-goals

Per the roadmap, M6.1 does not accumulate history (TAA), upscale, control resolution, integrate
MetalFX, or evaluate EDR. It also does not add skinning, morph targets, cubic animation samplers,
a runtime node hierarchy, alpha-masked materials, automatic camera-cut detection, persistent scene
IDs, or a GPU scene table.

## 14. Exit gate

The roadmap M6.1 gate applies: camera and rigid motion reproject correctly; camera cuts, scene and
projection changes and resize invalidate predictably; persistent history imports and three-frame
retirement are validation-clean. In addition, with temporal inputs off, the frame declaration and
fixed-camera output are unchanged from M5.5, and `[checkpoint-a]` passes with its sources
unchanged.

*Amended 2026-09-07*: the checkpoint claim is that every `[checkpoint-a]` test case is unchanged
(the filter reports the same 1,856 assertions in 19 cases). The frozen subset's source files are
compiled from the same tree as everything else, so "unchanged sources" was never the property
being verified.
