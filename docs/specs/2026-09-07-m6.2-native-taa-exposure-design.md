# M6.2 — Native TAA and Exposure Stability — Design Spec

**Date**: 2026-09-07
**Status**: Accepted
**Boundary authority**: `docs/roadmap.md` M6.2 and the M6 shared rules own the outcome,
deliverables, exit gate, and deferrals. This spec decomposes that boundary without expanding it;
where wording differs, the roadmap wins. M6.2 adds native-resolution temporal accumulation and
exposure stability over the M6.1 temporal inputs. It does not upscale, control resolution,
integrate MetalFX, or evaluate a display path; those are M6.3–M6.5.

## 1. Purpose

M6.1 gave the frame trustworthy motion, a jittered rasterisation nothing consumes, and one history
that is a copy of the raw scene colour. Auto exposure resolves an instantaneous target with no
adaptation, and a change of exposure makes every history texel describe a different brightness
than the frame it is blended with. M6.2 turns those inputs into a stable moving image: a native
resolution TAA that reprojects, rejects, clips and accumulates; a per-pixel reactive weight for
content that must not accumulate; exposure that adapts at a bounded rate and a history that is
corrected for whatever exposure it was recorded at; and inspectable raw, reprojected and
accumulated signals. Scripted scenarios with tolerances frozen in this spec, before any
measurement, are what make the stability claim reproducible.

## 2. Adopted boundary and reference model

- **Three temporal states.** `SceneView::temporal.enabled == false` remains the pre-temporal
  frame, declaration for declaration and byte for byte what M6.1 declared, and stays the M5.5
  parity check. With it on, `TemporalSettings::reconstruction` selects `Raw` (motion, reactive,
  depth history and debug views are declared, the colour history receives a copy of the raw frame
  as in M6.1, and bloom and display read the jittered raw frame) or `NativeTaa` (the resolve pass
  runs, its output is the colour history, and bloom and display read it). `Raw` is the roadmap's
  raw bypass; it shares every input with `NativeTaa`, which is what lets a test compare the two at
  identical inputs, and switching between them needs no reset because both leave a real frame in
  the history.
- **The default flips in the App, not in the Renderer.** A default-constructed `TemporalSettings`
  still means off, so every test keeps explicit control. `EditorRenderSettings` and the screenshot
  options default to temporal on, jitter on, `NativeTaa` (ADR 0013's forward note).
- **Auto exposure stays opt-in.** Adaptation applies only in auto mode. History exposure correction
  applies in both modes, since a manual EV edit also changes what the history holds.
- **Exposure keeps its App-owned reset policy.** The M6.1 spec noted that driving the exposure and
  history resets from one event was M6.2's job. `TemporalSettings::sceneGeneration` bumps on any
  content change, so deriving the exposure reset from it would restart metering on every Inspector
  drag, a behaviour change spec 9 never asked for. Exposure correction in the blend absorbs the
  discontinuity an exposure reset frame produces, so the unification buys nothing this slice needs.
  `App/ExposureReset.h` is untouched; the deviation is recorded here and in the milestone record.
- **Engine owns identity and previous transforms; Render owns every history.** Unchanged from
  ADR 0013. The new reconstruction stage is Renderer-owned and imports everything it persists.
- **Nothing encodes sRGB upstream of the display transform.** The resolve runs on pre-exposed
  scene-linear colour; a debug view that shows a colour signal encodes it through the same tone map
  and transfer the display pass uses, after the display pass.
- **RHI growth is additive.** One new colour format; every existing field, signature and
  `[checkpoint-a]` test case is unchanged.

## 3. Reconstruction contract (`Source/Render/TemporalResolve.h`)

The stage the Renderer composes. It owns its pipelines, both history pairs and the recorded
terminal use of each slot, and the reconstruction status. The Renderer builds its inputs from graph
handles and per-frame values and routes its output; it never reads the stage's internals.

```cpp
namespace lmx::render {

enum class ReconstructionMode : uint8_t { Raw, NativeTaa };

/// Everything one temporal frame hands the reconstruction stage. Graph handles are this frame's
/// versions; values are this frame's, with the previous frame's where the algorithm needs both.
struct TemporalInputs {
    GraphTexture sceneColor;        // RGBA16Float, pre-exposed scene-linear, jittered raster
    GraphTexture depth;             // D32Float, reversed, this frame's slot
    GraphTexture previousDepth;     // D32Float, the other slot (previous declared temporal frame)
    GraphTexture motion;            // RG16Float, ADR 0013 convention
    GraphTexture reactive;          // R8Unorm, 0 accumulates freely, 1 rejects history
    GraphTexture history;           // RGBA16Float, previous slot, valid when resetReason == None
    GraphBuffer exposure;           // {applied, previous}, the version the scene pass read (§7)
    CameraFrameState camera;        // this frame
    CameraFrameState previousCamera;
    FrameExtents extents;           // render == output in M6.2
    HistoryResetReason resetReason;
    ReconstructionMode mode;
};

struct TemporalResolveOutputs {
    GraphTexture resolved;     // this frame's colour slot: the resolve's output, or the raw copy
    GraphTexture rejection;    // RGBA8Unorm transient, declared only when a debug view sinks it
    GraphTexture reprojected;  // RGBA16Float transient, declared only when a debug view sinks it
};

constexpr uint32_t kTemporalWarmupFrames = 16;   // one jitter period
constexpr float kBaseAlpha = 0.1f;
constexpr float kMaxMotionAlpha = 0.25f;
constexpr float kMotionAlphaPixels = 8.0f;
constexpr float kClipGamma = 1.0f;
constexpr float kDisocclusionTolerance = 0.05f;  // relative view distance
constexpr float kReactiveEmissiveScale = 4.0f;    // pre-exposed luminance mapped to reactive 1
constexpr rhi::Format kReactiveFormat = rhi::Format::R8Unorm;

} // namespace lmx::render
```

`TemporalStatus` grows by `ReconstructionMode reconstruction`, `uint32_t historyAge` (declared
temporal frames since the last non-`None` reason, 1 on the reset frame, saturating at 65535),
`bool warmupComplete` (`historyAge >= kTemporalWarmupFrames`), and `uint64_t depthHistoryBytes`.
`historyBytes` now reports both colour slots.

The named constants are frozen values every shader, test and document cites by name. Tuning one
during implementation is allowed; the milestone record states the final value and the reason.

*Amended 2026-09-08*: `TemporalInputs` also carries `GraphTexture colorSlot` — this frame's colour
slot, the handle `TemporalResolveOutputs::resolved` is a later version of, symmetric with `depth`/
`previousDepth`. `recordFrame` takes an added `bool historyValid`, since under `Raw` the
reprojection diagnostic reads the other colour slot only when it survived culling, and guessing
that conservatively in either direction would misstate a WAW edge as a WAR one. Both depth slots'
imports state `ShaderRead`, not `RenderTarget`: the resolve samples both depth slots every
`NativeTaa` frame, so that is their true terminal use, and it is what M6.1's shipped, validation-
clean depth-import rule already covers. The unused `nearZ` uniform was dropped from
`TemporalResolveParams`; both sides of the disocclusion comparison are depths in the *previous*
frame's clip space, so one near plane inverts both, and `nearZ` was never read. `declare()` is
handed the display version before the display pass that produces it has been declared, and relies
on the graph's topological (Kahn) schedule to still order the debug view after that producer —
verified sound by review, and pinned by the regenerated golden's pass order.

## 4. Histories, terminal uses and reset

- **Ping-pong by declared temporal frame parity.** Two `RGBA16Float` colour histories
  (`lmx.render.historyColor0`, `lmx.render.historyColor1`; sampled, storage-write) and two
  `D32Float` depth targets (`lmx.render.sceneDepth0`, `lmx.render.sceneDepth1`; render target,
  sampled). A temporal frame renders depth into slot `m_temporalFrame % 2`, reads the other slot as
  previous depth, and writes colour into slot `m_temporalFrame % 2` while reading the other. Under
  `NativeTaa` the resolve writes the slot directly, so there is no copy: this frame's resolved
  colour is the next frame's history. Under `Raw` the slot receives M6.1's
  `lmx.pass.temporal.commitHistory` copy of the raw scene colour, so the invariant holds in both
  modes: **every temporal frame's colour slot holds that frame's output.** The single
  `lmx.render.historyColor` goes away. A frame with temporal off renders depth into slot 0 and
  touches no colour history.
- **Allocation** follows ADR 0013: created with the scene targets in `resize()` (and so in
  `create()`), recreated under the caller's idle guarantee, permanent for the renderer's life,
  reported by `TemporalStatus`. `Renderer::depthTarget()` and `historyTarget()` return this frame's
  slot.
- **Imports state the recorded previous-frame terminal use** (ADR 0013). The colour slot read this
  frame was last written by the previous temporal frame's resolve (`StorageWrite`) or by its raw
  copy (`CopyDestination`); the depth slot read this frame was last a depth attachment
  (`RenderTarget`). The stage records a terminal use per slot, the way the Renderer records
  motion's today, so a mode switch between two frames imports the slot with the use the other mode
  actually left it in.
  *Clarified 2026-09-08 (ADR 0015)*: last writer and terminal access are distinct. Under
  `NativeTaa`, bloom and display sample the current colour slot after the resolve, so `recordFrame`
  records `ShaderRead` for both the resolved current slot and the sampled previous slot. Under
  `Raw`, the current slot ends as `ShaderRead` when `HistoryAge` samples it, otherwise
  `CopyDestination`; the other slot changes to `ShaderRead` only when a valid reprojection
  diagnostic reads it. Both depth slots import `ShaderRead` as clarified in section 3. These are
  the actual imports; the writer-use names above describe the producing pass. See
  `docs/decisions/0015-temporal-slot-terminal-access.md` for the complete table.
- **No new reset reason.** Switching reconstruction mode is not a reset: both modes leave a real
  frame in the colour slot, and the exposure correction in the blend accounts for the exposure it
  was recorded at. `HistoryResetReason` and `FrameSignature` are unchanged from M6.1.
- **Warmup** is `kTemporalWarmupFrames`. The Renderer counts `historyAge` on the CPU, in every
  temporal frame whatever the mode; the resolve stores a per-pixel count in the colour history's
  alpha channel (section 6), reading the previous count as `floor(history.a)`. A raw copy leaves
  alpha at the scene's coverage, which an opaque frame makes 1, so a `NativeTaa` frame after a
  `Raw` one counts from 1 per pixel while the CPU count keeps running; the per-pixel count is
  diagnostic, the CPU count is what `warmupComplete` and the tests use.

## 5. RHI and render-graph growth

- **RHI** (`Format.h`, `Validate.cpp`, `Metal4Common.h`): `Format::R8Unorm` — colour-renderable,
  sampled, `bytesPerPixel` 1, not a storage or swapchain format — mapped to
  `MTL::PixelFormatR8Unorm`. `[rhi][validate]` cases cover renderable, non-storage and readback
  size; a new `[gpu][rhi]` MRT case renders a `BGRA8Unorm` primary with `RG16Float` and `R8Unorm`
  extras (three attachments, within `kMaxExtraColorTargets`) and reads all three back.
- **Graph**: no new descriptor fields. The third attachment reuses `PassDesc::extraColor`;
  `GraphDump` prints it as `color attachment[2]` following M6.1's spelling. A compute pass reading a
  `D32Float` import through `shaderTextureReads` is already supported (the depth accessor test
  samples depth from compute); the graph derives the `RenderTarget → ShaderRead` transition.
- **Shaders.** `ScenePass`, `ScenePassAuto`, `Sky` and `SkyAuto`'s *motion* entry points gain a
  third output, `float reactive : SV_Target2`; the non-temporal entry points and pipelines are
  untouched, which is what M5.5 parity rests on. The scene fragment writes
  `saturate(luminance(emissiveTerm · preExposure) / kReactiveEmissiveScale)` where `emissiveTerm`
  is the value already added to `litColor`; the sky writes 0. Uniform blocks do not grow. The
  motion pipelines add `kReactiveFormat` as `extraColorFormats[1]`.

## 6. Passes and the resolve algorithm

With temporal off, `declarePasses` is the M6.1 off declaration. With it on:

| Pass | Kind | Declares |
|---|---|---|
| `lmx.pass.shadow` | raster | unchanged |
| `lmx.pass.scene` | raster | colour, `lmx.render.motion` (extra 0), `lmx.render.reactive` (extra 1, cleared to 0), depth into this frame's slot |
| `lmx.pass.temporal.reproject` | compute | M6.1's diagnostic, now reading the previous colour slot; culled without the `ReprojectionError` view |
| `lmx.pass.exposure.seed` | compute | every manual-mode temporal frame, and auto-mode reset frames: `previous = applied; applied = exp2(EV)` (section 7) |
| `lmx.pass.temporal.resolve` | compute | `NativeTaa` only: reads scene colour, both depth slots, motion, reactive, the previous colour slot (when `resetReason == None`), the exposure buffer; writes this frame's colour slot and, when a debug view sinks them, the rejection and reprojected transients |
| `lmx.pass.temporal.commitHistory` | copy | `Raw` only: scene colour → this frame's colour slot (M6.1's pass, now mode-gated) |
| `lmx.pass.exposure.clearHistogram/histogram/resolve` | copy/compute | unchanged shape; the histogram meters *raw* scene colour, keeping metering independent of the accumulation it corrects; the resolve gains adaptation (section 7) |
| `lmx.pass.bloom.*` | compute | read the resolved colour under `NativeTaa`, raw scene colour under `Raw` |
| `lmx.pass.display` | raster | the same choice of input as bloom |
| `lmx.pass.temporal.debugView` | raster | after display; section 8 |

Frame order: seed, shadow, scene, reproject, resolve or commit, histogram and exposure resolve,
bloom, display, debug view. The scene pass, the histogram and the temporal resolve all read the
exposure buffer at the version the seed left, so "applied this frame" means the same thing to all
three. The graph derives every barrier.

**`Shaders/TemporalResolve.slang`**, `computeTemporalResolve`, `[numthreads(8, 8, 1)]`, per
pixel, in this order. Each rejection stores a reason code; the first that applies wins.

1. **Motion dilation.** Fetch the motion of the closest-depth texel (reversed-Z: greatest) in the
   3×3 neighbourhood, so silhouettes reproject with the foreground's motion. `isinf` on either
   channel → *Invalid*.
2. **History position.** `historyUv = uv − motion`. Any component outside `[0, 1]` → *OffScreen*.
3. **Disocclusion.** Reconstruct the world position from this frame's depth at the pixel centre
   through `camera.inverseViewProjection` (unjittered), transform through
   `previousCamera.viewProjection` (unjittered) to the expected previous NDC depth, fetch the
   previous depth slot at `historyUv` (point sample), convert both reversed depths to view
   distances (`nearZ / d`), and reject as *Disoccluded* when
   `|previous − expected| > kDisocclusionTolerance · expected`.

   *Amended 2026-09-08*: both sides of the comparison dilate instead of point-sampling. The
   reconstruction uses this frame's closest depth (reversed-Z: greatest) over the 3×3 neighbourhood
   already fetched for motion dilation in step 1, and the previous depth is the closest of the 3×3
   around `historyUv`. Point sampling rejected 32% of thin-geometry texels every frame — a jittered
   thin edge flips sub-pixel coverage each frame, and a single texel on either side reports that
   flip as a disocclusion the geometry never had. Dilating only the motion side (as originally
   specified) also left the two halves of the test describing different surfaces. Only a 6× looser
   `kDisocclusionTolerance` (≈0.30) reached the thin-geometry stability tolerance with point
   sampling, and at that looseness the motion/ghosting tolerance passed by a hair.
   `kDisocclusionTolerance` stays 0.05. A surface genuinely uncovered has no near depth anywhere in
   its neighbourhood, so ghosting detection is unaffected.
4. **History fetch.** Five-tap Catmull-Rom on the previous colour slot at `historyUv`, then
   `history.rgb *= exposure[0] / exposure[1]` (applied over previous). Alpha carries the previous
   age.
   *Clarified 2026-09-08*: divide by the sum of the five retained tap weights after dropping the
   four corner taps. Without this normalization, diagonal half-pixel reprojection loses 1.5625%
   of a constant signal before clipping. The constant-radiance regression pins this behavior;
   the frozen scenario tolerances and resolve constants remain unchanged.
5. **Neighbourhood clipping.** Convert the 3×3 current colours to YCoCg; compute mean `μ` and
   standard deviation `σ`; clip the history toward the current colour against the box
   `μ ± kClipGamma · σ`. A history the clip moved by more than 1e-4 in any channel is flagged
   *Clipped* (a flag, not a rejection).
6. **Blend weight.** `alpha = lerp(kBaseAlpha, kMaxMotionAlpha, saturate(|motion · extent| /
   kMotionAlphaPixels))`, then `alpha = max(alpha, reactive)`, then `alpha = 1` on any rejection.
   Blend in scene-linear RGB with inverse-luminance weights: `wCurrent = alpha / (1 + Y(current))`,
   `wHistory = (1 − alpha) / (1 + Y(history))`, normalised. A pixel whose `alpha == 1` reports
   *Reactive* when no earlier reason applied.
7. **Output.** `rgb` as blended; `a = 1` on rejection, otherwise `min(previousAge + 1, 65535)`.
8. **Reset frames** (`resetReason != None`) skip steps 1–6, write the current colour with age 1,
   and read neither history. The kernel receives `historyValid` as a uniform; the pass binds the
   same textures either way.

The reason codes, in the order tested, are `None`, `OffScreen`, `Invalid`, `Disoccluded`,
`Reactive`, with `Clipped` a separate bit. They are defined once in `TemporalResolve.slang` and
mirrored by `TemporalResolve.h` for the debug view's legend and the tests' readback.

**Diagnostics** are two graph transients the resolve writes only when a debug view sinks them
(`writeDiagnostics` uniform, conditional `textureWrites` in the pass descriptor):
`lmx.render.temporalRejection` (`RGBA8Unorm`: R reason code / 255, G blend weight, B clipped flag,
A 1) and `lmx.render.temporalReprojected` (`RGBA16Float`: the exposure-corrected history after
step 4, alpha 0 where rejected). A frame without a debug view declares neither write.
`writeDiagnostics` is a mask: bit 0 enables rejection and bit 1 enables reprojected history.
Every store, including reset-frame stores, respects its own bit so a bound fallback stays unwritten.

## 7. Exposure adaptation and history exposure correction

- **Buffer layout.** `lmx.render.exposureBuffer` grows from one float to two:
  `{ float applied; float previous; }`. `applied` is what the scene pass multiplies by this frame;
  `previous` is what it applied on the previous declared temporal frame. The buffer is the single
  source of applied exposure in both modes, so the resolve never needs a CPU-remembered value that
  could disagree with what the GPU actually applied across a mode switch. `HistogramAccumulate.
  slang` and the auto scene/sky pipelines keep reading index 0. The CPU reference in
  `GpuExposureBloomTests.cpp` follows the layout.
- **Seed.** `ExposureSeed.slang` becomes a shift-and-set: `previous = applied; applied =
  params.exposure` with `params.exposure = exp2(exposureEv)`. It is declared on every temporal frame
  in manual mode (one thread, so the buffer always records the manual value the scene pass applies
  and the value before it) and on spec 9's reset frames in auto mode, where it is what restarts the
  loop. With temporal off in manual mode it is not declared, keeping the M6.1 off declaration
  exact; the enabling frame is a reset, so a stale `previous` is never read. `SceneView::
  exposureReset` keeps its meaning.
- **Adaptation in `ExposureResolve.slang`.** After spec 9's metering produces the instantaneous
  target `targetExposure`:

  ```
  evTarget  = log2(targetExposure)
  evApplied = log2(applied)
  rate      = evTarget > evApplied ? adaptUpStopsPerSecond : adaptDownStopsPerSecond
  evNext    = evApplied + clamp(evTarget − evApplied, −rate · dt, +rate · dt)
  previous  = applied
  applied   = clamp(exp2(evNext), exp2(evMin), exp2(evMax))
  ```

  A bounded step in stops per second rather than an exponential lerp, so settle time follows from
  step size and rate exactly, which is what a frozen tolerance needs. `dt` is the App's fixed
  1/60 s per declared frame, passed in `ExposureResolveParams`, never wall time. A rate of 0
  disables adaptation and reproduces spec 9's instantaneous behaviour. The one-frame lag stays:
  frame N+1 applies what frame N resolved.

  *Amended 2026-09-08*: rate 0 is implemented as a `rate > 0` guard that skips the log2/exp2
  round trip and reproduces the instantaneous result bit-for-bit, not as the literal
  `clamp(evTarget − evApplied, −0, +0)`, which would freeze exposure at whatever `applied` already
  held instead of disabling adaptation.
- **Settings.** `SceneView` and `EditorRenderSettings` gain `exposureAdaptUpStopsPerSecond = 3.0f`
  and `exposureAdaptDownStopsPerSecond = 1.5f`; `ExposureResolveParams` grows by `adaptUp`,
  `adaptDown`, `deltaSeconds` (append-only, `static_assert` updated). The Inspector's Exposure block
  gains the two sliders (0–16 stops/s).
- **Manual mode.** The seed runs every temporal frame, so a manual EV edit lands in `applied` with
  the value before it in `previous`, and the resolve corrects history on the frame the edit lands.
- **Mode transitions.** Auto → manual: the first manual frame's seed shifts the auto value the
  previous frame applied into `previous`, so the ratio is exact. Manual → auto: the enable
  transition is a spec 9 reset frame, whose seed shifts the manual value into `previous` and sets
  `applied` to the manual value, so the ratio is 1 and the first auto frame blends two frames at the
  same exposure. Scene switch and resize also reset the history, which makes their ratio moot.

  *Amended 2026-09-08*: the auto → manual correction ratio is exact only up to the adaptation step
  the transition frame itself takes (at most `rate · dt`, 0.05 stops at the default up rate, zero
  once auto has settled), because the auto resolve leaves index 0 holding the value the *next*
  frame applies, not the value the transition frame itself applied. Accepted as a limit; the
  discontinuity is bounded by the same rate that bounds every other adaptation step.

## 8. Debug views and the shared tone map

`TemporalDebugView` keeps `Off`, `MotionVectors`, `ReprojectionError` and gains:

| View | Encoding, written unencoded into the display target |
|---|---|
| `ReprojectedHistory` | the reprojected transient through `pbrNeutralToneMap` and `linearToSrgb`, so it compares side by side with the picture; rejected pixels blue |
| `RejectionMask` | flat colours: `None` black, `OffScreen` blue, `Invalid` magenta, `Disoccluded` red, `Reactive` yellow; `Clipped` adds 0.5 green |
| `BlendWeight` | grey = blend weight |
| `HistoryAge` | grey = `min(age / kTemporalWarmupFrames, 1)`, so white means warm |

`pbrNeutralToneMap` moves from `DisplayTransform.slang` into a `Shaders/Tonemap.slang` module that
`DisplayTransform.slang` and `TemporalDebugView.slang` import. The display pass's output must stay
byte-identical, which the temporal-off parity screenshots verify; twin files are the fallback if a
shared module disturbs it (the `ScenePassAuto` precedent).

The three signals the roadmap names are therefore: raw (`ReconstructionMode::Raw`), reprojected
(`ReprojectedHistory`), accumulated (the default `NativeTaa` picture).

## 9. Engine: emissive tracks and the TemporalLab sign

- `SceneAnimation` gains `EmissiveTrack { uint32_t objectIndex; std::vector<EmissiveKey> keys; }`
  with `EmissiveKey { double time; float strength; }`, held (step) between keys, clamped outside
  the range, sampled by `sampleEmissiveTrack`. `SceneObject` gains `float emissiveStrength = 1`,
  which `Scene::animate` writes from the track and `Scene::view()` multiplies into the draw item's
  authored `emissive` colour, so the authored colour is never overwritten. No glTF import; authored
  scenes only.
- **TemporalLab** gains an emissive sign: a `1.5 × 0.75` quad at `(0, 2.5, −6)` facing +Z, base
  colour dark grey, emissive `(1, 0.8, 0.3)`, whose `EmissiveTrack` alternates strength `0` and
  `4` every 3 s (period 6 s, dividing the 24 s clip). `Tests/EngineSceneTests.cpp` verifies the
  placement and the track schedule the way it does the other objects.
- TemporalLab's once-only editor defaults are removed: temporal and jitter are on everywhere now,
  and the scene opens showing the accumulated picture like every other scene.
  `TemporalEditorState::temporalLabDefaultsApplied` and the branch in `onSceneSelected` go, with
  their tests.

## 11. Testing and evidence

**Scripted scenarios** are `[gpu][temporal]` Catch2 cases at 320×180 over small in-test scenes,
reading back this frame's colour slot (`historyTarget()`) and the raw HDR target each frame. All
metrics use Rec. 709 luminance of pre-exposed linear values; "mean" is over the stated pixel set.
Measurement starts at frame 17 (after `kTemporalWarmupFrames`). The tolerances are frozen here,
before any measurement; changing one requires a spec amendment recorded in the milestone record
with the reason.

| Scenario | Frozen assertion |
|---|---|
| Static stability: checker floor and poles, camera still, jitter on, 32 frames | mean frame-to-frame |ΔY| of `NativeTaa` ≤ 0.25 × that of `Raw` over frames 17–32, and ≤ 0.005 absolute |
| Thin geometry: five 2 px poles over the floor | over pole pixels, `NativeTaa` mean Y ≥ 0.75 × the mean of the 16 `Raw` frames 17–32; the static-stability ratio holds over the same pixels |
| Motion and ghosting: a cube translating 4 px/frame over the checker | in the region the cube vacated over the last two frames, mean |Y(TAA) − Y(Raw)| ≤ 0.1 × the cube-to-floor luminance contrast; ≥ 50 % of pixels vacated this frame report `Disoccluded` in the rejection mask |
| Emissive step: a quad steps strength 0 → 4 at frame 24 | quad-centre Y(TAA) ≥ 0.9 × Y(Raw) on frame 24 and ≥ 0.95 × on frame 25 |
| Manual EV step: +2 stops at frame 24 | on frame 24, |mean Y(TAA) − mean Y(Raw)| ≤ 0.02 × mean Y(Raw) |
| Auto adaptation: target 3 stops above the seed, up rate 3 stops/s, dt 1/60 | applied exposure after 30 frames = seed + 1.5 stops within 1e-3 relative; after 60 frames equals the target within 1e-3 |
| Reset and warmup | on a `CameraCut` frame TAA equals Raw bit-exactly and `historyAge == 1`; `warmupComplete` first true on the 16th frame after; `Raw → NativeTaa` derives `None` and the first `NativeTaa` frame blends from the raw copy |
| Raw bypass | `Raw` with jitter off matches the temporal-off display output within 1 LSB per channel on the same frame |

**Other tests.**

- RHI `[rhi][validate]` and `[gpu][rhi]`: `R8Unorm` rules and the three-attachment MRT smoke.
- Graph (FakeDevice, `[render][graph]`): `frame-temporal.txt` regenerated (resolve, no commit,
  three attachments), new `frame-temporal-raw.txt`, `frame-temporal-off.txt` unchanged; the
  diagnostic transients are declared only with a debug view and the reproject pass is culled
  without `ReprojectionError`.
- Exposure (`[gpu][exposure]`): the CPU reference port matches the two-float layout, the
  shift-and-set seed, and the adaptation step for both directions and for rate 0; the manual-mode
  seed records an EV edit and the value before it.
- Unit: `sampleEmissiveTrack` hold/clamp; `--temporal` and `--temporal-view` parsing including the
  error cases; `TemporalStatus` age bookkeeping through reset, off, re-enable and mode-switch

## 14. Non-goals

Per the roadmap, M6.2 does not upscale, separate render from output extent in practice, control
resolution, integrate MetalFX, or evaluate EDR. It also does not add a sharpening stage, alpha
test or transparency, skinning, automatic camera-cut detection, exposure reset unification, glTF
emissive animation, history resurrection, or a virtual reconstruction interface; `TemporalInputs`
is the seam M6.4 will use.

## 15. Exit gate

The roadmap M6.2 gate applies: scripted static detail, thin geometry, motion and emissive/exposure
changes meet the tolerances frozen in section 11; resets and the declared warmup are reproducible;
the raw bypass remains a reference. In addition: with temporal off, the frame declaration and
fixed-camera output are unchanged from M6.1; every `[checkpoint-a]` test case is unchanged; and the
`NativeTaa` default runs validation-clean through resize and cut.
