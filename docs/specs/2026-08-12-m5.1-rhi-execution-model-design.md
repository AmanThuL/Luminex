# M5.1 — RHI Execution-Model Decision — Design Spec

**Date**: 2026-08-12
**Status**: Accepted
**Boundary authority**: `docs/roadmap.md` M5.1 owns the outcome, deliverables, exit gate, and
deferrals. This spec decomposes that boundary without expanding it; where wording differs, the
roadmap wins. Per the roadmap, this spec owns the concrete scales and prototype architecture, and
freezes the baseline, hypotheses, representative graph, bounded workloads, rubric, and adoption
thresholds before any result is measured.

## 1. Purpose

M5.1 runs a measured experiment that decides whether to retain, partially reshape, or replace the
object-shaped RHI with a smaller GPU-address-first interface honest to Metal 4 and D3D12. The
comparison target is the data-oriented "No Graphics API" model described by Sebastian Aaltonen's
[article](https://www.sebastianaaltonen.com/blog/no-graphics-api),
[extended presentation](https://www.youtube.com/watch?v=aQv9pUl9PBM), and SIGGRAPH course slides.
The render graph retains logical ownership regardless of the outcome: the experiment is about the
execution interface beneath it, not about who schedules, validates, or owns frames.

## 2. Method decisions

- **Constrained hybrid workload.** One distilled offscreen graph — not two graphs — carries a
  scene-pass slice replicating the complete production binding surface on synthetic assets.
  Histogram, bloom, and copy shapes stay distilled. Binding scale, indirect work, resize/lifetime,
  and hazards are separate bounded stress cases. `SceneLibrary`, asset loading, UI, the swapchain,
  and the full renderer are not ported.
- **Scored core is frozen.** Section 6 and section 7 define the scored workloads exactly — pass
  tables, resource descriptors, generation algorithms, case identifiers, frame schedules, and
  counts. Exploratory cases may be added during execution only if marked **unscored** in the
  evidence document; unscored results cannot influence the ADR. Where a frozen value is defined by
  reference to a production declaration, the workload manifest records the resolved value before
  measurement begins and a consistency test asserts it; such references are frozen rules, not
  latitude.
- **Gate-first, change-proportional judgment.** Both models are scored symmetrically for wins and
  regressions, with non-negotiable gates (section 10) applied before any benefit comparison, and
  the smallest production change that captures a proven win preferred over a larger one.
- **Production runtime untouched.** Production runtime sources and public contracts — `RHI/`,
  `Source/`, `Shaders/`, and existing tests — are not modified during M5.1. Build manifests may
  gain the non-default experiment targets, and the experiment may link production libraries; that
  is the only production-tree change.
- **Shader-side control.** The incumbent encoder uses production shaders and pipelines unchanged.
  The prototype uses an experimental binding frontend around the same shared Slang math modules
  (`Lighting`, `Encode`, `Shadow`, and the distilled compute kernels); only resource and root-data
  plumbing may differ. Where Slang's Metal output cannot express address-first binding, a
  hand-written MSL frontend wrapping the same math is permitted and the constraint is recorded
  under the mapping classification. Generated-code differences are accounted for in the pipeline
  dimension; the byte-identical parity oracle bounds math divergence at zero.
- **Integration.** All work accumulates on the existing outcome branch, renamed
  `spike/m5.1-execution-model` per `docs/conventions/commits.md`, and reaches `main` in a single
  pull request. The spec and plan are committed on that branch; nothing lands on `main` directly.

## 3. Baseline freeze

The incumbent is the maintained RHI and render graph as shipped by M5 — the production tree at the
outcome branch's fork point from `main`. The frozen checkpoint A suite (ADR 0009, the
`[checkpoint-a]` filter) must be green at the start and at the end of the milestone, run
unchanged. Any drift of production runtime sources during the milestone invalidates all collected
measurements and requires recollection from both encoders. Baseline measurements for every rubric
dimension come from the maintained-RHI encoder of the harness, built and measured identically to
the prototype encoder. The evidence document records hardware model, macOS build, Xcode and Metal
toolchain versions, and power/thermal conditions for every scored run.

## 4. Hypotheses

- **H1 — API surface**: the address-first model needs a materially smaller interface to express
  the same workloads.
- **H2 — CPU encoding**: it records the same frame with materially less CPU time.
- **H3 — Binding traffic**: it issues materially fewer binding calls and writes materially fewer
  binding bytes per frame.
- **H4 — Synchronization**: it expresses the same hazard set with fewer or simpler primitives at
  equal correctness.
- **H5 — Observability**: capture quality, validation, and failure behavior remain at least as
  usable (a gate as well as a hypothesis).
- **H6 — Mapping honesty**: it maps to Metal 4 and D3D12 with only recorded, bounded emulation
  and no load-bearing gaps.

## 5. Prototype architecture and target boundaries

- The experiment lives in a repository-root `Experiments/NoApi/` directory under namespace
  `lmx::noapi`, with non-default xmake targets, all `set_default(false)`; a plain `xmake` never
  builds them.
- **`NoApiProto`** — the prototype library. Links metal-cpp and `Source/Core` only; includes
  nothing from `RHI/`. This isolation rule applies to the prototype and its tests, not to the
  comparison host.
- **`NoApiTests`** — prototype-only tests (smoke, misuse death-tests on the prototype side).
- **`NoApiBench`** — the comparison host. It links both the production RHI and `NoApiProto`, and
  executes the shared workload manifest through two adapters: a maintained-RHI adapter (production
  headers permitted here and only here, plus the incumbent misuse death-tests) and a prototype
  adapter. The workload manifest library itself is API-neutral and includes neither `RHI/` nor
  `NoApiProto` headers.
- The prototype interface is a minimal GPU-address-first surface covering the roadmap's six areas:
  linear allocations returning GPU addresses; small root constant blocks passed by value or
  address with no per-draw descriptor objects; texture and sampler handles through one bindless
  table; pipelines compiled from Slang output (or the permitted MSL frontend of section 2); flat
  command recording with attachments declared at pass boundaries; explicit barriers and fences
  honoring three frames in flight; one residency set; labels on every object, `LMX_ASSERT` misuse
  behavior with context, deterministic creation-failure reporting.
- Prototype polish is not held to production standard, but structural regressions and unbounded
  productionization work are gate failures (section 10).
- **Disposal is frozen now, independent of the result**: `Experiments/NoApi/` is retained
  permanently as a non-default, explicitly `Frozen — non-normative` research artifact. It is not
  part of the production RHI, accepts no feature growth, and never becomes a parallel supported
  API. The closing ADR records its frozen status and the environment it was last verified in. If
  the decision adopts any production change, the M5.x migration is a clean implementation in
  production code; the experiment is never promoted wholesale.

## 6. Scored core — representative graph

One shared, API-neutral workload manifest defines the graph below. Before measurement begins, a
consistency test declares the same graph to the production `RenderGraph` and asserts that the
manifest's schedule and barrier expectations match the compiled `CompiledFrameRecord`; the graph
planner runs outside all timed regions. Both encoders execute this manifest through their
adapters; a readback oracle asserts byte-identical output every frame.

**Fixed parameters**: offscreen, no swapchain; scene extent 1024×1024; fixed seed 0x4C4D5835;
correctness runs are exactly 32 frames (frame indices 0–31) with parity asserted on every frame's
readback; performance runs follow section 8.

**Resources** (formats written as fixed values; entries marked *prod* resolve to the production
declaration they mirror and are recorded in the manifest before measurement):

| Id | Kind | Descriptor |
|----|------|-----------|
| R1 `shadow` | texture | 2048×2048 D32Float, depth target + sampled, 1 mip |
| R2 `sceneColor` | texture | 1024×1024 RGBA16Float, render target + sampled, 1 mip |
| R3 `sceneDepth` | texture | 1024×1024 D32Float, depth target, 1 mip |
| R4 `histogram` | buffer | 1024 B (256 × uint32), storage |
| R5 `exposure` | buffer | *prod* (mirrors the production exposure buffer), storage, persistent across frames |
| R6 `bloomA` | texture | 512×512 RGBA16Float, 3 mips, storage + sampled |
| R7 `bloomB` | texture | 512×512 RGBA16Float, 3 mips, storage + sampled |
| R8 `out` | texture | 1024×1024 RGBA8Unorm, render target + copy source, 1 mip |
| R9 `readback` | buffer | 4 MiB, copy destination, CPU-readable |
| R10 `emissiveStaging` | buffer ring | 3 × 16 KiB upload ring for the per-frame texture upload |
| Materials | textures | 64 materials × five 64×64 textures (t0 base color sRGB, t1 normal, t4 metallic-roughness, t5 occlusion, t6 emissive sRGB; formats *prod*), full box-filtered mip chains, generated from splitmix64(seed, material, texture, texel) |
| Shared IBL | textures | irradiance cube, prefiltered environment cube, DFG LUT; dimensions and formats *prod*, deterministic synthetic content from the same generator |
| Geometry | buffers | one shared indexed quad (4 vertices in the production vertex layout, 6 indices), uploaded once at init (unscored setup) |

**Passes** (exactly thirteen, executed P01–P13):

| Id | Kind | Definition |
|----|------|------------|
| P01 `fill.histogram` | copy | fillBuffer R4 := 0 |
| P02 `upload.emissive` | copy | buffer→texture copy, R10 frame slot → material 0's t6 mip 0, full 64×64; staging content is a deterministic function of frame index |
| P03 `shadow` | raster | depth-only into R1; all 1,024 draws; production shadow pipeline on the incumbent, equivalent frontend on the prototype |
| P04 `scene` | raster | the real slice into R2+R3, reversed-Z; 1,024 draws with the complete production ScenePass binding surface: per-draw uniforms b1 (mvp, model, normal matrix, uvTransform, albedo, roughness, metallic, emissive, flags) through a per-frame ring; per-pass uniforms b2; per-material t0/t1/t4/t5/t6; pass-shared t3=R1, t7 irradiance, t8 prefiltered environment, t9 DFG LUT; linear sampler and shadow comparison sampler. The sky is excluded by design (this is the opaque slice; the exclusion is frozen) |
| P05 `histogram.accumulate` | compute | reads R2 and R5 (previous frame's exposure — the frozen cross-frame feedback edge), accumulates 256-bin log-luminance histogram into R4 |
| P06 `histogram.resolve` | compute | single threadgroup; reads R4, writes this frame's exposure into R5 |
| P07 `bloom.threshold` | compute | reads R2, writes R6 mip 0 (512×512) |
| P08 `bloom.down1` | compute | R6 mip 0 → R6 mip 1 (256×256) |
| P09 `bloom.down2` | compute | R6 mip 1 → R6 mip 2 (128×128) |
| P10 `bloom.up1` | compute | reads R6 mips 2+1, writes R7 mip 1 |
| P11 `bloom.up2` | compute | reads R7 mip 1 and R6 mip 0, writes R7 mip 0 |
| P12 `composite` | raster | fullscreen triangle reading R2, R7 mip 0, and R5 (this frame's resolve) into R8, display-transform-shaped tone map |
| P13 `readback` | copy | texture→buffer copy R8 → R9 |

**Sinks**: R9 readback and the persistent R5 export. R5's cross-frame read in P05 is the
three-frames-in-flight feedback edge both encoders must implement under the production import
semantics.

**Draw and update policy (frozen algorithm)**: draw i ∈ [0,1024) instances the shared quad at
grid position (i mod 32, i div 32) in a 32×32 grid; material index = i mod 64, so every
consecutive draw switches material (binding-heavy by construction); scalar material parameters
derive from splitmix64(seed, i). The camera animates as a fixed function of frame index; object
transforms are static; material 0's emissive texture is re-uploaded every frame via P02. Per-draw
b1 blocks are rewritten every frame through each side's per-frame ring.

**Shader control**: P03/P04 use production `ShadowPass`/`ScenePass` pipelines unchanged on the
incumbent; P05–P12 use distilled kernels/shaders shared by both encoders. The prototype applies
its binding frontend to the same math modules per section 2.

## 7. Scored core — stress cases

**Binding scale** (`S-BIND`): quads at exactly 1,024 and 4,096 draws over 256 unique 64×64
RGBA8Unorm textures (texture index = draw index mod 256), one sampled texture plus one per-draw
root/uniform block per draw, 512×512 RGBA8Unorm target, no depth. Scored metrics: encode CPU time
and binding traffic at both scales.

**Hazard matrix** (`H01`–`H24`, exactly 24, all positive correctness cases asserting expected
readback values; per M5's recorded limit, the absence of a barrier is not a scored failure case).
Whole-resource cases on single-mip textures; per-mip cases address distinct mips of a 4-mip
256×256 texture. Producer/consumer kinds: R=raster, C=compute, T=copy.

| Ids | Cases |
|-----|-------|
| H01–H09 | RAW, whole resource, all nine ordered pairs (R→R, R→C, R→T, C→R, C→C, C→T, T→R, T→C, T→T) |
| H10–H13 | WAR and WAW, whole resource, for C↔C and R↔C |
| H14–H18 | RAW per-mip: C→C, C→R, R→C, T→C, C→T |
| H19–H22 | WAR and WAW per-mip: C↔C and R↔C |
| H23–H24 | RAW per-mip: R→R and T→T (distinct mips) |

Each case's exact resources, ranges, operations, and expected values are fixed in the workload
manifest before measurement.

**Upload and resize-lifetime** (`S-LIFE`): a frozen 12-frame schedule over extents E1=1024×1024,
E2=1536×864, E3=512×512 — frames 0–2 at E1, resize to E2 issued during frame 3 with frames 1–2 in
flight, frames 3–5 at E2, resize to E3 at frame 6, frames 6–8 at E3, resize to E1 at frame 9,
frames 9–11 at E1 — plus one mid-flight upload: frame 4 uploads new content to a texture consumed
by frame 4's own graph. Assertions: no use of a retired resource (validation clean plus
generation checks) and allocation counters settled by frame 11.

**Indirect** (`I1`–`I4`): I1 `drawIndirect`, CPU-written arguments at byte offset 256; I2
`drawIndexedIndirect`, arguments written by a prior compute pass at offset 0; I3
`dispatchIndirect`, CPU-written at offset 64; I4 `dispatchIndirect`, compute-written at offset
128. All readback-verified.

**Misuse** (`M1`–`M6`, exactly six, each a contract both interfaces own and validate; executed as
subprocess death-tests capturing the assert category and message on both sides):

- M1 pass-scope violation: dispatch recorded outside any compute pass.
- M2 usage mismatch: a texture created without storage usage bound for storage write.
- M3 view/range overflow: a view whose mip range exceeds the texture's mip count.
- M4 alignment violation: a binding offset violating the documented alignment contract.
- M5 invalid handle: use of a destroyed (or never-created) resource handle.
- M6 retired frame-slot use: reusing a per-frame allocation from a frame slot that has not been
  proven retired.

Graph-declaration validation is shared logic above both interfaces and is not a scored misuse
case.

## 8. Measurement protocol

- **Run separation**: performance runs use release builds with Metal validation and capture off.
  Correctness, misuse, and capture-checklist runs are separate executions with
  `MTL_DEBUG_LAYER=1` (and capture enabled where needed). Validation state never mixes within a
  run.
- **Paired protocol**: one repetition = one fresh process executing both encoders back to back;
  encoder order alternates by repetition parity (AB on even indices, BA on odd). Exactly 12
  paired repetitions per time metric. Each repetition: 16 warm-up frames then 256 measured
  frames; the repetition's statistic is the median per-frame value; the pair yields a percentage
  delta relative to the incumbent.
- **Decision statistic (time metrics)**: the claim is material only if the median of the 12
  paired deltas is ≥25% and the two-sided 95% bootstrap confidence interval (10,000 resamples,
  fixed seed) over the paired deltas excludes zero. The same rule defines material regressions.
- **Count metrics** (API calls, binding bytes, barrier counts, allocation counts, API surface):
  deterministic exact counts; material = ≥25% difference; no statistics needed.
- **Timed region**: begins after the frame-slot pacing wait completes; includes per-frame
  allocator reset, root/table/uniform/binding writes, command encoding, and the submit call;
  excludes pacing waits, one-time resource and pipeline creation, and readback waits. Binding and
  root-data work cannot be moved outside the timed region; each adapter documents where its
  per-frame work happens and the review gate checks it.
- **Pipeline compile and cache**: recorded as descriptive evidence only (cold = first compile in
  a fresh process; warm = recompile in the same process), with metallib versus runtime-MSL noted.
  Driver cache state is not reliably controllable, so this dimension never triggers adoption
  thresholds.
- **Environment**: every scored run records hardware model, macOS build, Xcode/Metal toolchain
  versions, power source, and thermal state at run start; all scored runs execute on AC power
  within one session per collection round.
- **Measurement freeze gate**: once scored collection starts, any change to the interface, the
  workloads, the shaders, or the instrumentation invalidates all previously collected scored data
  and requires full recollection from both encoders.

## 9. Rubric dimensions

- **Correctness**: byte-identical readbacks between encoders on the representative graph (every
  frame of the 32-frame run) and on every stress case claiming output.
- **Failure and validation behavior**: the M1–M6 death-tests, judged on determinism and
  diagnostic usefulness.
- **Capture quality**: a fixed checklist against an Xcode GPU capture of the representative graph
  on both encoders — passes labeled and grouped, resources named and inspectable, bindless
  indirection traceable to the textures it reaches.
- **API surface**: primary metrics are concept count (public types), operation count (public
  entry points), and caller-side ceremony (calls and arguments required per workload operation),
  counted over the interface subset each side needs for the scored workloads under the same
  counting rules; public-header line count is auxiliary evidence and never decisive alone.
- **CPU encoding**: the section 8 timed region.
- **Binding traffic**: binding-related API calls per frame plus **all** binding-purpose CPU bytes
  written per frame — root structs, argument/bindless table entries, handle arrays, and amortized
  table population.
- **Pipeline and cache behavior**: descriptive only (section 8).
- **Barriers**: count and kind of synchronization primitives each side needs for H01–H24 and the
  representative graph.
- **Allocation**: allocation call counts and resident bytes for the same workloads, including the
  prototype's own table/metadata/heap overhead; resident bytes are the sum of Metal-reported
  allocated sizes for every live heap, buffer, and texture the encoder created.

## 10. Gates and adoption thresholds (frozen)

Non-negotiable gates, applied before any benefit comparison; failing any gate fails the
alternative regardless of measured wins:

1. Correctness parity on everything the prototype claims to cover, including the three-frame
   lifetime rules.
2. Deterministic, diagnosable failure behavior on M1–M6 — no silent corruption.
3. Capture-quality checklist passes; the model remains debuggable in practice.
4. Honest mappings: no load-bearing **unknown** Metal 4 mapping; emulated paths recorded and
   bounded.
5. No permanent parallel API and no unbounded productionization work implied by adoption.

**Material win** and **material regression** are defined symmetrically by section 8's rules. Core
dimensions are CPU encoding, binding traffic, API surface, and barrier simplicity. Judgment is
change-proportional:

- **Retain** if no material win survives the gates, or results are inconclusive. Ties retain the
  incumbent.
- **Partial reshape** requires: at least one core-dimension material win capturable by a change
  bounded to one contract area preserving checkpoint A semantics; no material regression in any
  core dimension attributable to that bounded change; and the affected contract area's D3D12
  mapping classified native or bounded-emulated. Unknown or unavailable semantics may remain only
  behind retained incumbent contracts.
- **Replace** requires: material wins in at least three core dimensions; no material regression
  in any other core dimension; evidence that a smaller reshape cannot capture the wins; a
  D3D12 column with no load-bearing **unknown**, **unavailable**, or unbounded emulation; and a
  coverage matrix showing, for every checkpoint A semantic area, whether it is covered by the
  representative graph, a stress case, the paper mapping, or an explicitly recorded gap.

## 11. Mapping classification

Every prototype concept in the six areas of section 5 is classified for Metal 4 and for D3D12 as
**native**, **emulated**, **unavailable**, or **unknown**, with shader-language constraints
(including Slang → MSL limits) recorded alongside. The Metal 4 column is grounded in the
prototype; the D3D12 column is a documented paper mapping. Vulkan appears as an unscored
comparative column and carries no backend commitment.

## 12. Evidence artifacts

- A dated evidence document under `docs/research/` (frozen, non-normative) holds the mapping
  classification, all scored measurements with their uncertainty, unscored exploratory results
  clearly separated, rubric scoring, gate results, and the recorded environment.
- An ADR under `docs/decisions/` states the selected production direction — retain, partial
  reshape, or replace — against the frozen thresholds, records the experiment's frozen-artifact
  status and last verified environment per section 5, and, if production change is adopted, names
  the separately accepted M5.x migration the roadmap requires.
- `docs/milestones/m5.1.md` records shipped evidence and limits; the roadmap's current-baseline
  section updates; the active plan closes per `docs/conventions/documentation.md`.

## 13. Stages

The active plan under `docs/plans/` decomposes execution; in outline:

| # | Stage | Delivers |
|---|-------|----------|
| 1 | Model synthesis and mapping draft | Prototype interface definition distilled from the sources; workload manifest with resolved *prod* values and consistency test; draft Metal 4/D3D12 classification |
| 2 | Prototype core | The address-first Metal 4 implementation of section 5 |
| 3 | Harness and representative graph | Both adapters over the shared manifest, parity oracles, the 32-frame correctness run |
| 4 | Stress cases and measurement | Section 7 cases, section 8 protocol, all scored collection |
| 5 | Judgment and record | Evidence document, scoring against section 10, the deciding ADR, milestone record |

## 14. Non-goals

Per the roadmap's M5.1 deferrals: a production D3D12 backend, Vulkan/Linux support, multi-queue
optimization, ray tracing, production interface migration, and later rendering features.
Additionally out of scope: any modification to production runtime sources or public contracts
during the milestone, porting `SceneLibrary`/assets/UI/swapchain into the experiment, and any
scored workload beyond the frozen definitions above.

## 15. Exit gate

The roadmap's M5.1 exit gate applies verbatim: checkpoint A stays green; the prototype reproduces
the output, failure behavior, and three-frame lifetime rules it claims to cover; all emulation,
fallback, shader constraints, gaps, and risks are recorded; evidence is judged against the frozen
thresholds; an ADR selects one production direction and disposes of the experiment. M5.1 does not
migrate production: any adopted change requires a separately accepted M5.x migration completed
before M6, with no parallel API left.
