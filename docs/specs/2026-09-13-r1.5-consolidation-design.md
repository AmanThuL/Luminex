# Shared Primitives and Responsibility Boundaries

**Status**: Implemented (2026-09-13)

This design follows the [initial milestone record](../milestones/r1.5.md) and implements every
item in the [R1.5 boundary](../roadmap/codebase-module-boundaries.md#r15--consolidation-and-decomposition)
under [ADR 0020](../decisions/0020-module-layering-and-units.md). Implementation follows the plan.

## Shared primitives

Core owns whole-file byte reading, JSON string escaping without framing, whole-string numeric
parsing, two distinctly named alignment contracts and one integer ceiling division helper.
Each extraction requires existing consumers sharing its contract. Preserve binary read failure
and empty-file handling at the caller boundary. Preserve JSON escaping bytes, including control
characters and non-ASCII input; object/array formatting remains domain-owned. Parsing primitives
only accept complete numeric strings; positivity, bounds and finiteness remain caller decisions.
Keep power-of-two alignment distinct from general alignment with zero treated as identity, with
tests pinning their difference. CaptureSchema retains its atomic writer; other writers keep their
existing truncation behavior. No cross-domain error hierarchy is added.

## Implementation responsibilities

Renderer composes exposure, bloom and display stage owners beside the existing draw stages.
Resource/history ownership and pass declaration order stay explicit at the composition root.
RenderGraph separates declaration/execution, compilation and lifetime assignment, transition
derivation and validation, sharing private implementation declarations only where necessary.
TemporalResolve separates native, upscale and vendor declaration responsibilities while retaining
one history owner and its existing kernel-selection/reset rules. RenderGraphPanel separates the
node canvas, selection details and record dumping from window coordination. Borrowed callback
inputs remain valid through graph execution and GPU resource destruction boundaries are unchanged.

Split RenderGraphTests, GpuTemporalTests, RHIValidateTests, scene tests and GpuRendererTests by
the behavior each tests. Keep every test name, tag, assertion and checkpoint-A selection; shared
test fixtures belong to test-owned headers. Source moves do not justify renamed cases.

## Header visibility and build ownership

The module contract explicitly enumerates private headers for each unit. Cross-unit inclusion,
including transitive reach through an exported header, is rejected. Existing exported headers
remain public when another unit uses or transitively requires them; location alone grants no
visibility. Test the checker with same-unit, foreign direct/transitive and malformed/stale entries.

Root xmake retains project configuration and includes. Setup and reusable rules/tasks live under
`xmake/`; each project unit owns a local `xmake.lua`. Preserve target names, dependency closures,
public package exposure, output directories, source membership and existing setup pins/patches.
AppModel sources compile once; Tests continue linking libraries and relink after library changes.

## Shader structure

Move shared Slang modules to `Shaders/Modules/` and test oracles to `Shaders/Tests/`. Entry-point
filenames and runtime artifact paths stay unchanged. Add module import search paths, recursive
dependency tracking and basename-collision rejection. A policy checker allows entry points and
modules to import only modules, and rejects unresolved imports and production-to-test edges.
Document the existing twin variant pairs and their sole intentional differences in shader style;
deduplication and generated source rewriting remain deferred.

## Acceptance

The planned acceptance uses the roadmap comparison protocol with eight paired rounds maximum
and no new exception.
Compare all existing cases/tags, validation-clean GPU/checkpoint runs, byte artifacts and semantic
captures. A clean build must preserve generated MSL after dropping only `#line` directives and the
metallib inventory. An imported-module edit must rebuild all importers; a restored source must
restore generated output. Verify runtime-MSL fallback with metallibs absent in an isolated copy,
unchanged runtime paths, target closures, single AppModel compilation and Tests relinking.
No performance or gate B approval follows from this structural slice.

All five groups are implemented. At the fixed cap, two candidate-only image hashes remained
unexplained; on 2026-09-13 the owner explicitly accepted a
[slice-specific integration exception](../milestones/r1.5.md#integration). The strict comparison
remains failed, with all evidence intact and no relaxation of later slices' validation.
