# M7.1 — GPU Scene Foundation

**Status**: Frozen — non-normative

This is the milestone's design specification, prepared before implementation. It summarizes the
intended behavior and verification and becomes the evidence record at closure. The
[roadmap](../roadmap/gpu-driven-hybrid-rendering.md#m71--gpu-scene-foundation) owns the outcome,

owns the identity and update semantics this design implements. Where wording differs, those win.
No M7.1 implementation, plan or acceptance result is recorded yet.

## Objective and baseline

Existing scenes draw correctly from shared GPU identities and tables through the retained CPU draw
path. The baseline is [M6.5](../milestones/m6/m6.5.md) plus R1 and [UX1](../milestones/ux1.md), entered under
[interface gate B](../milestones/m6/interface-gate-b.md). Today `Scene::view` rebuilds a frame-local `DrawItem` span
with borrowed mesh pointers, a copied material per draw and per-object previous transforms;
`ShadowStage` and `SceneStage` upload a 368-byte `ObjectUniforms` block per draw, bind five
material textures per draw and select pipelines by alpha mode, double-sided flag, exposure source,
motion and wireframe. Nothing in the frame has a stable identity: object index, draw position and
CPU pointer are the only names. This slice replaces where per-draw inputs come from, not their
meaning: scene-linear materials, pre-exposure, masked coverage (ADR 0018), the motion convention
(ADRs 0013–0017) and the display boundary (ADR 0019) are unchanged.

## Intended implementation

### Identities and scene records

`Source/Scene/SceneIds.h` defines four distinct handle types, `InstanceId`, `MeshId`, `MaterialId`
and `TextureId`, each `{uint32_t slot, uint16_t generation, uint16_t store}`. The store value comes
from a per-process counter assigned when a `Scene` is constructed, so a handle from a replaced
scene is rejected by any other scene. Removing an entity increments its slot's generation, so a
stale handle never resolves to a later occupant. `Scene` offers one checked query per handle type
that reports an unresolvable handle instead of dereferencing it; every other call that takes a
handle asserts on one, so an invalid reference is caught before any GPU access. Row index equals
slot index for the entity's life, so identities never relocate and no per-frame remap table exists.

`Scene` keeps `objects` as the dense authored list the editor and playback index today; each
`SceneObject` gains its `InstanceId`, and `SceneSession` keeps editing by editor index. Meshes,
textures and materials move behind the scene's identity store and are reached by handle:
`addMesh(render::MeshData, label) → MeshId`,
`addTexture(std::unique_ptr<rhi::Texture>) → TextureId`, `addMaterial(MaterialRecord) → MaterialId`,
`addObject(SceneObject) → InstanceId`,
`removeObject(InstanceId)`, `finalize(rhi::Device&)`, `prepareFrame(uint64_t frameNumber)`,
`view(...) const`, `commitFrame()` and `tableStats() const`. `MaterialRecord` is today's
`render::Material` with optional `TextureId`s instead of texture pointers. Removing a texture still
referenced by a live material is misuse. The glTF loader, San Miguel, MaterialLab, TemporalLab and
the shared environment build through these calls; `SceneLibrary` and the catalog are unchanged.

Draw order remains object order, which is deliberately not row order: after a removal, later
objects keep their rows while their draw positions shift, which is the identity-independence
ADR 0021 requires. The editor's selection index and `SelectionOutline`'s draw position stay
editor-local, as UX1 recorded.

### Shared row vocabulary and geometry pool

`Source/Render/SceneTables.h` and the module `Shaders/Modules/SceneTables.slang` own the row
layouts, flags and slot constants that Scene produces and the stages consume. The module declares
structs and constants only; entry shaders declare the resources at their own slots, following the
existing module rule. Fixed-width mirrors carry `static_assert` size and offset checks, and
`registerUniformLayoutsForCapture` publishes them to `rhi::debug::CaptureSchema`.

| Row | Fields (byte offset) | Size |
|---|---|---|
| `InstanceRow` | model (0), previousModel (64), normalMatrix as 4×4 (128), meshRow (192), materialRow (196), flags (200), emissiveScale (204) | 208 |
| `MaterialRow` | uvTransform (0), albedo (64), emissive (80), roughness (92), metallic (96), occlusionStrength (100), alphaCutoff (104), flags (108) | 112 |
| `MeshRow` | firstIndex (0), indexCount (4), firstVertex (8), vertexCount (12) | 16 |

Instance flags carry `kInstanceMotionInvalid`; material flags carry `kMaterialHasNormalMap`,
`kMaterialMasked` and `kMaterialDoubleSided`. `emissiveScale` keeps the per-instance emissive
strength that `Scene::view` folds into the copied material today; the shader multiplies the
material's emissive by it, the same single product as now. `normalMatrix` stays a CPU-computed
inverse transpose stored as 4×4 for one unambiguous layout in both constant and structured storage.

Each scene owns one geometry pool: a single vertex buffer and a single index buffer built at
`finalize` from every added mesh, including the sky sphere, which becomes a mesh row with no
instance. Indices are rebased at merge time, so `gVertices[vertexId]` is unchanged and
`baseVertex` is zero; the retained CPU path draws with the existing `drawIndexed(indexBuffer,
indexCount, firstIndex)`. The pool is immutable after `finalize`; appending geometry later is
residency scope (M11), and adding a mesh after `finalize` is misuse. `render::Mesh` and
`createMesh` are retired once their last consumer moves.

Textures stay scene-owned `rhi::Texture` objects and are not descriptor indices. `view()` resolves
each material's optional `TextureId`s to `rhi::Texture*` or null, and the stages keep substituting
the Renderer-owned white, flat-normal, black-cube and zero-DFG fallbacks per draw, exactly as now.
`kMaterialHasNormalMap` is set only when the normal texture resolves.

`SceneView::items` becomes a frame-local span of `{instanceRow, MeshRow, resolved texture
pointers, alphaMode, doubleSided}` plus a `SceneTables` binding: the five `rhi::Buffer` pointers
for the slot in use and their row counts. `SceneView::skySphere` becomes the sky mesh row.

### Update, growth and retirement

This is the concrete safe update mechanism ADR 0021 requires: paced per-slot tables.

- The RHI gains `BufferDesc::cpuWrite` and `Buffer::write(offset, data, size)`. `write` requires
  `cpuWrite`, checks the range, and states the same precondition as `readback`: no submitted
  command list may still read the written range. The Metal 4 backend already allocates every
  buffer Shared, so `write` is a bounds-checked `memcpy` into `contents()`. The portable meaning
  is host-visible upload memory; a backend with discrete memory serves GPU reads from that memory
  or copies internally. `Validate` rejects `write` on a buffer created without the flag, and the
  public header records that this is the first consumer and the justification.
- Instance, material and mesh tables each own three slot buffers, one per frame in flight,
  created with `cpuWrite`. `Scene::prepareFrame(frameNumber)` runs after `Device::beginFrame` and
  before frame declaration; the slot is `frameNumber % 3`, and the device's pacing is the proof
  that the slot's previous frame retired, the same proof `Metal4FrameArena` and `TransientPool`
  rely on. It recomputes instance rows from `objects` and material rows from the material
  records, compares them with the CPU shadow copy, sets three dirty bits on any changed row, and
  writes only rows dirty for this slot before clearing that bit; mesh rows are written once at
  `finalize`. A static scene converges to zero writes after three frames; an
  animated scene writes only the rows that moved plus their promoted previous transforms.
- `commitFrame` promotes `model` to `previousModel` on the CPU records only when the frame was
  accepted, as today; the next `prepareFrame` picks up the change. Skipped frames commit nothing.
- A new instance seeds its previous transform from its own transform, so a reused slot never
  inherits the removed entity's motion; identity continuity therefore never needs a history reset,
  and scene switching keeps its existing `sceneGeneration` reset (ADR 0013). Table relocation does
  not occur, so it can never be mistaken for a scene change.
- Initial capacity is the count at `finalize`, rounded up to a small minimum; growth doubles the
  capacity, allocates three new slot buffers, marks every row dirty for every slot and moves the
  old buffers to a deferred-release list with `releaseAtFrame = lastFrame + 3`, the
  `TransientPool` rule. `prepareFrame` releases what has retired. Destroying a `Scene` still
  requires the owner's `Device::waitIdle`, as `EditorShell::selectScene` already performs;
  `SceneLibrary` never destroys a built scene today, so no new call site appears.
- The Renderer imports the five buffers of the slot in use each frame as named read-only
  resources (`lmx.scene.vertices`, `.indices`, `.meshes`, `.instances`, `.materials`) and the shadow
  and scene passes declare them as buffer reads, so the compiled record, graph dumps and Render
  Graph window show them. Nothing on the GPU writes them in M7.1, so no previous use is recorded
  and no barrier is derived; a GPU writer (M7.3) records terminal uses like the exposure buffer.

### Stage and shader consumption

The per-draw frame-data block shrinks to `DrawUniforms {uint32_t instanceRow; uint32_t padding[3];}`.
Vertex shaders compute `mul(gPass.viewProj, mul(instance.model, position))` from the instance row,
read the previous transform, motion flag and normal matrix from the same row, and the fragment
shaders read material factors, cutoff and flags from the material row. This changes floating-point
rounding relative to the CPU-precomputed `mvp` and is why the comparison rule below is
tolerance-based. M7.2's indirect baseline replaces `DrawUniforms` with `firstInstance`.

| Pass | Buffer slots | Textures | Samplers |
|---|---|---|---|
| Scene (all four twins) | 0 vertices (once per pass), 1 `DrawUniforms`, 2 `PassUniforms`, 3 exposure override (auto twins), 5 instances, 6 materials | 0 diffuse, 1 normal, 2 sky, 3 shadow, 4 metallic-roughness, 5 occlusion, 6 emissive, 7 irradiance, 8 prefiltered, 9 DFG | 0 linear, 1 shadow, 2 IBL |
| Shadow (both entries) | 0 vertices, 1 `DrawUniforms`, 2 `ShadowPassUniforms {lightViewProj}`, 5 instances, 6 materials | 0 diffuse (masked) | 0 linear (masked) |
| Selection mask (editor) | 0 vertices, 1 params, 5 instances, 6 materials | 0 diffuse (masked) | 0 linear |

`AlphaMaskParams` and buffer slot 4 are removed; `Shaders/Modules/AlphaMask.slang` becomes a pure
function taking the cutoff from the material row. Pipeline selection is unchanged: alpha mode,
double-sided flag, exposure source, motion and wireframe stay permutation axes read from the
CPU-side item, and cutoff stays data. The four `ScenePass` twins, both shadow entries and
`SelectionMask` are edited in lockstep under the shader-style twin rule; no deduplication happens
here, since the [refactoring roadmap](../roadmap/codebase-module-boundaries.md#later-refactoring-milestones)
opens that candidate only after this slice settles the binding model. `SelectionMask` reads the
same rows and composes position the same way so the outline stays consistent with scene depth.
Sky, exposure, bloom, temporal and display passes are untouched. `Renderer::declarePasses` and
`FrameDeclaration` keep their order; the editor and screenshot loops call `prepareFrame` between
`beginFrame` and declaration through `SceneSession`.

### Diagnostics

`Scene::tableStats` publishes `SceneTableStats`: instance, material and mesh counts and
capacities, vertex and index bytes, rows and bytes written last frame, the slot in use, growth
events and buffers pending release. `SceneSession` exposes it, and the Rendering Inspector's
Display & Details gains a read-only "Scene tables" block with the UX1 field helpers; formatting is
CPU-testable AppModel logic. Growth and retirement log at INFO through the Console. No new CLI
option, capture field or lab scene is added.

## Verification plan

### Fixtures

GPU fixtures under `[gpu][scene-tables]` turn the ADR 0021 requirements into checks, each rendering
through the real stages into readback targets and asserting pixels or readback rows:

- **Identity sharing:** two instances share one mesh and one material; their handles differ, their
  rows differ, and moving one leaves the other's previous transform and motion untouched.
- **Update and reorder:** editing transforms and removing an earlier object leaves later objects'
  rows and handles valid, draws them at new positions, and renders the same image as a scene
  authored without the removed object.
- **Remove and reuse:** a removed handle fails resolution; a new object reuses the slot with a new
  generation, seeds its own previous transform, and its first frame writes zero motion.
- **Scene replacement:** two scenes alternate across frames without `waitIdle`; a handle from one
  is rejected by the other; the old scene is destroyed after `waitIdle` while the new one keeps
  rendering the expected image.
- **Texture fallback:** a material with null textures shades to the factor-only result today's
  fallbacks produce, and a stale `TextureId` is rejected before any bind.
- **Capacity growth:** objects added past the initial capacity across frames render correctly,
  existing rows keep their values, the old buffers release exactly three frames later, and
  `tableStats` reports the growth.
- **Three-frame overlap:** four or more consecutive frames each edit one instance without
  `waitIdle`; each frame's image reflects that frame's transform, and per-slot readback after the
  run shows each slot holding the rows of the last frame that used it.
- **Row ABI:** a compute oracle copies every field of one instance, material and mesh row into a
  readback buffer; the values match the CPU mirrors byte for byte, and a CPU test pins the
  registered capture-schema layouts.
- **RHI write:** `Buffer::write` round-trips through readback, rejects buffers without `cpuWrite`
  in validation, and is exercised under `MTL_DEBUG_LAYER=1`.

`Tests/SceneTableTestSupport.h` builds tiny scenes through the production `Scene` calls; the GPU
suites that construct `DrawItem`s directly today migrate to it while keeping every case name, tag
and assertion, including the masked-coverage cases in `GpuAlphaMaskTests` and the motion-class
cases in `GpuTemporalMotionTests`. These migrated cases are the "masked coverage and motion
classes agree with the pre-table path" evidence: their expected coverage counts and motion values
are unchanged.

### Output preservation and comparison rule

Parent and candidate release binaries are frozen on the same device before and after the change,
with raw evidence outside the source tree. The unchanged fifteen-case strict matrix runs paired on
both and is reported in full; because vertex math moves to the shader, exact hash agreement is
expected to fail and is not the gate. `reference.json`, the strict runner and every golden
tolerance stay unchanged.

The gate is a new `Tools/Screenshots/compare.py` that compares each candidate image with its
parent counterpart and reports differing pixels, pixels whose largest channel delta exceeds
8/255, maximum channel delta and mean absolute delta, with self-tests. The frozen thresholds,
chosen here before any measurement, are at most 1.0% of pixels differing at all and at most 0.05%
of pixels differing by more than 8/255 in every one of the fifteen images. A failing image is
recorded as a failure with its numbers; thresholds are never loosened after measurement, and any
exception is the owner's explicit decision. A paired TemporalLab motion-target readback at frame
32 must agree within 1/4096 UV, and the three-frame TemporalLab sequence is captured on both
builds and compared frame by frame under the same thresholds, with its manifest retained.

### Regression inventory

Build, `xmake test`, the GPU suite under `MTL_DEBUG_LAYER=1`, format, `xmake policy` with the
module, header, comment and shader-import checks, and the unchanged `[checkpoint-a]` filter all
pass. `Tests/Golden/frame-*.txt` change only by the five added imports and their reads, with the
pass order unchanged; the diff is reviewed and recorded. `CaptureSchemaTests` pins the new layouts.
A validation-clean editor session switches every catalog scene, edits and resets an object during
playback, and shows the Scene tables block converging to zero writes on a static scene. No
performance conclusion is drawn; `tableStats` numbers are diagnostics, not a benchmark.

## Known limits and design boundaries

- No visibility, culling, indirect drawing, GPU-written tables, bindless textures, descriptor
  indexing or new capability query; M7.2 and M7.3 own those, and ICB stays optional.
- The mesh table has no production shader consumer until M7.2; the ABI fixture is its only reader.
- The geometry pool is immutable after `finalize`; runtime geometry growth is residency scope.
- Handles do not persist across scenes, processes or files, and there is no ECS or asset database.
- Existing image-parity exceptions and manual/capture follow-ups from M6.4, M6.5, R1.3 and R1.5
  carry forward unchanged; this slice neither closes nor broadens them.
- `Buffer::write` is the only RHI addition; a retirement query, upload API or copy-based update
  path needs its own consumer.
