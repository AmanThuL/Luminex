# M5.4 — Render Graph Node View — Design Spec

**Date**: 2026-09-04
**Status**: Accepted
**Boundary authority**: `docs/roadmap.md` M5.4 owns the outcome, deliverables, exit gate, and
deferrals. This spec decomposes that boundary without expanding it; where wording differs, the
roadmap wins. M5.4 changes the App-owned Render Graph panel and adds one vendored UI dependency.
It does not change render-graph compilation or execution, renderer image formation, Engine scene
data, or RHI semantics.

## 1. Purpose

M5 left the compiled frame inspectable two ways: a deterministic text dump and a list panel over
`GraphInspectorModel`. Both are exact and both are linear, so the shape the compiler proved — which
pass feeds which, where a sink roots the graph, which passes fell out, and where transient memory
was reused — has to be reconstructed by the reader. M5.4 draws that shape. The Render Graph panel
becomes a node canvas over the same retained `CompiledFrameRecord`, with a details pane scoped to
the selected node, while the text dump stays the deterministic alternate view of the same frame.

The milestone delivers observability, not a rendering technique. The renderer, graph, timing
publication, and three-frames-in-flight behavior remain the baseline being inspected.

## 2. Adopted boundary and reference model

- **Same record, same frame.** The canvas reads the newest retained frame whose GPU timings have
  retired, joined by frame ID, exactly as the M5.3 panel did. Performance pause does not retarget
  it. Dump Frame still serializes the displayed record.
- **Read-only.** Nothing on the canvas mutates a graph, a pass, a schedule, or a resource. Dragging
  a node moves a picture.
- **Selection-scoped details.** The M5.3 full list is replaced by a details pane that shows the
  selected node's facts. This is the one place M5.4 narrows an M5.3 surface, and `docs/roadmap.md`
  is amended in the same change to say so.
- **Culled is not scheduled.** A culled pass never shares a pin, an edge, a band, or a style with
  the scheduled DAG.
- **Alias is not dependency.** A transient reuse link is drawn from a separate list, in a separate
  style, anchored differently from an execution edge.
- **Nothing new in Render or RHI.** M5.4 adds no field to `CompiledFrameDebug`; every edge, band,
  and detail derives from what M5 already records.

The canvas is built on [imgui-node-editor](https://github.com/thedmd/imgui-node-editor) (MIT),
vendored and pinned like Dear ImGui, per ADR 0011. The layout algorithm is Luminex's own and lives
in a pure model, because the library positions nodes only where it is told to.

## 3. Dependency, build, and containment

`xmake setup` fetches `thedmd/imgui-node-editor` at the pinned commit recorded in `xmake.lua`
(`master` at `021aa0ea4da1`, 2026-03-29) into `ThirdParty/imgui-node-editor`, asserts the checkout
matches the pin, and applies `Tools/Patches/imgui-node-editor-imgui-1.93.patch` with the same
apply / reverse-check / diff-equals-patch discipline the Dear ImGui patch uses. The patch is small
and fully enumerated:

- gate the library's `operator*(float, ImVec2)` behind the Dear ImGui version that now ships it;
- add `<exception>` to `crude_json.cpp`, which calls `std::terminate` without including it;
- upstream pull request 339's four call-site fixes for Dear ImGui 1.92.8's swapped
  `AddRect` / `PathStroke` argument order — a silent drawing bug, not a compile error.

With the patch, all four translation units compile under C++23 against the pinned Dear ImGui
docking commit; runtime drawing is proved by stage 1 of the plan, not assumed.

A new `ImGuiNodeEditor` static target compiles `imgui_node_editor.cpp`,
`imgui_node_editor_api.cpp`, `imgui_canvas.cpp`, and `crude_json.cpp`, depends on `ImGui`, and is
linked by `App` only. `Tests`, `RHI`, `Render`, and `Engine` never see it; the Tests target keeps
linking no UI dependency (M5.3 spec section 12 holds).

The library includes `imgui_internal.h`. Its header is included only inside
`Source/App/Panels/RenderGraphPanel.cpp`, the containment rule `EditorShell.cpp` already applies to
DockBuilder. No `ax::NodeEditor` type appears in any Luminex header; the editor context is held
behind an opaque owner.

`Config.SettingsFile` is null and no save/load callbacks are registered: the library writes no
`NodeEditor.json`, node positions are session state, and Luminex's `imgui.ini` workspace schema
stays at 1.

**Fallback.** If stage 1 cannot draw, drag, and select in-app under Metal validation, the dependency
is removed and the canvas is drawn with `ImDrawList` directly. `GraphNodeModel` (section 4) is
unchanged either way; only the panel's drawing code differs.

## 4. Node model and edges

`Source/App/GraphNodeModel.h/.cpp` shapes one `CompiledFrameRecord` plus its joined
`rhi::PassTiming` span into a display-ready graph. It is a pure function of its inputs, contains no
ImGui, SDL, or node-editor type, and compiles into the Tests target beside `GraphInspectorModel`.

**Nodes.** One node per declared pass — scheduled or culled — identified by declaration index, and
one endpoint node per declared sink, identified by sink index. Imported resources are not nodes: a
version-0 input appears as an unconnected input pin on the consuming pass, which states honestly
that the contents came from outside the frame.

**Pins.** A pass node has one input pin per distinct `(resource, version)` it names and one output
pin per distinct version it produces; a write of version `v` produces `v + 1`, per the graph's
version contract. A pin is labelled `r3 "sceneColor" v1`. A sink node has one input pin for the
version it roots.

**Execution edges.** For every scheduled pass naming `(r, v)` with `v > 0`, one edge from the output
pin of the scheduled pass that produced `(r, v)` to that input pin. For every sink rooting `(r, v)`,
one edge from that producer to the sink node. Producer lookup uses only `DebugUse` roles and
versions. The model then checks that every edge's producer precedes its consumer in the compiled
schedule and that every producer is scheduled; a disagreement is a test failure, never a drawing.

**Culled passes.** Nodes in a separate culled group carrying their `CullReason`, with no pins and no
edges in either direction — not even the would-be dependencies their uses declare. Their uses are
still available to the details pane, marked as never executed.

**Alias links.** One per `DebugTransition` whose `aliasedFrom` is set: from the last scheduled pass
touching the freed transient to the first scheduled pass touching the resource that took its
memory, carrying both resource names and the placement (offset, size). Alias links live in a list
separate from execution edges, so the panel cannot draw them through the same path.

**Node facts.** Each pass node carries kind, label, schedule position (or cull reason), joined GPU
milliseconds when the timing join matched, its uses as `GraphInspectorUseRow`-equivalent rows, the
barriers emitted before it, and the transients whose lifetime spans it with offset, size,
alignment, and whether they aliased. Sink nodes carry sink kind, resource, version, and producing
pass. The details pane reads these facts; it does not re-derive from the record.

## 5. Layout, stability, and dragging

**Layered layout** is computed in the model. A scheduled pass's layer is the length of the longest
execution-edge path from any scheduled pass with no producers. A sink sits one layer past its
producer. Within a layer, nodes order by schedule position. Culled passes form a band below the
DAG, ordered by declaration index. Positions are `x = layer × column spacing` and
`y = rank × row spacing` with fixed constants declared in the header, so an unchanged record yields
identical positions on every machine and run. Timings and frame ID do not participate.

**Shape signature.** The model emits a deterministic string over node identities (declaration
index, kind, label, culled or not), pins, execution edges, sink endpoints, and alias links. Timing,
frame ID, byte offsets, and memory totals are excluded. Two frames with equal signatures are the
same graph.

**Dragging is session state owned by the library.** The editor context keeps node positions
between frames. On the first draw, and whenever the signature changes, the panel applies the
model's layout to every node and navigates to content. While the signature holds, the library keeps
whatever the user dragged. Selection clears on a signature change, since declaration indices are
not stable across shapes. A **Reset Layout** button re-applies the model's layout on demand.

Zoom (wheel), pan (right-drag), fit-to-content, hover highlighting of a node's edges, and
click-to-select come from the library.

## 6. The Render Graph panel

**Panel shape.** The client area splits horizontally: the node canvas on the left in an ImGui child
taking about 65% of the width, a scrolling details pane on the right. A header row above both keeps
`frame N — pooling on/off`, the existing Dump frame button, and Reset Layout. Before any frame has
retired the panel shows `no retired frame yet` and creates no editor context.

**State lifetime.** `drawRenderGraphPanel` takes a `RenderGraphPanelState` owned by `EditorShell`,
holding the opaque editor context, the last applied shape signature, and the selected node. The
context is created lazily on the first draw that has a retired frame, after the ImGui context
exists, and destroyed in the shell's shutdown sequence before `ImGui::DestroyContext` — the
boundary the shell already owns. It survives the panel being closed and reopened, and a layout
reset does not touch it.

**Selection.** Single node selection through the library, read back every frame into the state.
Selection is panel-local. `EditorSelection` is not extended: the Inspector stays scene-subject
scoped, and a pass is not a scene subject.

**Details pane.**

| Selected | Shows |
|---|---|
| nothing | transient totals (requested, high-water, saved) and a one-line hint |
| scheduled pass | schedule position, kind, GPU ms; uses with role, version, subresource range; barriers before it (with `alias-of` where set); transients alive across it with offset, size, alignment, aliased |
| culled pass | cull reason; declared uses, marked never executed |
| sink | sink kind, resource, version, producing pass |

**Visual encoding.** Node colour by pass kind (raster, compute, copy); sinks a distinct endpoint
shape; culled nodes dashed and desaturated with no pins; execution edges solid; alias links dashed
in a separate colour and anchored to node bodies rather than pins. Node header text is
`#order label kind ms` for a scheduled pass and `label kind — culled` for a culled one.

## 7. Testing and evidence

- **Unit tests** (`Tests/AppGraphNodeModelTests.cpp`, `[app]`, over `GraphTestSupport.h`
  fixtures): edges match version producers and precede consumers in the schedule; version-0 inputs
  have no edge; sinks connect to their producer; culled passes have no pins or edges and sit in the
  culled band; alias links come only from `aliasedFrom` transitions; the layout of an unchanged
  record is identical across two builds and unaffected by timings or frame ID; the signature is
  stable under timing, frame-ID, and offset changes and changes when a pass, edge, sink, or alias
  changes; node facts agree with the `GraphInspectorModel` rows for the same pass.
- **GPU test** extending `GpuGraphInspectorTests`: for a real compiled frame, node model, inspector
  model, and dump name the same frame ID, pass set, schedule, and culled set.
- **Runtime evidence** on Metal 4 Apple Silicon: `MTL_DEBUG_LAYER=1 xmake test Tests/gpu`; the
  frozen `[checkpoint-a]` filter unchanged; a 120-frame validation-clean run with the panel open;
  bloom and automatic-exposure toggles exercising a shape change with relayout.
- **Parity.** Fixed-camera 1280×720 screenshots of Sponza, Damaged Helmet, and MaterialLab stay
  byte-identical to a fork-point baseline; nothing in Render, RHI, or shaders changes.
- **Manual QA**, recorded in the milestone record: drag persists across frames; Reset Layout restores
  positions; culled band and alias links are visibly distinct; details agree with the dump for a
  selected pass; panel close and reopen keeps the context; default lower-dock height is usable.
- Formatting and `xmake policy` pass.

## 10. Non-goals

Per the roadmap, M5.4 does not add graph mutation, user-authored passes, capture-file browsing,
manual scheduling, or changes to Render Graph execution or RHI semantics. It also does not persist
node positions across runs, extend `EditorSelection`, add a sixth panel or bump the workspace
schema, render resource nodes, draw per-subresource pins, or introduce a second node library.

## 11. Exit gate

The amended roadmap M5.4 exit gate applies: unchanged frames produce stable positions;
dependencies agree with resource versions and schedule; culled passes and aliases cannot resemble
scheduled edges; details agree with the selected pass, version, and transient assignment; node
view and dump identify the same frame; and fixed-camera renderer output is unchanged.
