# R2.3 — Mechanical Rename Design

**Status**: Proposed

This design implements the [R2.3 boundary](../roadmap/codebase-restructuring.md#r23--mechanical-rename)
under [ADR 0024](../decisions/0024-rhi-relocation-to-rojorhi.md). The
[R2 milestone record](../milestones/r2.md#r23--mechanical-rename) owns the outcome and exit gate;
this document fixes how the slice reaches them. The identity itself — namespace `rojoRHI`,
includes `<rojoRHI/...>`, macros `ROJORHI_*`, label prefix `rojorhi.`, targets `RojoRHI` and
`RojoRHIMetal4ImGui`, directory `RojoRHI/` — is settled in `rojo-rhi` and is not reopened here.

## Why the recorded table needs an amendment

`rojo-rhi`'s `Tools/Rename/substitution.tsv` was dry-run before R2.2. R2.2 then moved the RHI
tests, smoke shaders, tools and build files under `RHI/` and created names the table never saw:
the `RHITests` target with its `rhi-test` build directory and `RHITests/unit|gpu` test groups, the
Lua rule `rhi_slang2metallib` and host globals `rhi_thirdparty`/`rhi_imgui_target`, the probe
define `LMX_IMGUI_BACKEND_SOURCE`, the private namespace `lmx::rhi::base`, the component's own
`"lmx.test.*` GPU labels, and component paths in the CI workflow, `Source/Asset/xmake.lua`, the
format task's globs and `Tools/check_checkpoint_a.py`. The extraction guide already requires R2.3
to re-derive its rows against the tree it finds.

## Owner decisions, 2026-09-19

| Topic | Decision |
|---|---|
| Rename reach | Identity-bearing build names follow the identity: `RHITests` → `RojoRHITests` (build directory `rojorhi-test`, groups `RojoRHITests/unit` and `RojoRHITests/gpu`), `rhi_slang2metallib`/`rhi_thirdparty`/`rhi_imgui_target` → `rojorhi_*`, `LMX_IMGUI_BACKEND_SOURCE` → `ROJORHI_IMGUI_BACKEND_SOURCE`; `lmx::rhi::base` follows the namespace row. | Hand edits | They land as the third commit of the R2.3 pull request, reviewed on their own |

## Approach

A script, `Tools/Rename/apply.py` in `rojo-rhi`, reads the table and applies it to a Luminex
checkout: `path` rows through `git mv`, `regex` rows with Python `re` over `git ls-files`
restricted to each row's declared scope, in `order`. Rejected: hand-run `sed`/`perl` per row (BSD
`sed` has neither `\b` nor lookbehind, and nothing would prove reproducibility); a clang-based
rename (exact for C++, blind to Lua, JSON, Python, YAML, label strings and include paths, and it
would replace the accepted record).

The script offers `--dry-run` (per-row match and file counts, inside and outside the component,
in the form the guide embeds), `--check` (fails when any pattern still matches inside its scope after a run, or when a row
marked strict still matches anywhere outside `docs/` and Markdown) and `--selftest` (a fixture tree that
pins ordering of the include-root and component-directory rows, the no-quoting TSV reader and the
lookbehind of the namespace-relative row).

## Stage 0 — amend the record in `rojo-rhi`

- Re-derive every existing row's scope and counts against Luminex `main` after R2.2. Scopes are
  stated as path globs the script reads, no longer as prose file lists in the `note` column; the
  guide states the column change.
- Add rows for the approved reach above, and extend the component-directory row to the CI
  workflow, `Source/Asset/xmake.lua`'s `../../RHI/Include`, the format globs,
  `Tools/check_checkpoint_a.py` and `RHI/xmake/*`.
- The default-label row applies as written, so the component's own `"lmx.test.*` labels become
  `rojorhi.test.*`. Labels in Luminex's `Tests/` keep `lmx.`.
- Tool-test fixtures under `Tools/tests/` are in scope. They exercise the real checker constants
  (`check_shader_imports.py`'s trees, the module contract's paths), so they must be rewritten by
  the same rows as those constants. Three ordered rows separate the two meanings of `RHI/` in any
  tool file: `Include/RHI/` becomes `Include/rojoRHI/`; a quoted string that is exactly
  `RHI/<Name>.h` or `RHI/Metal4/<Name>.h` is an include spelling and becomes `rojoRHI/...`; every
  remaining `RHI/` is the component directory. This retires the extraction guide's hand-edit entry
  for `test_module_deps.py`.
- A second `path` row renames the ImGui adapter's own public include root,
  `Backends/Metal4/ImGui/Include/RHI`.
- The guide keeps the R2.1 dry-run table and adds a dated post-R2.2 table beside it.

**Gate:** `apply.py --selftest` passes; `--dry-run` output equals the guide's new table; a trial
application in a scratch Luminex worktree builds and passes every gate listed under commit 1; the
owner accepts the `rojo-rhi` pull request.

## The Luminex pull request: three commits

**Commit 1 — mechanical.** Exactly the output of `apply.py` at the accepted `rojo-rhi` commit,
applied to the parent; nothing else. Re-running the script on the parent must reproduce the
commit's tree byte for byte. It configures, builds, and passes all four test groups,
`xmake policy`, both checkpoint-A checks and the Python tool suites. The one declared exception is
`xmake format --check`, because includes that move from quoted to angle form change group.
Anything a gate needs is therefore a table row or a whole-file exclusion, never a manual touch-up
inside this commit.

**Commit 2 — format.** `xmake format` output only.

**Commit 3 — hand edits.** The nine unused `namespace rhi = rojoRHI;` lines; prose comments naming
old paths or `rhi::` symbols in the component and `Benchmarks/FrameData`; the
`Tools/GpuDebug/xctracelib.py` docstring; the `test_module_deps.py` fixtures; commands and paths in
`AGENTS.md`, README and guides (`xmake -P RojoRHI`, `RojoRHITests`); the R2.3 acceptance section of
the milestone record and the roadmap row. The `LMX_CAPTURE_PATH` wording in the capture-failure
message stays; its owner is decided after extraction. ADR, other milestone and architecture prose
waits for R2.4, as the guide records.

## Evidence

The [R1 comparison protocol](../roadmap/codebase-module-boundaries.md#r1--module-boundaries-and-shared-foundations)
as R2.2 ran it: parent and candidate in separate worktrees, release, `--ccache=n`, matching
`imgui.ini`; bundle outside the repository beside R2.2's.

- **Tier 1, every commit:** case-name inventories of both test binaries equal the parent's; all
  four groups pass with `MTL_DEBUG_LAYER=1` and are validation-clean; both checkpoint-A checks,
  policy and the Python suites pass; `RojoRHI/` copied out builds and tests from its own root.
- **Tier 2, at the head:** Sponza graph dump, tagged PNG bytes and metadata, a capture sequence
  with its manifest, and capture-schema JSON are byte-identical. `gputrace_dump.py` output and
  timestamp-stripped stdout are compared after the substitution's label and text rows are applied
  to the parent side — the one declared difference. `Tools/Screenshots/parity.py` runs alternating
  parent/candidate rounds. As in R2.2, equality is judged on objects, symbols and MSL, not the
  `App` binary hash; symbol lists are compared after the namespace rows are applied to the
  parent's.
- **Residue gate:** inside `RojoRHI/` nothing matches `lmx::rhi`, `LMX_ASSERT`, `LMX_LOG_` or a
  quoted `RHI/` include; outside it, `rojoRHI`/`rojorhi` appear only at the consumer sites the
  table names. Renderer-owned `lmx.*` labels, `LMX_*` environment variables and the `lmx`
  namespace outside the component are unchanged.

## Execution shape

Work happens in a Luminex worktree (`-P .` and a seeded `ThirdParty`, per the nested-worktree
rule). Agents that touch the `rojo-rhi` checkout run one at a time, since they share its index.
Stage 0 and the commit 1 dry run are design-sensitive; the format commit is mechanical; hand edits
and documents are standard work. Each is reviewed one model tier above its implementer.

## Defer

Any edit the table cannot express beyond the list under commit 3; renaming files, tags or test
cases; any RHI capability or semantic change; the submodule, history extraction and `rojo-rhi` CI
(R2.4); the R2 journal entry, written once at R2 close.
