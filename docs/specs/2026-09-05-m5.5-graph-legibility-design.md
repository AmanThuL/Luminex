# M5.5 — Render Graph Legibility and Detached Window — Design Spec

**Date**: 2026-09-05
**Status**: Accepted
**Boundary authority**: `docs/roadmap.md` M5.5 owns the outcome, deliverables, exit gate, and
deferrals. This spec decomposes that boundary without expanding it; where wording differs, the
roadmap wins. M5.5 changes App-owned editor code and the ImGui platform configuration only. It does
not change render-graph compilation or execution, renderer image formation, Engine scene data, RHI
semantics, or the vendored libraries' sources.

## 1. Purpose

M5.4's node view is exact but, on the shipped frame, unreadable: Sponza's scheduled graph is a
thirteen-pass chain whose nine bloom passes each carry full-width pin labels, so the canvas is one
long line squeezed into the lower dock. M5.5 fixes the two causes separately. The Render Graph
panel becomes its own OS window so the canvas gets a screen's worth of pixels, and a pure layout
step compacts nodes, collapses stages into groups, and wraps long chains into rows. What is drawn
is still the M5.4 model of the exact newest retired frame; only how much of it is expanded, and
where it sits, changes.

## 2. Adopted boundary and reference model

- **Same model, new layout owner.** `GraphNodeModel` keeps its nodes, pins, execution edges, alias
  links, node facts, and shape signature. Its M5.4 layout fields move out: a new pure `GraphLayout`
  step owns layers, ranks, rows, and positions, and adds groups. There is one layout owner.
- **Read-only.** Expanding a group, changing the column count, or moving the window mutates a
  picture, never a frame.
- **Deterministic.** Positions are a pure function of the record, the set of expanded groups, and
  the column count. Timing, frame ID, and byte offsets never influence layout.
- **One OS window, one panel.** Only the Render Graph window is forced into its own OS window. The
  other panels keep the M5.3 dockspace; nothing else changes behavior when the feature ships.
- **Nothing new in Render or RHI**, and no change to the vendored sources beyond the existing
  maintained patches.

## 3. Detached window

Dear ImGui platform viewports are enabled (`ImGuiConfigFlags_ViewportsEnable`). The Render Graph
window is submitted with a dedicated `ImGuiWindowClass`: its own class ID, docking with unclassed
windows disallowed, and `ImGuiViewportFlags_NoAutoMerge` in the viewport flags override. When the
panel is open it therefore always owns an OS window and can never dock into the main dockspace.
Auto-merge stays on for every other window, so the rest of the editor behaves as in M5.3 unless a
user deliberately drags a panel outside the main window, which the roadmap defers as a workflow.

The frame loop calls `ImGui::UpdatePlatformWindows()` and `ImGui::RenderPlatformWindowsDefault()`
after the device's `endFrame`, on the frames that presented; a skipped drawable opens no ImGui
frame and renders no platform window. The vendored Metal 4 ImGui backend renders each extra window
with its own Metal 4 command buffer on the device queue and the backend's per-slot allocator, and
paces it with its own event. Stage 1 of the plan proves this validation-clean over open, resize,
move, close, reopen, and a GPU capture that shows the extra window's pass. If it cannot be made
clean, the plan stops and the decision is re-opened (a second swapchain through the RHI is the
recorded alternative); it is not guessed around.

Workspace: visibility persists exactly as today and the schema stays 1. The dock builder no longer
docks Render Graph into the Performance dock, and Reset Default Layout leaves it detached. The
first open sizes the window to 1280×800 beside the main window with first-use-ever conditions;
afterwards ImGui persists its position and size in `imgui.ini` as for any window. Closing the OS
window writes the same visibility value the Window menu and the panel close button write.
Relative-mouse look already releases on focus loss, which covers focus moving to the new window.
The node-editor context, panel state, and their lifetime are unchanged. Screenshot and headless
paths run no ImGui frame and are unaffected.

## 4. Layout model

`Source/App/GraphLayout.h/.cpp` is ImGui-free and tested like `GraphNodeModel`:

```cpp
struct GraphLayoutOptions {
    uint32_t columnsPerRow = 0;               // 0 = unlimited
    std::vector<std::string> expandedGroups;  // group keys; everything else collapsed
};
GraphLayout layoutGraph(const GraphNodeModel& model, const GraphLayoutOptions& options);
```

**Stage groups.** A pass label with at least four dotted segments (`lmx.pass.<stage>.<step>`)
belongs to the group keyed by all segments but the last; a label with fewer segments belongs to no
group. A key with fewer than two member passes forms no group. Members must share culled-ness; a
key whose members differ splits into a scheduled group and a culled group with distinct keys
(`<key>` and `<key>#culled`). A group's display label is its `<stage>` segment, its count, and the
sum of its members' joined GPU milliseconds when at least one member is measured, with the
measured count stated when it is not all of them. Groups are collapsed unless their key is in
`expandedGroups`. Sinks never group.

**Items and visible edges.** The layout draws *items*: every node outside a collapsed group, plus
one item per collapsed group. Each model edge maps its endpoints to items; an edge whose endpoints
map to the same collapsed group is hidden; the rest are kept, deduplicated per
(from item, to item, resource, version). A collapsed group's pins are the distinct
(resource, version) pairs its visible edges enter and leave through, in the order first seen. Alias
links map the same way and are hidden when both ends fall in one collapsed group.

**Layering and wrapping.** Layer is the longest visible-edge path from producer-less scheduled
items; sink items sit one layer past their producer. Rank within a layer orders by the item's
lowest schedule position, then sinks by sink index. With `columnsPerRow = C > 0`, layer L sits in
row `L / C`, column `L % C`; each row's height is its largest rank count times the row spacing plus
a row gap, rows stack top to bottom, and `x = column × column spacing`. With `C = 0` there is one
row. Culled items form a band below the last row, ordered by declaration index. Constants
(`kGraphLayoutColumnSpacing = 260`, `kGraphLayoutRowSpacing = 110`, `kGraphLayoutRowGap = 80`,
`kGraphLayoutCulledBandGap = 120`) are declared in the header; the compact node style of section 5
is what makes a 260 pitch fit.

**Layout signature.** `GraphLayout::signature` is the model's shape signature followed by the
options (column count and the sorted expanded keys). Equal signatures mean the same picture; the
panel relayouts and clears selection when it changes, exactly as M5.4 does on a shape change.

## 5. Panel behavior

**Compact nodes.** A pin draws as a small dot in the node's accent colour with a short label: the
resource name's last dotted segment and its version (`sceneColorHdr v1`). The full M5.4 label
(`r5 "lmx.render.sceneColorHdr" v1`) appears as a tooltip when the pin is hovered, and is drawn in
place for the selected item and every item joined to it by a visible edge. Node width is measured
from the short labels, so a scene pass is about 200 px wide.

**Groups.** A collapsed group draws as one node with a distinct header style and the display label
from section 4; double-clicking it, or pressing Expand in the details pane, adds its key to
`expandedGroups`; double-clicking any member of an expanded group, or pressing Collapse, removes
it. The expansion set is panel session state alongside the editor context and survives shape
changes, since keys are label-derived rather than index-derived.

**Columns per row.** The header row gains a `columns` integer control (1–32). The first draw with a
retired frame sets it to `max(2, floor(canvas width / column spacing))`; Reset Layout recomputes it
from the current width and re-applies positions; the user's edits are session state. The window
title bar and header keep `frame N -- pooling on|off`, Dump frame, and Reset Layout.

**Details pane.** Selection is an item. A pass or sink shows the M5.4 details unchanged. A group
shows its key, member count, summed and measured timing, a member table (schedule position, label,
GPU ms), and an Expand or Collapse button. The selected node's details are unchanged when its group
expands, since selection is cleared on relayout and the user re-selects.

**Ids.** Node items keep `nodeIndex + 1`; group items use `100000 + groupIndex + 1`; pins and links
are numbered per item as in M5.4. Ids are stable while the layout signature holds.

## 6. Testing and evidence

- **Unit tests** (`Tests/AppGraphLayoutTests.cpp`, `[app]`): grouping by prefix with the
  four-segment rule, the two-member minimum, and the culled split; a collapsed group's pins and
  visible edges are exactly the boundary-crossing ones and internal edges are hidden; expanding a
  group restores the M5.4 item graph; summed timing and the measured count; layering over items;
  wrapping row/column arithmetic and row heights; culled band placement; determinism across two
  compiles and under timing or frame-ID changes; the layout signature changes with the expansion
  set and the column count and not with timing. The M5.4 layout tests move from
  `AppGraphNodeModelTests.cpp` to this file, rewritten against `GraphLayout`.
- **GPU test**: the existing inspector agreement case additionally lays out the frame with every
  group collapsed and expanded and checks item counts against the model.
- **Runtime evidence** on Metal 4 Apple Silicon: `MTL_DEBUG_LAYER=1 xmake test Tests/gpu`; the
  frozen `[checkpoint-a]` filter; a 120-frame validation-clean run with the detached window open,
  including a resize and a move driven through SDL; a GPU capture with the detached window open,
  dumped with the existing tooling to show the extra window's pass; bloom toggled to force a shape
  change with a group expanded.
- **Parity.** Fixed-camera 1280×720 screenshots of the three scenes stay byte-identical to the
  M5.4 tip.
- **Manual QA** (owner): the window opens detached and readable at its default size; groups expand
  and collapse by double-click; hover shows full pin labels; columns wrap; drags survive frames and
  reset on relayout.

## 9. Non-goals

Per the roadmap, M5.5 does not make other panels' OS windows a supported workflow, persist node
positions, add manual grouping or an orientation toggle, mutate graphs, or change Render Graph
execution or RHI semantics. It also does not add a minimap, edge labels, or a second node library.

## 10. Exit gate

The roadmap M5.5 gate applies: the detached window is validation-clean across open, resize, move,
close, and GPU capture; a collapsed group carries exactly the edges that cross its boundary and its
members' summed timing; positions are deterministic for a given record, expansion set, and column
count; the M5.4 exit gate still holds; fixed-camera renderer output is unchanged.
