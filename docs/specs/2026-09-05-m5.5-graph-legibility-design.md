# M5.5 — Render Graph Legibility and Detached Window — Design Spec

**Date**: 2026-09-05
**Status**: Accepted
**Boundary authority**: `docs/roadmap.md` M5.5 owns the outcome, deliverables, exit gate, and
deferrals. This spec decomposes that boundary without expanding it; where wording differs, the
roadmap wins. M5.5 changes App-owned editor code and the ImGui platform configuration only. It does
not change render-graph compilation or execution, renderer image formation, Engine scene data, RHI
semantics, or the vendored libraries' sources.

## 1. Purpose

M5.4's node view is exact but, on the shipped frame, unreadable: Sponza's scheduled graph is a
thirteen-pass chain whose nine bloom passes each carry full-width pin labels, so the canvas is one
long line squeezed into the lower dock. M5.5 fixes the two causes separately. The Render Graph
panel becomes its own OS window so the canvas gets a screen's worth of pixels, and a pure layout
step compacts nodes, collapses stages into groups, and wraps long chains into rows. What is drawn
is still the M5.4 model of the exact newest retired frame; only how much of it is expanded, and
where it sits, changes.

## 2. Adopted boundary and reference model

- **Same model, new layout owner.** `GraphNodeModel` keeps its nodes, pins, execution edges, alias
  links, node facts, and shape signature. Its M5.4 layout fields move out: a new pure `GraphLayout`
  step owns layers, ranks, rows, and positions, and adds groups. There is one layout owner.
- **Read-only.** Expanding a group, changing the column count, or moving the window mutates a
  picture, never a frame.
- **Deterministic.** Layers, ranks, rows, and columns are a pure function of the record, the set of
  expanded groups, and the column count; pixel positions are those plus the font metrics of the
  cards. Timing, frame ID, and byte offsets never influence layout.
- **One OS window, one panel.** Only the Render Graph window is forced into its own OS window. The
  other panels keep the M5.3 dockspace; nothing else changes behavior when the feature ships.
- **Nothing new in Render or RHI**, and no change to the vendored sources beyond the existing
  maintained patches.

## 3. Detached window

Dear ImGui platform viewports are enabled (`ImGuiConfigFlags_ViewportsEnable`). The Render Graph
window is submitted with a dedicated `ImGuiWindowClass`: its own class ID, docking with unclassed
windows disallowed, and `ImGuiViewportFlags_NoAutoMerge` in the viewport flags override. When the
panel is open it therefore always owns an OS window and can never dock into the main dockspace.
Auto-merge stays on for every other window, so the rest of the editor behaves as in M5.3 unless a
user deliberately drags a panel outside the main window, which the roadmap defers as a workflow.

The same class clears `ImGuiViewportFlags_NoDecoration`, which Dear ImGui otherwise sets on every
secondary viewport from `io.ConfigViewportsNoDecoration`. The SDL3 backend reads that flag, so
clearing it for this window alone is what turns a borderless surface into a real macOS window with
a title bar and close, minimise, and zoom buttons. The window would then carry two title bars
unless the ImGui one stands down, so the panel submits `ImGuiWindowFlags_NoTitleBar` while it owns
a viewport of its own -- a question `ImGui::Begin` answers only after the flags are chosen, so the
previous frame's answer is carried forward. The OS title comes from the ImGui window name, which
the platform backend sets. Closing through the OS button reaches `PlatformRequestClose`, which Dear
ImGui turns into the same `*p_open = false` the Window menu and the panel's own close button write;
the frame loop's `windowID` filter is what keeps that close from ending the run.

The frame loop calls `ImGui::UpdatePlatformWindows()` and `ImGui::RenderPlatformWindowsDefault()`
after the device's `endFrame`, on the frames that presented; a skipped drawable opens no ImGui
frame and renders no platform window. The vendored Metal 4 ImGui backend renders each extra window
with its own Metal 4 command buffer on the device queue and the backend's per-slot allocator, and
paces it with its own event. Stage 1 of the plan proves this validation-clean over open, resize,
move, close, reopen, and a GPU capture that shows the extra window's pass. If it cannot be made
clean, the plan stops and the decision is re-opened (a second swapchain through the RHI is the
recorded alternative); it is not guessed around.

The spike found one defect, and it is not a validation failure: the vendored backend deadlocked the
second frame after any extra window rendered. `ImGui_ImplMetal_RenderWindow` signalled a single
monotonic counter onto `events[currentFrameSlot]`, while `ImGui_ImplMetal4_NewFrame` waited for
`events[frameInFlightIndex]` to reach that same global counter -- so the next frame, which runs on a
different slot, waited forever on a value that slot's event was never signalled with. Zero platform
windows meant zero signals, which is why the counter had been harmless until now. The fix lives in
Luminex's maintained patch on that file (`Tools/Patches/imgui-metal4-remove-texture.patch`,
alongside the texture-removal entry point): one pending value per slot, sized with the allocators
at init, so a slot waits only on its own last signal. The main window is unaffected -- our RHI paces
it and never signals these events, so its slots keep a pending value of 0, which a fresh shared
event already satisfies. With that patch the detached window opens, resizes, moves, closes and
reopens over 140 frames with Metal validation on, no validation message, and a capture whose blob
inventory carries both windows' drawables. Any remaining validation failure would still re-open the
decision rather than be worked around.

Manual QA then found a second defect the validation runs could not: the detached window's
physical footprint grew by one IOSurface per frame, without bound. The backend is compiled without
ARC and the frame loop drains no autorelease pool, so `ImGui_ImplMetal_RenderWindow`'s autoreleased
drawable and encoder, and its owned command buffer, outlived every frame; a drawable that is never
released keeps its surface, and the layer allocates a fresh one each frame. The same patch now
wraps that function and the window's creation in an autorelease pool and releases what the backend
owns. The regression check is the Objective-C runtime's own probe: `OBJC_DEBUG_MISSING_POOLS=YES
LMX_MAX_FRAMES=240 xmake run App` with the panel open must report no `CAMetalDrawable` or render
context autoreleased without a pool.

Workspace: visibility persists exactly as today, and `kWorkspaceSchemaVersion` becomes 2 because
the required default topology changed -- a legacy M5.3/M5.4 ini (`Schema=1`) still carries dock
data with a node holding Render Graph, and dock data is restored wholesale, so such an ini
rebuilds the default layout once. The dock builder no longer docks Render Graph into the
Performance dock, and Reset Default Layout leaves it detached. The window is also submitted with
`ImGuiWindowFlags_NoDocking`, because a window class only refuses drop targets while a persisted
`DockId` is rebound without any class check. The first open sizes the window to 1280×800 beside
the main window with first-use-ever conditions; afterwards ImGui persists its position and size in
`imgui.ini` as for any window. Closing the OS window writes the same visibility value the Window
menu and the panel close button write. Relative-mouse look already releases on focus loss, which
covers focus moving to the new window. The node-editor context, panel state, and their lifetime
are unchanged. Screenshot and headless paths run no ImGui frame and are unaffected.

## 4. Layout model

`Source/App/GraphLayout.h/.cpp` is ImGui-free and tested like `GraphNodeModel`:

```cpp
struct GraphLayoutOptions {
    uint32_t columnsPerRow = 0;               // 0 = unlimited
    std::vector<std::string> expandedGroups;  // group keys; everything else collapsed
};
GraphLayout layoutGraph(const GraphNodeModel& model, const GraphLayoutOptions& options);
```

**Stage groups.** A pass label with at least four dotted segments (`lmx.pass.<stage>.<step>`)
belongs to the group keyed by all segments but the last; a label with fewer segments belongs to no
group. A key with fewer than two member passes forms no group. Members must share culled-ness; a
key whose members differ splits into a scheduled group and a culled group with distinct keys
(`<key>` and `<key>#culled`). A group's display label is its `<stage>` segment, its count, and the
sum of its members' joined GPU milliseconds when at least one member is measured, with the
measured count stated when it is not all of them. Groups are collapsed unless their key is in
`expandedGroups`. Sinks never group.

**Items and visible edges.** The layout draws *items*: every node outside a collapsed group, plus
one item per collapsed group. Each model edge maps its endpoints to items; an edge whose endpoints
map to the same collapsed group is hidden; the rest are kept, deduplicated per
(from item, to item, resource, version). A collapsed group's pins are the distinct
(resource, version) pairs its visible edges enter and leave through, in the order first seen. Alias
links map the same way and are hidden when both ends fall in one collapsed group.

**Layering and wrapping.** Layer is the longest visible-edge path from producer-less scheduled
items; sink items sit one layer past their producer. Rank within a layer orders by the item's
lowest schedule position, then sinks by sink index. With `columnsPerRow = C > 0`, layer L sits in
row `L / C`, column `L % C`; with `C = 0`, the default, there is one row and the chain runs left to
right without wrapping. Culled items form a band one row past the last, ordered by declaration
index, each taking its ordinal as its column.

Layers, ranks, rows, and columns are a pure function of the record, the expansion set, and the
column count; pixel positions are those plus font metrics, computed by the panel, because a card's
width is the width of the text in it and nothing ImGui-free can measure that. `GraphLayout`
therefore declares no spacing constants and carries no coordinates -- a cell, never a pixel.

**Layout signature.** `GraphLayout::signature` is the model's shape signature followed by the
options (column count and the sorted expanded keys). Equal signatures mean the same picture; the
panel relayouts and clears selection when it changes, exactly as M5.4 does on a shape change.

## 5. Panel behavior

**Cards.** An item draws as a card in the manner of Falcor's Mogwai graph editor. A filled title
band in the kind's colour -- raster blue, compute violet, copy green, group amber-brown, sink
amber, culled grey -- runs the full card width, carrying `#order name` on the left and
`kind X.XXX ms` on the right; a culled pass reads `culled <reason>` there instead, and a group
`> stage` against `N passes X.XXX ms`. The body below it keeps the editor's node background and
holds two columns: inputs down the left, each a dot then a label, and outputs down the right, each
a label then a dot. Every dot's centre sits exactly on the card's edge, drawn into the node's
content channel rather than as an ImGui item, because an item reaching past the edge would grow the
card around it and move the very edge the dot is centred on. The editor's node padding is zero for
the whole canvas so the band reaches the rounded corner, node rounding is 6, and card width is
`max(title, inputs + 32 + outputs)` over the measured label widths.

**Pins and links.** `ed::BeginPin`/`EndPin` still wrap a whole row so hit-testing and the hover
tooltip work over dot and label together, and `ed::PinPivotRect(dot, dot)` anchors the link at the
dot's centre rather than at the row, which is what stops a link collapsing into a diagonal between
two card edges. `StyleVar_SourceDirection` and `StyleVar_TargetDirection` are stated explicitly as
`(1,0)` and `(-1,0)` -- the editor's own defaults -- and `StyleVar_LinkStrength` is 180, so a link
leaves and arrives horizontally on a round curve. Links draw 2.5 thick in one of eight readable
hues indexed by `resource % 8`, so the same resource always reads in the same colour and two
crossing links are told apart by what travels along them. Alias links stay dashed magenta on the
background draw list, a culled card keeps its dashed border, and a sink keeps its arrowhead.

**Compact pins.** A pin's label is the resource name's last dotted segment and its version
(`sceneColorHdr v1`). The full M5.4 label (`r5 "lmx.render.sceneColorHdr" v1`) appears as a tooltip
when the pin is hovered, and is drawn in place for the selected item and every item joined to it by
a visible edge.

**Measured placement.** The panel turns cells into pixels from the sizes the cards report. A column
is as wide as its widest card; a row is as tall as its rank count times its tallest card plus a
gap; `x` accumulates the widths of the columns before it, and `y` is the row's base plus the rank
times the row's card pitch. The gaps are the panel's own (`kColumnGap = 120`, `kRankGap = 40`,
`kRowGap = 100`, `kCulledBandGap = 140`). A card has no size until the editor has laid it out once,
so a picture is drawn one frame at a coarse provisional grid purely to be measured, placed from
those measurements on the next frame, and then left alone; `RenderGraphPanelState::layoutPhase`
(`Provisional`, `Measured`, `Settled`) is that sequence, and the view fits to content on the
settling frame. Placement is deterministic for a given record, expansion set, column count, and
font, and drags are kept once settled, exactly as in M5.4.

**Groups.** A collapsed group draws as one card with the amber-brown title band and the display
label from section 4; double-clicking it, or pressing Expand in the details pane, adds its key to
`expandedGroups`; double-clicking any member of an expanded group, or pressing Collapse, removes
it. The expansion set is panel session state alongside the editor context and survives shape
changes, since keys are label-derived rather than index-derived.

**Columns per row.** The header row gains a `columns` integer control (0–32) whose default and
resting value is 0, labelled `no wrap`: one row running left to right, panned and zoomed rather
than folded, which is what keeps an edge from ever running back across the canvas. A positive value
wraps as section 4 describes. Reset Layout re-applies placement from a fresh measurement and seeds
no column count; the user's edits are session state. The header keeps `frame N -- pooling on|off`,
Dump frame, and Reset Layout.

**Details pane.** Selection is an item. A pass or sink shows the M5.4 details unchanged. A group
shows its key, member count, summed and measured timing, a member table (schedule position, label,
GPU ms), and an Expand or Collapse button. The selected node's details are unchanged when its group
expands, since selection is cleared on relayout and the user re-selects.

**Ids.** Node items keep `nodeIndex + 1`; group items use `100000 + groupIndex + 1`; pins and links
are numbered per item as in M5.4. Ids are stable while the layout signature holds.

## 6. Testing and evidence

- **Unit tests** (`Tests/AppGraphLayoutTests.cpp`, `[app]`): grouping by prefix with the
  four-segment rule, the two-member minimum, and the culled split; a collapsed group's pins and
  visible edges are exactly the boundary-crossing ones and internal edges are hidden; expanding a
  group restores the M5.4 item graph; summed timing and the measured count; layering over items;
  wrapping row/column arithmetic; culled band placement; determinism of the cells across two
  compiles and under timing or frame-ID changes; the layout signature changes with the expansion
  set and the column count and not with timing. The M5.4 layout tests move from
  `AppGraphNodeModelTests.cpp` to this file, rewritten against `GraphLayout`.
- **GPU test**: the existing inspector agreement case additionally lays out the frame with every
  group collapsed and expanded and checks item counts against the model.
- **Runtime evidence** on Metal 4 Apple Silicon: `MTL_DEBUG_LAYER=1 xmake test Tests/gpu`; the
  frozen `[checkpoint-a]` filter; a 120-frame validation-clean run with the detached window open,
  including a resize and a move driven through SDL; a GPU capture with the detached window open,
  dumped with the existing tooling to show the extra window's pass; bloom toggled to force a shape
  change with a group expanded.
- **Parity.** Fixed-camera 1280×720 screenshots of the three scenes stay byte-identical to the
  M5.4 tip.
- **Manual QA** (owner): the window opens detached with a macOS title bar and is readable at its
  default size; the OS close button hides the panel and the Window menu reopens it; groups expand
  and collapse by double-click; hover shows full pin labels; cards never overlap and links leave and
  arrive at the pin dots; a positive `columns` wraps; drags survive frames and reset on relayout.

## 9. Non-goals

Per the roadmap, M5.5 does not make other panels' OS windows a supported workflow, persist node
positions, add manual grouping or an orientation toggle, mutate graphs, or change Render Graph
execution or RHI semantics. It also does not add a minimap, edge labels, or a second node library.

## 10. Exit gate

The roadmap M5.5 gate applies: the detached window is validation-clean across open, resize, move,
close, and GPU capture; a collapsed group carries exactly the edges that cross its boundary and its
members' summed timing; placement is deterministic for a given record, expansion set, column count,
and font, and no two cards overlap; the M5.4 exit gate still holds; fixed-camera renderer output is unchanged.
