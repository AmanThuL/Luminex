# M6.4 — MetalFX Temporal Adapter — Design Spec

**Date**: 2026-09-12
**Status**: Accepted
**Boundary authority**: `docs/roadmap.md` M6.4 and the M6 shared rules own the outcome,
deliverables, exit gate and deferrals. This spec decomposes that boundary without expanding it;
where wording differs, the roadmap wins. M6.4 makes MetalFX a replaceable reconstruction
implementation over the same engine-owned temporal contract the native kernels consume. It does not
evaluate a display path, add a spatial or denoising scaler, interpolate frames, or add another
vendor; those are M6.5 and independent research.

## 1. Purpose

M6.2 and M6.3 gave the frame a native reconstruction path — TAA at scale 1, TAAU below it — over
engine-owned motion, jitter, exposure, extents and reset semantics, with `TemporalInputs` and
`TemporalResolveOutputs` named as the seam a second implementation would use (ADR 0014). M6.4
supplies that second implementation: Apple's MetalFX temporal scaler, reached through a
vendor-neutral RHI object the Metal 4 backend implements, selected by a device capability, and
falling back to the native kernels when the capability is absent. The vendor's own conventions —
motion sign and units, jitter sign, the invalid-motion sentinel, exposure, the dynamic-resolution
content rectangle, its private history and its reset flag — are translated inside the adapter, so
nothing upstream of the reconstruction step learns that MetalFX exists.

## 2. Adopted boundary and reference model

- **The native path is untouched and stays the reference.** Temporal off, `Raw` and `NativeTaa`
  at every render scale declare exactly what M6.3 declared: the same passes under the same names,
  the same kernels, every golden, tolerance, parity hash and `[checkpoint-a]` case unchanged. The
  vendor path is a third `ReconstructionMode`, opt-in; the App default stays `NativeTaa`.
- **Same engine-owned inputs.** A vendor frame consumes the same `TemporalInputs` the native
  kernels do: pre-exposed scene colour, this frame's depth slot, motion as a UV delta with the
  `+inf` invalid sentinel (ADR 0013), the reactive weight, the `{applied, previous}` exposure
  buffer (ADR 0014), jitter in render pixels, the active render extent inside output-extent
  capacity (ADR 0016) and the derived `HistoryResetReason`. The scene pass, the motion shader and
  the reset derivation do not change for it.
- **Vendor packing stays inside the adapter.** Sign conventions, the sentinel, the exposure texel
  and the content rectangle are translated by the adapter's own pass and parameter mapping.
- **Two separately valid histories.** The engine's colour and depth ping-pong slots stay valid
  under the vendor mode: the scene pass still writes this frame's depth slot, and the vendor writes
  its output into this frame's colour slot, so ADR 0014's invariant — every temporal frame's colour
  slot holds that frame's output — holds in all three modes. MetalFX's internal history is its own.
  `NativeTaa → VendorTemporal` and back therefore derive `None`, and the adapter alone decides when
  to tell the scaler to discard its history.
- **Capability-selected, with native fallback.** A `VendorTemporal` request on a device whose
  capability reports no temporal scaler, or whose scaler creation fails, runs `NativeTaa`, and
  `TemporalStatus` reports the effective mode and the reason.
- **The RHI stays vendor- and Metal-free in its public headers.** The capability, the scaler
  object and the encode call are named for what they do; the Metal 4 backend is the only place
  `MTL4FX` appears. A future backend implements the same object with its platform's scaler or
  reports the capability unavailable.
- **RHI and graph growth is additive.** One capability query, one owned object, one command-list
  call outside any pass, one storage-writable single-channel format, two texture uses, one graph
  pass kind. Every existing field, signature and `[checkpoint-a]` case is unchanged.

## 3. RHI contract

```cpp
namespace lmx::rhi {

/// What the device offers for vendor temporal reconstruction. `minInputScale`/`maxInputScale`
/// bound the ratio of the content rectangle to the output extent, per axis.
struct TemporalScalerSupport {
    bool available = false;
    float minInputScale = 0.0f;
    float maxInputScale = 0.0f;
    std::string_view name; ///< Human-readable algorithm name, empty when unavailable.
};

struct DeviceCapabilities {
    TemporalScalerSupport temporalScaler;
};

/// Sizes and formats a scaler is built for. Inputs are described by their allocated capacity —
/// the output extent under ADR 0016 — and the per-frame content rectangle moves inside it.
struct TemporalScalerDesc {
    uint32_t inputWidth = 0, inputHeight = 0;   ///< Capacity of every input texture.
    uint32_t outputWidth = 0, outputHeight = 0; ///< Extent of the output texture.
    Format colorFormat = Format::RGBA16Float;
    Format depthFormat = Format::D32Float;
    Format motionFormat = Format::RG16Float;
    Format reactiveFormat = Format::R8Unorm;
    Format outputFormat = Format::RGBA16Float;
    float minInputScale = 0.0f, maxInputScale = 0.0f; ///< Content range; within the capability's.
    std::string_view label;
};

/// An opaque, device-owned reconstruction object with private history. Destroying it while a
/// frame that encoded it is in flight is safe: the backend retires it with that frame slot.
class TemporalScaler {
public:
    virtual ~TemporalScaler() = default;
};

/// One frame's inputs to `CommandList::temporalScale`. Textures must match the descriptor's
/// formats and capacities; the exposure texture is 1×1 `R16Float` and the scaler reads texel (0,0).
struct TemporalScaleParams {
    Texture* color = nullptr;
    Texture* depth = nullptr;
    Texture* motion = nullptr;
    Texture* reactive = nullptr;
    Texture* exposure = nullptr;
    Texture* output = nullptr;
    uint32_t inputContentWidth = 0, inputContentHeight = 0; ///< The active render extent.
    float jitterOffsetX = 0.0f, jitterOffsetY = 0.0f; ///< Texels of the colour texture, +y down.
    float motionScaleX = 1.0f, motionScaleY = 1.0f;   ///< Stored motion × scale = pixels to the previous position.
    float preExposure = 1.0f; ///< The fixed factor the colour input is already multiplied by.
    bool reset = false;       ///< Discard the scaler's private history before this frame.
    bool reversedDepth = true;
    std::string_view label;
};

} // namespace lmx::rhi
```

- `Device::capabilities()` returns a `const DeviceCapabilities&` fixed at device creation. The
  Metal 4 backend answers `available` from `MTLFX::TemporalScalerDescriptor::supportsMetal4FX`, the
  scale bounds from the descriptor's supported content-scale queries, and `name = "MetalFX
  Temporal"`. `FakeDevice` reports unavailable unless a test enables its fake support.
- `Device::createTemporalScaler(const TemporalScalerDesc&)` returns
  `Result<std::unique_ptr<TemporalScaler>>`. Misuse — a zero extent, a content range outside the
  capability's, a format the scaler cannot take — is `LMX_ASSERT`; the vendor declining to create
  is a `Result` error carrying the vendor's reason. Metal 4 builds an `MTL4FX::TemporalScaler`
  through the device's `MTL4::Compiler` with synchronous initialisation, dynamic content enabled,
  the reactive mask enabled, auto exposure off, and labels the object with `desc.label`.
- `CommandList::temporalScale(TemporalScaler&, const TemporalScaleParams&)` is valid only
  between passes, like `textureBarrier`. It is a timed pass under `params.label`: the backend
  brackets the vendor's encoding with the same command-buffer timestamps every pass kind uses, so
  the pass appears in `PassTiming`, the Performance panel and the resolution controller's summed
  GPU time. Validation (`Validate.h`): every texture non-null, formats and capacities equal to the
  descriptor's, content within capacity and within the content range, output at the output
  extent.
- **Hazards.** Metal 4 barriers are encoder operations, and the vendor's encoders are opaque. The
  backend emits the pending between-pass barrier from a short carrier compute encoder it opens and
  closes before the vendor encodes, naming all stages as the consumer, and after the vendor's work
  sets the pending barrier's producing stages to all stages. `TextureUse::ExternalRead` and
  `TextureUse::ExternalWrite` name these accesses in the public vocabulary; the backend maps both
  to all stages. If the validation layer shows the carrier is insufficient, the scaler's fence
  property is the recorded alternative; the spike in §11 settles this before anything depends on
  it.
- **Residency and usage.** Input and output textures are RHI-owned and already registered in the
  device residency set. Whether the scaler's private resources need registration is unknown until
  the spike runs with `MTL_DEBUG_LAYER=1`; the backend does whatever that shows and the ADR
  records it. The scaler's required texture-usage bits are read at creation and asserted against
  what the RHI grants each `TextureDesc` flag; if the output requires render-target usage, the
  colour slots' descriptors grant it, which changes no image.
- **Format.** `Format::R16Float` — half-precision single channel, sampled and storage-writable,
  added because the exposure texel is the first consumer.
- **Lifetime.** A destroyed scaler is retired with the frame slot that last encoded it, the rule
  the backend already applies to buffers and textures, so a resize that recreates the scaler is
  validation-clean with three frames in flight.

## 4. Render graph: the external pass kind

`PassKind::External` joins `Raster`, `Compute` and `Copy`: a pass whose GPU work is encoded by an
RHI-owned object rather than a pipeline. `RenderGraph::addExternalPass(label, ExternalPassDesc,
ExecuteFn)` takes the texture reads and writes the object performs; the graph derives barriers
from them exactly as for a compute pass, with `ExternalRead`/`ExternalWrite` as the resulting
uses, and opens no RHI scope — the execute lambda makes the one `temporalScale` call. Culling,
sinks, transient lifetimes and the compiled record treat the kind like any other. `GraphDump`
prints `external` for the kind, so no existing golden moves; the `CompiledFrameRecord` and the
Render Graph panel's title band carry it. `FakeDevice` gains the capability, a fake scaler and a
`FakeCommandList::temporalScale` that records its parameters, so declaration goldens and
switching tests run on the CPU.

## 5. The vendor path (`Source/Render/VendorTemporalScaler.h`, `TemporalResolve`)

`ReconstructionMode` gains `VendorTemporal`. `TemporalResolve` keeps ownership of both slot pairs,
the terminal-use bookkeeping, the reprojection diagnostic and the debug view; only the
reconstruction step switches. A `VendorTemporalScaler` helper, composed by `TemporalResolve`, owns
the `rhi::TemporalScaler`, creates it lazily on the first vendor frame at the current output
extent, recreates it after an output-extent change, and declares two passes. No virtual
reconstruction interface is introduced: the two implementations share every stage responsibility
but the kernel, so the seam is the kernel step, and the ADR records why.

**Passes** on a temporal frame whose effective mode is `VendorTemporal`, at every scale:

| Pass | Kind | Reads | Writes |
|---|---|---|---|
| `lmx.pass.temporal.vendor.pack` | compute, over the active render rectangle | motion, reactive, exposure buffer | `lmx.render.vendorMotion` (`RG16Float`, output-extent transient), `lmx.render.vendorReactive` (`R8Unorm`, output-extent transient), `lmx.render.vendorExposure` (1×1 `R16Float` transient) |
| `lmx.pass.temporal.vendor` | external | scene colour, this frame's depth slot, the three packed transients | this frame's colour slot |

`Shaders/VendorTemporalPack.slang` (`computeVendorTemporalPack`, `[numthreads(8, 8, 1)]`) copies
motion unless it is the sentinel, in which case it writes zero motion and a reactive weight of 1 —
unsupported motion stays explicit, expressed as "do not accumulate this pixel" in the vendor's
vocabulary — passes the reactive weight through otherwise, and thread (0,0) writes `exposure[0]`
into the exposure texel. `lmx.pass.temporal.reproject`, `lmx.pass.temporal.debugView`, bloom and
display are declared as under `NativeTaa`; the native resolve, upscale and commit passes are not.
ADR 0016's native/upscale kernel split is untouched: it selects between native kernels, and the
vendor pass replaces them wholesale.

**Parameter packing**, each a hypothesis §9's scenarios pin, with the confirmed sign recorded in
the milestone:

| Parameter | Value | Reason |
|---|---|---|
| `motionScaleX/Y` | `−renderWidth`, `−renderHeight` | engine motion is `uvCurrent − uvPrevious` over the active extent; the vendor wants pixels pointing at the previous position |
| `jitterOffsetX/Y` | `jitterTexelOffset(jitterPixels)` | the texel-space offset the jittered raster applied, +y down |
| `inputContentWidth/Height` | the active render extent | ADR 0016's rectangle inside output-extent capacity |
| `reversedDepth` | `true` | reversed-Z since M4 |
| `preExposure` | `1.0` | the exposure texel carries `applied`, so the scaler's own exposure handling absorbs an exposure step the way ADR 0014's `applied / previous` correction does natively |
| `reset` | below | |

**Reset rule** (adapter-owned): `reset = resetReason != None || previousMode != VendorTemporal ||
scalerRecreatedThisFrame`, where `previousMode` is the previous declared temporal frame's
effective mode. A frame with temporal off in between counts as a non-vendor previous frame.

**Effective scale.** Under the vendor mode the render scale is clamped into
`[max(kMinRenderScale, minInputScale), min(kMaxRenderScale, maxInputScale)]` before
`renderExtentsForScale`; `TemporalStatus::renderScale` reports the clamped value. The vendor
assumes the input aspect does not change; per-axis rounding of the render extent deviates from the
output aspect by under a pixel, recorded as an accepted limit.

**Terminal use.** A vendor frame records this frame's colour slot `ExternalWrite`, the depth slot
it read `ExternalRead`, the other depth slot `ShaderRead` as before, and the Renderer's scene
colour record `ExternalRead`. ADR 0015's table gains these rows; every other row is unchanged.

**Fallback.** `resolveReconstruction(requested, support, creationFailed)` is a pure function
answering the effective mode and a `VendorFallback` reason (`None`, `Unsupported`,
`CreationFailed`). A creation failure is logged once at WARN and remembered for the output extent
it failed at; a resize retries.

**Status.** `TemporalStatus` gains `VendorFallback vendorFallback`, `std::string_view vendorName`
(the capability's name, empty when unavailable), `bool vendorReset` (the flag the last vendor
frame passed) and `uint32_t vendorScalerGeneration` (creations so far). `reconstruction` keeps
reporting the mode the frame ran, now the effective one.

**Diagnostics.** `MotionVectors`, `ReprojectionError` and `ReprojectedHistory` are engine-owned and
work under the vendor mode. `RejectionMask`, `BlendWeight` and `HistoryAge` describe native kernel
internals the vendor does not expose and are native-only: the Renderer declares no rejection
diagnostic on a vendor frame, and `TemporalResolve` asserts it is not asked for one. `historyAge`
stays the engine's frames-since-reset count.

## 6. App, Inspector, screenshot

- `EditorRenderSettings::reconstruction` takes the third value. The Inspector's Reconstruction
  combo lists `Raw`, `Native TAA` and the capability's name, or `Vendor temporal (unavailable)`
  when the device has none; the temporal status rows show the effective mode with the fallback
  reason, the vendor name, and whether the last vendor frame reset. A pure App helper clamps a
  native-only debug view to `Off` while the effective mode is vendor, and the combo greys those
  three entries.
- `--temporal metalfx` (`AppOptions::TemporalMode::Vendor`) selects the vendor mode for a
  screenshot or scripted run; on an unsupported device the run proceeds under the fallback with one
  WARN line. Naming a native-only `--temporal-view` with it is a usage error, like `--temporal off`
  with any view.
- Dynamic resolution needs no change: the external pass is timed, so the controller's summed GPU
  time includes it, and the controller's clamp range is unchanged because the Renderer clamps the
  vendor's narrower range itself.

## 7. Allocation

| Resource | Allocated at | Lifetime |
|---|---|---|
| `lmx.render.vendorMotion`, `lmx.render.vendorReactive` | output extent | one-frame transients |
| `lmx.render.vendorExposure` | 1×1 | one-frame transient |
| the vendor scaler | output extent | until the next output-extent change; retired with its last frame slot |

Every new descriptor is independent of the render scale, so a scale change still creates no pool
generation, and the scale-oscillation assertions of M6.3 hold under the vendor mode.

## 8. Captures and dumps

The external pass label `lmx.pass.temporal.vendor`, the scaler label
`lmx.temporal.vendor.scaler` carrying the capability name, and the packed transients' labels are
what a GPU capture shows around the vendor's own encoders; `Tools/GpuDebug/gputrace_dump.py`
lists them. `LMX_GRAPH_DUMP` prints the pass as `external` with its reads — the frame inputs —
and its write. This is the roadmap's "captures identify algorithms and frame inputs".

## 9. Testing and evidence

**Scripted scenarios** are `[gpu][temporal][vendor]` Catch2 cases in
`Tests/GpuVendorTemporalTests.cpp`, at a 320×180 output extent, jitter on, reading back this
frame's colour slot, using `renderSequence` and the M6.2/M6.3 metrics. A case whose device reports
the capability unavailable skips with a message naming it. Nothing under this tag carries
`[checkpoint-a]`: the vendor path is platform-specific by construction. Tolerances are frozen
here before any measurement; the vendor's are deliberately looser sanity bounds than the native
ones, since the algorithm is a black box, and the milestone record states every measured value.
Changing one requires a spec amendment recorded in the milestone.

| Scenario | Frozen assertion |
|---|---|
| Declaration | golden `frame-temporal-vendor.txt`: the pack and external passes, the three packed transients, no resolve, upscale or commit; with the fake capability off the dump equals `frame-temporal.txt` byte for byte |
| Static convergence: checker floor and poles, camera still, 32 frames, at scale 0.5 and at scale 1 | frames 17–32 mean frame-to-frame \|ΔY\| ≤ 0.5 × spatial raw's; no display pixel holds the clear colour (pins the jitter sign) |
| Moving quad at 4 output px/frame, scale 0.5 | in the region vacated over the last two frames, mean \|Y(vendor) − Y(spatial raw)\| ≤ 0.25 × the quad-to-floor contrast (pins the motion sign) |
| Mode switching: 8 frames `NativeTaa`, 8 `VendorTemporal`, 8 `NativeTaa` | both switches derive `None`; `vendorReset` is true on the first vendor frame and false on the next; the native frame after the switch back keeps `historyAge` advancing; every frame's colour slot differs from the clear colour |
| Exposure step: the M6.2 exposure-step sequence under the vendor mode | by the eighth frame after the step, whole-image mean Y within 5 % of the raw frame's; the per-frame transition recorded |
| Invalid-motion packing | an object of `MotionClass::Invalid` reads back zero motion and reactive 1 in the packed transients; a rigid object reads back its motion and reactive unchanged (no scaler needed) |
| Resize and scale change | a 320×180 → 256×144 resize derives `ExtentChanged`, increments `vendorScalerGeneration` and resets; a render-scale change alone derives `None`, creates nothing and moves `inputContent` |
| Overlap | five frames alternating scales, no `waitIdle`, the debug view toggled, validation clean |
| Fallback | fake capability off: effective `NativeTaa`, `vendorFallback == Unsupported`, declaration identical to native; a fake creation failure: `CreationFailed`, retried after a resize |

**Other tests.**

- RHI `[gpu][rhi][vendor]`: capability reported; a scaler created and encoded over synthetic
  inputs writes a non-zero output at the output extent; destruction with a frame in flight is
  validation-clean; `[rhi][validate]` cases cover the parameter rejections.
- Graph (`FakeDevice`, `[render][graph]`): an external pass derives the same barriers a compute
  pass with the same uses would, with `ExternalRead`/`ExternalWrite`; `external` in the dump.
- Unit (`[render][temporal]`): `resolveReconstruction`, the reset rule, the scale clamp,
  `motionScale` and `jitterOffset` from `FrameExtents` and `jitterPixels`.
- App unit: `--temporal metalfx` parsing and its conflicts; the debug-view clamp; the combo names
  with and without the capability.
- `[checkpoint-a]` unchanged.

**Parity and runtime evidence** on Metal 4 Apple Silicon: every existing golden and scenario
untouched; temporal-off, `NativeTaa` scale-1 and `--render-scale 0.5` screenshots of Sponza,
Helmet and MaterialLab byte-identical (SHA-256) to the M6.3 tip; new `--temporal metalfx`
baselines at scale 1 and 0.5 recorded by hash; a 240-frame validation-clean TemporalLab run under
`--temporal metalfx` with dynamic resolution on; a capture dumped with `gputrace_dump.py` naming
the pack pass, the external pass and the vendor's encoders; scaler creation time recorded;
`xmake format --check` and `xmake policy` clean.

**Manual QA** (owner): switch Native TAA ↔ MetalFX on Sponza in motion and at rest with no
flash, ghost or seam; the Inspector rows name the effective mode; the Render Graph window shows the
external card; the three native-only views grey out and return.

## 12. Non-goals

Per the roadmap, M6.4 does not evaluate EDR, add another vendor adapter or interpolate frames. It
also does not add the MetalFX spatial or denoised scalers, use the vendor's auto exposure, add a
sharpening stage, change the native kernels or any frozen native tolerance, introduce a virtual
reconstruction interface, make the vendor mode the default, or expose the vendor's private history
to the engine's diagnostics.

## 13. Exit gate

The roadmap M6.4 gate applies: native and vendor replay the same scripted sequences with separate
valid histories; switching in either direction is correct with no reset of the engine history;
the native fallback and every labelled resource are validation-clean; captures and dumps identify
the algorithm and the frame's inputs. In addition: with the vendor mode not selected, every frame
declaration, kernel and fixed-camera output is unchanged from M6.3; every `[checkpoint-a]` test
case is unchanged; and the default runs validation-clean through resize, cut, mode switches and
dynamic scaling under both reconstructions.
