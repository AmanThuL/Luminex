# R2.4 — Extract, Mount and Wire Design

**Status**: Implemented (2026-09-20)

This design implements the [R2.4 boundary](../roadmap/codebase-restructuring.md#r24--extract-mount-and-wire)
under [ADR 0024](../decisions/0024-rhi-relocation-to-rojorhi.md). The
[R2 milestone record](../milestones/r2.md#r24--extract-mount-and-wire) owns the outcome and exit
gate; this document fixes how the slice reaches them. Identity, mount path, build system and the
two-repository workflow are settled and are not reopened here.

## Owner decisions, 2026-09-20

| Topic | Decision |
|---|---|
| Visibility | `rojo-rhi` becomes public during R2.4. Luminex is public, and a private submodule would leave every public clone unable to build and every fork pull request without the component. This amends the "private" wording of ADR 0024's consequences and of the R2 record's Defer list; CI needs no credential, and the pin check needs none either |
| Licence | Apache-2.0, as Luminex. The imported revisions were already published under it |
| Policy home | RojoRHI owns its source policy. The comment, layout, shader-import and project-policy checkers are ported into the component with their tests; Luminex's checkers stop covering `RojoRHI/`. Copies, not shared code, as with the shader rule; drift is an accepted cost |
| Order | Complete the component in place while parent/candidate comparison is possible, then extract mechanically, then mount. Rejected: completing the component only after extraction (its policy gate could be tested only after the destructive step); mounting at the raw import and bumping later (Luminex would sit on a component with no policy or CI, and evidence would be taken twice) |

Releases, a package registry entry, a second backend and samples stay deferred.

## Findings that shape the work

- **History.** On `main`, 26 commits touch the component; none is a merge; the largest blob is
  83 KB. Lineage is `Source/RHI/` → `RHI/` → `RojoRHI/`, plus 38 single paths in the
  flat `Tests/`, `Shaders/`, `Shaders/Tests/` and `Tools/` trees. Several renames across the two
  directory moves fall below git's 50 % similarity threshold, so the path list is written out and
  never derived from `--follow`. Nine further commits exist only on abandoned `exp/` lines.
- **Copies.** R2.2 copied files whose origins still live in Luminex: six smoke shaders,
  `Shaders/Modules/Shadow.slang`, four `Source/Core` base files, the test bootstrap and the shader
  rule. One component file, `RHI/Backends/Metal4/ImGui/xmake.lua`, was folded into
  `xmake/targets.lua` rather than renamed.
- **Host coupling.** Outside the public include root, Luminex reaches the component at:
  `Tests/GpuTestSupport.h` (includes `RojoRHI/Tests/RhiGpuTestSupport.h`, 21 test files behind it);
  `xmake.lua` (targets include and two globals); `xmake/setup.lua` (the ImGui patch path);
  `xmake/tasks.lua` (format globs, the `check_rhi_headers.py` call);
  `Source/Asset/xmake.lua` (include directory); `Tools/module_contract.json` (the external entry
  and its test carve-out); `Tools/check_checkpoint_a.py` (the component's frozen inventory); four
  checkers' roots; CI cache keys and four checkouts with no `submodules:`.
- **Silent loss.** `check_project_policy.py` enumerates with `git ls-files`; a gitlink is not a
  file, so its coverage of the component would vanish without a message. The comment, layout and
  shader-import checkers walk directories and would pass over an uninitialised mount.
- **Inside the component** nothing points outward except two `LMX_*` names, in the capture-failure
  message and one comment. It has no `.clang-format`, `.gitignore`, licence, policy or CI, and no
  path collides with the `foundations` line. `git filter-repo` is not installed.

## Stage 1 — Luminex: complete the component in place

One pull request from a worktree; every commit meets Tier 1.

- `Tests/GpuTestSupport.h` takes a Luminex-owned copy of the bootstrap it layered onto. The
  contract's `RojoRHI/Tests/RhiGpuTestSupport.h` allowance is removed. Case names do not change.
- The component gains `.clang-format` and `.gitignore` copies; `Tools/check_cpp_comments.py`,
  `check_cpp_layout.py`, `check_shader_imports.py` and `check_project_policy.py`, each trimmed to
  the component's own tree, with tests under `RojoRHI/Tools/tests/`; and `xmake/tasks.lua` with
  `format` and `policy` tasks, included by the standalone root only. The ported project-policy
  checker validates commit ranges it is given and never the imported history.
- Luminex's checkers drop `RojoRHI` from `SOURCE_ROOTS`, `EXCLUDED_ROOTS`, `CPP_ROOTS`, `TREES` and
  `PROCESS_ROOTS`. Until the mount, `xmake policy` runs the component's checkers where it runs
  `check_rhi_headers.py` today, and the format task keeps its two globs, so coverage does not
  lapse between the two pull requests.
- Root `xmake.lua` and `xmake/setup.lua` stop with a message naming
  `git submodule update --init` when `RojoRHI/xmake/targets.lua` is absent.

**Gate:** Tier 1; a bare copy of `RojoRHI/` passes setup, build, all tests with the validation
layer, `format --check` and its own `policy`; `App` objects and shader outputs equal the parent's,
so Tier 2 is not required. After merge the head is tagged `r2.4-pre-extraction-evidence`.

## Stage 2 — extraction

Performed in a scratch clone of Luminex. Nothing is pushed before the owner confirms.

- `rojo-rhi` records `Tools/Extract/` on `foundations`: the path list, the invocation and a
  commit-message callback. Scope is `main` only. Included: `Source/RHI/`, `RHI/`, `RojoRHI/` and
  the 38 single paths exactly. Excluded: the abandoned `exp/` commits and every copy origin
  that still lives in Luminex, so a copied file's history starts at the R2.2 commit. Renames:
  `RojoRHI/` and `RHI/` both map to the repository root; every other path keeps its spelling, so
  a file's R2.2 move from `Tests/X` to `RHI/Tests/X` disappears and `Source/RHI/` stays as the
  library's earliest layout. The callback rewrites `(#N)` to `(AmanThuL/Luminex#N)`.
- **Gates before any push:** the import tip's tree hash equals
  `r2.4-pre-extraction-evidence:RojoRHI`; the commit set, authors and author dates match the
  recorded source commits; no path outside the list appears at any commit; a bare checkout
  configures, builds and passes tests and policy.
- `foundations` is rebased onto the import. The archive tag `archive/2024-cmake-nri-stub` is
  verified on the remote. The owner confirms explicitly; `main` is force-replaced once; the import
  tip is tagged `import/luminex-r2.4`.

## Stage 3 — rojo-rhi: make it a repository

One pull request onto the new `main`. No file under `Include/`, `Source/`, `Backends/`, `Tests/`
or `Shaders/` changes, which keeps the pin comparable to the tag.

- `LICENSE` (Apache-2.0). README, `AGENTS.md` and the documentation convention replace "private"
  and "planned" wording with the real commands and licence; the extraction guide is closed out
  with what R2.4 did.
- `.github/workflows/ci.yml`: a policy job on Ubuntu (ported checkers, their tests, the public
  header check) and a `macos-26` job (setup, configure, build, `RojoRHITests/unit`, the GPU case
  inventory count, `format --check`). Hosted runners lack Metal 4, so GPU conformance runs on
  Metal 4 Apple Silicon before merge, as in Luminex.
- After merge with green CI, the owner changes the repository's visibility to public. The plan
  supplies the command; the executor does not run it.

## Stage 4 — Luminex: mount

- One swap commit: remove the tracked directory and add the submodule at
  `https://github.com/AmanThuL/rojo-rhi.git`, pinned to a `main` commit. An absolute URL, because
  a relative one would resolve against a fork that has no sibling repository.
- CI: every checkout takes `submodules: true`; ThirdParty cache keys follow the patch path.
  `Tools/check_submodule_pin.py`, with tests and an `xmake policy` entry, fails when the gitlink
  commit is not an ancestor of the submodule's `origin/main` or when `.gitmodules` names another
  URL; `--fetch` refreshes the remote first and is what CI passes. A branch pin therefore fails
  the pull request until the RojoRHI change is merged, as ADR 0024 requires.
- The policy calls into the component and the format task's two globs are removed; the three dead
  `.gitignore` lines go; `check_checkpoint_a.py` keeps reading the component's inventory.
- Documents: `AGENTS.md`, `docs/conventions/modules.md`, the architecture overview, the README
  directory table, the worktree recipes in `docs/guides/gpu-debugging.md`
  (`git submodule update --init` per worktree), the roadmap row and the milestone record. The
  R2 record is four lines under its budget, so R2.4's evidence goes to
  `docs/milestones/r2.4-validation.md` and the record links it.

**Exit-gate evidence** (bundle beside R2.2's and R2.3's, outside the repository): the mounted
tree's source directories are file-for-file equal to the tag's; Tier 1 on the swap commit and the
head; Tier 2 byte-identical against the tag, with `Tools/Screenshots/parity.py` in alternating
rounds; a fresh recursive clone passes `xmake setup && xmake`; a clean `rojo-rhi` clone with no
Luminex checkout builds, tests and passes policy; policy is green in both. Equality is judged on
objects, symbols, MSL and output, not the `App` binary hash, as R2.2 recorded.

## Evidence tiers

As R2.2 and R2.3 ran them. **Tier 1, every commit:** case-name inventories of both test binaries
equal the parent's; all four groups pass with `MTL_DEBUG_LAYER=1`, validation-clean; both
checkpoint-A checks, policy, format and the Python suites pass. **Tier 2, where stated:** Sponza
graph dump, tagged PNG bytes and metadata, a capture sequence with its manifest, capture-schema
JSON, `gputrace_dump.py` output and timestamp-stripped stdout, parent and candidate in separate
worktrees, release, `--ccache=n`, matching `imgui.ini`.

## Execution shape

An Opus main thread executes; Opus is the highest subagent tier. Opus takes the checker port, the
extraction record and the pin check; Sonnet takes documents and CI; Haiku only mechanical edits.
The review rule places Opus work under a reviewer that session does not have, so three owner
checkpoints stand in: after the stage 1 checker port, before the force-replace, and at the stage 4
evidence. Luminex work happens in worktrees (`-P .`, seeded `ThirdParty`); agents that touch the
`rojo-rhi` checkout run one at a time. The plan stops for the owner before installing
`git-filter-repo`, before any push to `rojo-rhi` `main`, and before the visibility change.

## Limits recorded in advance

Imported commit messages carry Luminex pull-request numbers as cross-repository references. The
history of copied files before R2.2 stays in Luminex only. The capture-failure message and one
comment still name `LMX_*` variables; rewording them changes component source and becomes the
first ordinary two-repository change after R2. No automated job exercises a recursive clone of
Luminex beyond CI's own checkout.

## Defer

Any RHI capability or semantic change; unifying the two shader rules or the two checker sets;
releases and a registry entry; a second backend (ADR 0007 as restated); the R2 journal entry,
written once at R2 close.
