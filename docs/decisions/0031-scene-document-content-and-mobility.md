# ADR 0031 — Scene document content, mobility and editor gizmos

**Status**: Proposed
**Date**: 2026-10-03

## Context

MaterialLab, TemporalLab and LightLab previously rebuilt their objects in generators. Their
object poses were session-only, so Save could not retain an authoring edit. Imported objects also
needed an explicit file-authored pose permission shared by Inspector, Session and viewport tools.
This proposal amends [Proposed ADR 0028](0028-scene-document-contract.md); that historical record
and the identity/update contract in [ADR 0021](0021-gpu-scene-handoff-contract.md) remain intact.

## Proposed contract

### Saved content and hashes

`LMX_scene` schema 2 adds saved mesh nodes, materials, textures and file-authored `mobility`.
The supported glTF subset stores POSITION/NORMAL/TANGENT/TEXCOORD_0 vertices and uint32 indices,
with shared geometry referenced by material primitives. MaterialLab, TemporalLab and LightLab
store their object content in the document. VisibilityLab keeps its population generator;
LightLab keeps its generated lights and closed-form orbits. Referenced Helmet/Truck assets remain
Assets-relative and hashed separately, as does the required environment.

Geometry lives in `<stem>.scene.geometry.bin`, images in `<stem>.scene.textures/*.png` and animation
in the separate `<stem>.scene.bin`. `contentHashes` records the immutable geometry/image SHA-256
values in JSON. The reader verifies and decodes the same byte snapshots before GPU allocation.
CPU `DocContent` is shared and immutable; export copies editable pose/enabled state while retaining
material/content definitions without regenerating geometry or PNG bytes. Save installs absent immutable companions, accepts existing
matching hashes and refuses conflicting files before staging. Save As copies companions beside
the new stem and rejects aliases of any active content. Reported failures roll back created and
replaced files; the operation is not crash atomic. Post-write reread/hash failure can leave changed
disk bytes without adopting a new in-memory baseline.

The loaded-document hash remains raw JSON followed only by the external animation buffer.
Geometry/images participate through JSON `contentHashes`; the hash helper and Session watcher do
not reread immutable companions. Loading verifies them. Capture Manifest v3, measurement schema 5
and proposal sidecars retain this provenance rule; unsaved edits do not enter the loaded hash.

Saved mesh TRS channels support LINEAR/STEP; `KHR_animation_pointer` targets material emissive
strength. Tracks retain authored Rigid/Invalid motion behavior and fixed-step playback. Camera
rails and referenced asset clips keep their existing paths. Animated poses are never exported as
manual overrides. Renderer row layouts, bindings, passes and reconstruction defaults do not change.

### Mobility and generated subjects

Schema 2 absent `mobility` means Static. Mesh, asset-placement and punctual-light nodes may author
`static` or `movable`; imported-node overrides inherit from placement, then the nearest source
ancestor override wins. Cameras, groups and generator nodes reject mobility fields, and animated
source nodes reject mobility overrides. Schema 1 remains readable with Static objects and Movable
authored lights; successful Save upgrades to schema 2 while retaining those permissions.

`DocMobility` is an authoring permission, separate from enabled state and renderer motion class.
Inspector shows a disabled Static checkbox with a file-authoring tooltip. Static poses are locked;
enabled flags and non-pose light fields remain editable. Movable unanimated objects allow TRS;
point lights allow position and spot lights position/direction. The shared `SceneSession` check
also refuses animation-owned poses and measurement edits. Inspector, reset, bridge preview/apply
and gizmo routes use the same check. Bridge pose refusals name the subject/field and lock reason;
mobility edits answer that mobility is authored in the scene file.

Generated groups start collapsed and their rows say “Generated by <name>”. Generated objects
refuse pose edits because their generator places them. Generated lights retain existing session-only
Inspector edits; generated lights bypass the authored orbit pose lock, and playback samples can
overwrite their positions. Generated changes do not dirty or export,
and bridge proposals still require persistent subjects. Selection and enabled state retain full
identities across filtering and multi-primitive edits.

### Gizmo boundary and interaction

App vendors pinned MIT ImGuizmo following the App-only dependency pattern in
[ADR 0011](0011-vendored-imgui-node-editor.md). `GizmoModel` stays ImGui/SDL/Metal-free;
`ViewportGizmo.cpp` alone includes the vendor header. It draws clipped ImGui geometry into the
editor UI pass using the unjittered view and viewport rectangle, with colors from existing theme
roles. No scene encoder, render pass, shader, workspace or capture schema is added.

View > Gizmo and the toolbar choose View (Q), Move (W), Rotate (E), Scale (R), Transform (Y) and
World/Local (X). Choices start Move/World, stay transient and remain available during measurement;
the gizmo itself is inert during measurement or playback. Tool shortcuts require no text input,
popup, RMB look or another focused surface. RMB WASD/QE camera flight keeps its existing mapping.
Objects support all transform tools; points only Move and spots Move/Rotate. Cameras and
directional lights have no viewport gizmo. Disabled, Static, generated-object, animated, playing or
measuring subjects draw gray inert handles with a hover reason when their operation is supported.
Unsupported tools/subjects and invalid geometry/view inputs draw none.

The pinned vendor scales on local axes: World/Local applies to Move/Rotate, and Scale edits local
TRS factors. Combined Transform uses `SCALEU` to retain the requested space for Move/Rotate;
its scale handles also edit local TRS. There is no World-axis nonuniform scale/shear contract.
Finite matrices decompose through shared math; accepted object scales clamp to 0.01–100 and spot
directions normalize. Edits fan out through the same source binding as Inspector.

A drag retains the original pose, full selection identity and activation generation. Escape restores
that pose exactly. Selection/tool/space changes, scene replacement, playback/measurement, hidden or
collapsed viewport, focus loss, text input, popup or RMB look end interaction. Stale captured
identities never apply to a new scene; release is required before resuming an interrupted held
mouse gesture. No Undo/Redo history is introduced.

## Consequences and evidence

Scene-only screenshots/sequences and Session headless children omit gizmos and other editor cues.
A native GPU trace can contain the UI pass; inspect scene and UI encoders separately before
claiming scene-encoder isolation. The [UX6 validation](../milestones/ux/ux6-validation.md),
[mobility evidence](../milestones/ux/ux6-validation-mobility.md) and
[gizmo evidence](../milestones/ux/ux6-validation-gizmo.md) retain original failures, corrective
runs and native verification limits. Automated wrapper/model passes and exact headless screenshot
pairs do not establish a successful native drag or complete native scene-encoder inventory.
This ADR remains Proposed and supplies no milestone acceptance or integration decision.
