# R1.4 — Renderer Seams for M7

**Status**: Implemented (2026-09-13)

This record preceded the [design](../specs/2026-09-13-r1.4-renderer-seams-design.md)
and [execution plan](../plans/2026-09-13-r1.4-renderer-seams.md); implementation followed both,
as requested. The [refactoring roadmap](../roadmap/codebase-module-boundaries.md#r14--renderer-seams-for-m7)
and [ADR 0020](../decisions/0020-module-layering-and-units.md) own the boundary.

## Implementation

- Renderer composes concrete ShadowStage and SceneStage owners. They create opaque/masked
  pipeline variants, declare the existing passes and encode object bindings/draws. SceneStage
  draws sky last in the same scene pass. Renderer retains targets, shared fallback textures and
  samplers, temporal state and exposure/bloom/display orchestration. Stage callbacks copy frame
  values and borrow commands, scene resources and Renderer-owned fallbacks through execution.
- ShadowMatrices and fitShadowOrtho move with ShadowStage; Renderer.h includes the declaration
  for compatibility. AlphaMaskParams has one shared 4-byte layout header. The existing public
  capture registration entry point composes object, shadow/cutoff and pass/sky registration in
  the original serialized order. No shaders, RHI interfaces or SceneView fields change.
- CompiledFrameRecord.h owns the record and diagnostic value vocabulary. RenderGraph.h includes
  it; GraphDump and App's FrameRecordRing, GraphNodeModel and GraphInspectorModel consume the leaf.
  Render owns shared FrameDeclaration construction/execution, returning the accepted record for
  App to retain before endFrame and motion commit. Pool rotation, sink selection and waits keep
  the original ordering. Tests link the owning libraries and keep every prior case name/tag.
- The unchanged nativeOnlyTemporalView predicate moves to Temporal, removing AppModel's last
  transitive builder dependency through the vendor header. The module contract's forbidHeaders
  restriction rejects direct and transitive AppModel reach into RenderGraph.h, including through
  otherwise allowed units. Negative tests cover these paths and malformed/stale configuration.
  The migration allowlist remains empty.

## Verification

Evidence lives outside the repository in `/tmp/luminex-r1.4-evidence`: fresh same-device parent
and candidate release binaries, runtime shaders, hashes, commands and raw artifacts. Parent
runtime was frozen before source edits, candidate after the final build and independent review.

App, Tests and TextureBake build. Format, full policy, module/link checks, 65 standalone Source
headers and 22 standalone RHI headers pass. Tooling tests pass: 141 general Python cases, four strict-runner
self-tests, and 11 temporal comparison tests with one optional FLIP case skipped because its
package is absent. All 763 C++ case names/tags and the 19-case checkpoint-A selection match the
parent exactly. Both builds pass 592 CPU cases / 101,725 assertions and 19 checkpoint-A cases /
1,856 assertions. Both App and Tests shader trees are byte-identical (82 artifacts combined).

Independent review and `verify_draw_stage_extraction.py` verify 14 source-preservation checks:
seven uniform layouts, shadow fitting, all post-scene orchestration, labels, serialized capture
registration, both full pass declarations/draw bodies and pipeline descriptors. Owner/member
remapping and copied stage inputs are the only normalization applied to moved draw bodies.
No rendering-performance conclusion is drawn from this structural change.

All 14 required byte artifacts match: graph dumps, the three-frame temporal sequence and its
manifest, deterministic PNG and capture-schema JSON, and sRGB/linear/normal-map DDS bakes and
manifests. The stable MaterialLab capture matches ordered pass labels, resource declarations,
uniform layouts and frame-data upload layouts. Decoded uniform values match except the existing
editor wall-clock `time` field in upload 38; physical GPU addresses and timings are not semantic
comparisons. The original capture dumps and diagnostic limitations remain retained. Separate
Metal System Trace exports compare 60 frames and 900 engine encoder Encoding events on each
build: names, per-frame event order and aggregate label counts match exactly. Trace timings are
diagnostics only, and no opaque vendor encoder behavior is inferred from these native captures.

The unchanged fifteen-case strict matrix passes in its first paired round: both parent and
candidate match all 15 historical hashes and both runners exit zero. Every candidate hash is also
present in the parent run. Sampling stops immediately at one of the maximum eight paired rounds;
no reference change, re-baseline, retry-until-pass or historical exception is used. The runner,
reference, frozen binaries, all shaders and candidate source hashes remain unchanged throughout.
`paired-parity.json` retains all 30 images' hashes and original runner results.

## Validation-tool investigation

The parent's initial Metal-validation GPU run passes 171 cases / 252,423 assertions. After an
Instruments Metal System Trace, the candidate's first GPU run fails eight vendor cases with
nine unexpected exceptions. The unchanged pure RHI scaler case then fails identically in both
frozen builds. The parent debugger records an Objective-C unrecognized-selector exception:
`MTL4DebugComputeCommandEncoder globalTraceObjectID`, reached from MetalFX's
`MFXDevice4::emitSignPostForComputeEncoder` through GPUToolsCapture. Original runs and debugger
output remain in the evidence bundle.

Read-only framework inspection identifies the guard as MTLTraceEnabled(), which reads IOAccel's
shared tracing flag, currently 0x1; ordinary logging environment switches do not control it.
No foreground Instruments process remains. One non-Metal trace and one explicitly timed Metal
trace both completed their recording, but neither cleared the flag. The timed trace returned 54
after saving; its log and state probes are retained, and no task-owned App process remains.
The background trace owner is the pre-existing tailspind process; its ownership alone does not
prove how the flag changed. A supported ktrace disable/enable attempt needs administrator
credentials unavailable to the task. No daemon or persistent preference changes were made,
and renderer source stayed frozen.

The owner ran ktrace disable and remove. Neither cleared the flag after background tracing
resumed, and both retained parent repros failed. A subsequent probe while a foreground Time
Profiler trace of `/bin/sleep` was still active measured the flag at 0x0; the parent scaler then
passed 78 assertions with Metal validation enabled. Earlier probes had only measured after
recording ended and background tracing resumed.

Validation now uses that supported, temporary non-Metal foreground trace to keep the measured
flag zero for both frozen builds. Only the idle sleep process is profiled; renderer binaries,
shaders, test selectors, strict runner and Metal validation remain unchanged. Exact trace command,
process identities, state probes and logs are retained. This isolates a system tracing condition;
it does not fix Apple's debug encoder or establish success under the failing background state.
Both full GPU suites now pass 171 cases / 252,423 assertions, with the tracing flag verified zero
before and after each suite and Metal validation enabled. Original failed runs remain retained.
The unchanged strict matrix also passes its first paired round in this state, with flag zero
verified after the matrix. The task-owned foreground trace and sleep are closed after measurement;
cleanup state is retained separately. Background tailspind ownership and flag 0x1 return after
cleanup, so the background Apple tracing/debug incompatibility remains. No temporary process is
left running, and no further administrator action is needed. No rendering exception or
performance conclusion is inferred.

## Integration

The owner requested one commit and local main integration without a PR. The implementation,
current documentation and this passing evidence record land together from codex/r1.4-renderer-seams
by fast-forwarding local main, preserving its existing history. No remote publication is implied.
The retained plan is closed following the preceding slices. This slice completes the structural
prerequisite for interface gate B; it does not approve that review or start M7.1. Exposure/bloom/
display extraction and graph implementation splits remain outside its scope.
