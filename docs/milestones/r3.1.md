# R3.1 — Documentation Records

**Status**: Proposed

R3.1 regroups `docs/` so that a milestone's design, record, validation notes and postmortem sit in
one series folder. It deletes the fifteen closed executor plans, removes `docs/specs/` and
`docs/postmortems/`, and states where a new design and a new plan are written. It then copyedits
the living documents for plain prose. It touches documents, the policy checker and the checker's
tests. Three path comments under `Benchmarks/FrameData/` follow a moved design. No other source,
shader, build file or rendered output changes, so the comparison protocol does not apply.

[Part III](../roadmap/codebase-restructuring.md#r31--documentation-records) owns the outcome and
the exit gate. [R3](r3.md#r31--documentation-records) owns the series design. This record keeps
the path table, the rules the executor follows, and later the evidence.

## Inventory before R3.1

`docs/milestones/` holds 46 records in one folder. `docs/specs/` holds 19 designs: the founding
design and 18 slice designs, two more than R3 counted because the R2.3 and R2.4 designs landed
afterwards. `docs/plans/` holds 15 plans, all `Implemented` or `Frozen`, which the
[documentation convention](../conventions/documentation.md#status-lifecycle) says should already
be gone. `docs/postmortems/` holds two closed postmortems.

Seven of the slice designs are longer than 300 lines (the longest is 458). The checker applies a
300-line budget to everything under `docs/milestones/`, while the convention exempts historical
specs. The checker has to learn that exemption before the first design moves.

## Moves

A short resolver script performs each move. It takes a subset of the path table, runs `git mv`,
and then rewrites Markdown link targets across the repository. It resolves each link against the
directory of the file that contains it. That matters in two directions: links that point at a
moved file change, and so do the relative links inside a moved file, because the file is now one
level deeper. Anchors, link text and everything outside link targets stay byte-identical. The
script lives in the executor plan and leaves with it. The table above is what remains.

There is one commit per destination folder, seven in all, and the policy check passes at each.

## Closed plans

The tag `r3.1-closed-plans` marks the commit before the deletion, and every one of the fifteen
plans is reachable from it. One commit deletes them. Each link that pointed at a plan becomes
plain text that names the tag and the old path, so no current document depends on a deleted file.
`docs/plans/` stays as the one transient folder, empty between milestones.

## Checker

The test comes first, in `Tools/tests/test_project_policy.py`.

- `STATUS_DIRS` drops `specs` and `postmortems`. Status is still required for every file under
  `docs/milestones/` and `docs/decisions/`, so no moved document loses its status check.
- `LINE_BUDGETS` drops `docs/postmortems/`. Files under `docs/milestones/` whose name ends in
  `-design.md` are exempt from the 300-line budget, as the convention already says.
- A new rule rejects a Markdown file placed directly in `docs/milestones/`. A new record has to
  name its series folder.

## Convention and navigation

`docs/conventions/documentation.md` restates three document types. A milestone record lives in its
series folder. A retained design sits beside its record as `<id>-design.md` and is frozen once the
slice is implemented. A postmortem sits in the series of its period. Precedence order does not
change.

`AGENTS.md` retargets its golden sources and states the two locations the design and planning
skills should use: a brainstormed design is written as the `Proposed` milestone record in its
series folder, and an executor plan goes to `docs/plans/`. `AGENTS.md` is at 246 of its 250 lines
today. Removing the section described below frees five.

R3 and Part III get their counts corrected: 19 designs where they say 17, and 15 files in `r/`.
Their R3.1 sections also gain the two additions below, so the roadmap still owns the full scope.

## Private notes stay out of the repository

The owner keeps personal development notes outside the repository and asked that tracked files
stop mentioning them. Four places do: a section near the top of `AGENTS.md`, one clause in each
of the R2.3 and R2.4 designs, and one clause in the UX2 record. R3.1 removes all four. The two
designs are frozen, so this is an owner-approved exception to the links-only rule, limited to
those two clauses. Git history is left as it is.

## Prose pass

After the moves, the living documents are copyedited so they read as plain technical prose. In
scope: `README.md`, `AGENTS.md`, `docs/conventions/`, `docs/guides/`, `docs/architecture/`,
`docs/frame-pipeline.md`, `docs/roadmap.md` with its parts, and milestone records that are not
frozen. Out of scope: accepted ADRs, the founding design, every `-design.md`, research notes and
postmortems. Their text stays as it is, so the convention's immutability rules remain true.

Rules for the pass:

1. Every claim, number, identifier, date, status value, gate result and evidence limit survives.
   A lost or added fact is a defect.
2. Headings do not change, because other documents link to their anchors.
3. Code spans, code blocks, commands, paths, link targets, tables of data and status lines do not
   change. The status value `Frozen — non-normative` keeps its dash because the convention defines
   it.
4. Line budgets still hold, and `README.md` still passes the public-copy rule.
5. One commit per folder. A reviewer checks each commit against rule 1 before the next slice of
   R3 starts.

## Verification

- `python3 Tools/check_project_policy.py` passes at every commit, including the commit range check
  on messages.
- `python3 -m unittest discover -s Tools/tests` passes.
- Every local link resolves. The checker proves this for link targets; a separate sweep confirms
  that plain-text mentions of `docs/specs/`, `docs/postmortems/` and the deleted plan paths
  remain only where they name the tag.
- `git log --follow` reaches the pre-move history for a sample of files in each series.
- Each move commit shows its files as renames, with changes confined to link targets.
- A search of tracked files finds no mention of the private notes.

## Limits

Anchors are not machine-checked, which is why headings stay fixed. The prose pass is reviewed by
reading, so its evidence is a reviewer's statement per folder and cannot be a byte comparison.
