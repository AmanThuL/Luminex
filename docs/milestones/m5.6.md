# M5.6 — GPU Work-Submission Evidence Closure

**Status**: Implemented
**Date**: 2026-09-06

The frozen M5.6 experiment implemented a native Metal 4 comparison of `direct`, `cpu-indirect`, `gpu-args`, and
`batched`, with a separate untimed production RHI correctness anchor. Production M5.5 runtime
code in `Source/` and `RHI/` remains unchanged, including the
[ADR 0010](../decisions/0010-execution-model-partial-reshape.md) frame-data contract.
M5.6 closed on 2026-09-06 as **reliability failure / DEFER / NO performance conclusion**, under
the user-authorized terminal contract accepted in [ADR 0012](../decisions/0012-gpu-submission-defer.md).
Implemented means completed administrative and evidence closure, not successful validation.
The user waived the full 1,920-pair measurement requirement solely for closure; the original
gates were not passed. Future adoption still requires full validity. Retain the incumbent;
no root-cause fix, performance win, experimental runtime, ICB or RHI extension is adopted or claimed.

## Collection stopped; no accepted performance conclusion

The campaign stopped after GPU global restarts and retirement failures. There are 1,043
structurally valid pairs, two aborted processes and one operator-interrupted pair; the supported
1,920-pair matrix is incomplete. Partial results are not accepted performance evidence. The
frozen protocol required 20 workload cases in S
(shared precomputed visibility) and E (end-to-end culling), 12 alternating AB/BA pairs per
comparison, and 32 warmup plus 256 measured frames per run. Each other implemented mode was
paired against `direct`, and `gpu-args` was also paired against `batched`.

The [closure report](../research/2026-09-06-gpu-submission-closure.md) records bundle indexes,
diagnostic conclusions and reopening conditions.
Native-host results concern execution mechanisms; they are not production renderer speedups.
Missing GPU-span guards and capture evidence defer adoption even if headline wins emerge.

## Known limits and handoff

- ICB remains unavailable for this experiment: pinned Slang 2026.14.1 reports E30015 for the
  opaque `command_buffer`, `render_command`, and `primitive_type` probe. The route is unresolved;
  this is not a universal impossibility claim or proof of ICB runtime/production graph support.
- GPU-span and stage lanes are not implemented, with workload boundaries unproven. Their
  metrics are unavailable, not zero, and no physical GPU limitation is inferred.
- The capture gate remains unavailable: the sparse blob contains initial warmup phase 6
  state, not post-dispatch phase 0. Decoded labels/images and source-checked bindings do not
  establish captured generated arguments. Separately passed post-retirement parity remains valid.
- Retain the pre-freeze long-replay IOGPU fault with unknown cause. Final replay success does
  not establish a fix or erase the failed attempt.
- No-verify pairs p02932 and p03037 subsequently aborted; the campaign was interrupted during
  p03073 for safety. Kernel logs show global GPU restarts. Faulting modes and root cause are
  unresolved; independent source and shader/ABI audits found no proven cause. All records remain.
- A subsequent user-authorized single-mode diagnostic
  reproduced gpu-args/S command-queue timeout in warmup with API/shader validation off. It preserved
  pipelining without readback; the validation-on run retired. This narrows the reproducer, not the
  original two-mode failures or root cause. Diagnosis stopped after the new reset; no fix is claimed.
- A same-binary dependency comparison
  used identical 32+900-frame requests without validation. Original masks retired twice; all-stage
  retired once and timed out once during warmup, with a global reset. A wider mask is not a fix;
  individual retirement passes do not establish reliability. GPU testing stopped at that reset.
- Selective shader instrumentation
  retired all four 32+900-frame configurations, including neither pipeline instrumented, with no
  new reset. Queried states matched requests. API/global validation remained on, so this neither
  localizes a shader defect nor establishes stability without validation. Root cause remains open.
  A later pair with global shader validation off retired with API validation on, then timed out
  with it off. The warmup failure triggered a reset; GPU testing stopped. This is sensitivity
  evidence, not proof that validation repairs a particular defect.
- A producer comparison
  retained full-N indirect draws with CPU-filled arguments: two such runs retired; original GPU
  generation retired once and timed out once. Root cause is unresolved and GPU testing stopped
  after the new reset. ADR 0012 now accepts terminal closure without treating these runs as gate passes.
