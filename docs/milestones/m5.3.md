# M5.3 — Editor Workspace and Selection

**Status**: Implemented (2026-08-13)

M5.3 turned the docked editor into a five-panel selection-driven workspace — Scene, Viewport,
Inspector, Performance, and Render Graph — without changing render-graph execution, image
formation, or RHI semantics. A main menu (File/Window/Layout/Debug) exposes quit, panel visibility,
default-layout reset, and next-frame GPU capture (shown with its existing `C` shortcut) as
App-owned action intents; the frame loop consumes quit and capture at the boundary that already
owns each operation, and the shell consumes a layout reset itself, at the start of the next frame.
Workspace visibility and a schema version persist in `imgui.ini` through a registered ImGui
settings handler, as Luminex's own section alongside Dear ImGui's own docking data: a clean run or
an M5.2-era ini with no matching schema builds the default topology once; a matching schema
restores the user's docking, sizes, and visibility unchanged; Reset Default Layout rebuilds only
the Luminex topology, idempotently, leaving unrelated ini entries untouched.

Selection is `EditorSelection` — a scene ID, subject kind (`Camera`/`Rendering`/
`DirectionalLight`/`Object`), and index — resolved fresh against the active scene on every use
rather than cached as a pointer. Startup and every successful scene switch select the new scene's
`Camera` and clear the Scene filter; a failed switch retains the active scene, selection, and
filter exactly; a stale scene ID or out-of-range index heals to `None` before the Inspector draws.
The Scene panel groups Workspace / Directional Lights / Objects rows behind a case-insensitive
filter over the existing flat scene list, without introducing a hierarchy into Engine. The
Inspector draws only the selected subject's fields (Camera, Rendering, Directional light, or
Object), sharing state with the Viewport's compact toolbar so a toggle in either place is visible
in the other on the same UI frame. Relative-mouse look releases on right-button up, Viewport
close/collapse, application window focus loss, a layout reset, or shutdown.

The Performance panel replaces the Inspector's former Stats section with a coherent, pausable
snapshot: a Pass/Average/Latest/Min-Max/Samples table over the unchanged 60-retired-frame rolling
window, a wall-clock frame-interval plot, an FPS reading smoothed over a 120-sample interval
history, a `Timed pass sum` explicitly not claimed as total GPU frame time, and the transient
memory figures of the retained compiled frame. Pause freezes every field together; Clear History
empties both histories and shows a waiting state until the next accepted sample. Render Graph keeps
its own, independent time domain — the exact newest retired frame, joined by frame ID — regardless
of Performance's pause state, and remains independently dockable and closable.

## Evidence

**Automated**, at branch tip `8a0b15f` on Metal 4 Apple Silicon (M-series, macOS 26):

- `xmake test Tests/unit` and `MTL_DEBUG_LAYER=1 xmake test Tests/gpu` both 100% pass.
- The frozen `[checkpoint-a]` filter passed unchanged under `MTL_DEBUG_LAYER=1`: 1,856 assertions
  in 19 test cases.
- `xmake format --check` and `xmake policy` clean.
- `LMX_MAX_FRAMES=120 MTL_DEBUG_LAYER=1 xmake run App` presented 120 frames, skipped 0, with no
  validation errors, including the built-in mid-run window resize hooks.
- Fixed-camera 1280×720 offscreen screenshots of Sponza, Damaged Helmet, and MaterialLab at the tip
  are byte-identical (SHA-256) to the fork-point baseline captured at the milestone start: renderer
  output is unchanged.
- Workspace migration runs (from stage-2 verification, re-verified conceptually at the tip): a
  clean ini builds the default five-panel layout once and records `Schema=1`; a matching-schema ini
  restores without rebuilding; a legacy (Luminex-section-free) ini and an unknown `Schema=99` ini
  each rebuild the default once; two consecutive Reset Default Layout requests produce identical
  dock nodes (IDs 0x1–0x6, no accumulation) and restore default visibility while preserving
  unrelated `[Window]` entries; programmatic GPU capture via `LMX_CAPTURE_AT_FRAME` works
  end-to-end; an all-panels-hidden run keeps every dock node recoverable from the menu.

**Manual visual QA**: an operator pass on the shipped workspace found the layout generally
correct, with one finding — the Performance panel's original vertical stack overflowed the default
lower dock height, hiding the pass table until the panel was dragged taller. The panel was
relaid out into side-by-side stats, plot, and scrolling-table regions that fit the default height.
Remaining unexercised spot checks: the full resolution matrix at 1440×900 and 2560×1440 including
Retina backing scale, long-name overflow, and toolbar behavior at the 640 pt Viewport minimum.

## Deliberate limits and deviations

- **Spec §3's minima wording was amended on-branch.** The literal ≥1280×720 work-area gate under
  the menu bar was unsatisfiable — the menu bar consumes work-area height the gate did not budget
  for. The shipped behavior is unconditional per-panel minima (Scene ≥220 pt, Inspector ≥320 pt,
  Viewport content region ≥640×360 pt) with the Viewport winning and the side panels narrowing when
  a window cannot satisfy all of them.
- **Menu Quit completes its frame before exiting.** Drawing the menu only sets a pending intent;
  the frame loop consumes it at the top of the *next* iteration, so the frame that drew the menu
  still finishes and presents normally.
- **Performance FPS is a mean, not an instantaneous reading.** The published `framesPerSecond` is
  `1000 / mean(frameIntervalsMs)` over the rolling 120-sample wall-clock interval history, chosen
  because the instantaneous `1000 / latestFrameIntervalMs` read jittery at the panel's 4 Hz
  republish cadence.
- **Performance's object/draw counts are approximate.** They are read from the shell's
  current-frame scene state and attached to whichever GPU frame the ring currently reports as
  newest-timed, so they can trail or lead the frame the timing row actually measured.
- **Spec §13's input-exit coverage is runtime-verified, not unit-tested.** Right-button release,
  Viewport close/collapse, focus loss, layout reset, and shutdown were exercised in-app under Metal
  validation rather than through an automated input harness.
- **A pre-existing double-shutdown was found, not introduced, in `EditorShell::create`'s
  initial-scene-failure path.** When the initial scene fails to load, `create()` explicitly shuts
  down the ImGui backends and context before returning `nullptr`; the local owning pointer holding
  those same resources then destructs on the same return, running the shell's destructor's shutdown
  sequence a second time. This path predates M5.3 unchanged and is recorded here as a known limit
  rather than fixed, since startup error handling is outside this milestone's scope.
