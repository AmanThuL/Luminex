# R3.3 — Engine Validation Record

**Status**: Implemented

`Source/Asset` and `Source/Scene` are now `Source/Engine/`. `Engine/Types/` holds the scene
vocabulary that left Render plus the three extracted leaf headers, `Engine/Scene/` the scene,
its identities and the table row ABI, `Engine/Upload/` the GPU uploads, `Engine/Catalog/` the
catalog and labs, and `Engine/Asset/` the unchanged Asset unit in `Image/`, `Model/` and
`Texture/`. `Bounds.h` is in `Core/`. Target `Scene` has dissolved into static library `Engine`,
`lmx::scene` and the moved vocabulary are `lmx::engine`, and Render builds `SceneView` through
`render::buildSceneView` in `Render/SceneViewBuilder.{h,cpp}`. Render depends on Engine; Engine
reaches no Render header, and its archive carries no undefined `lmx::render::` reference.

Against the [exit gate](../../roadmap/codebase-restructuring.md#r33--engine): the per-commit
protocol and the format check held at every code commit of the branch; the Asset archive has no
undefined `rojoRHI::` reference and `TextureBake` links `Core` and `Asset` only, with no Metal
framework; the Engine archive has no undefined `lmx::render::` reference; the test case and tag
inventory equals the parent's at every commit. Nothing rendered or observable changed: GPU tests,
graph dumps, screenshots, capture sequences, capture dumps, baked textures and the parity matrix
match the parent.

Parent for every comparison: `75dd539`, the tip of `main`. Head protocol candidate: `17cba47`,
whose tree equals the branch's `c314bef`. Device: Apple M3 Max, macOS 26.7, Metal 4, release
builds, xmake 3.0.9.

## The per-commit gate

`gate.sh <worktree> <label>` builds `App`, `Tests`, `FrameDataBench`, `TextureBake` and
`RojoRHITests` in release, then:

1. strips `#line` from every `.metal` file of the three shader output directories and diffs them
   against the parent's (63 per directory);
2. diffs the Catch2 case list (849 lines), tag list and case-to-tag list against the parent's;
3. asserts `LocalLightMath.cpp` alone keeps `-ffp-contract=off` in the compile database and that
   `Tools/module_allowlist.json` has no entries;
4. runs `check_submodule_pin.py`, `check_project_policy.py`, `check_shader_imports.py`,
   `check_source_headers.py`, `check_cpp_layout.py`, `check_module_deps.py --link` and
   `check_cpp_comments.py --public-api-docs error`;
5. runs the `Tools/tests` and `Tools/TemporalCompare` Python suites, `xmake format --check`, and
   the CPU filters of both test binaries.

A passing log ends `All tests passed (903868 assertions in 650 test cases)`, the RojoRHITests line
`All tests passed (419 assertions in 143 test cases)`, then `GATE PASS <label>`.

The gate was proven to fail before use: at the parent it stops on `LocalLight.h`'s header
(`self-before-repair`), a renamed test case produces a case-list diff (`probe-case`), a dropped
floating-point flag trips the assertion (`probe-flag`), and a failing Python test fails the run
(`probe-unittest`). Two defects found in review were fixed before any commit was gated: an
`&&`-joined line that let a failing Python suite pass, and a `grep` status that could exit 0.

## Namespace substitution

`identifiers.txt` holds 44 names, 4 bound for `lmx` (`Bounds.h`) and 40 for `lmx::engine`,
generated from the declaring headers and read against them. `namespace.py` tokenizes C++, skipping
literals, comments and preprocessor lines, and tracks namespace blocks by brace depth; its 49
cases cover the record's examples and idempotence. The commit rewrote 182 files and 1,438 lines
and introduced no using-directive; existing `using namespace lmx::scene;` lines became
`lmx::engine`. Where a test file has `using namespace lmx::render;` and not `lmx`, the rename
writes `lmx::engine::X` in full.

## Deviations from the record

- **Steps 5 and 6 are one commit.** Step 5 alone leaves `Source/Engine/` with a header and no
  compiled source, which `check_source_headers.py` rejects (`v-S5-27fd8f8`); step 6 alone lets
  the vocabulary in `Engine/Types/` include `Render/SceneTables.h`, which the unit table rejects
  (`v-S6-3834888`). The record's "a header needs no target" held for the module checker only.
- **Steps 17 and 18 are swapped.** The link check reads every member object of the archive, so
  while Engine's own vocabulary was still in `lmx::render` it reported `makeCube`, `makePlane`
  and `makeLightRow`. The contract commit follows the rename.
- **The contract gained `pendingPaths`.** The checker rejects a unit path that does not exist, and
  `Source/Engine` could not exist at step 3. The optional list names paths a staged move has not
  created or has emptied; step 17 removes it, and `modules.md` describes it.
- **An added documentation commit** turns the research note's two links to moved sources into
  text, as R3.2 did for a shader path; frozen notes keep the paths they were written with.
- **Step 2** repaired `LocalLight.h`'s envelope by making its `@brief` one line. The header's
  closing ruler existed; its summary wrapped onto line four.
- **Two follow-up commits** from the branch review: comments that still qualified moved names with
  `render::` or `scene::`, and `load_pending_paths` no longer writing into the loaded contract.
- **Step 20** names a README directory table that does not exist; the README is unchanged.

## Limits

- ADR 0025 keeps lighting modes in Render, but the record's path table moved `LocalLight.h` and
  `SceneTables.h` whole, so `LocalLightMode`, `LightDebugView` and Render's binding-slot
  constants are now `lmx::engine` names Engine never uses. A later change can extract them to a
  Render header; R3.3 moves files and does not split them.
- Render's use of `Engine/Scene/Scene.h` is confined to `SceneViewBuilder.cpp` by review, not by
  the checker.
- `docs/roadmap/codebase-module-boundaries.md` still describes the layout before R3.3; ADR 0025
  and `modules.md` are authoritative.
- The temporal documentation's "engine reset" and "engine history", meaning Luminex's own path
  as opposed to the vendor scaler's, now read close to the Engine subsystem's name.
- The mechanical commit bodies cite scripts that live only in the evidence bundle.
