# R3.6 — App

**Status**: Proposed

R3.6 gives `Source/App` its second level, decomposes its two files over the review budget, and
finishes App's adoption of Core: three history holders sit on `RingBuffer`, the console's
severity type gives way to `log::Level`, two timing sites use `Stopwatch`, and selection framing
takes its geometry from Core. Rendered output, shipped behaviour, the workspace file and every
CLI surface remain unchanged.

[Part III](../../roadmap/codebase-restructuring.md#r36--app) owns the outcome and the exit gate.
[R3](r3.md#r36--app) owns the series design and the accepted layout. This record keeps the
inventory, the path table, the two decompositions, the Core adoption table, the commit sequence
and the rules the executor follows. It is delivered as two pull requests under one record and one
validation record: **A** contains changes intended to be neutral (moves and decompositions);
**B** contains the Core adoptions, one of which retires a public AppModel type.

### Decompositions

Public headers, window names and every panel string are unchanged; the new units hold members
or sections of the same class or panel.

- **EditorShell.** `EditorWorkspace.cpp`: the `[LuminexWorkspace][Workspace]` settings handler
  and its four callbacks, the default dock layout builder and its extents, `setPanelVisible`,
  `setUiScale` and `updateUiScaleShortcuts`; the handler's registration stays in `create` and
  calls a private member the new unit defines. `EditorInput.cpp`: `updateCameraInput` and
  `endMouseLook`. `EditorShell.cpp` keeps creation, destruction, the viewport resize, the frame
  hooks, `buildUI`, `buildMainMenu`, `buildPanels`, scene selection and the render-graph
  bridging, and lands near 770 lines. Workspace schema 3 files written by the parent build load
  unchanged and are re-saved byte-identical.
- **InspectorPanel.** `InspectorInternal.h` (private): the three row helpers `beginFieldRow`,
  `valueRow` and `beginReadings`, the rendering reset row, and the section entry points
  `drawCameraSection`, `drawRenderingSection`, `drawTemporalSection`, `drawDisplaySection`,
  `drawDirectionalLightSection` and `drawObjectSection`, all taking the existing
  `InspectorPanelContext`. `InspectorCamera.cpp`, `InspectorRendering.cpp` (rendering, temporal
  and display, the three Rendering-topic sections), `InspectorLight.cpp` (the directional light)
  and `InspectorObject.cpp` hold the bodies as they are today; `InspectorLighting.cpp` is
  unchanged. `InspectorPanel.cpp` keeps the row helpers' definitions and the dispatch, near 130
  lines. Section order, ImGui IDs and strings do not change.

### Core adoption

Each row is one commit in part B, after `RingBuffer::popOldest` lands with its own test.

| Site | Becomes | Note |
|---|---|---|
| `RingBuffer` | gains `popOldest()`: discards the oldest held value; asserts on empty | Core test cases added and declared before the first gate; the existing capacity, index and iteration contracts are unchanged |
| `FrameRecordRing::m_frames` | `RingBuffer<RetainedFrame>(kCapacity)` | `retain`, `joinTimings`, `newestTimedFrame`, `find`, `size` keep their signatures and results; `kCapacity` stays 4 and the comment preferring a vector is retired with the vector |
| `PassTimingHistory::Series::samples` | `RingBuffer<double>(kSampleCapacity)` | `summaries` iterates through the ring's forward iterators; a schedule change still resets every series; the summary values are exact |
| `ConsoleLog::m_entries` | `RingBuffer<ConsoleEntry>(kMaxEntries)` with `popOldest` for the byte bound | `append`, `snapshot`, `snapshotAfter` and `clear` keep their signatures; sequence identities, loss counters and truncation are unchanged; snapshots copy through the ring's iterators |
| `ConsoleSeverity` | `log::Level` from `Core/Diagnostics/LogSink.h` | `ConsoleEntry::severity` changes type; the sink's switch is deleted; `ConsoleModel.h`, `ConsolePanel.cpp` and `AppConsoleTests.cpp` follow. Case names and tags stay; only the enum they spell changes |
| `main.cpp` measurement timing | two `Stopwatch` values; encode time by `elapsedMilliseconds`, wait time by `elapsedMillisecondsUntil` | the shared boundary sample stays one sample, as R3.5 added the method for; the clock is the same `steady_clock` |
| `Measurement.cpp` `Clock`, `elapsedMs` | `Stopwatch` | the local alias and helper are deleted |
| `SelectionBounds.cpp` `frameSelection` | `center(bounds)` and `boundingSphere(bounds).radius` | adopted only if `AppSelectionBoundsTests` stays exact under the same assertions; the double-precision distance and the clamps stay App's. If the float centre or radius changes any asserted value, the row is reverted and recorded as a limit |

No other Core helper has an App consumer: `Aabb`'s transform is already used by
`SelectionBounds`, and no App source implements math or a container that Core's charter claims
after these rows.

## Rules

- The [R1 comparison protocol](../../roadmap/codebase-module-boundaries.md#r1--module-boundaries-and-shared-foundations)
  applies. R3.5's cheap gate runs at every commit: build, generated MSL, test inventory by case
  name, tag and pairing, CPU tests, every checker, the format check, and the flag-carrier set,
  which must stay the parent's five Render files.
- Every code commit (A23–A24, B1–B8) also reproduces, byte for byte against `7b57102`: the
  Sponza, LightLab and TemporalLab `--temporal off --frames 4` screenshots, the Sponza frame-1
  graph dump, and the fresh-default-workspace editor graph dump. Every commit that touches
  `Shell/` or `Model/Workspace/` also passes the workspace round trip: the parent build's
  schema 3 `imgui.ini` is loaded by the candidate under `LMX_MAX_FRAMES` and re-saved
  byte-identical, and a fresh default workspace saves the same bytes as the parent's. B2–B5 also
  compare a `--measure` schema 4 JSON with the parent structurally (schema, keys, frame and pass
  counts; values vary per run) and the Console panel's displayed text for a scripted run.
- At each pull request's head: a scripted editor run under `MTL_DEBUG_LAYER=1` with
  `LMX_MAX_FRAMES` is validation-clean; the full GPU suites, both checkpoint A filters, the
  three-frame sequence and manifest, `xmake policy`, and the link check proving `AppModel` has no
  ImGui, SDL or Metal reference; temporal modes are compared by the eight-round parity protocol.
- An adoption that cannot hold its gate is reverted and recorded; the record then names the
  site as a limit.
- No class, pass or pipeline label, shader basename, CLI option, environment variable, schema,
  file format, window or panel string, test tag or test case name changes. `RojoRHI/` is not
  edited. No base class, factory or persistence type is introduced.

## Limits

No Tests folder moves (R3.7 owns them) and no Render or Engine change. `RenderGraphCanvas.cpp`
(829 lines) is under budget and stays whole. `ImGui` settings-handler and `DockBuilder` calls
remain internal-API uses contained in one unit, as today. The measurement JSON gate is
structural, so B6–B7 make no performance claim; the durations they publish are the same clock
differences. UX2 owns every behaviour change to the editor.
