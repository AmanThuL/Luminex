# R3.5 — Render

**Status**: Accepted

R3.5 gives `Source/Render` its second level, finishes Render's adoption of Core, decomposes its
three largest functions, writes down the shape its stages share and corrects the departures, and
replaces setup and encoding code repeated across stages with shared free functions. Rendered
output and shipped behaviour do not change.

[Part III](../../roadmap/codebase-restructuring.md#r35--render) owns the outcome and the exit gate.
[R3](r3.md#r35--render) owns the series design. This record keeps the inventory, the path and
interface tables, the commit sequence and the rules the executor follows. It is delivered as two
pull requests under one record and one validation record: **A** is provably neutral (moves, Core
adoption, decompositions); **B** edits signatures, test call sites and the draw-encoding path.

Implementation is active under the R3.5 executor plan in `docs/plans/`; PR A and PR B remain pending.

## Delivery progress

Part A implements the 82-file move, the four Core adoptions and the Renderer, SceneStage and
transition decompositions. Part B remains active for stage shape and shared helpers. The
[validation record](r3.5-validation.md) owns the checked revisions, results and remaining gates;
this accepted design is not marked Implemented until both parts finish.

One additive Core adjustment preserves A18's exact timing boundary: `Stopwatch` exposes
`elapsedMillisecondsUntil(const Stopwatch&)`, so the classifier ends at the same captured clock
sample that begins preparation. Its direct unit case is the only new test in part A.

### Decompositions

Public headers and every pass label are unchanged; the new units hold members of the same class.

- **Renderer.** `RendererCreate.cpp`: fallback texels, constructor, destructor, `create`, `resize`,
  `createTemporalTargets`. `RendererFrame.cpp`: two private members,
  `deriveFrameState(view) -> RendererFrameState` (mode, scale, extents, signature, reset reason,
  slots, jitter, camera state, shadow fit) and `importFrameResources(graph, state) ->
  RendererFrameImports` (persistent targets, temporal pairs, exposure, scene and light tables).
  `RendererStatus.cpp`: `recordFrameStatus` (temporal status, previous uses, counters) and the
  target accessors. `Renderer.cpp` keeps `declarePasses` as the stage wiring between them, and
  `render`. `Renderer.h` forward-declares the two structs; `RendererInternal.h` defines them.
- **SceneStage.** `SceneStageInternal.h`: the four uniform structs with their assertions and the
  slot constants. `SceneStageLayouts.cpp`: the two capture registrars. `SceneStagePipelines.cpp`:
  `create`. `SceneStageDraw.cpp`: the pass body as a private member. `SceneStage.cpp` keeps
  uniform packing and the `PassDesc`.
- **deriveTransitions.** The function becomes a sequence of private steps over one state object
  declared in `RenderGraphInternal.h`: seeding from earlier-frame texture and buffer accesses,
  alias waits at lifetime boundaries, read-after-write, write-after-read. Its comments move with
  the step they explain. The emitted `DebugTransition` sequence keeps its order.

## The stage shape

Written into the [engineering convention](../../conventions/engineering.md) as the first commit of
pull request B. A stage is a class that creates GPU objects when it is constructed and declares
passes each frame.

1. `static rojoRHI::Result<std::unique_ptr<X>> create(rojoRHI::Device&, …)`, a private
   constructor, no second initialisation phase. Extra parameters are creation facts only: a
   format, an extent the stage allocates at, `cpuReadback`.
2. One `declare(RenderGraph&, rojoRHI::CommandList&, [const SceneView&,] const XInputs&)`
   returning the `GraphTexture` or `XOutputs` it produces, or `void` when it only writes a target
   its inputs name. More than three arguments after `commands` means an inputs struct.
3. `resize(width, height)` only on a stage that owns extent-dependent resources, with its
   identity-and-history policy stated in its comment; `std::array<Slot, 3>` for paced data and
   `[2]` for ping-pong history.
4. Failures propagate as `auto x = …; if (!x) { return std::unexpected(x.error()); }`.
5. Pipelines, libraries and resources are labelled; new pipelines use `lmx.render.<name>Pipeline`
   and new passes `lmx.pass.<family>.<step>`. Existing labels are frozen.
6. Shared mechanics come from `Render/Common/`; a stage keeps its shader mirror structs, slot
   constants and policy.

Named exceptions, recorded in the convention: `VendorTemporalScaler` is an adapter and not a stage
(its constructor creates nothing and cannot fail; creation happens in `prepare`, which reports a
native fallback instead of an error), and keeps `declarePack` beside `declare`; `ExposureStage`
keeps `declareSeed` and `declareMetering`, which run before and after the scene;
`OcclusionReference::declare` returns `Result<void>` because it allocates per frame; the pipeline
labels under `lmx.visibility.*`, `lmx.light.*`, `lmx.selection.*`, `lmx.occlusion.reference.*`
and `lmx.pipeline.temporal.vendor.*` stay as captures and guides know them.

Defaulted parameters become defaulted fields, so every call site states the same values it does
today. Collapsing the three-phase initialisation changes the order in which Renderer's GPU objects
are created, not which exist: a **declared difference**, visible only as object order in a GPU
capture. Images, graph dumps, labels and the validation layer do not see it.

## Shared helpers

Free functions and one template; no base class, factory, cache or virtual call. A caller passes
the full label, so no label changes.

| Header | Declares | Replaces |
|---|---|---|
| `Dispatch.h` | `kComputeThreadsPerGroup2D`; `dispatchGroups2D(width, height)` | five constants, 11 sites; CPU unit tests |
| `GraphResources.h` | `texture(resources, handle)`, `buffer(resources, handle)`: unwrap with `LMX_ASSERT` on the graph's message | 60 sites; two stages gain the assertion they omit |
| `StageSetup.h` | `fullscreenPipelineDesc(library, fragmentEntry, colorFormat, label)`; `createTexel(device, format, kind, bytes, label)`; `createComputePipelines(device, names, labelPrefix, threadsFor)` | 6 descriptors; 5 textures; the `GpuVisibility` and `LightClusterStage` loops |
| `PacedSlots.h` | `importPaced(graph, buffer, name, use, used)`; `declareZeroFill(graph, commands, passName, buffer, bytes)`; `retireThrough` and `takeRetired` over a pending vector and a frame projection | 2 imports, 3 fills, 3 drains |
| `DrawEncoding.h` | `bindSceneTables(commands, tables, slots)`; `template <class PerRun> void encodeDrawRuns(commands, draws, PerRun&&)`: the run loop with the pipeline-switch cache and the direct or indirect draw, calling `PerRun` for the stage's pipeline choice and mask binding | 4 triples; the loops of `SceneStage`, `ShadowStage`, `SelectionOutline`, `OcclusionReference` |
| `TemporalResolveInternal.h` | `declareReconstruction(const ReconstructionDeclaration&)`: parameter bytes, pipeline, pass name, dispatch extent | the bodies of `declareResolve` and `declareUpscale`, which stay as entry points; kernels, shaders and ADR 0014–0016 contracts stay separate |

`encodeDrawRuns` is a header template so the per-run callable inlines; it takes no
`std::function`. Each helper lands in its own commit before its adoptions, and adoption is one
commit per helper.

## Rules

- The [R1 comparison protocol](../../roadmap/codebase-module-boundaries.md#r1--module-boundaries-and-shared-foundations)
  applies. R3.4's cheap gate runs at every commit: build, generated MSL, test inventory by case
  name, tag and pairing, CPU tests, every checker, the format check, and the flag-carrier set,
  which must stay the parent's five files under their new paths.
- Every code commit (A16–A22, B2–B20) also reproduces, byte for byte against `2f37615`: the
  Sponza, LightLab and TemporalLab `--temporal off --frames 4` screenshots, and the Sponza frame-1
  graph dump. A commit that touches `SelectionOutline` adds the editor graph dump; one that
  touches visibility or occlusion adds a VisibilityLab screenshot under `--classify gpu
  --occlusion on`. Temporal modes are compared at each pull request's head by the eight-round
  parity protocol, with the full GPU suite under the validation layer, both checkpoint A filters,
  the three-frame sequence and manifest, and `xmake policy`.
- The draw-encoder adoption (B19) is also measured: fresh-process AB/BA pairs of the parent and
  candidate `App` with `--measure` schema 4 on Sponza and VisibilityLab at 16,384 instances, under
  direct, indirect and batched submission, using the frozen W32/N256 plan. If the paired CPU
  frame cost regresses beyond its bootstrap interval, that stage's adoption is reverted and
  recorded as a limit; the helper and the other adoptions stay. No performance claim is made in
  either direction.
- An adoption or correction that cannot hold its gate is reverted and recorded; the convention
  then names the class as an exception.
- No class or file name, pass or pipeline label, shader basename, CLI option, schema, file format,
  `SceneView` field, test tag or test case name changes. Method signatures change only as the
  corrections table lists. `RojoRHI/` is not edited.

## Limits

No Tests folder moves (R3.7 owns them) and no App change beyond `EditorShell.cpp`'s one call site.
`resize` policies are documented, not unified: making `TemporalResolve` or `SelectionOutline`
keep identity on an unchanged extent would preserve history a caller today resets. The two
`sameExtents` helpers, the per-stage shader mirror structs and slot constants, and the allocation
lambdas of `GpuVisibility` and `LightClusterStage` (which differ in growth and suffix policy)
stay. M8 and M9 reshape draw submission; `encodeDrawRuns` is the loop as it is today, not a
submission abstraction.
