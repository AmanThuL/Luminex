# R1.5 — Consolidation and Decomposition

**Status**: Implemented (2026-09-13)

This record preceded the [design](r1.5-design.md) and
the execution plan (tag r3.1-closed-plans, docs/plans/2026-09-13-r1.5-consolidation.md); implementation followed both.
The owner selects all five formerly optional groups from the

for one commit on local main without a PR. Gate B remains a separate review.

## Implementation

- Core owns whole-file binary reads with open/size/read failures, JSON string escaping without
  framing, complete numeric parsing, distinct power-of-two/general alignment and integer ceiling
  division. DDS and TextureBake share the same seek/read contract; bounded image decoder reads
  and the backend's streaming text read keep their different contracts. JSON's three consumers
  preserve lowercase control escapes and UTF-8 bytes. Numeric callers retain positivity, range
  and finiteness decisions; the benchmark's permissive stoul parsing stays separate. CaptureSchema
  retains atomic writing; no truncating writer changes its failure or replacement behavior.
- Renderer composes private ExposureStage, BloomStage and DisplayStage owners alongside its
  existing draw stages. Library, pipeline and resource initialization phases preserve GPU creation
  order; Renderer still controls targets, frame history and declaration order. Callbacks borrow
  their stage owner through execution. Resources are regrouped at Renderer teardown under the
  existing GPU-idle lifetime boundary; individual member deletion order is not a new API promise.
- RenderGraph separates declaration/execution, compile/lifetime assignment, transitions,
  validation and shared range calculations. TemporalResolve separates native, upscale, vendor
  and diagnostic declarations under the existing history owner. RenderGraphPanel coordinates
  the detached window; separate canvas, selection-details and dump units retain its behavior.
- Five large test families become 28 implementation files and five shared fixture headers, grouped
  by responsibility. All 341 moved cases retain names, tags, assertions and body tokens. Existing
  color cases move with their family without renaming; five Core contract tests are additive.
- The module contract lists private headers by unit. Foreign direct/transitive includes fail,
  including file aliases and different letter case on a case-insensitive filesystem. Private
  inventory entries must be canonical, existing, owned and unique. Public API documentation uses
  the same file identity boundary; private files still receive envelope and standalone checks.
  Shell/panel and selected Render/Scene implementation headers are private. Backend headers the
  separate ImGui adapter needs remain shared with that permitted consumer. The allowlist is empty.
- Root xmake includes unit-owned target scripts plus shared setup, dependencies, shader rule and
  maintenance tasks under `xmake/`. All setup source/pins and 13 target configurations are retained.
  Seven shared Slang modules move to `Shaders/Modules/`, twelve test/benchmark oracles to
  `Shaders/Tests/`, with twenty-two production entries at the root. Every shader's source bytes
  remain unchanged. Named module imports and globally unique artifact basenames are checked in
  policy/CI; dependencies are tracked recursively. The three exposure twin pairs and their one
  intentional exposure-source difference are documented without deduplicating shader code.

## Verification

Evidence lives outside the source tree in `/tmp/luminex-r1.5-evidence`: fresh same-device parent
and candidate release binaries, shader outputs, source hashes, commands and raw results. Parent
binaries were frozen before implementation; candidate binaries after clean builds and review.

App, Tests, TextureBake and FrameDataBench clean release builds pass. The fifteen AppModel sources
compile once each across those builds. Touching a library source without changing its bytes
rearchives AppModel and relinks Tests. The benchmark binary and paired driver selftests pass.
Format, policy and module/link checks pass; 75 Source headers and 22 RHI headers compile standalone,
202 owned files pass comment checks, and 1,696 definitions in 177 files pass layout checks.
Tooling passes 158 general tests, four strict-runner selftests and eleven temporal-comparison tests;
one additional optional FLIP test skips because its package is absent.

All 41 Slang source files are byte-identical to parent. Each of App, Tests and FrameDataBench has
41 generated MSL files with the same basenames and byte-identical contents after removing only
`#line` directives. This host lacks the optional offline Metal toolchain: both metallib inventories
are empty and runtime shader validation exercises the supported MSL fallback. Editing an imported
module triggers all 41 shader compilations, and restoring it restores the normalized output.
A real duplicate basename fails the build rule. Original failed verification attempts are retained:
one clean invocation reset xmake to debug before the explicit release configure was added; this
was a verification-script configuration error, not an accepted debug/release comparison.

Source-preservation audits compare 60 graph/temporal/renderer method bodies, 36 panel functions,
the panel coordinator with its extracted creation call expanded, and all moved test/fixture
bodies. Only whitespace/comments, recorded owner/name substitutions and fixture linkage markers
are normalized. GPU creation ordering and callback lifetime were independently reviewed.

All 763 existing C++ cases retain their names/tags; five Core cases are additive. Parent CPU
validation passes 592 cases / 101,725 assertions; candidate passes 597 / 101,796. The unchanged
checkpoint-A inventory selects nineteen cases. All fourteen required byte artifacts match: graph
dumps, sequence PNGs and manifest, tagged PNG/schema fixtures and three DDS/manifest bake modes.
The stable capture has identical ordered passes, resource declarations, uniform layouts and upload
layouts. Decoded values differ only at the existing editor wall-clock `time` field in upload 38;
physical addresses and timings are not semantic comparisons. Both bounded encoder traces contain
60 frames / 900 engine Encoding events with identical names, per-frame order and aggregate counts.

Separate no-metallib runtime copies produce identical fallback PNGs. A 220-frame candidate editor
run with the detached Render Graph enabled, both resize directions and Metal validation passes
with no skipped frames or validation errors, exercising canvas creation and destruction.

The final staged whitespace review removed only extra EOF blank lines from eleven extracted Lua
files after candidate freeze. `build-eof-cleanup.json` retains each before/after hash and proves
that exact limited transformation; original and final source manifests are retained separately.
Frozen binaries and shaders remain unchanged. No executable source or build instruction changed.

Both builds pass the full Metal-validation GPU suite: 171 cases / 252,423 assertions, plus the
unchanged checkpoint-A suite: nineteen cases / 1,856 assertions. Strict image parity fails at the
fixed eight-paired-round cap as recorded below. Sampling stopped; the owner subsequently accepted
the slice-specific integration exception recorded below. The comparison result is unchanged.

## Validation environment

The prior MetalFX/Metal-validation interaction with background Metal tracing remains reproducible
in the preceding record. Both builds use the same temporary, supported non-Metal foreground trace
for GPU validation, with tracing-state probes and cleanup retained. No daemon, system preference,
shader, validation selector or renderer code is altered to obtain a passing result.

The first parent encoder-profile attempt blocked while opening an asset through the repository's
Documents path and produced a long trace. Its interrupted/debugger-inspected output is retained as
diagnostic only. The bounded replacement uses identical frozen App/shaders and a local copy of
the same MaterialLab HDR bytes, avoiding that path. Encoder traces measure labels/order only;
profiler timing warnings and the raw unsuccessful attempt imply no performance conclusion.

## Integration

On 2026-09-13, after reviewing the failed comparison and both residual hashes above, the owner
explicitly accepted their integration exception. All five selected groups are delivered in one
commit from `codex/r1.5-consolidation`, fast-forwarded into local main, without a PR or remote push.
The exception applies only to these two hashes in this slice; their cause remains unknown and
image parity remains failed. Original runner results, references, images and the eight-round cap
remain intact. R1.5 is no longer an integration blocker; every later slice still meets the full
comparison protocol. This structural slice neither approves gate B nor starts a rendering feature.
