# R4.1 — Shader source deduplication experiment validation

**Status**: Implemented

This record validates the [design](r4.1.md) against measured evidence. The decision under the
rule fixed before measurement is **DEFER**. Candidate A passes every gate except rendered parity on
the two San Miguel Native TAA cases, where the parent itself produced 8 and 6 distinct hashes in 8
rounds. Candidate B keeps a runtime coverage branch and changes 18 of 29 rendered cases. Whether A proceeds to R4.2 under a
scoped exception is the owner's decision; this record does not grant one.

## Static comparison

`Tools/Experiments/R4_1/static_compare.py` (on H; copied to the evidence `scripts/`) ran against each candidate's four `ScenePass*` variants,
with slangc invoked using the build rule's own arguments plus `-reflection-json`. Full output is in
`static/A/static.json`, `static/B/static.json` and their per-variant `.msl.diff` files.

| Variant | A gate 1 | A diff lines | B gate 1 | B diff lines | B masked hits |
|---|---|---|---|---|---|
| ScenePass | true | 1524 | true | 1169 | 4 |
| ScenePassAuto | true | 1540 | true | 1194 | 4 |
| ScenePassMask | true | 1602 | true | 1171 | 4 |
| ScenePassAutoMask | true | 1618 | true | 1192 | 4 |

Gate 1 (decision item 1) holds for all four variants of both candidates: each candidate's reflected
parameter/entry-point layout is deep-equal to H's after sorting by name, each variant's entry-point
buffer/texture/sampler bindings are an equal multiset, and slangc reproduces both the parent's and
the candidate's shipped `.metal` from the rule's own arguments. `rawEqual` (the reflection JSON's
unsorted ordering) is false only for `ScenePassAuto` and `ScenePassAutoMask` in both candidates,
because Slang lists the entry file's own `gExposureOverride` parameter first; the binding values
under it are identical, so this does not affect gate 1.

**A's MSL differences**, read from the diff files: renamed Slang temporaries, reordered function
definitions, one small wrapper function per exposure and per coverage method (`ManualExposure`,
`AutoExposure`, `OpaqueCoverage`, `MaskedCoverage`), an added call level at each of the three entry
helpers (`sceneVertex`, `sceneMotionVertex`, `sceneMotionOutput`), the exposure value bound to a
named temporary before use, the lit-colour sum bound to a temporary before the exposure multiply
(same grouping), and, in the motion fragment, the `gInstances` load now coming after shading rather
than before it. No arithmetic expression, operand order, or grouping changed in any variant.

**B's masked hits**: every one of B's four variants keeps `bool masked_0` as a parameter of
`shadeSurfaceDetailed_0` in its generated MSL, with three `if(masked_0)` tests in the function body,
including the two opaque variants (`ScenePass`, `ScenePassAuto`) where the literal argument is
`false` at every call site. Slang did not fold the constant. Per the design's rule, B is therefore
not branch-free and is evidence only regardless of its parity result.

**Inventory**: both candidates' `.metal` and `.metallib` sets equal H's plus one extra member,
`ScenePassShared`, with nothing missing (`static/A/static.json#inventory`,
`static/B/static.json#inventory`).

**Diff scope** (`static/diff-scope.txt`): both candidates touch only
`Shaders/Passes/Scene/ScenePass.slang`, `ScenePassAuto.slang`, `ScenePassAutoMask.slang`,
`ScenePassMask.slang` and the new `ScenePassShared.slang`. No other file changed in either
candidate's diff from H.

**Policy checkers**: every root checker (project policy, shader import, C++ comment, C++ layout,
submodule pin, format, module policy, source header) passes in both the `a` and `b` worktrees
(`policy/a.log`, `policy/b.log`); module policy and the header check passed on a rerun after
`compile_commands.json` was regenerated. H's checker run kept no log.

## Decision

Applied as fixed in the [design](r4.1.md#decision-rule):

| Item | A | B |
|---|---|---|
| 1. Layout and entry signatures | pass | pass |
| 2. 29 cases unchanged, coverage complete | **fail**: 27/29; both San Miguel TAA cases unresolved (12 of A's 16 captures there produced hashes H never produced) | **fail**: 11/29 |
| 3. Suites equal and validation-clean | pass | pass |
| 4. Diff scope, inventory, checkers | pass | pass |
| Branch-free | yes | **no**: `masked_0` and three tests in every variant |

A does not pass, and B neither passes nor is branch-free, so the decision is **DEFER**. The twin
files and the shader-style convention stay as they are. The two unresolved cases are the blocker.
Over 8 rounds the parent produced 8 distinct hashes in `san-miguel-manual-taa-1` and 6 in
`san-miguel-auto-taa-1`, one of them three times; A produced that same hash four times in the auto
case, and its other 12 San Miguel TAA captures produced hashes H never produced. The design fixes
the cap at 8 rounds, so R4.1 cannot resolve these cases.

The owner's options, each with its consequence under the R4 rules:

- **Close R4 with this evidence.** This is what a DEFER does by default in Part III.
- **Accept A with a scoped exception for the two cases.** This is a new, explicit owner exception for
  the two cases, which the R1 protocol calls "unresolved"; Part III inherits no earlier exception,
  and the closest precedent is R1.3/R1.5, whose unresolved hashes the owner accepted at their
  eight-round caps. Adopting A also requires the owner to confirm the design's recorded inference
  that A's listed MSL differences, with no arithmetic change, do not block adoption. It changes the
  R4.1 decision: R4.2's gate as written names the strict parity matrix, meaning the 15 established
  cases, which A passes, so the owner must decide whether R4.2 carries R4.1's 14 extension cases
  and, with them, the exception. Under the exception, masked-variant motion parity rests only on the
  VisibilityLab TAA cases, whose masked-pixel coverage is unproven (see the "Coverage limit" section
  above).
- **Explain the San Miguel TAA non-repeatability first.** R4.1 does not retry a failure, so this is
  a new, separately gated experiment. The parent produced a new hash in almost every San Miguel TAA
  capture while B produced one hash in all eight. Under the strict rule no build measured here passed
  either case: the manual case's parent hashes never repeated across 8 rounds, and in the auto case
  the parent repeated one hash only 3 of 8 times, leaving no stable target to match.

B changes 18 of 29 cases, in opaque-only and masked scenes alike; this record does not isolate
whether the retained `masked` parameter, exposure passed by value or other code-generation
differences cause it.

## Limits

- One device, one session, release builds only; no capture, graph or performance comparison ran.
- The harness is on H, A and B alike and never reached `main`; the parent is H, not `aa9db9b`.
- MSL differences are listed, not explained instruction by instruction; the compiled metallibs
  were not disassembled.
