# R3.2 — Shader Folders

**Status**: Proposed

R3.2 gives `Shaders/` its second level: `Passes/<family>/` for ten pass families, `Common/`
replacing `Modules/`, and `Tests/` as it is. It moves files, teaches the build rule and the import
checker the new layout, and retargets the comments and living documents that name a shader path.
No shader source byte changes in a move, no import line changes at all, and the runtime still loads
`Shaders/<basename>`, so no `loadShaderLibrary` call changes.

[Part III](../../roadmap/codebase-restructuring.md#r32--shader-folders) owns the outcome and the
exit gate. [R3](r3.md#r32--shader-folders) owns the series design. This record keeps the path
table, the rules the executor follows, and later the evidence.

## Inventory before R3.2

`Shaders/` holds 63 Slang files at `e9c6e30`: 37 entry files at the root, 13 modules in `Modules/`
and 13 oracles in `Tests/`. R3 estimated 68 with 18 oracles; that count predates R2, which took
the RHI smoke shaders to `RojoRHI/Shaders/Tests/`. App, Tests and FrameDataBench each compile all
63 into their own target directory, and this host has the offline Metal toolchain, so each holds
63 `.metal` and 63 `.metallib` files.

Three facts were probed with the pinned `slangc` before this design was written:

- `import X;` resolves a file beside the importer before any `-I` directory. A family's entries
  therefore find their local modules with no search path.
- `VisibilityClassifyOcclusion`, compiled from a `Passes/Visibility/` copy beside its three
  modules with only `-I Common`, produces MSL identical to today's once `#line` directives are
  dropped. `Tests/OcclusionProbe` does the same with `-I Common -I Passes/Visibility`.
- `slangc` accepts a `-I` directory that does not exist, so the rule can name both the old and
  the new module directory while the moves are in flight.

`Common/` holds a module imported by two or more families, or one kept shared by a recorded

mislead. The module `Occlusion` lives in `Passes/Visibility/` because
`VisibilityClassifyOcclusion` is its only production importer; the folder `Passes/Occlusion/`
holds the HZB and reference entries.

## Build rule

`xmake/shaders.lua` passes `-I Shaders/Common` for every shader. A source under `Shaders/Tests/`
also receives `-I` for each `Shaders/Passes/<family>/`, because an oracle may test a family
module. The compiler then rejects a production shader that imports another family's module,
before the checker runs. The `-fp-mode precise` selection stays keyed on the basename prefix and
is not edited. The dependency list becomes every `.slang` source of the target, which already
includes every module. `slang.moduledir` remains the override for a target with another tree.

## Import checker

`Tools/check_shader_imports.py`, tests first:

- A module is a file without a shader entry point in `Common/` or `Passes/<family>/`.
- A `Common/` module imports `Common/` modules only.
- A family-local module is imported only from its own folder.
- A file under `Tests/` may import any module; an oracle is not a family.
- No import reaches a file that declares an entry point.
- Every file sits in `Common/`, `Tests/` or `Passes/<family>/`; none at the root, none deeper.
- A basename collision is rejected across the whole tree, case-insensitively.

Rule and checker both accept `Modules/` beside the new folders until the moves finish, so every
intermediate commit builds and passes policy. One edit commit then removes that tolerance.

Step 7 edits comments inside Slang files. It changes no token, and the gate below proves it.

## Evidence

The owner chose, on 2026-09-20, a cheap gate at every commit and the full comparison protocol
once at the head, compared with `e9c6e30`. Identical MSL at every commit means no intermediate
commit can be the origin of a rendered difference. The evidence bundle lives outside the tree.

**Every commit:** App, Tests and FrameDataBench build in release; each target's 63 `.metal` files
equal the frozen parent's with `#line` directives dropped; the `.metal` and `.metallib` name
inventories equal the parent's; the import checker, the policy checkers, `xmake format --check`
and the CPU unit tests pass. Metallib bytes are a declared difference: `-frecord-sources` embeds
source paths.

**Once at the head:** the validated GPU suite and checkpoint A; the byte-stable artifacts; capture
dump semantics; fallback PNGs from a runtime copy without metallibs; an importer-rebuild probe
that touches one `Common/` module and one family module; a collision probe with one basename in
two family folders, against both the build rule and the checker; the strict parity matrix with a
cap of eight alternating rounds fixed before measurement.

## Limits

The precise-float selection still depends on basename prefixes; keying it on folders is left for
a slice that may change generated code. `RojoRHI/Shaders/` is the component's tree and does not
move. R4 owns deduplication inside `Passes/Scene/`.
