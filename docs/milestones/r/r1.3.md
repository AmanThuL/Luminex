# R1.3 — App Model Library and Shared Scene Session

**Status**: Implemented (2026-09-13)

R1.3 is accepted with an owner-authorized exception for the six unresolved image hashes recorded
below. The bounded parent/candidate comparison did not pass; the owner approved local main
integration on 2026-09-13 after reviewing that limitation. This record preceded the
execution plan (tag r3.1-closed-plans, docs/plans/2026-09-13-r1.3-app-session.md), which preceded source changes, following
R1.2's ordering. The boundary belongs to the [refactoring roadmap](../../roadmap/codebase-module-boundaries.md#r13--app-model-library-and-shared-scene-session)
and [ADR 0020](../../decisions/0020-module-layering-and-units.md).

## Current implementation

- App and Tests link the AppModel static library. Its 30 existing files move mechanically into
  `Source/App/Model`: options, capture metadata, selection, workspace schema, actions,
  performance/graph models, timing history, frame records, dynamic-resolution policy,
  temporal/exposure state, light roles and render settings. Tests compiles its own C++ sources
  only. All 14 shared-source exceptions are removed; the module allowlist is empty.
- `SceneSession` borrows the scene and owns its camera, sharing activation, playback, view
  production into caller-owned items and motion reset/commit. EditorShell composes it alongside
  its ImGui settings handler; panels, input and settings remain shell responsibilities.
  Inspector step and rewind use the same session. `SceneDefaults.h` removes headless capture's
  dependency on EditorShell for the shared clear value.
- Activation requires an explicit motion policy. Editor startup/switches reset previous transforms;
  headless preserves loaded motion, including MaterialLab's historical identity previous matrices.
  Making both reset would change existing first-frame inputs, so this difference is retained and
  tested. Screenshot frame zero preserves the authored pose; later screenshots use wrapped fixed
  steps. Sequences sample absolute frame/bake-rate time, including warmup. Editor playback keeps
  paused camera follow and the fly-camera override.
- `FrameDeclaration` rotates the pool after device slot retirement, constructs the graph, applies
  pooling, declares renderer passes and retains the accepted record. Editor appends UI/present;
  headless exports display color. Each loop retains its own begin/end/wait, timing join, motion
  commit and presentation order. Pool declaration precedes renderer declaration, preserving
  shell/renderer/pool/device/SDL-layer destruction order. Views/items/scene data remain borrowed
  through declaration and execution. No Render implementation, RHI or shader source changes.

candidate round added a different one. Native differences against the corresponding parent round
span 9–57 pixels with maximum channel deltas of 1–2/255; vendor differences span 18,563–83,787

Both builds' 41 App and 41 Tests shader artifacts are byte-identical. M6.5's earlier investigation
does not establish the cause of these hashes or substitute for this session's parent evidence.

`paired-parity.json` owns the full hashes and every runner result; `sponza-variant-diagnostics.json`
owns per-image pixel counts, bounds and channel histograms. No ninth round, reference change,
re-baseline or expanded M6.5 exception was used. Sampling stopped at the plan's maximum; the
strict comparison remains failed and the cause remains unknown.

The owner explicitly approved merging on 2026-09-13 after the failed comparison and pixel
differences were explained. This acceptance exception covers only the six hashes listed above
for R1.3. It neither establishes image parity nor attributes the differences to a benign cause.
The original failures and evidence remain intact; the comparison protocol for later slices is
unchanged.
