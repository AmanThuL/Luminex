# R4 — Shader Source Deduplication

**Status**: Proposed

First draft for owner revision. R4 promotes the shader source deduplication candidate the
refactoring roadmap has carried since R1.5 into a milestone.
[Part III](../../roadmap/codebase-restructuring.md#r4--shader-source-deduplication) owns the
outcome and gates; this record keeps the observed state, the experiment's shape and its evidence.

**Placement:** R3 → **R4** → UX2 → N1. R3.2 first places the family in `Shaders/Passes/Scene/`;
R4 then changes source inside that folder only.

## Observed state before R4

| File | Lines | Differs from `ScenePass.slang` by |
|---|---|---|
| `ScenePass.slang` | 320 | — |
| `ScenePassAuto.slang` | 341 | Exposure source: `gExposureOverride[0]` instead of `gPass.preExposure` |
| `ScenePassMask.slang` | 325 | Alpha-cutoff coverage and two-sided shading |
| `ScenePassAutoMask.slang` | 346 | Both |

About 1,330 lines carry roughly 320 lines of distinct logic; a diff between any pair is 33 to 42
lines. The [shader-style convention](../../conventions/shader-style.md) names the twins, the one
difference each pair keeps, and requires every other edit to be mirrored by hand. It also forbids
a runtime exposure branch and whole-file deduplication, because earlier byte-parity evidence
required distinct manual shader output. M7.5 already moved the local-light loop into one shared
module, `LocalLights.slang`, which all four import; the rest of each file is still duplicated.

The cost rises with the accepted order: M9's surface-path experiments and M8's cascades, shadow
atlas and screen-space lighting all edit scene shading, and each edit is mirrored four times.

## Approach

Thin entry-point files over one shared implementation module. Exposure source and alpha coverage
become compile-time choices, so each variant still compiles to its own pipeline with no runtime
branch. Pass labels, pipeline inventory, bindings and uniform layouts do not change.

`TemporalResolve` and `TemporalUpscale` are not merged for overlap alone: each keeps its kernel,
and only a helper with one contract moves into the temporal family's shared module.

## R4.1 — Bounded experiment

On a short-lived `exp/` branch, as the hard rule for experimental source requires. For each of
the four variants, against the parent build in one session on one device:

- generated MSL, compared after dropping `#line` directives, with every difference listed;
- reflected resource layout, which must be identical;
- rendered output under the strict parity matrix, with the round cap fixed before measuring.

The branch gets an immutable evidence tag. The record states adopt or DEFER with the evidence that
decided it. A difference in generated MSL is reported, not excused: the convention's ban rests on
byte-parity evidence, so adoption needs evidence of the same kind.

## R4.2 — Adoption

Only after an adopt decision: the production change lands on `main`, and the convention's twin
rule is replaced by the rule the shared module enforces. On DEFER the twin files and the
convention stay as they are, and R4 closes with its evidence.

## Boundaries

No merged pipelines, no runtime exposure or coverage branch, no shading, binding or uniform-layout
change. `Sky`/`SkyAuto` and `ShadowPass`/`ShadowPassMask` wait until the `ScenePass` result is
adopted.
