# R3 — Subsystems and Tree Restructure

**Status**: Proposed

Draft for owner revision. R3 gives Luminex the four subsystems of NVIDIA's
[Donut](https://github.com/NVIDIA-RTX/Donut/tree/main#structure) — core, engine, render, app — over
the [RojoRHI](r2.md) submodule, reverses the Scene-to-Render dependency so Render sits on Engine,
and gives every source, shader, test and documentation tree a second level. It is refactoring, not
only moving: the owner accepted header extractions, a function relocation, target and namespace
renames and decompositions where the structure needs them. Rendered output and shipped behaviour
do not change.
[Part III](../../roadmap/codebase-restructuring.md#r3--subsystems-and-tree-restructure) owns the
outcome and gates; this record keeps the design, the file estimates, evidence and limits.

**Placement:** R2 → **R3** → R4 → UX2 → N1. After R2, so RHI tests and paths leave before the
trees are regrouped and the contract is rewritten once; before R4, which edits shader source inside
a folder R3.2 creates; before UX2, so new editor and scene code lands in the final layout.

## Observed structure before R3

| Tree | Today | Problem |
|---|---|---|
| Subsystems | `Core`, `Asset`, `Scene`, `Render`, `App`, with Scene depending on Render | Scene description (`Mesh`, `Camera`, `LocalLight`, table rows) is owned by the renderer, so the scene cannot exist below it |
| `Source/Render/` | 88 files, flat | Graph, ten pass families, scene vocabulary and the orchestrator interleave alphabetically |
| `Source/App/Model/` | 70 files, flat | Eleven responsibilities share one folder |
| `Source/App/Panels/` | 25 files, flat | `InspectorPanel.cpp` is 846 lines covering four subjects |
| `Source/App/` root | 17 files | Shell, headless runners and glue mixed; `EditorShell.cpp` is 1,025 lines, over the review budget |
| `Shaders/` | 37 entries flat, 13 in `Modules/` | A pass's entries are found by name prefix only; five modules serve one pass family |
| `Tests/` | 131 sources, flat | No correspondence to subsystems |
| `docs/` | `milestones/` flat; `specs/` 17 frozen; `plans/` 15 closed; `postmortems/` 2; one 300-line architecture page | A milestone's design and record live apart; closed plans contradict the [documentation convention](../../conventions/documentation.md#status-lifecycle) |

Scene reaches seven Render headers. Five include nothing else from Render (`Mesh.h`, `Camera.h`,
`Bounds.h`, `AlphaMode.h`, `LocalLight.h`); `LocalLightMath.h` adds only `SceneTables.h`.
`SceneView.h` is the exception: beside `DrawItem` and `DirectionalLight` it carries
`TemporalSettings`, `TemporalStatus` and `ShadowFilter`, and includes `Temporal.h` and
`Visibility.h`, which pulls three occlusion headers. It is scene description plus renderer
configuration. Render includes nothing from Scene or Asset, and Asset nothing from either.

## Checked against Donut's tree

| Donut | Luminex after R3 | Verdict |
|---|---|---|
| `core`: math (box, frustum, sphere), log, JSON, VFS, string utilities | `Core`, gaining `Bounds.h` | Adopted. `Bounds.h` is glm-only math with consumers in three units, as `core/math/box.h` is |
| `engine`: `GltfImporter`, `DDSFile`, `KeyframeAnimation`; `Scene`, `SceneGraph`, `SceneTypes`, `View`; texture, binding and descriptor-table caches | `Engine/Asset` for decoding; `Engine/{Scene,Types,Upload,Catalog}` for scene, vocabulary, GPU uploads and tables | Adopted. Donut links one library; Luminex keeps Asset separately linked and CPU-only so `TextureBake` and GPU-free builds link no Metal |
| `engine/ShadowMap.h` interface with `render/CascadedShadowMap` implementing it | Shadow fitting and stage stay in Render | Not needed: one shadow caster, no second implementation |
| `engine/ShaderFactory`, `BindingCache`, `FramebufferFactory`, `CommonRenderPasses` | RojoRHI loads compiled libraries; the render graph owns attachments and transients | Not adopted: the graph and RHI already cover them |
| `render`: one file pair per pass, flat; `DrawStrategy` culling; `DLSS`; `ManipulatorPass` | `Render/Passes/<family>/`; CPU and GPU visibility, the vendor scaler and the selection outline stay in Render | Adopted with folders: Donut's passes are one pair each, Luminex's families reach fifteen files |
| `app`: device managers, `ApplicationBase`, camera controllers, ImGui renderer and console | `App` keeps the shell, fly camera, panels and Console; the ImGui adapter left with RojoRHI in R2 because it builds on backend-private headers, unlike Donut's public-API renderer | Adapted. Donut's app is a framework that never sees render; Luminex's App is the application and depends on Render |
| `shaders/passes/` flat, shared includes under `include/donut/shaders/`, with `*_cb.h` shared by C++ and HLSL | `Shaders/Passes/<family>/` and `Shaders/Common/` | Adapted to the owner's one-folder-per-pass preference. Shared C++/Slang layout headers are deferred; ABI oracle tests already pin the mirrors |
| `tests/src/{core,engine}/` | `Tests/<subsystem>/…` | Adopted |
| `include/donut/` beside `src/` | Headers stay beside sources | Not adopted: the module convention rejects a repository-wide include directory; only RojoRHI, which is distributed, splits them |
| No render graph, no built-in scenes | `Render/Graph/`; `Engine/Catalog/` | The graph is frame-execution infrastructure the passes declare on, and App inspects its records. Labs are renderer fixtures that tests load, so they sit below App |

The largest leaf is 16 files. Two single-file folders remain on purpose:
`Shaders/Passes/Display/`, so shader and Render pass names stay identical, and `Tests/Tools/`.
Five two-file pass folders remain by the owner's one-folder-per-pass rule; M8 adds cascades and an
atlas to `Shadow/`.

**Rules behind the layout.** Pass folders carry the same ten names in `Render/Passes/` and
`Shaders/Passes/`. A Slang module imported by one family lives in that family's folder, one
imported by two or more in `Common/`, and test oracles do not count: `Visibility`,
`VisibilityPrefix` and `Occlusion` move to `Passes/Visibility/`, `LightCluster` to
`Passes/LocalLights/`, `TemporalCommon` to `Passes/Temporal/`; eight stay common. App keeps its
`Model/` and `Panels/` layers, because the checker proves by directory that AppModel reaches no
ImGui, SDL or Metal, and repeats feature names under both. Tests have no `Gpu/` folder: CPU and
GPU cases of one family sit together, and the `[gpu]` tag still selects GPU runs.

## R3.1 — Documentation records

Series folders `m1-m4`, `m5`, `m6` (with interface gate B, which Part I owns), `m7`, `r` and `ux`;
each frozen design beside its record as `<id>-design.md`; the two postmortems in the series of
their period; the founding design (D1–D10) in `docs/decisions/`; `docs/specs/` and
`docs/postmortems/` removed; the fifteen closed plans deleted, with records that linked them
pointing at the tag that retains them. The convention, the policy checker's tables and
`AGENTS.md` follow. `AGENTS.md` states the two agent-flow locations — a brainstormed design is
the `Proposed` milestone record, a plan goes to `docs/plans/` — which both Superpowers skills
accept as overrides. Frozen text changes in links only.

## R3.2 — Shader folders

The `Shaders/` layout above; the shader-style and module conventions restate where entry points
live; the import checker learns `Common/`, family-local modules and their one rule. Evidence is
R1.5's: generated MSL identical once `#line` directives are dropped, inventory and runtime paths
unchanged, importer rebuilds intact, runtime-MSL fallback loading, collisions rejected tree-wide.

## R3.3 — Engine

1. The ADR is accepted first. It supersedes the parts of
   [ADR 0020](../../decisions/0020-module-layering-and-units.md) that retired the Engine name and
   allowed Scene to depend on Render; it keeps Asset a checked CPU-only unit.
2. Moves: `Source/Asset` → `Engine/Asset/{Image,Model,Texture}`; `Source/Scene` →
   `Engine/{Scene,Upload,Catalog}`; from Render, `Mesh`, `Camera`, `AlphaMode.h`, `LocalLight.h`,
   `LocalLightMath` → `Engine/Types/`, `SceneTables.h` → `Engine/Scene/`, `Bounds.h` → Core.
3. Two leaf-header extractions the old headers keep including, as R1.2 did for `TextureDesc.h`:
   `DrawItem` and `DirectionalLight` out of `SceneView.h`; `MotionClass` out of `Temporal.h`.
4. `Scene::view()` becomes a builder in Render taking the scene, the caller's item vector and the
   same arguments. `SceneView` stays Render's plain input contract, so tests that build one by
   hand are unaffected.
5. The contract reverses the edge: `render` may depend on `engine`; the checker rejects an Engine
   include of Render, and a link check proves the Engine archive has no undefined `lmx::render`
   references.
6. One mechanical commit from a recorded substitution: target `Scene` → `Engine`, `lmx::scene` →
   `lmx::engine`, moved vocabulary `lmx::render` → `lmx::engine`. `lmx::asset` stays.

## R3.4 — Render

`Graph/`, `Renderer/` and `Passes/<family>/` as above. Each family folder takes its stages, CPU
mirrors, checks and readbacks: `Passes/Occlusion/` holds `HzbStage`, `Occlusion`, `OcclusionCheck`,
`OcclusionHistory` and `OcclusionReference`; `Passes/Temporal/` holds the resolve units, the vendor
scaler, `Temporal`, `TemporalHistory` and `ResolutionController`, whose only consumer is temporal.
Class and file names do not change.

## R3.5 — App

The `App/` layout above, then two decompositions in their own commits: `InspectorPanel.cpp` into
camera, rendering, light and object units under `Panels/Inspector/` beside `InspectorLighting`;
`EditorShell.cpp` under the 1,000-line budget by moving frame-loop and input handling into units
like its existing `EditorTransport` and `EditorMeasurement` partials. Workspace schema 3 files
from the parent build must load unchanged.

## R3.6 — Tests and architecture pages

`Tests/` as above with tags, case names, the `unit` and `gpu` filters and Luminex's checkpoint A
filter unchanged. `docs/architecture/overview.md` becomes the subsystem diagram and an index over
`core.md`, `engine.md`, `render-graph.md`, `render-passes.md`, `app.md`, `shaders.md`, a pointer
page for RojoRHI, and the frame walkthrough. README's directory table, the module convention and
`AGENTS.md` describe the tree as built.

## Rules for every slice

- The [R1 comparison protocol](../../roadmap/codebase-module-boundaries.md#r1--module-boundaries-and-shared-foundations)
  applies to R3.2–R3.6 at every commit; R3.1 touches documents only. Earlier parity exceptions
  (M6.5, R1.3, R1.5) relax nothing here.
- Moves are one commit per destination folder, separate from edits, reproducible from a recorded
  path and include substitution. Each extraction, the builder relocation, the namespace
  substitution and each decomposition is its own commit.
- No pass label, shader basename, CLI option, schema, file format, test tag or test case name
  changes. Formatting and policy are green at every commit.

## Deferred

Donut's `include/`–`src/` split; headers shared by C++ and Slang; an engine-level shader factory,
binding cache or shadow-map interface; moving the render graph or the labs; subfolders for Core;
renaming Stage classes; shader source deduplication ([R4](r4.md)); every behaviour
[UX2](../ux/ux2.md) owns. UX2 later retires `SponzaLightRig` and `SponzaCameraTour` from
`Engine/Catalog/` and adds the scene document to `Engine/Asset/`.
