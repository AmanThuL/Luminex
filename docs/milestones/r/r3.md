# R3 — Subsystems and Tree Restructure

**Status**: Proposed

Draft for owner revision. R3 gives Luminex the four subsystems of NVIDIA's
[Donut](https://github.com/NVIDIA-RTX/Donut/tree/main#structure) — core, engine, render, app — over
the [RojoRHI](r2.md) submodule, reverses the Scene-to-Render dependency so Render sits on Engine,
gives Core the responsibility Donut's `core` has, the math and the data structures that carry no
domain meaning, and gives every source, shader, test and documentation tree a second level. It is
refactoring, not only moving: the owner accepted header extractions, function relocations, target
and namespace renames, extraction into Core, removal of duplicated implementations and
decompositions where the structure needs them. Rendered output and shipped behaviour do not
change.
[Part III](../../roadmap/codebase-restructuring.md#r3--subsystems-and-tree-restructure) owns the
outcome and gates; this record keeps the design, the file estimates, evidence and limits.

**Placement:** R2 → **R3** → R4 → UX2 → N1. After R2, so RHI tests and paths leave before the
trees are regrouped and the contract is rewritten once; before R4, which edits shader source inside
a folder R3.2 creates; before UX2, so new editor and scene code lands in the final layout.

## Observed structure before R3

| Tree | Today | Problem |
|---|---|---|
| Subsystems | `Core`, `Asset`, `Scene`, `Render`, `App`, with Scene depending on Render | Scene description (`Mesh`, `Camera`, `LocalLight`, table rows) is owned by the renderer, so the scene cannot exist below it |
| `Source/Render/` | 88 files, flat | Graph, ten pass families, scene vocabulary and the orchestrator interleave alphabetically |
| `Source/App/Model/` | 70 files, flat | Eleven responsibilities share one folder |
| `Source/App/Panels/` | 25 files, flat | `InspectorPanel.cpp` is 846 lines covering four subjects |
| `Source/App/` root | 17 files | Shell, headless runners and glue mixed; `EditorShell.cpp` is 1,025 lines, over the review budget |
| `Shaders/` | 37 entries flat, 13 in `Modules/` | A pass's entries are found by name prefix only; five modules serve one pass family |
| `Tests/` | 131 sources, flat | No correspondence to subsystems |
| `docs/` | `milestones/` flat; `specs/` 19 frozen; `plans/` 15 closed; `postmortems/` 2; one 300-line architecture page | A milestone's design and record live apart; closed plans contradict the [documentation convention](../../conventions/documentation.md#status-lifecycle) |

Scene reaches seven Render headers. Five include nothing else from Render (`Mesh.h`, `Camera.h`,
`Bounds.h`, `AlphaMode.h`, `LocalLight.h`); `LocalLightMath.h` adds only `SceneTables.h`.
`SceneView.h` is the exception: beside `DrawItem` and `DirectionalLight` it carries
`TemporalSettings`, `TemporalStatus` and `ShadowFilter`, and includes `Temporal.h` and
`Visibility.h`, which pulls three occlusion headers. It is scene description plus renderer
configuration. Render includes nothing from Scene or Asset, and Asset nothing from either.

The largest leaf is 16 files. Two single-file folders remain on purpose:
`Shaders/Passes/Display/`, so shader and Render pass names stay identical, and `Tests/Tools/`.
Five two-file pass folders remain by the owner's one-folder-per-pass rule; M8 adds cascades and an
atlas to `Shadow/`.

**Rules behind the layout.** Pass folders carry the same ten names in `Render/Passes/` and
`Shaders/Passes/`. A Slang module imported by one family lives in that family's folder, one
imported by two or more in `Common/`, and test oracles do not count: `Visibility`,
`VisibilityPrefix` and `Occlusion` move to `Passes/Visibility/`, `LightCluster` to
`Passes/LocalLights/`, `TemporalCommon` to `Passes/Temporal/`; eight stay common. App keeps its
`Model/` and `Panels/` layers, because the checker proves by directory that AppModel reaches no
ImGui, SDL or Metal, and repeats feature names under both. Tests have no `Gpu/` folder: CPU and
GPU cases of one family sit together, and the `[gpu]` tag still selects GPU runs.

## R3.3 — Engine

1. The ADR is accepted first. It supersedes the parts of
   [ADR 0020](../../decisions/0020-module-layering-and-units.md) that retired the Engine name and
   allowed Scene to depend on Render; it keeps Asset a checked CPU-only unit.
2. Moves: `Source/Asset` → `Engine/Asset/{Image,Model,Texture}`; `Source/Scene` →
   `Engine/{Scene,Upload,Catalog}`; from Render, `Mesh`, `Camera`, `AlphaMode.h`, `LocalLight.h`,
   `LocalLightMath` → `Engine/Types/`, `SceneTables.h` → `Engine/Scene/`, `Bounds.h` → Core.
3. Two leaf-header extractions the old headers keep including, as R1.2 did for `TextureDesc.h`:
   `DrawItem` and `DirectionalLight` out of `SceneView.h`; `MotionClass` out of `Temporal.h`.
4. `Scene::view()` becomes a builder in Render taking the scene, the caller's item vector and the
   same arguments. `SceneView` stays Render's plain input contract, so tests that build one by
   hand are unaffected.
5. The contract reverses the edge: `render` may depend on `engine`; the checker rejects an Engine
   include of Render, and a link check proves the Engine archive has no undefined `lmx::render`
   references.
6. One mechanical commit from a recorded substitution: target `Scene` → `Engine`, `lmx::scene` →
   `lmx::engine`, moved vocabulary `lmx::render` → `lmx::engine`. `lmx::asset` stays.

## R3.4 — Core

Core is 506 lines at R3.3: log, assert, alignment, file, JSON, parse, colour, `Bounds.h` and one
division helper. The math and the data structures a renderer needs exist, but in the units that
first needed them, some of them more than once. R3.4 moves them down, gives them tests of their
own, and leaves Engine, the first consumer, holding only scene meaning.

### The ADR

[ADR 0026](../../decisions/0026-core-charter-and-placement.md) was accepted on 2026-09-21, before a
file moves. It narrows ADRs 0020 and 0025 in one place each: Core's ownership
row, and the placement rule. Today a helper reaches Core only with consumers in two or more units,
which is what kept SHA-256 in a texture baker and solid-angle math in an IBL generator. The rule
becomes: math and data structures with no domain meaning go to Core whatever their consumer count;
a domain meaning still keeps code in its owning unit; everything else keeps the two-consumer rule.
It records glm as the one vector vocabulary and the three things Core will not grow without a
consumer: its own vector types, container wrappers, and platform services (VFS, threads,
profiling). Core's dependencies do not change: spdlog and glm, no project unit, no RojoRHI.

### Order inside the slice

1. The ADR; the contract and convention rows for Core and for the new `scenes` unit.
2. Core's subfolders: a path-and-include move of the fifteen existing files, one commit per
   folder.
3. Each row of the table as two commits: the Core type with its unit tests, then the call sites.
   Engine and Asset call sites are rewritten; Render and App adopt only where a whole function
   or helper leaves them, as the [R3.4 record](r3.4.md#adoption-in-this-slice) lists.
4. `Engine/Types/` divided into `View/`, `Lights/`, `Geometry/`, `Material/`; then
   `SceneTables.cpp` into the paced table, identity allocation and per-kind row builders, and
   `Scene.cpp` by responsibility, each its own commit.
5. Engine's three references into the catalog are cut (a loader callback replaces the Sponza rig
   test inside `loadGltfScene`), then `Engine/Catalog/` → `Source/Scenes/`: target `Scenes`, namespace `lmx::scenes` by a recorded
   substitution, linked by App, AppModel and Tests, its consumers today.

`-ffp-contract=off` follows any code that is compiled with it today. Moving a function between
translation units can change inlining, so image and bake hashes are checked at every commit of
step 3, not at the end.

## R3.5 — Render

`Graph/`, `Renderer/` and `Passes/<family>/` as above. Each family folder takes its stages, CPU
mirrors, checks and readbacks: `Passes/Occlusion/` holds `HzbStage`, `Occlusion`, `OcclusionCheck`,
`OcclusionHistory` and `OcclusionReference`; `Passes/Temporal/` holds the resolve units, the vendor
scaler, `Temporal`, `TemporalHistory` and `ResolutionController`, whose only consumer is temporal.
Class and file names do not change.

After the moves, in their own commits: the stages take frustum, shadow-fit, jitter and
froxel-sphere math from Core and `RenderGraphRanges` takes `Interval`; `Renderer.cpp` (776 lines)
and `SceneStage.cpp` (820) are decomposed by responsibility as the `Renderer*` partial units
already began; the stage shape the ten families share is written into the engineering convention
and departures from it corrected; pipeline and resource setup repeated across stages moves into
shared Render helpers. No base class, factory or cache is introduced: a common shape followed by
convention is what the code needs, and an interface with one implementation per family is not.

The [R3.5 record](r3.5.md) owns the path and interface tables and the commit sequence. It places
`RhiLog` and the shared helpers in `Render/Common/`, adds the decomposition of
`RenderGraph::deriveTransitions`, a shared draw-run encoder and one declaration behind the two
temporal kernels, lists the method signatures the shape corrections change, and delivers the slice
as two pull requests: the neutral moves and decompositions, then shape and helpers. Both parts are implemented and owner-accepted for integration on 2026-09-22; the executor plan is closed. The slice record and validation retain the scoped part A parity exception, passing part B local gates and measured adoption limits. [Validation](r3.5-validation.md) retains the gates and limits.

## Rules for every slice

- The [R1 comparison protocol](../../roadmap/codebase-module-boundaries.md#r1--module-boundaries-and-shared-foundations)
  applies to R3.2–R3.7 at every commit; R3.1 touches documents only. Earlier parity exceptions
  (M6.5, R1.3, R1.5) relax nothing here.
- Moves are one commit per destination folder, separate from edits, reproducible from a recorded
  path and include substitution. Each extraction, the builder relocation, the namespace
  substitution and each decomposition is its own commit.
- No pass label, shader basename, CLI option, schema, file format, test tag or existing test case
  name changes; R3.4 adds Core test cases and declares them. Formatting and policy are green at
  every commit.
- Code extracted into Core lands with its own tests before any call site uses it.

## Deferred

Donut's `include/`–`src/` split; headers shared by C++ and Slang; an engine-level shader factory,
binding cache or shadow-map interface; a pass base class; moving the render graph; Core vector
types of its own, container wrappers, a VFS, a thread pool, platform or profiling layers;
renaming Stage classes; shader source deduplication ([R4](r4.md)); every behaviour
[UX2](../ux/ux2.md) owns. UX2 later retires `SponzaLightRig` and `SponzaCameraTour` from
`Source/Scenes/` and adds the scene document to `Engine/Asset/`.
