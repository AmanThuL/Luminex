# R5 — Luminex Runs on the RojoRHI v2 Interface

**Status**: Implemented (R5.1–R5.5 accepted 2026-11-08; R5.6 merged 2026-11-08; R5.7 2026-11-09)

R5 moved Luminex from RojoRHI's frozen v1 interface to its v2 interface, so that RojoRHI can
delete v1. [Part III](../../roadmap/codebase-rojorhi-port.md#r5--luminex-runs-on-the-rojorhi-v2-interface)
owns the outcome, slices and gates; this record keeps the design decisions, the parity gate, its
results, the exceptions and the limits. Proposed on 2026-10-22. R5.1–R5.5 were implemented on the
integration branch `feat/rojorhi-v2`, passed the parity gate against the frozen v1 build and were
accepted on 2026-11-08. R5.6 pinned the RojoRHI release without v1 the same day, and R5.7 closed on
2026-11-09 with its own [record](r5.7.md). The [test ledger](r5-tests.md) reconciles every v1 test
case.

## Why

RojoRHI froze its v1 interface under `Legacy/` and deletes it once its required consumer, Luminex,
no longer builds on it. The v2 interface changes the model underneath every call site:
address-first roots replace binding slots, value handles with deferred destruction replace owned
objects, explicit layouts and pipeline stages replace use pairs in barriers, explicit queues and
fences replace `endFrame(swapchain)`, and nothing is virtual. The two interfaces share one include
root, namespace and symbol set, so each Luminex binary flips at once. R5 kept that flip small and
judgeable: first it moved every difference Luminex could absorb on v1 behind Luminex-owned seams,
then it flipped on an integration branch that merges only when a parity gate against a frozen v1
build passes, and it optimizes against the same frozen build afterwards.

**Placement:** UX6 → **R5** → N1, execution-sequence step 18 in the
[roadmap](../../roadmap.md#execution-sequence). R5 continues the line R2 started when it moved the
RHI into RojoRHI, so it stays in the R series. Luminex `main` took no work outside R5 until R5.5
integrated.

## Coupling before R5

Recorded on 2026-10-22 on the pre-port `main`: the render graph's `execute` opened every pass and
emitted every barrier in v1 `TextureUse`/`BufferUse` vocabulary, about 35 pass registrations
recorded through a captured `rojoRHI::CommandList&`, and Source made 168 slot-binding calls. All 63
Slang files bound through v1 slots (309 `[[vk::binding]]` declarations mirrored by unchecked
`k…Slot` constants). 145 members owned RojoRHI objects through `std::unique_ptr`. `rojoRHI::Result`
served as Luminex's general error type at 127 sites. Nineteen CPU test files faked v1's virtual
interfaces. The suites held 1,197 Release unit cases and 229 runnable `[gpu]` cases, all passing;
Debug failed one pre-existing float-codegen case.

## Decisions

| Topic | Decision |
|---|---|
| Two repositories | Every RojoRHI change is a RojoRHI pull request merged first; Luminex pins only commits on RojoRHI `main` |
| Phases | Seams on v1 (R5.1–R5.3), the switch on `feat/rojorhi-v2` (R5.4–R5.5), optimization after parity (R5.7) |
| Integration branch | Built a subset of stage families while they ported in parallel; `main` never did |
| Identity | Milestone R5 in Part III; [ADR 0033](../../decisions/0033-rojorhi-conformance-replaces-checkpoint-a.md) replaces portability checkpoint A, which could not outlive v1 |
| Upscaler name | No display-name query in RojoRHI; Luminex maps the upscaler kind to "MetalFX Temporal" |
| What stays in Luminex | Idle waits, blocking readback, frame numbers, texture and buffer getters, pixel-size helpers and path-based shader loading |
| Graph vocabulary | Luminex-owned use enums; a table lowers them to v2 stage, access and layout; layouts are tracked per subresource, and a `TextureStateTable` carries persistent textures across frames |
| Scene draws | Per-run root with material views; indirect records carry `drawId`; the `SceneTables` row ABI is unchanged. [R5.7](r5.7.md) moves the views into `MaterialRow` and pushes one root per pass on indirect and batched submission |
| Timing | Raster passes timed by their render-pass scope, compute and copy by explicit scopes, under one outer `lmx.frame` scope; `gpuSumMs` sums the depth-1 scopes |
| Tests | Hosted Null configure; backend-agnostic `[device]` cases; Debug `[tracker]` frame smokes; graph and model tests device-free on the lowered frame |
| Exceptions | Per-case image and cost exceptions only, recorded with the owner's or lead's approval; none for tests or smokes |

A compatibility shim that re-creates v1 on top of v2 (a slot table, a virtual device wrapper, an
idle wait hiding fences) was rejected, and so were convenience entries in RojoRHI for Luminex,
which would break its thinness.

## What R5 delivered

- **RojoRHI, merged there first:** the Slang rule for consumer shader modules (extra include
  directories, Null libraries on every host, embedded libraries, entry-only check, precise files);
  upscaler input ranges and capture availability in the capabilities; the optional ImGui adapter
  with multi-viewport surfaces; T1 conformance cases for reversed-Z, single-mip views,
  storage-texture hazards and frame data across overlapping frames; and native drawing of a lone
  indirect record (shader ABI 3). Luminex pins the commit that holds all of them.
- **R5.1** pinned RojoRHI `main` with v1 under its Legacy target names. **R5.2** added Luminex's own
  `Result`/`Error`, `GpuContext`, readback, descriptor-keeping GPU owners, `CaptureSchema`,
  `asset::ImageData`, pass timings and upscaler support. **R5.3** added the use vocabulary, the
  lowered frame and its emitter, the state table, the transient backend and pure root builders.
  All three kept every pixel and test count.
- **R5.4** switched to v2: the RojoRHI shader rule, the GPU layer, the v2 graph emitter, the three
  frame loops, the editor on the adapter with detached windows, capture, the hosted Null configure
  and `[tracker]` job; then scene and shadow, post and editor passes, temporal and vendor,
  visibility and occlusion, and local lights, each with its `[gpu]` cases and image gate.
- **R5.5** brought FrameDataBench to v2 and removed the pending-family machinery, decoded captures
  by root name and address in `Tools/GpuDebug`, added the smoke resize hook, retired checkpoint A,
  added the paired cost driver against a parent build, and ran the parity gate below.
- **R5.6** (2026-11-08, [#105](https://github.com/AmanThuL/Luminex/pull/105)) pinned RojoRHI
  `v0.2.0`, which deletes v1, and dropped the Legacy target names from the module contract, its
  tests and hosted CI; sources, shaders and build files were unchanged. Hosted CI and the Release
  Metal `Tests/gpu` suite passed, and parity was byte-identical to R5.5's v2 images in 15 of 15
  cases. Evidence: `../rojo-rhi-evidence/luminex-port/P6.11/2026-11-08-a014cc94/` (`SHA256SUMS`
  SHA-256 `56ead34eb9ba0378d77ff4eb86db0fc2fe704126805db244df182e0640180034`).
- **R5.7** (2026-11-09, [record](r5.7.md)) reported frame GPU time in the paired cost tools, kept
  bindless material rows and counted draws for large scene pipeline groups, parked fragment-only
  raster reads and dropped static pass roots.

## Parity gate

**Frozen v1 reference.** Tag `r5-v1-reference` on the pre-port `main`, built Release once in a
dedicated worktree; SHA-256 sums of `App`, `Tests`, `FrameDataBench` and the compiled shaders are
checked before every use. Both arms render freshly on the same machine and OS build; an OS update
forces both to re-render. The gate ran on an Apple M4 Pro.

1. **Tests.** Release `Tests/unit` and `Tests/gpu` pass, with counts equal to 1,197 and 229
   adjusted only by the test ledger. Debug passes. The hosted `[tracker]` job is green. RojoRHI's
   own suites are green on the pinned commit.
2. **Images.** `Tools/Screenshots/parity.py` renders the 15 cases (Sponza, MaterialLab and
   TemporalLab × Off, Native TAA at 1 and 0.5, MetalFX at 1 and 0.5) on both arms, then
   `compare.py`: `strict` for Off and Native TAA (at most 1.0% of pixels differ and at most 0.05%
   by more than 8), `vendor-quantization-v1` for MetalFX. Each case reports byte identity,
   `maxChannelDelta` and `meanAbsoluteDelta`; each non-identical case gets a heat map and a
   localized one-line cause. TemporalLab capture sequences use `compare.py --sequence`. Thresholds
   never move; a case that fails needs a recorded per-case exception.
3. **Smokes.** `MTL_DEBUG_LAYER=1 LMX_MAX_FRAMES=600 ./App --windowed` (Release, a detached
   Performance window, one resize) exits 0 with `600 presented, 0 skipped` and no validation line;
   the Debug App does the same with `--rhi-validation`.
4. **Costs** (not slower beyond noise). Paired fresh-process AB/BA runs against the frozen App over
   the five baseline scenes. A regression is a paired median above +5% on `encodeMs`, `gpuSumMs` or
   a stage's GPU time whose bootstrap 95% interval excludes +5%; it is fixed, resolved by moving
   bindless material rows forward when per-draw roots are the cause, or recorded as an exception.
   `frame_data_paired.py` must match digests; its timing is reported only.

Images and costs admit a recorded per-case exception; tests and smokes have none.

**Tests.** The [ledger](r5-tests.md) carries 1,197 − 4 + 151 = 1,344 unit cases and 229 − 1 + 20 =
248 GPU cases, with every removed and renamed case and its replacement. Every Release skip is a
new case that runs in another configuration: the 24 tracker cases in Debug, and seven
transaction-fixture cases on Null. The one golden change is the vendor dump's display sink,
which an executed frame exports. The known Debug MilkTruck failure was fixed, so its carve-out was
not needed.

**Images.** Every non-identical case has a cause localized by stage controls and frame-count
bisection: a Metal fast-math contraction difference in the spatial upscale and temporal resolve,
accumulated by Native TAA or MetalFX history, which disappears with `-fno-fast-math` in both arms;
or a single lit pixel flipping one code value. No case shows a wrong view, a missing barrier or a
flipped default. Per-case metrics, heat maps and causes are in the review package.

## Gate 4: costs

Measured 2026-11-07 23:39 to 2026-11-08 00:01 with the same Apps as gates 1–3 (v2 at `42fd8920`,
the scored copy of frozen v1). The paired tools came from a later tools-only change on the branch
(Luminex #101), which let `visibility_paired.py` and `lighting_paired.py` rate a parent build; the Apps were not
rebuilt. A first attempt on 2026-11-07 is kept in the evidence's `costs-contended-lmstudio/` and is
not evidence: LM Studio was running inference on the GPU and a screen-sharing session was open, so
GPU pairs swung by up to ten times.

**Conditions.** LM Studio had no model loaded and screen sharing was off; the machine was on AC
power. The idle GPU still carried a steady 24–34% device utilization from system processes (a
wallpaper extension and Siri AI), and Spotlight indexing ran from 23:42 to 23:49, during the
visibility runs. None was stopped; the AB/BA pairing cancels a steady background, and the interval
widths below show how far it did.

**Gate, `parent_paired.py`** scored, 12 AB/BA pairs per scene, warmup 32 and 256 frames. Positive
means v2 is cheaper; a regression would be a median below −5% whose 95% interval also lies below
−5%.

| Scene | `encodeMs` % [95% CI] | `gpuSumMs` % [95% CI] | Scene pass GPU % [95% CI] | Shadow GPU % |
|---|---|---|---|---|
| Sponza | +4.3 [+3.4, +7.0] | +6.2 [+5.4, +7.1] | +8.8 [+8.4, +10.0] | +2.7 |
| MaterialLab | +12.8 [+11.7, +13.8] | +5.9 [−4.2, +13.6] | +5.2 [+3.2, +9.7] | +49.1 |
| TemporalLab | +13.6 [+10.5, +15.3] | +0.75 [−5.9, +10.5] | −4.4 [−12.2, +5.3] | +51.7 |
| LightLab | +5.9 [+5.7, +6.3] | +7.8 [+7.4, +8.3] | +6.9 [+6.7, +7.0] | +1.9 |
| VisibilityLab | +42.3 [+41.6, +42.7] | +19.0 [+18.6, +19.5] | +14.2 [+13.8, +14.5] | +39.3 |

No metric is flagged, so gate 4 passes. Sponza's and LightLab's lighting stages are also cheaper
(+1.2% and +4.1%).

**Known limitation: three wide intervals.** MaterialLab `gpuSumMs` (width 17.8 points),
TemporalLab `gpuSumMs` (16.4) and TemporalLab's scene pass (17.5) do not resolve the ±5% bound on
their own; they come from the two lightest scenes, about 0.7 ms of GPU time per frame, where the
background load weighs most. TemporalLab's scene pass has a median of −4.4%, so it is not a
regression by the rule, but this run cannot exclude a scene-pass regression of up to about 12%
there. `lighting_paired.py` gives the same picture for that cell, with an interval of
[−17.4, +15.6].

**Reported beside the gate.**

- `visibility_paired.py --parent`, six cells of 12 pairs: v2 is cheaper on Sponza in all three
  submission modes and on VisibilityLab at 16,384 instances with direct and indirect submission.
  VisibilityLab 16,384 with batched submission has `encodeMs` at **−5.20% [−5.85, −4.71]**
  (2.390 → 2.514 ms): the tool lists it, but it is not a regression under the rule above because
  its interval does not lie wholly below −5%. It sits at the boundary and is the cell to watch in
  R5.7. Its GPU metrics are 2.0–2.3% cheaper. CPU classification and preparation are slower on v2
  by up to about 0.13 ms; the gate does not cover them.
- `lighting_paired.py --control zero --parent`, six workloads of 12 pairs: `encodeMs` is 11–39%
  cheaper everywhere and `gpuSumMs` 1.4–18.8% cheaper.
- Single runs (warmup 32, 256 frames) of both arms are in the evidence beside the pre-R5 medians,
  for example VisibilityLab `encodeMs` 2.659 → 1.551 ms and `gpuSumMs` 2.869 → 2.301 ms.
- `frame_data_paired.py`, 12 repetitions: the digests of all five workloads equal v1's, which is
  the gated half. The timing is reported only, because `bindFrameData` became `uploadFrameData`:
  v2 is 7.5–20.7% slower, from F-DYNAMIC-1024 (98.3 → 105.8 µs) to F-STATIC-4096
  (322.2 → 390.0 µs).

## Recorded exceptions

Thresholds are unchanged.

- **Images, TemporalLab Native TAA at render scale 0.5** (accepted by the owner 2026-11-01):
  `strict` measures 2.2144% of pixels differing against the 1.0% limit, 0.0013% above 8 and a
  maximum channel delta of 13, identical at R5.5 to the first measurement. The Metal device compiler
  contracts the fast-math multiply-adds of the spatial upscale and the temporal resolve differently
  in the two arms; with every shader library compiled `-fno-fast-math` in both, v1 and v2 render
  byte-identical images. Record:
  `../rojo-rhi-evidence/luminex-port/P6.8e/2026-11-01-taa05-exception/exception.md` (SHA-256
  `f9388f996c2f103195891ba8d6a02558f47191cc2422e2e7ed648554a7147b3e`).

## Known issues and limits

- **San Miguel's first frame varies** from run to run in a few to about 120 pixels, on v1 as on v2;
  Native TAA and MetalFX carry it into later frames. From the second frame on, Off and Raw are
  byte-stable and equal between the arms. A transient read before it is written on the first
  frame is the likely mechanism, not yet proven. San Miguel is not a parity case.
- **Two light count views are flat images** on v1 as on v2, and the screenshot guard rejects them:
  Sponza's `--light-view count`, whose cause is not yet localized, and Light Lab's count view with
  `--lab-light-pile 1024`, which exhausts the global light-list budget so visible froxels get
  empty lists.
- **Tracker coverage** comes from per-command shader resource declarations; nested frame-arena data
  without exposed handles and adapter texture-ID reads are not fully declared, so a clean tracker
  run alone cannot prove complete shader coverage.
- **Hosted CI runs on Null.** Metal-only failures are caught by the local Metal 4 `Tests/gpu` run
  every renderer pull request requires.
- **No Windows run belongs to R5.** Luminex does not run on D3D12; RojoRHI's D3D12 backend awaits
  its hardware run.
