# R5 — Luminex Runs on the RojoRHI v2 Interface

**Status**: Proposed

R5 moves Luminex from RojoRHI's frozen v1 interface to its v2 interface, so that RojoRHI can
delete v1. [Part III](../../roadmap/codebase-rojorhi-port.md#r5--luminex-runs-on-the-rojorhi-v2-interface)
owns the outcome, slices and gates; this record keeps the design, the parity gate in full, and,
at closure, the evidence and limits. Proposed on 2026-10-22.

## Why

RojoRHI froze its v1 interface under `Legacy/` and deletes it once its required consumer, Luminex,
no longer builds on it. The v2 interface changes the model underneath every call site:
address-first roots replace binding slots, value handles with deferred destruction replace owned
objects, explicit layouts and pipeline stages replace use pairs in barriers, explicit queues and
fences replace `endFrame(swapchain)`, and nothing is virtual. The two interfaces share one include
root, namespace and symbol set, so they cannot coexist in one binary: each Luminex binary flips at
once. R5 keeps that flip small and judgeable by moving every difference Luminex can absorb on v1
behind Luminex-owned seams first, flipping on an integration branch that merges only when a parity
gate against a frozen v1 build passes, and optimizing against the same frozen build afterwards.

**Placement:** UX6 → **R5** → N1, execution-sequence step 18 in the
[roadmap](../../roadmap.md#execution-sequence). R5 continues the line R2 started when it moved the
RHI into RojoRHI, so it stays in the R series; its section lives in its own Part III file because
the restructuring file is at its line budget. Luminex `main` takes no work outside R5 until R5.5
integrates.

## Observed coupling before R5

Recorded on 2026-10-22 on the pre-port `main`:

- The render graph's `execute` is the one place that opens render, compute and copy passes and
  emits barriers, all in v1 `TextureUse`/`BufferUse` vocabulary. About 35 pass registrations
  (12 raster, 19 compute, 3 copy, 1 external), 32 of them under `Source/Render/Passes/`, record
  through a captured `rojoRHI::CommandList&`; Source makes 168 slot-binding calls.
- All 63 Slang files under `Shaders/` bind through v1 slots: 309 `[[vk::binding]]` declarations,
  each mirrored by a `k…Slot` constant on the C++ side that nothing checks at build time. None uses
  RojoRHI's shader ABI module.
- 145 members own RojoRHI objects through `std::unique_ptr` (43 textures, 31 shader libraries, 26
  graphics and 17 compute pipelines, 19 buffers, 6 samplers, 2 heaps, 1 temporal scaler), and 20
  Source files borrow raw `Texture*`/`Buffer*` pointers.
- `rojoRHI::Result` serves as Luminex's general error type at 127 sites, with `InvalidDesc` used 35
  times outside the RHI.
- Nineteen CPU test files fake v1's virtual interfaces through `Tests/Support/GraphTestSupport.h`;
  v2 has no virtual interface, so that seam disappears.
- The suites held 1,197 Release unit cases and 229 runnable `[gpu]` cases, all passing; Debug
  failed one pre-existing case, `loadGltf MilkTruck baked key bytes match the frozen parent`, a
  float codegen difference unrelated to the RHI.

## Proposed decisions

| Topic | Decision |
|---|---|
| Two repositories | Every RojoRHI change is a RojoRHI pull request merged first; Luminex pins only commits on RojoRHI `main`, and release tags once RojoRHI deletes v1 |
| Phases | Prepare on v1 (R5.1–R5.3), switch on the integration branch `feat/rojorhi-v2` (R5.4–R5.5), optimize after parity (R5.7) |
| Legacy-target bump | R5.1 pins the RojoRHI commit that keeps v1 under `Legacy/` with its targets renamed; v1 code is unchanged since the current pin, so the value is de-risking the build interface; hosted CI configures RojoRHI's Null backend |
| Integration branch | May build a subset of stages while families port in parallel; `main` never does |
| Identity | Milestone R5 in Part III; [ADR 0033](../../decisions/0033-rojorhi-conformance-replaces-checkpoint-a.md) replaces portability checkpoint A, which cannot outlive v1 |
| Upscaler name | No display-name query in RojoRHI; Luminex maps the upscaler kind to the text it shows today, "MetalFX Temporal" |
| What stays in Luminex | Idle waits, blocking readback, frame numbers, texture and buffer getters, pixel-size helpers and path-based shader loading |
| Parity gate | The gate below: frozen v1 tag and worktree, ledger-adjusted test counts, strict and vendor image profiles with byte identity reported per case, 600-frame smokes under the Metal layer and RojoRHI's validation tracker, paired costs |
| Graph vocabulary | The graph keeps Luminex-owned use enums; a table lowers them to v2 stage, access and layout; layouts are tracked per subresource, and a `TextureStateTable` carries persistent textures across frames |
| Scene draws | Per-run root with material views; indirect records carry `drawId`; the `SceneTables` row ABI is unchanged, so its oracles hold across the switch |
| Timing | Raster passes are timed by their render-pass scope, compute and copy work by explicit scopes, under one outer `lmx.frame` scope; `gpuSumMs` is the sum of depth-1 scopes, comparable with v1's per-pass sum |
| Tests | Hosted Null configure; backend-agnostic `[device]` cases; Debug `[tracker]` frame smokes; graph and model tests run device-free on the lowered frame and synthetic handles |
| CI | Hosted Luminex CI runs on Null; Metal 4 builds, GPU suites, parity and timing run locally |
| Exceptions | Per-case image and cost exceptions only with the owner's recorded approval; none for tests or smokes |
| Freeze | Luminex `main` takes no other work until R5.5; if anything lands, the integration branch is refreshed onto it and the frozen reference rebuilt at the new base |

The owner accepts ADR 0033, the integration and any per-case exception, and receives a
non-blocking acceptance package of editor walkthrough screenshots, heat maps and the exception
list.

Alternatives rejected: a compatibility shim that re-creates v1 on top of v2 (a slot table mapping
`bindTexture(n, …)` onto roots, a virtual device wrapper, or an idle wait hiding fences everywhere);
the R5.2 and R5.3 seams absorb Luminex's own concerns and none simulates slot binding. Convenience
entries added to RojoRHI for Luminex (blocking readback, idle waits, frame numbers, getters, pixel
helpers, an upscaler display name), which would break its thinness.

## RojoRHI additions

Each is a RojoRHI change merged on green before the switch consumes it:

- **Consumer shader build rule**: RojoRHI's Slang rule builds a consumer's shader modules with
  extra include directories, writes Null shader libraries on every host so a consumer's pipelines
  can run under the validation tracker on hosted CI, embeds libraries in a generated header, and
  rejects a file with no entry point.
- **Upscaler input range**: capabilities report each upscaler's supported input scale range, which
  Luminex's dynamic-resolution controller clamps to.
- **Capture availability**: capabilities report whether GPU capture is available, which enables the
  editor's capture menu; a submission with no lists is stated valid outside a frame, which Luminex's
  idle wait relies on.
- **ImGui adapter**: an optional target written only against the public interface, with an embedded
  shader, multi-viewport support through host surface callbacks and textures named by view index.

## Slices

- **R5.1 Legacy-target bump** — outcome: Luminex builds v1 from RojoRHI `main`. Exit: hosted CI
  green; local `Tests/gpu` 229/229 and RojoRHI's legacy GPU cases 58/58; parity 15/15
  byte-identical.
- **R5.2 Foundation seams** (two or three pull requests) — outcome: Luminex's own error type, a
  `GpuContext` with frame counter, idle wait and shader loader, a readback API, GPU owners without
  getters, `CaptureSchema` in Luminex, `asset::ImageData`, Luminex pass timings and upscaler
  support info, all still on v1. Exit per pull request: hosted green, `Tests/gpu` green, parity
  15/15 byte-identical, test counts unchanged.
- **R5.3 Graph and test seams** — outcome: Luminex use vocabulary, a lowered frame with a v1
  emitter, the state table with stateful imports, a transient backend interface, pass scopes in the
  lowering, pure root builders per stage; graph tests assert the lowered frame and fakes shrink to
  Luminex seams. Exit: as R5.2, and the graph dump goldens unchanged.
- **R5.4 Interface switch and stage ports** (on `feat/rojorhi-v2`) — outcome: first a minimal
  frame (display transform and UI) on v2 with the RojoRHI shader rule, the GPU layer, the v2 graph
  emitter, all three frame loops, the editor on the adapter with detached windows, capture, and the
  Null CI configure with its `[tracker]` job; then the stage families: scene and shadow, visibility
  and occlusion, local lights, post and editor passes, temporal and vendor. Exit: the branch builds
  on Null (hosted) and Metal 4 (local); the editor runs 600 frames validation-clean; dumps
  byte-identical; each family's `[gpu]` cases green and its lab images within the image gate.
- **R5.5 Parity and integration** — outcome: every stage back, the test ledger
  `docs/milestones/r/r5-tests.md`, goldens re-recorded only with frozen-v1 comparisons,
  `FrameDataBench` on v2, `Tools/GpuDebug` re-keyed, architecture pages and `AGENTS.md` current,
  ADR 0033 accepted; the gate run; tag `r5-validated-<date>` on the branch tip; one squash commit
  `rhi: run on RojoRHI v2 (R5)`. Exit: the gate below passes in full and R5 is accepted.
- **R5.6 Pin the release without v1** — outcome: Luminex pins the RojoRHI release that deletes
  v1, and no Luminex tool or document names the legacy targets. Exit: hosted green, `Tests/gpu`
  green, parity 15/15 byte-identical against R5.5's v2 images.
- **R5.7 Optimization** (several pull requests) — outcome: bindless material rows, one counted
  multi-draw per pipeline bucket fed by visibility, static pass roots built once, narrowed raster
  stages; then profile-led items. Exit per pull request: gates 1–3 against the frozen v1 build,
  costs reported with paired evidence, and no cost-gate regression.

R5.6 and R5.7 are separate squash pull requests after the integration. If the cost gate fails at
R5.5 and per-draw roots are the measured cause, the bindless material rows move forward behind the
gate as a parity fix.

## Parity gate

**Frozen v1 reference.** Tag `r5-v1-reference` on the pre-port `main`, checked out in a dedicated
worktree `../luminex-worktrees/v1-reference`, built Release once and never rebuilt; SHA-256 sums of
`App`, `Tests`, `FrameDataBench` and the compiled `Shaders/` are recorded beside the build and
checked before every use. Every comparison renders both arms freshly on the same machine (Apple
M3 Max) and OS build; if the OS updates during R5, both arms are re-rendered and nothing is
compared against stale hashes. The checked-in `Tools/Screenshots/reference.json` already fails
its 6 MetalFX cases on macOS 27, so it is not the reference.

**Evidence.** Raw evidence lives outside the source tree with a `SHA256SUMS` file and is linked
from the integration pull request; a summary goes in this record, and a small readable copy under
`../Luminex-evidence/reports/r5/`, as the [evidence archive guide](../../guides/evidence-archive.md)
describes for report copies.

All four gates must pass:

1. **Tests.** Release `Tests/unit` and `Tests/gpu` pass with counts equal to 1,197 and 229,
   adjusted only by the test ledger, each line accounted for. Debug passes except the known
   MilkTruck case, which stays known-failing as on v1. The hosted `[tracker]` job is green.
   RojoRHI's own suites are green on the pinned commit.
2. **Images.** `Tools/Screenshots/parity.py` with the v2 App renders the 15 cases (Sponza,
   MaterialLab and TemporalLab × Off, Native TAA at 1 and 0.5, MetalFX at 1 and 0.5), then
   `compare.py --parent <fresh frozen-v1 render> --candidate <v2>`:
   - Off and Native TAA cases use the `strict` profile: at most 1.0% of pixels differ and at most
     0.05% differ by more than 8 per channel.
   - The 6 MetalFX cases use `--profile vendor-quantization-v1`.
   - For every case the evidence states whether it is byte-identical, its `maxChannelDelta` and
     its `meanAbsoluteDelta`. A case that is not byte-identical gets a heat map and a one-line
     cause, localized by a pass-by-pass capture diff, before the gate is called passed.
     Pointer loads in place of argument-table bindings and different multiply-add contraction
     produce ±1–2 code-value SDR noise; a wrong view, a missing barrier or a flipped default
     produces structured deltas above 8 or large areas, which the strict profile separates.
   - TemporalLab's `--capture-sequence` is compared against the frozen build with
     `compare.py --sequence` under the same profiles.
   - Thresholds are fixed now and never tuned after results. A case that fails its profile for a
     documented numeric cause blocks the merge unless a per-case exception is approved and
     recorded in the evidence and here, with the heat map and the pass-level analysis.
3. **Smokes.** `MTL_DEBUG_LAYER=1 LMX_MAX_FRAMES=600 ./App --windowed` (Release, editor on, one
   detached viewport opened, one resize) exits 0 with `600 presented, 0 skipped` and no validation
   line. The Debug App runs the same 600 frames with `--rhi-validation` under RojoRHI's tracker
   with no valid-usage failure and no validation line.
4. **Costs** (target: not slower beyond noise). `Tools/Bench/visibility_paired.py` and
   `lighting_paired.py --parent <frozen v1 App>`, fresh-process AB/BA, cover all five scenes. A
   regression is a paired median above +5% on `encodeMs`, `gpuSumMs` or a stage's GPU time whose
   bootstrap 95% confidence interval excludes +5%; it is resolved before merge by a fix, by moving
   the bindless material rows forward when per-draw roots are the measured cause, or by a recorded
   exception with its capture or profile analysis. The single-run `--measure` medians at warmup 32
   and 256 frames recorded before R5 are reported beside them. `frame_data_paired.py --baseline
   <v1 FrameDataBench> --candidate <v2>` must match digests; its timing is reported, not gated,
   because `bindFrameData` became `uploadFrameData`.

Exception paths: images (gate 2) and costs (gate 4) admit an approved, recorded per-case
exception. Tests (gate 1) and smokes (gate 3) have none.

## Test strategy

Hosted Luminex CI configures `--rojorhi_backend=null`, builds everything and runs `Tests/unit` in
Release; a second hosted job runs Debug on Null and executes `[tracker]`. Graph, model and
transient-pool tests move to synthetic handles, the lowered frame and fake Luminex seams, with no
device. Cases that need a command list become `[device]` cases that pass on Null and Metal 4. A new
renderer frame smoke per scene and feature toggle runs four frames under the tracker
(`[device][tracker]`, Debug), catching missing barriers and wrong layouts without a GPU. Locally,
Metal 4 runs `Tests/unit`, all `[gpu]` cases under `MTL_DEBUG_LAYER=1`, the parity gate and timing.
Graph dump goldens stay byte-identical; every hash-based golden is re-recorded only with a frozen-v1
comparison attached.

## Known risks

- The switch stays large after the seams: 168 binding calls, 63 shader files and 145 owners.
- Images may differ beyond `strict` for a codegen reason; the threshold does not move, so such a
  case needs pass-level localization and an exception, or it blocks.
- Layout errors on persistent textures cross frames and show only in Debug; the state table is
  unit-tested and the tracker smokes run several frames per scene.
- ImGui's multi-viewport lifecycle meets v2's frame rules; swapchain changes are deferred to the
  adapter's new-frame step and the smoke opens a detached window and resizes.
- Per-draw roots may cost more CPU than v1's frame-data binding at visibility-lab's draw count
  (2.86 ms encode median before R5).
- v2 times scopes where v1 timed encoders, so `gpuSumMs` may shift with no real change; paired
  AB/BA runs and whole-frame GPU time guard the comparison.
- Hosted Null CI misses Metal-only failures; every pull request runs the Metal 4 build and
  `Tests/gpu` locally before merge.
- SDL may write the drawable size on resize behind RojoRHI; the resize smoke checks it.
- Slang's HLSL and SPIR-V lowering of Luminex shaders may hit bugs Metal never needed; each becomes
  a RojoRHI issue, and the rule can restrict Luminex to MSL with the reason recorded.
