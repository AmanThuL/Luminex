# R2.3 — Mechanical Rename Validation Record

**Status**: Implemented

The component carries the RojoRHI identity everywhere Luminex's tree names it. The branch carries
four source commits — the unedited mechanical output, one comment reword the rename required, a
formatting commit, and one hand-edit commit (`rhi: correct comments that name the old identity`) —
then one documentation-only commit (`docs: follow the RojoRHI rename in comments and commands`)
that extends the hand-edit scope; see "Why three commits became four" below. The [exit gate](r2.md#r23--mechanical-rename) holds with its one
declared difference: default GPU labels and log text containing the old prefix change exactly as
the substitution predicts, and capture-dump comparison applies the substitution before comparing.
The owner accepted R2.3 and its integration on 2026-09-20, retaining the limits below.

## Why three commits became four

`xmake format` rewrapped `Source/Render/SceneTables.h`'s `lights` declaration across two lines,
because the rename lengthened it past the column limit; the public-API comment checker cannot read
a Doxygen comment on a wrapped declaration. Rather than let the format commit fail that gate or
touch comment text inside the mechanical commit, one comment was reworded shorter first, as its own
commit, so both the mechanical and format commits keep passing every gate on their own. That gives
the source-changing work its four commits: the mechanical output, the comment reword, formatting,
and one hand-edit commit that corrected comments naming the old identity inside the component and
`Benchmarks/FrameData`, deleted nine unused `namespace rhi = rojoRHI;` aliases from Luminex's
`Tests/`, and updated the `lmx.` needle and docstring in `Tools/GpuDebug/spike_inventory.py` and
`Tools/GpuDebug/xctracelib.py`.

A further, documentation-only commit follows on the same branch. Its scope was widened during
review beyond the design's original list to `docs/conventions/cpp-style.md`,
`docs/conventions/modules.md`, `docs/frame-pipeline.md`, `ThirdParty/README.md` and
`docs/architecture/overview.md`. The design had deferred architecture prose to R2.4; that commit
changes only paths, target names and namespace tokens that state the current layout, not
narrative prose, and R2.4 still keeps the `RojoRHI/` mount path these edits already name.

## Evidence

Bundle `../Luminex-evidence/r2.3/`, outside the repository, following the
[R1 comparison protocol](../../roadmap/codebase-module-boundaries.md#r1--module-boundaries-and-shared-foundations)
as R2.2 ran it.

**Tier 1, at the mechanical commit, the format commit, the documentation commit's tree and the
record commits:** build; all four test groups pass under `MTL_DEBUG_LAYER=1`; both checkpoint-A
checks and both `[checkpoint-a]` binary filters; `xmake policy`; the Python tool suites; the
standalone `RojoRHI/` copy-out configures, builds and tests from its own root. The comment-reword
and hand-edit commits were covered transitively: each differs from a fully gated tree only by
formatter output, Markdown, or a Python tool change whose suites passed.

**Tier 2, at the head:** the Sponza graph dump, tagged PNG bytes and metadata, a capture sequence
and its manifest, and a five-frame stdout run (timestamps stripped) are byte-identical between
parent and candidate. `Tools/Screenshots/parity.py` ran eight alternating rounds (four parent, four
candidate) over all fifteen reference cases: zero cases were unresolved (every candidate hash was
also produced by the parent in the same session), `allMatched` is `false` on both builds — the
documented, pre-existing historical-reference failure — and `reference.json` was not touched.

The capture-schema JSON is **not** byte-identical, which is the declared difference: its only
differing rows are the component's default `frameData` page labels (`lmx.device.frameData.N.page.M`
→ `rojorhi.device.frameData.N.page.M`), on three buffer rows and twenty-one `pageLabel` rows; every
other field — sizes, offsets, slots, `gpuAddress` — is identical, and normalizing those label
prefixes makes the sidecars byte-equal. `gputrace_dump.py`'s decoded manifest, uniforms and images
are equal after the same normalization in every capture except the first candidate capture, whose
manifest difference the Limits section describes, checked against a same-session parent-vs-parent
control that shows the identical two-path-string difference. Archive symbols are equal only after
three steps applied to the parent list: the namespace substitution (`lmx::rhi` → `rojoRHI`),
stripping `nm` addresses, and adjusting the assert macro's `__FILE__` string-literal length by the
four bytes the directory rename (`RHI/` → `RojoRHI/`) predicts; no other symbol, `#cond` or message
length differs. Generated MSL is equal once the worktree path in `#line` directives is normalized
(35 of 63 files were already byte-identical); `xcrun metal-objdump -D` disassembly of all 63
metallibs is identical once the worktree root and module offsets are normalized. The residue gate
is clean: inside `RojoRHI/`, nothing matches `lmx::rhi`, `LMX_ASSERT`, `LMX_LOG_` or a quoted `RHI/`
include. Outside the component, every `rojoRHI`/`rojorhi`/`RojoRHI` occurrence is attributed to a
substitution-table row, the source hand-edit commit, or the documentation commit — the latter
also reaches `AGENTS.md` and `ThirdParty/README.md`, which sit outside both the component and
`docs/`. Renderer-owned `lmx.*` labels, `LMX_*` identifiers and the `lmx` namespace outside the
component are unchanged in count.

## Limits

The first candidate GPU capture carried two extra unlabeled 28,180,480-byte texture blobs of
unidentified content and shifted Metal object IDs, including a `CAMetalLayer` object index shifted
from 4319 to 4323. The parent control and two later candidate captures did not reproduce this;
every labelled resource, uniform and image is equal in all seven captures taken. It is recorded
unattributed, not folded into normalization and not re-baselined, the same treatment R2.2 gave its
own unattributed parity flake. Raw captures were pruned from the evidence bundle except that one
anomalous pair (candidate and its matching parent-A control); every other capture's decoded
artifacts remain.

No same-commit rebuild control was taken to confirm it, so absolute worktree paths and per-build
UUIDs are an inferred, not proven, cause of the raw shader-output (`.metallib`) and archive byte
differences across worktrees; equality is instead judged on disassembly and stripped symbols, not
raw bytes, the same method R2.2 used for the `App` link.

Several identities keep the word "RHI" by decision, not omission: `RojoRHI/Tools/check_rhi_headers.py`
and its check message, the `[RHI]` stderr prefix in `RojoRHI/Source/Base/Message.cpp`, file names
such as `RHIResultTests.cpp` and `RhiGpuTestSupport.h`, Catch2 tags such as `[rhi]`, every test case
name, and Luminex's `Render/RhiLog`. `Tools/GpuDebug/xctracelib.py` keeps its `lmx.` label marker
unwidened, because no encoder emits a default `rojorhi.` label today; `Tools/GpuDebug/spike_inventory.py`'s
needle was widened instead, since it hunts the component's own renamed spike-test labels.

The rename lengthened some non-C++ lines (Lua, Python, YAML) past 100 columns; `xmake format` does
not cover those files and nothing else enforces a column limit on them. Paths inside the component
still assume the Luminex root until R2.4 mounts it as a submodule, and the `LMX_CAPTURE_PATH`
wording in the capture-failure message is unchanged, waiting for its owner to be decided after
extraction. Rows 46 and 47 of the substitution table changed Markdown link targets, not link text,
in four existing documents — a guide, a frozen milestone record, a research note and a closed
spec — because the project's broken-link policy check requires it once the directory moved.
