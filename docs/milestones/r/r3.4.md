# R3.4 — Core

**Status**: Implemented

R3.4 gives Core the math and the data structures that carry no domain meaning, tested there, and
leaves Engine, their first consumer, holding only what describes or owns a scene. The catalog
leaves the Engine library for its own unit. Rendered output and shipped behaviour do not change.

[Part III](../../roadmap/codebase-restructuring.md#r34--core) owns the outcome and the exit gate.
[R3](r3.md#r34--core) owns the series design and the table of sources and cuts.
[ADR 0026](../../decisions/0026-core-charter-and-placement.md) owns the decision. This record keeps
the interfaces, the path tables, the commit sequence and the rules the executor follows; the
[validation record](r3.4-validation.md) keeps the evidence, deviations and limits.

## Inventory before R3.4

Measured at `52945a6`, build files excluded.

- `Source/Core/` holds 14 files and 501 lines in one folder, built with `add_files("*.cpp")`.
- `Scene::Storage`, identity allocation, the paced tables and every `Scene` member that touches
  them share `Engine/Scene/SceneTables.cpp` (776 lines). `Scene.cpp` (495) holds the glTF scene
  builder, playback, draw-item filling and three catalog loaders.
- `loadGltfScene` authors the Sponza rig by scene name before `finalize`, and `Scene` befriends
  `SponzaLightRig` so it can write `m_sponzaLightIds`. `Scene.h` declares all eight catalog
  loaders. These are Engine's references into the catalog.
- The bounding-sphere expression appears five times (`Scene.cpp`, all four labs) and the min/max
  accumulate loop nine times in six files (`Scene.cpp`, `SceneTables.cpp`, the four labs), mostly
  over bare `glm::vec3` locals. Identity slots are allocated and released for instances, textures
  and lights; mesh and material identities are always generation 1.
- `Engine/Catalog/` is included from 32 files in App, AppModel and Tests; no tool or benchmark
  loads a catalog scene.
- `forbidUndefined` in the module contract takes one namespace prefix, and a unit path that does
  not exist yet must be listed in `pendingPaths`.
- `Tests/` compiles `*.cpp` from one flat folder, so new cases need no build-file edit.

The two radical inverses keep both names. A test pins them equal for base 2 over indices 0 to
65,535, where both are exact; neither caller changes which one it calls.

Punctual attenuation and the cone term stay in Engine, correcting R3's table: they are compiled
with `-ffp-contract=off` inside `LocalLightMath.cpp`, a shader mirrors them, and the windowed
falloff is a lighting convention, which ADR 0026 counts as a domain meaning.

### Adoption in this slice

Asset, Engine and the catalog adopt everything they use. Render and App adopt only where a whole
function or helper leaves them: `Visibility.cpp` takes `Frustum`, `extractFrustum` and
`planeRejects` (`FrustumPlanes` becomes an alias, `extractFrustumPlanes` a wrapper passing
`kVisibilityGuardWorldUnits`); `Temporal.cpp` takes `radicalInverse`; `fitShadowOrtho` keeps its
signature over `fitOrthoToSphere`; `LightClusters.cpp` takes `divRoundUp`; users of `Transform`
and `Sha256` change an include and a qualifier. `RingBuffer`, `Interval`, `Stopwatch`,
`toLowerAscii`, `intersects` and `distanceSquared` land with tests and are adopted by R3.5 and
R3.6, which own the files that would use them.

## Rules

- The [R1 comparison protocol](../../roadmap/codebase-module-boundaries.md#r1--module-boundaries-and-shared-foundations)
  applies. A cheap gate runs at every commit: build, generated MSL, test inventory, CPU tests,
  every checker, the format check, and the `-ffp-contract=off` assertion. Test inventory may only
  grow, and only by the cases this record's new test files declare.
- S16–S26 each also reproduce the parent's texture bake and three `--temporal off` screenshots
  byte for byte, because moving arithmetic between translation units can change inlining; only
  Temporal Off is byte-repeatable, so temporal modes are compared once at the head by the
  eight-round parity protocol. An
  adoption that cannot hold them is reverted and recorded as a limit; its Core type stays.
- A Core header lands with its tests in the same commit and before any caller uses it. Tests
  compare against constants captured from the replaced code at `52945a6`, not against a second
  call of the new code.
- No pass label, shader basename, CLI option, schema, file format, test tag or existing test case
  name changes. `Scene::sponzaLightIds` is the one public rename. `RojoRHI/` is not edited.

## Limits

No Render, App or Tests folder moves, and no decomposition of their files; R3.5–R3.7 own them.
`ConsoleSeverity`, the three App histories, the timing sites, `SelectionBounds`, the froxel test and
`RenderGraphRanges` keep their own code until then. `Scene::lightLabGridCount`, a member that
exists for one catalog scene and is read by App, stays until UX2's scene documents replace it, and
the accumulate loops in `Tests/EngineGeometryTests.cpp` and `Tests/RenderTests.cpp` stay as
independent checks. UX2 later retires `SponzaLightRig` and
`SponzaCameraTour` from `Source/Scenes/`.
