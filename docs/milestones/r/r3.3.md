# R3.3 — Engine

**Status**: Implemented

R3.3 puts scene description below the renderer. `Source/Asset` and `Source/Scene` become
`Source/Engine/`, the scene vocabulary leaves Render for `Engine/Types/`, `Scene::view()` becomes a
Render-side builder, and the module contract reverses the edge: Render depends on Engine, and
Engine never on Render. Rendered output and shipped behaviour do not change.

[Part III](../../roadmap/codebase-restructuring.md#r33--engine) owns the outcome and the exit
gate. [R3](r3.md#r33--engine) owns the series design.
[ADR 0025](../../decisions/0025-engine-subsystem-and-render-on-engine.md) owns the decision and is
accepted before the first file moves. This record keeps the path tables, the commit sequence and
the rules the executor follows; the [validation record](r3.3-validation.md) keeps the evidence,
deviations and limits.

## Inventory before R3.3

Measured at `75dd539`, build files excluded.

- `Source/Asset/` holds 23 files in one folder; `Source/Scene/` holds 28.
- Ten Render files are scene vocabulary: `Mesh`, `Camera` and `LocalLightMath` as pairs, and the
  headers `AlphaMode.h`, `LocalLight.h`, `Bounds.h` and `SceneTables.h`. None includes another
  Render header outside this set.
- Scene includes seven Render headers from five files. `SceneView.h` is the only one that brings
  renderer configuration with it, and `Scene.h` needs it for `Scene::view()` alone; it names
  `DrawItem`, `DirectionalLight` and `MotionClass` beside that.
- `Scene::view()` reads public members and one private assertion, `validateObjects()`. It has 42
  call sites in 22 files; App reaches it through `SceneSession::view`, and most test cases through
  one support header.
- Target `Scene` links `Render`, and Render's build file compiles `LocalLightMath.cpp` with
  `-ffp-contract=off`.
- `xmake policy` fails on `main`: `Source/Render/LocalLight.h` lacks the closing ruler of its file
  header. `AGENTS.md` documents `xmake policy --link`, which does not exist; the check is
  `python3 Tools/check_module_deps.py --link`.

## Units and targets

| Unit | Paths (target) | Namespace | May depend on |
|---|---|---|---|
| `core` | `Source/Core` (`Core`) | `lmx` | — |
| `asset` | `Source/Engine/Asset` (`Asset`) | `lmx::asset` | `core` |
| `engine` | `Source/Engine` outside `Asset` (`Engine`) | `lmx::engine` | `core`, `asset` |
| `render` | `Source/Render` (`Render`) | `lmx::render` | `core`, `engine`, `asset` |

`app-model`, `app-shell` and `tests` replace `scene` with `engine` and change nothing else.
`Source/Engine/xmake.lua` defines `Engine` and `Source/Engine/Asset/xmake.lua` defines `Asset`.
`Engine` carries `-ffp-contract=off` for `Types/LocalLightMath.cpp` and declares
`forbidUndefined: lmx::render::`. `Asset` keeps `forbidUndefined: rojoRHI::`, its RHI header
allowance and `TextureBake`'s empty framework set.

## Extractions and the builder

Each extraction moves declarations, comments included, into a leaf header the old header includes,
with no signature or semantic change, as R1.2 did for `TextureDesc.h`. `SceneView.h` includes
`Engine/Types/DrawItem.h` and `Engine/Types/DirectionalLight.h`; `Temporal.h` includes
`Engine/Types/MotionClass.h`.

`Render/Renderer/SceneViewBuilder.h` declares
`SceneView buildSceneView(const Scene&, std::vector<DrawItem>&, ShadowFilter, bool wireframe)`.
`Scene` gains a public `fillDrawItems(std::vector<DrawItem>&) const` that holds today's item loop
and its private `validateObjects()` call unchanged; the builder calls it and composes the remaining
fields from public members in today's order. `Scene::view()` is removed in the same commit, and
`Scene.h` stops including `SceneView.h`. `SceneSession::view` keeps its signature and calls the
builder. `SceneView` has no field change. In that commit target `Scene` drops `Render` and
`Render` links `Scene`.

## Namespace substitution

One commit, from a script kept with the evidence, run and then followed by `xmake format`:

- `lmx::scene` and `scene::` become `lmx::engine` and `engine::`.
- For a frozen list of the identifiers the moved vocabulary declares, `render::X` becomes
  `engine::X`, the declaring files change namespace, and an unqualified use inside
  `namespace lmx::render` gains `engine::`. `Bounds.h`'s identifiers take `lmx::` instead.
- The script works on tokens: it skips string literals and comments, so an ImGui label such as
  `"Camera"` and prose are untouched. Comments are step 19's.
- No using-directive is introduced. `lmx::asset` and `lmx::app` do not change.

The identifier list is fixed from the declaring headers before the script runs and is recorded in
the validation record. A successful release build of every target is the script's oracle.

## Evidence

The owner chose, on 2026-09-21, R3.2's cadence: a cheap gate at every commit and the full
comparison protocol once at the head. The evidence bundle and the scripts live outside the tree.

**Every commit:** App, Tests, FrameDataBench and TextureBake build in release; generated MSL
equals the frozen parent's; `xmake format --check`, every policy checker and
`check_module_deps.py --link` pass with an empty allowlist; the CPU unit groups pass; the test
case inventory, by name and tag, equals the parent's. From step 17 the link check includes the
Engine archive.

**Once at the head:** the validated GPU suite and both checkpoint A halves; byte-stable artifacts
— graph dumps, capture manifests and PNG metadata, baked DDS and manifests from a `TextureBake`
run; capture dump semantics; `TextureBake`'s linked frameworks and the Asset and Engine archive
symbol checks; the strict parity matrix with a cap of eight alternating rounds fixed before
measurement.

## Execution shape

The owner runs execution with Opus as the main thread and as the highest subagent tier, and asked
for the widest parallelism the chain allows. Commits are linear, so parallelism sits around them:

- **Before the chain, in parallel:** the contract and checker work; the move and include
  substitution scripts; the frozen parent build and the per-commit gate script; the namespace
  script, developed in a scratch worktree with the moves already applied.
- **The chain:** one writer, script-driven.
- **After the chain, in parallel:** per-commit gates, one worktree per commit, four at a time. A
  failure is fixed at its commit and every later commit is gated again.
- **At the head, in parallel:** the GPU protocol, owned by one agent because GPU runs must not
  overlap, beside the living-document drafts, one agent per file.

Review runs one tier above the implementer and stops at the cap: Sonnet work is reviewed by an
Opus subagent, Opus work by the Opus main thread.

## Limits

No Render, App or Tests folder moves; R3.5–R3.7 own them. No class, file, pass label, shader
basename, CLI option, schema, file format, test tag or test case name changes. `RojoRHI/` is not
edited. Render's dependency on Engine is confined to the builder by review, not by the checker.
UX2 later retires `SponzaLightRig` and `SponzaCameraTour` from `Engine/Catalog/`.
