# R1.2 — Asset and Scene Replace Engine

**Status**: Implemented (2026-09-13)

R1.2 implements the [Asset/Scene boundary](../roadmap/codebase-refactoring.md#r12--asset-and-scene-replace-engine)
under [ADR 0020](../decisions/0020-module-layering-and-units.md). Engine is retired. Rendering,
RHI signatures, shader sources, frame inputs, pass labels and output bytes remain unchanged.
The [execution plan](../plans/2026-09-13-r1.2-asset-scene.md) records the ordered extraction.

## Shipped structure

- `Core/Color.h` replaces both colour helpers with the same scalar/GLM expressions; Core exports
  glm alongside spdlog. `RHI/TextureDesc.h` holds the unchanged allocation, upload, range, view
  and copy vocabulary; `Texture.h` includes it and `RHI.h` remains unchanged.
- `Render/SceneView.h` holds the unchanged material, draw, lighting, temporal and frame-input
  declarations. The reconstruction, fallback and debug enums move unchanged to `Temporal.h`,
  avoiding an orchestrator dependency; `AlphaMode.h` remains a leaf included by SceneView.
- `Asset` owns CPU decoding, deterministic PNG/BMP writing, mip baking/SHA-256, IBL generation,
  procedural geometry, clip data/sampling and asset errors. Transform composition/decomposition
  moves here because both glTF validation and scenes consume it. Repository discovery shares one
  nearest-first search while retaining exists-versus-regular-file and seven-parent contracts.
- `Scene` owns GPU DDS/cubemap/IBL uploads, scenes, catalog, environment, labs, motion and playback,
  initial-camera conversion and camera-track following. App retains its scheduling and input
  guards. glTF uses `asset::GltfAlphaMode`, explicitly translated at upload; BLEND stays rejected.
- Asset links Core only and names only the RHI format/descriptor headers. TextureBake links Core
  and Asset, with neither Render nor any Metal framework. The transitive checker grants this CPU
  tool the same two descriptor headers because Asset's unchanged mip-chain API exposes them.
  All 20 R1.2 migration allowances are removed; only 14 R1.3 shared-App-source allowances remain.

## Verification

Evidence is outside the source tree in `/tmp/luminex-r1.2-evidence`. Parent and candidate are
release builds compiled in this session on the same Apple Silicon device. `PARENT-COMMANDS.md`,
`CANDIDATE-COMMANDS.md`, runtime hash manifests, raw outputs and comparison JSON retain provenance.

- App, Tests and TextureBake build; format, project/module policy, standalone Source and RHI
  headers, comment/layout policy, Python tooling and module `--link` checks pass. The header
  checks compile 58 Source and 22 RHI headers with no exemptions. The Asset symbol backstop finds
  no undefined `lmx::rhi::` references; TextureBake's framework set is empty.
- Parent CPU: 580 cases / 101,627 assertions. Candidate CPU: 586 / 101,659. The Python suite has
  169 passing cases. Candidate GPU validation passes all 170 cases, matching the parent inventory.
  The unchanged checkpoint-A filter passes 19 cases / 1,856 assertions on each build.
- Catch2 XML inventories preserve all 750 existing case names and GPU/checkpoint tags. The only
  existing tag changes are 95 `[engine]` replacements by owning `[asset]`, `[scene]` or `[core]`;
  `test-tag-map.json` records each case. Six additive tests pin discovery predicates/search depth,
  BMP bytes/failure and both camera seams. Existing test filenames remain stable.
- Both Sponza and TemporalLab graph dumps are byte-identical. TemporalLab TAA at half render scale
  produces identical sequence manifests and all three tagged PNG frames after four warmup frames.
  A deterministic CPU probe produces byte-identical PNG and capture-schema JSON; all three bake
  modes produce identical DDS bytes and manifests.
- The strict fifteen-image matrix passes 15/15 on both parent and candidate in each of two
  alternating paired rounds. The second confirms the final binary after removing orphan layout
  separator comments (assertion line metadata changed). Both builds match the historical
  references and each other; no candidate-only hash exists. `paired-parity.json` retains all
  rounds within the predeclared maximum of eight, with no exception, reference change or re-baseline.
- GPU capture semantics match: 15 pass labels in order, 44 resource declarations, six uniform
  layouts and 88 frame-data upload layouts. Every decoded value agrees except the editor's
  wall-clock `time` field; its raw values are retained. Runtime validation is clean. The capture
  dumper reports the same two known errors and nine warnings on each build; these are recorded
  parser limitations, not a claim that the raw dump is diagnostic-free.

## Integration and limits

The owner requested one commit merged directly into local main without a pull request. This
supersedes separate move/rename commits for this slice only; the ordered plan, mechanical
namespace mapping, preserved parent and final diff make the extraction reviewable. Existing main
history is preserved, with no remote publication implied.

The archive-symbol check sees non-virtual calls only; the include boundary and executable link
check remain the stronger proof. Live capture schema contains GPU addresses, so exact schema
bytes come from the deterministic CPU probe; captures compare semantic declarations and layouts.
No performance conclusion is drawn. AppModel and shared scene-session extraction remain R1.3;
renderer stage decomposition remains R1.4. This slice does not approve interface gate B.
