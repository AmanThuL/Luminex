# M7.2 — Detached Performance Window

**Status**: Implemented and verified — owner-accepted for integration 2026-09-15

The owner requested Performance in a separate native window, following Render Graph, with
Console alone in the main editor's bottom dock. Its plan addendum preceded source edits; the
executor plan is now closed. This follow-up preserves the [transport semantics](m7.2-editor-transport.md)
and all existing image-gate failures. The [owner decision](m7.2-validation.md#owner-acceptance-and-integration)
on 2026-09-15 authorizes integration without relabelling those failures; the GitHub PR records the merge state.

## Authorized behavior

- Performance and Render Graph are detached native windows, closed by default. Console alone
  occupies the default bottom dock. Window > Performance is a normal visibility toggle.
- Workspace schema 3 restores visibility and window geometry. Schema 2 migrates to the new
  default topology while preserving valid UI scale. Reset Default Layout preserves UI scale,
  closes Performance/Graph and resets Performance's next-open bounds.
- Selecting Measure mode opens no window. Measure Play opens/focuses Performance once and
  expands its Measure section. Closing the window does not cancel the run; completion and
  cancellation do not reopen it. Toolbar options > Show measurement explicitly opens/focuses
  that section anytime, including during a run.
- Performance retains plan counts, live metrics, results and Export. CLI scheduling and
  measurement validity rules remain unchanged. The [guide](../guides/gpu-debugging.md#measure-visibility-and-submission)
  owns current operation.

## Native-window corrections

Detached-window interaction exposed an actual GPU lifetime race in the maintained Dear ImGui
Metal4 backend. RenderDrawData returned its vertex/index uploads directly to the reusable slot
cache, so a later native window could overwrite those bytes before the main window's submitted
GPU reads completed. The correction retains uploads in per-slot `usedBuffers` and returns them
to the reusable cache only on slot revisit. The platform event wait and the application's main-frame
pacing protect reuse/eviction; ownership transfers before clearing the used list.
The maintained `Tools/Patches/imgui-metal4-remove-texture.patch` carries this backend correction.

Performance's explicit focus path also treats SDL3 ImGui `PlatformHandle` as an `SDL_WindowID`,
resolves it with `SDL_GetWindowFromID`, and restores the native window only if minimized before
raising it. Ordinary frame updates do not raise or restore the window.

### Full GPU validation and preserved failures

The direct `[gpu]` suite passed 199 cases / 793,279 assertions under `MTL_DEBUG_LAYER=1` in
`gpu-validation-isolated.log`. This pass requires the documented M7.1/M7.2 Time Profiler tracing
isolation: a profiler attached to a task-owned idle sleep temporarily displaced background
Metal tracing. It did not disable Metal API validation. The final test environment had no
`DYLD_INSERT_LIBRARIES`; no exception suppression was used to obtain the pass.

`gpu-validation-isolation-record.json` records the exact Tests hash and commands, tracing state
before/during/after, the successful test exit, and cleanup. `MTLTraceEnabled` was false during
the run and returned to its original true state after cleanup; the profiler and task-owned sleep
were stopped. This is an environment prerequisite for the validated result, not an unqualified
pass under the original background tracing state.

The initial `xmake test` wrapper failed without useful details. Unisolated diagnosis then reproduced
the existing `NSInvalidArgumentException` involving `MTL4DebugComputeCommandEncoder globalTraceObjectID`
on both the prior baseline and current binary. `gpu-validation.log`, `vendor-parent-exception.log`,
`vendor-current-exception.log` and `vendor-exception-debugger.log` retain these failures separately.

`01-console-only.jpg` through `05-show-results.jpg`, `App-before-flicker-fix` and
`editor-before-flicker-fix.log` preserve the initial UI attempt before the buffer-lifetime fix.
Those screenshots are retained but not accepted as post-fix evidence. The earlier
[transport screenshots](m7.2-editor-transport.md#verification-and-evidence) likewise retain their
historical layout. Original and revised image-gate failures remain unchanged. Integration is
separately authorized by the owner's manual-review decision linked above, not inferred from these checks.
