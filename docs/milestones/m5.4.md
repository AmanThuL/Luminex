# M5.4 — Render Graph Node View

**Status**: Implemented (2026-09-04)

M5.4 turned the Render Graph panel from a rolling list into a canvas-first node view of the exact
newest retired compiled frame, without changing render-graph execution, image formation, or RHI
semantics. `GraphNodeModel` (`Source/App/GraphNodeModel.h`) is a pure, ImGui-free shaping of a
`CompiledFrameRecord` into nodes, pins, execution edges, alias links, and a deterministic layered
layout: every declared pass in declaration order, then every declared sink; pins for each distinct
`(resource, version)` a pass reads or writes; an edge from a producing pass's output pin to a
consuming pass's input pin for every version above zero; culled passes keeping their declarations
but no pins or edges, placed in an edgeless band below the scheduled graph; alias links drawn apart
from execution edges, one per `aliasedFrom` transition. A `shapeSignature` over node identities,
pins, edges, and alias links (never timings, frame ID, or byte offsets) tells the panel when the
drawn shape has actually changed.

The panel (`Source/App/Panels/RenderGraphPanel.h/.cpp`) draws that model on a vendored, patched
`imgui-node-editor` canvas (ADR 0011): nodes colored by `PassKind`, sinks amber with an arrowhead,
culled nodes desaturated with a hand-drawn dashed border, alias links as dashed lines apart from
the editor's own solid execution-edge links. A selection-scoped details pane on the right replaces
the M5.3 list outright — nothing → a hint and the frame's transient totals; a scheduled pass →
schedule position, kind, label, GPU time, uses, barriers, and live transients; a culled pass → its
cull reason and declared uses; a sink → its kind, rooted resource/version, and producing pass. The
layout reapplies only when `shapeSignature` changes or Reset Layout is pressed; dragged node
positions are otherwise session state, kept across frames and lost on process exit.
`RenderGraphPanelState` (node-editor context, applied signature, selected node) is owned by
`EditorShell` and released before `ImGui::DestroyContext()`, alongside the shell's other panel
state.

## Evidence

**Automated**, on Metal 4 Apple Silicon (Apple M3 Max, macOS 26.5.2):

- `xmake test Tests/unit` and `MTL_DEBUG_LAYER=1 xmake test Tests/gpu` both 100% pass, including
  eight new `AppGraphNodeModelTests` cases (244 assertions covering execution edges, version-0
  imports, sink edges, the culled band, alias links, layout stability across two independent
  compiles, the shape signature, and node-fact agreement with `GraphInspectorModel`) and an
  extension to the existing `[gpu]` inspector test: for one real compiled frame, `GraphNodeModel`
  agrees with the dump and the list model on frame ID, scheduled label order, and the culled label
  set, and no edge names a culled pass (45 assertions in that case).
- The frozen `[checkpoint-a]` filter passed unchanged under `MTL_DEBUG_LAYER=1`: 1,856 assertions
  in 19 test cases — identical to the M5.3 baseline, confirming the node view added no portability
  surface.
- `xmake format --check` and `xmake policy` clean.
- `LMX_MAX_FRAMES=120 MTL_DEBUG_LAYER=1 xmake run App` presented 120 frames, skipped 0, with no
  Metal validation diagnostics.
- Fixed-camera 1280×720 offscreen screenshots of Sponza, Damaged Helmet, and MaterialLab at the tip
  are byte-identical (SHA-256) to the fork-point baseline: renderer output is unchanged.
- A headless smoke (Task 1, throwaway, reverted before commit) confirmed the vendored library
  renders cleanly and the app stays validation-clean over 120 frames with the panel visible; a
  second headless smoke (Task 3, throwaway, reverted before commit) injected synthetic ImGui mouse
  events inside `ed::Begin`/`ed::End` and confirmed a node's canvas position moves under a
  press/move/release sequence, an empty-canvas click clears the selection, and a click on the node
  sets it — both under `MTL_DEBUG_LAYER=1` with no validation output. A third throwaway smoke
  toggled bloom and automatic exposure at runtime and logged exactly one relayout on the first
  retired frame carrying each new shape, and none on an unchanged shape.

**Manual visual QA** is left for the operator: default lower-dock-height readability of the canvas
and details pane, that the culled band and alias-link styling read as visually distinct from
scheduled nodes and execution edges, that the details pane's fields agree with a `Dump frame` text
dump for a selected pass, that closing and reopening the panel keeps the node-editor context (zoom,
pan, dragged positions), and that Reset Layout visibly restores the deterministic positions.

## Deliberate limits and deviations

- **The overlay draw list deviates from the design spec.** The design named
  `ed::GetHintForegroundDrawList()` for the culled-border, sink-arrowhead, and alias-link overlays;
  that API asserts without a live group-node hint (`IM_ASSERT(nullptr != m_CurrentNode)`) and its
  channel is not canvas-transformed. The panel draws them on `ed::GetNodeBackgroundDrawList(id)`
  instead, which has no such precondition and is canvas-transformed like the rest of the node's
  geometry. The consequence: overlays land behind node bodies, so a very long alias link could in
  principle pass under an intervening node — not observed in any shipped scene.
- **Alias links have no runtime evidence.** Every shipped scene's graph transients have
  lifetime-overlapping spans, so the compiler never emits an `aliasedFrom` transition and
  `GraphNodeModel::aliasLinks` is empty in every observed frame (confirmed with `LMX_GRAPH_DUMP`:
  zero `alias-of`, `saved 0`). The alias-link derivation and its dashed-line drawing code are
  unit-tested against a synthetic `TransientPool` fixture, but neither has been seen on screen.
- **Drag and click-select were verified by a headless ImGui-event-injected smoke, not by a human**
  (see Evidence). The interaction code itself is unmodified upstream `imgui-node-editor` logic.
- **Shape-change relayout was exercised by writing `EditorRenderSettings` fields directly**, the
  same fields the Inspector's Rendering checkboxes write, rather than by driving the checkboxes
  themselves through the UI.
- **Visual sign-off is entirely left to the operator's manual QA pass** (see above); every
  automated check above is log- or hash-based, not a human look at the canvas.
- **The roadmap's M5.4 entry was amended in the design commit before implementation began**: the
  M5.3 list is not a preserved alternate view toggled alongside the canvas — it was replaced
  outright by the selection-scoped details pane, and the exit gate reads "node view and dump
  identify the same frame" rather than requiring the list's continued existence.
- **A pre-existing double-shutdown in `EditorShell::create`'s initial-scene-failure path**,
  recorded in the M5.3 milestone, still stands. It predates M5.3 and M5.4 alike and remains outside
  either milestone's scope.
