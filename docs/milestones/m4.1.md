# M4.1 — RHI Boundary Cleanup

**Status**: Implemented (2026-08-10)

M4.1 preserved the M4 renderer while turning the RHI into a repository-root component. Its public
surface now lives under `RHI/Include/RHI/`, its shared implementation under `RHI/Source/`, and its
Metal 4 backend under `RHI/Backends/Metal4/Source/`. `RHI/xmake.lua` owns the component build, keeps
metal-cpp and backend headers private, and exposes Dear ImGui integration through the separate
`RHIMetal4ImGui` target and its own integration include tree. Existing `RHI/...` includes,
namespaces, signatures, and runtime failure behavior remain unchanged.

RHI failures remain domain-owned. `RHI/Result.h` now carries `ErrorCode`, `Error`, and `Result<T>` as
a self-contained public contract; Engine assets, Render Graph declarations, and App options retain
their more specific error types instead of collapsing into a shared cross-domain error.

Every project-owned C++ source and header under `Source/` and `RHI/` now begins with a checked
120-character file envelope. Public and protected header APIs use Doxygen contracts, while private
implementation comments retain the existing sparse function-boundary style. Policy uses Clang's AST
and parsed comments to distinguish public API from private declarations, and independently compiles
each core RHI header to prevent accidental transitive, Metal, or ImGui dependencies.

## Evidence

- `xmake format --check`, `xmake policy`, and `xmake` passed. Policy checked all 62 owned C++ files,
  parsed public API documentation through the compilation database, and compiled all five core RHI
  headers independently. The optional ImGui extension compiled with its owning adapter target.
- `xmake test Tests/unit` and the complete `xmake test` suite passed.
- `MTL_DEBUG_LAYER=1 xmake test Tests/gpu` passed on an Apple M3 Max with Metal API validation.
- Offscreen Sponza, Damaged Helmet, and MaterialLab runs each produced a 1280x720 screenshot; visual
  review showed the maintained M4 scenes and diagnostics rendering normally.
- The core `RHI` target built without ImGui, while App built through the explicit
  `RHIMetal4ImGui` dependency. Normal RHI consumers inherited only `RHI/Include`.
- Three forced RHI rebuilds measured 4.05, 4.10, and 4.07 seconds. That scale did not justify a
  target-private precompiled header, so explicit self-contained includes remain the maintained path.

## Deliberate limits

The root component is extraction-ready, not standalone: its implementation still uses Luminex Core
logging and assertions, and capture/debug tooling remains integrated with the host repository. The
Metal 4 capture and ImGui headers are explicit backend extensions rather than part of the neutral
surface. Publishing a separate repository would still need a diagnostics integration contract,
package metadata, and ownership decisions for conformance tests. Caller-facing interface experiments
remain reserved for M5.1; this maintenance boundary did not pre-empt them.
