# M5 — Execution Substrate and Observability

**Status**: Implemented (2026-08-11)

M5 gave the RHI and render graph a compute/copy/barrier execution substrate, made the compiled
frame observable, and exercised both with histogram exposure and a bloom chain, while preserving
the deterministic manual-exposure image M4.1 shipped.

The RHI gained `ComputePipeline`/`ComputePipelineDesc`, a compute pass scope
(`beginComputePass`/`bindComputePipeline`/`bindStorageBuffer`/`bindStorageTexture`/`dispatch`), a
copy pass scope (`beginCopyPass`/`copyBuffer`/`copyBufferToTexture`/`copyTextureToBuffer`/
`copyTexture`/`fillBuffer`), and range-aware `textureBarrier`/`bufferBarrier` between passes.
`TextureSubresourceRange` and `TextureViewDesc` let a per-mip or per-layer bind, copy, or barrier
reach any subresource — sRGB/linear view reinterpretation is validated against the texture's
format family. `dispatchIndirect`, `drawIndirect`, and `drawIndexedIndirect` consume caller-filled
GPU buffers through `DispatchIndirectArgs`/`DrawIndirectArgs`/`DrawIndexedIndirectArgs`, whose
layout is verified against the vendored Metal 4 headers with `static_assert`s pinning size and
member offsets. Placement heaps (`Heap`/`HeapDesc`, `createPlacedTexture`/`createPlacedBuffer`)
place resources at explicit offsets with untracked hazard tracking, the substrate the render
graph's transient pool builds on.

`lmx::render::RenderGraph` declares raster, compute, and copy passes over per-subresource uses on
imported resources and on one-frame transients the graph itself creates and owns
(`createTexture`/`createBuffer`, ADR 0008). Dead-pass culling runs reverse reachability from
declared sinks (`exportTexture`/`exportBuffer`/`presentTexture`/`readbackTexture`/
`readbackBuffer`) only; a frame that roots nothing schedules nothing, and every declared pass —
scheduled or culled — is still validated. Barrier derivation covers read-after-write and
write-after-read at subresource-range granularity: a later read is skipped only when an earlier
transition's range provably encloses it, and a write only discharges the parts of a pending read it
actually overlaps. Transients whose lifetimes do not overlap alias into a `TransientPool` placement
heap — one per frame-in-flight slot, reused once the RHI's pacing has proved the previous occupant
of that slot retired — with a runtime pooling toggle that leaves the image unchanged. Every
compiled frame is captured in a `CompiledFrameRecord`: resources, sinks, passes with uses and cull
reasons, the proved schedule, derived transitions, transient lifetimes/placements, and memory
totals (requested, high-water, alias savings). `GraphDump.h` renders that record as deterministic
text (`LMX_GRAPH_DUMP=<absolute path>` for the first compiled frame of a run), and a read-only
editor "Render Graph" panel renders the same record live from the retained frame ring, plus a
button to dump the displayed frame on demand.

Histogram auto-exposure (Render Settings opt-in, off by default) builds a 256-bin log-luminance
histogram of pre-exposed scene color each frame, resolves a percentile-trimmed target exposure, and
feeds it back into the next frame's scene and sky shading through a persistent GPU-resident buffer
— no CPU readback, no `waitIdle`. Manual and auto-exposure shading run through separate compiled
pipelines (`ScenePass`/`Sky` vs. `ScenePassAuto`/`SkyAuto`) so the manual path's compiled output is
structurally unaffected by auto-exposure's existence, not merely by an unused runtime branch. Reset
follows four rules (first frame, scene switch, enable, resize) implemented as one pure function.
Bloom (Render Settings toggle, on by default) is a threshold/downsample/upsample chain over two
graph-owned transients, 4 levels deep where the target extent supports it, composited before the
display tone map; disabled bloom contributes exactly zero.

## Deliberate limits

**Aliasing is resource-identical only.** Two transients share bytes only when every descriptor axis
matches exactly — kind, format, extent, mip count, usage, size, and alignment. The first consumers
that benefit are ping-pong and chain-scratch shapes; relaxing compatibility to place differing
layouts in shared bytes is a later decision (ADR 0008).

**Bloom uses two transient textures, not one.** The spec described a single graph-owned FP16
transient; accumulating the upsample chain in place would need one compute pass to read and write
the same mip in the same dispatch, which the graph's disjoint-range rule forbids. Two textures route
every upsample step's reads through disjoint resources instead.

**Manual and auto-exposure shaders are kept in sync by convention, not tooling.** `ScenePassAuto`/
`SkyAuto` are near-complete copies of `ScenePass`/`Sky`, diverging in the one line that reads the
exposure buffer instead of the manual uniform — structurally necessary to keep the manual path's
compiled output unperturbed, but a future change to shared lighting logic has to be hand-applied to
both files.

**Auto-exposure's clear color carries a pre-exposure bias for skyless views.** The editor's clear
color is decoded once and pre-exposed at scene-build time; in auto mode that pre-exposure uses the
frame's evolving target rather than a fixed manual value. No shipped scene renders a skyless view,
so the bias is unreachable today.

**Barrier derivation covers reads and writes; write-after-write still rests on the version chain.**
Two passes writing one resource are ordered by the version chain, not by an explicit barrier — the
pre-existing M4 contract, unchanged by M5's read-after-write and write-after-read additions.

**Exposure convergence is instantaneous, not adapted.** The target exposure each frame is this
frame's histogram resolve with no temporal smoothing; adaptation speed is M6's temporal-foundation
scope.

**The storage-hazard conformance cases prove sufficiency, not necessity.** Every case in the frozen
suite verifies that the declared barrier produces the correct result; none proves the result would
be wrong without it, because this hardware has been observed to order some of these accesses
correctly on its own. ADR 0009 records this as an accepted, currently unclosed gap in what
checkpoint A can promise a less strictly-ordered backend.
