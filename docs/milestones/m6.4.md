# M6.4 — MetalFX temporal adapter

**Status**: In progress

The capability-selected vendor reconstruction is implemented on the feature branch; native TAA
remains the default and reference. [ADR 0017](../decisions/0017-vendor-reconstruction-capability.md)
owns the contract and the [amended design](../specs/2026-09-12-m6.4-metalfx-temporal-adapter-design.md)
records changes driven by the initial probe and frozen scenarios. Automated evidence is complete;
owner visual QA and opaque-encoder inspection remain open before closure.

## Verified implementation

- Neutral device capability/scaler/encode API, external graph passes, translated motion/reactivity
  and reciprocal exposure, independent vendor reset with preserved engine histories.
- Capability and creation-failure fallback, retry after output resize, fixed-capacity dynamic input
  rectangle; optional command-line and Inspector selection.
- Engine motion/error/history diagnostics; native-only internals disabled under vendor mode.
- Fence handoff into opaque encoders, private output and CPU-readable output-copy adaptation,
  per-slot retained scaler state, named inputs and timed external operation.

## Backend probe

Apple reports scale bounds 1–3 (output/input); the neutral capability reports 1/3–1 (input/output).
A barrier-only carrier triggered `_outputTextureBarrierStages not set`; the public fence path
completed cleanly. Required usages are read for inputs and read/write/render-target for output;
a shared output triggered the private-storage assertion. No private MetalFX allocation required
application residency registration. Constant half-float input 0.5 produced approximately
(0.5,0.5,0.5,1) at the full output extent.

Synchronous creation: first observed 589.030 ms, followed by separate-process observations
154.626, 155.161, 160.212 and 164.605 ms. These are cached-state-dependent observations, not a
performance claim. Experimental source remains outside the repository.

## Runtime and capture

Two TemporalLab runs use `--temporal metalfx`, dynamic resolution and API validation. Each presents
240 frames with zero skipped frames and no validation errors. At a 5 ms GPU budget the controller
stays at scale 1; at 1 ms it steps 1 → 0.5 in ten bounded 0.05 steps and holds. These demonstrate
controller operation, not a frame-rate or relative-performance claim.

A frame-32 capture (`LMX_CAPTURE_AT_FRAME=32`, `LMX_MAX_FRAMES=42`) completes with 42 presented
frames. The graph dump declares the pack and external passes and all five inputs. The capture
stream contains `lmx.pass.temporal.vendor.pack`, `lmx.pass.temporal.vendor`,
`lmx.temporal.vendor.scaler MetalFX Temporal` and the handoff label between packing and bloom;
the schema/stream identify all three packed resources. Stream SHA-256:
`1ad0641177bf26a5e50c83cd2f81abe5fa798e39c71f67c2f6003f28cf6d9aed`.

The dump completes but cannot decode individual MetalFX internal encoders or transient heap image
contents. Registry category strings are not evidence of executed algorithms. Its two legacy error
checks expect the obsolete scene-color label and shadow transform convention; nine resource-format
warnings also remain. These are tool limitations, separately recorded from the clean runtime API
validation. Xcode inspection of opaque work remains pending; the capture gate is not claimed closed.

A Sponza editor smoke run visibly renders the vendor output and lists both vendor pass timings;
it closes normally after 5,355 presented frames with zero skips. UI automation reports
`noWindowsAvailable` on coordinate interaction despite successful snapshots, so this does not
establish manual switching, disabled-menu behavior or motion quality.

Raw images, old executable, logs, capture, graph dump and comparison JSON are retained outside the
source tree in `~/Documents/Luminex-evidence/m6.4/`. The initial standalone probe is alongside them
in `~/Documents/Luminex-evidence/m6.4-a0/`. The recorded commands and test fixtures reproduce the
checks; no raw evidence or experimental source is included in the production commit.

## Known limits and review

The private output scratch is allocated per scaler even when the private editor output uses the
direct path, so initialization remains a recoverable allocation boundary. Its memory and opaque
vendor history are additional to the engine history and graph transient totals. Integer content
rounding can differ from output aspect by less than a pixel. The fake declaration golden uses
synthetic allocation sizes; native GPU goldens independently pin actual device allocations.

Owner QA remains: switch Native TAA ↔ MetalFX on Sponza at rest/in motion, review effective status,
the external graph card and the three disabled native-only debug views. Main remains unchanged
until the single squash pull request is accepted.
