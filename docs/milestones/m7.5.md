## Objective and baseline

The implementation builds on [M7.4](m7.4.md), retaining its [validation limits](m7.4-validation.md).
Three directional lights remain in the 400-byte `PassUniforms`, with ambient and emissive inside
the single `preExposure` multiply. Only light 0 casts shadows. No depth prepass is added: colour,
reversed infinite-far `D32Float` depth, motion and reactive share the jittered scene pass.

This slice adds point and spot lights with defined units and attenuation, a direct-loop reference
path, and a clustered Forward+ path over compact per-froxel lists built on the GPU. Two claims:

- **The light model is one function.** Both paths call the same `ComputePunctualLight` inside the
  same loop body, so they can differ only in which light indices they visit.
- **The cluster lists are lossless.** Attenuation reaches exactly zero at `range`, so a
  conservative list drops only exact-zero terms. Losslessness is proven by integer oracles that
  floating-point order, jitter and temporal history cannot disturb; image equality is gated only
  where it holds by construction.

Materials, pre-exposure, masked coverage, the motion convention, the display boundary, the M7.1
identity rules, the M7.2–M7.4 visibility, row, slot and occlusion contracts and the three
directional lights are unchanged. A scene with zero local lights imports nothing new and declares
no new pass, so the default goldens do not change.

## Implemented behavior

### Light model

`Source/Render/LocalLight.h` defines the CPU light: `type` (`Point`, `Spot`), world position,
linear-RGB `colour`, scalar `intensity`, `range` in metres, and for spots a unit direction of ray
travel with `innerCone` and `outerCone` half-angles (`0 ≤ inner < outer ≤ 89°`). `range` is
mandatory, finite and positive; creation rejects anything else with a `Result` error.

- **Units.** A point light of intensity I at distance 1 m and normal incidence produces exactly
  the response of a directional light whose `strength` is `colour × I`. This anchors local lights
  to the existing relative scale and is the candela–lux relation of `KHR_lights_punctual`, so a
  later glTF import maps without conversion. Absolute photometric calibration is not claimed.
- **Attenuation.** `window(d) / max(d², (0.01 m)²)`, `window(d) = saturate(1 − (d/range)⁴)²`:
  the glTF/UE/Frostbite form, exactly zero for `d ≥ range`.
- **Cone.** `saturate(cosθ × spotScale + spotOffset)²` with `spotScale = 1 / max(cosInner −
  cosOuter, 1e-4)` and `spotOffset = −cosOuter × spotScale`. A point light stores scale 0 and
  offset 1, so one expression serves both types and the shader never branches on type.
- **Shader.** `ComputePunctualLight` joins `Shaders/Modules/Lighting.slang` and shares the BRDF
  core with `ComputeDirectionalLight`. It returns exact zero through one ordered early-out when
  `d ≥ range`, the cone term is zero, or `N·L ≤ 0`. `Source/Render/LocalLightMath.h` is its CPU
  mirror for tests. The local sum is added after the three directional lights and before ambient
  and emissive, inside the single `preExposure` multiply. Local lights cast no shadow and the
  shadow passes are untouched.
- **ADR.** [ADR 0023](../decisions/0023-local-light-and-cluster-contract.md) records the units,
  attenuation, row and cluster contract, accepted on 2026-09-19 with the follow-up amendment.

### Light table

A sixth paced table, `lmx.scene.lights`, follows the M7.1 recipe: generational `LightId`, stable
row slots across removal and reorder, memcmp dirty rows written only into the paced slot, capacity
doubling with retirement at lastFrame + 3, and `kMaxLocalLights = 4096`. `LightRow` is 64 bytes
with `static_assert` offsets and a Slang mirror, and joins the `SceneTableAbi` oracle:

| Offset | Field | Meaning |
|---|---|---|
| 0 | `position.xyz`, `range` | world metres; `range = 0` marks a free slot |
| 16 | `strength.rgb`, `spotScale` | `colour × intensity`, decoded once at build |
| 32 | `direction.xyz`, `spotOffset` | unit ray-travel direction |
| 48 | `boundCentre.xyz`, `boundRadius` | CPU-computed world bounding sphere |

The bounding sphere is the range sphere for a point light and the standard tight cone sphere for
a spot (`outer ≤ 45°`: centre `position + direction × range / (2 cos outer)`, that radius;
otherwise the range sphere). `boundRadius` is inflated by the factor `1 + 2⁻¹⁰`, fixed here, so
all trigonometry stays on the CPU. A free slot has radius 0, is never assigned, and early-outs in
the direct loop. Light edits and motion do not advance `coverageEpoch`; occlusion history is
unaffected. `Scene::localLights()` exposes live IDs; `SceneView` borrows the buffer, high-water
`lightRowCount`, separate `liveLightCount` and CPU row span. Edits precede `prepareFrame`, with no
mutation until declaration. The Scene tables topic reports the sixth table.

### Paths and selection

`LocalLightMode { Off, Direct, Clustered }` is a runtime integer in a new `LocalLightParams`
frame-data block at b11, not a pipeline permutation, following the `ShadowFilter` precedent; the
scene pipeline count does not change and `PassUniforms` stays 400 bytes. All four scene entries
import one module, `Shaders/Modules/LocalLights.slang`, which holds a single loop over `i < n`
that adds `ComputePunctualLight(lights[index])`, where `index` is `list[offset + i]` when
clustered and `i` otherwise, and `n` is high-water `lightRowCount` (`Direct`), the cluster's count
(`Clustered`) or 0 (`Off`). Both paths share the loop body and accumulation site, and cluster
lists are ascending, so the nonzero terms and their order are identical by construction. The
scene pass uses read-only `bindBuffer` for b8 lights, b9 grid and b10 indices, with b11 params
through `bindFrameData`. Every slot stays bound; missing row/grid/index resources use stage-owned
fallbacks outside the graph per the M7.1 replay lesson. `lmx.scene.lights` is imported only when
`liveLightCount > 0`; retained high-water rows cannot keep the import alive after removals.

### Cluster grid

The grid is 16 × 9 × 24 = 3,456 froxels over the scene pass's active render rectangle, independent
of render extent and scale (ADR 0016). No floating-point arithmetic enters any lookup:

- **Tile.** `tile = (pixel − activeOrigin) × (16, 9) / activeExtent` in unsigned integers.
- **Slice.** The CPU uploads 25 reversed-Z boundary depths: slice 0 covers view distance `[near,
  0.3 m)`, slices 1–22 divide `[0.3 m, 100 m)` exponentially, slice 23 covers `[100 m, ∞)`. The
  fragment compares the rasterized `SV_Position.z` to the table; finite lights need no far plane.
- **Bounds.** Tile t owns pixel edges `[⌈t·W/16⌉, ⌈(t+1)·W/16⌉)` (9, H on y). A froxel's view-space
  AABB is the hull of that rectangle at the slice's two boundary depths under the inverse of the
  jittered projection that rasterizes the frame, so it covers each member pixel whole. Slice 23
  extends its near face to the light's far reach; pixel-less tiles and slices the near plane
  collapsed list nothing. `LightClusters.h` states the rules all four consumers share.

### `LightClusterStage`

`Source/Render/LightClusterStage.h` is public for fixtures and composed by `Renderer`, following
`GpuVisibility`: three paced slots of owned buffers, explicit capacities in its params, a
fixture-only capacity override, and counters read at retirement before slot reuse (frame − 3).
It declares only when the mode is `Clustered` and live lights exist:

| Pass | Work |
|---|---|
| `lmx.pass.light.reset` | copy pass; zero-fills the counter buffer |
| `lmx.pass.light.count` | per froxel: raw sphere–AABB hits against every addressable row |
| `lmx.pass.light.scan` | one thread: applies the cap, grants offsets, sums the counters |
| `lmx.pass.light.fill` | per froxel: repeats the test in ascending row order, writes its range |

This is the `(offset, count)` grid over one flat index list used by clustered shading since
Olsson et al. and by UE, DOOM 2016, Filament and HDRP; count → scan → fill replaces atomic
allocation so list order is deterministic, as M7.3's classify/scan/emit did. The
`Shaders/LightCluster*.slang` kernels and the CPU mirror `Source/Render/LightClusters.h` hold one
ordered fp32 sequence: the prefix joins the safe-math shader set in `xmake/shaders.lua` and the
backend, and the mirror's unit disables contraction. Scene-pass shaders keep their math mode.

- **Records and capacities.** A grid record is `offset` u32 and `count` u32 with bit 31 =
  `truncated` (27 KiB per paced slot); an index entry is a u32 row. `kMaxLightsPerCluster = 128`
  and the global index capacity is 65,536 entries (256 KiB per slot); both are fixed constants.
- **Overflow policy.** A froxel keeps its lowest row indices up to the per-cluster cap. The scan
  grants ranges in froxel-index order; the first froxel that does not fit is truncated to the
  remaining entries and every later froxel gets count 0. Each affected record carries
  `truncated`. Counters (candidates, assigned, dropped per-cluster, dropped global, truncated
  froxels, maximum count) reconcile as assigned + dropped = candidates. No write can leave its
  range. Overflow darkens deterministically, never corrupts, and is always visible in the
  counters, an immediate Inspector warning and the `overflow` view.

### Diagnostic views and checks

`--light-view <off|count|overflow|missed>` follows the `--hzb-level` shape: a `SceneView` field, a
lazily created pipeline in `Shaders/LightDebugView.slang`, and one raster pass
`lmx.pass.light.debug` over the display output that loads scene depth and reads the lights, grid
and list. It requires `Clustered`, conflicts with the temporal and HZB views, and needs
`--unscored` under `--measure`. Zero-live scenes keep Final with an unavailable-view explanation.

- `count` maps the pixel's froxel count through a fixed legend; `overflow` paints truncated
  froxels magenta over a dimmed frame.
- `missed` is the **missed-light oracle**. For each non-sky pixel it reconstructs the world
  position from the loaded depth, evaluates the *reach* predicate (`d < range` and cone term > 0,
  ignoring the normal) for every live row, and merge-walks the pixel's ascending list. A reaching
  light absent from the list paints the pixel pure red, or pure yellow when the froxel's record
  is `truncated`; otherwise pure black. Overflow therefore never masquerades as a culling defect.
- `--light-check` compares the retired GPU grid and list with `LightClusters.h` evaluated on the
  same rows, params and capacities and requires exact equality; it is unscored and reports to the
  console and Inspector, as `--classify-check` does.

### Content, playback, CLI, editor and measurement

- **LightLab.** The eighth catalog scene, procedural `light-lab`: a matte floor, a deterministic
  field of pillars and spheres spanning the material range, a 12-second camera rail, and
  `--lab-lights <n>` (default 256, 1–4096) lights on a jittered grid, one in four a spot. Range
  scales with `1/√n` so density stays constant and every n is overflow-free, pinned by a CPU test
  through the mirror. One light in four orbits. `--lab-light-pile <p>` (default 0, n + p ≤ 4096)
  stacks p lights at one point to force visible overflow. Both flags require `--scene light-lab`.
- **Moving lights.** `asset::SceneAnimation` gains a closed-form `LightOrbitTrack` (centre, axis,
  radius, phase, period) over lights authored before `finalize`; runtime lights are static.
  Playback moves only position: first Play captures it, Stop restores it and leaves other light
  edits alone, and Step advances 1/60 s.
- **Sponza rig.** `Source/Scene/SponzaLightRig.cpp` authors at most 32 deterministic point and
  spot lights from constants. `--local-light-rig <on|off>` (default `off`, Sponza only) and an
  Inspector toggle add and remove them at runtime through `LightId`s. With the rig off the scene
  bytes and images are unchanged. glTF `KHR_lights_punctual` import is deferred.
- **CLI and editor.** `--local-lights <off|direct|clustered>` defaults to `Clustered` under the
  correctness rule below; zero-live frames are effectively Off. A
  `Lighting` Rendering topic holds the mode, capacities, view selector, rig toggle and coherent
  250 ms readings of the counters and `lmx.pass.light.*` times, with immediate overflow and check
  warnings and a scoped Reset. Hierarchy gains a collapsible, clipped `Local lights` group; a
  selected light edits colour, intensity, range, cone and position with per-light reset keyed by
  `LightId`. Directional-light subjects are unchanged; formatting stays CPU-testable AppModel logic.
- **Measurement.** The report moves to schema version 4: local-light mode, live lights, lab
  plan fields, cluster counters, list bytes, and `lightingGpuMs` as the sum of matched
  `lmx.pass.light.*` timings, reported apart from the scene pass.

## Verification plan

The frozen families remain separate; results and retained failures are in the [validation record](m7.5-validation.md).

### 1. Light model

CPU tests pin the unit identity against `ComputeDirectionalLight`'s mirror, exact zero at and
beyond `range`, the distance floor, cone endpoints, the point-as-degenerate-spot encoding, the
bounding spheres and creation errors. A GPU function oracle under `[gpu][light]` evaluates
`ComputePunctualLight` on a fixed sample table and matches the CPU mirror within 1e-5 relative; comparison/outside-cone zeros stay exact,
while fast-math cone-edge leakage is bounded. `LightRow` passes the ABI oracle, and table fixtures repeat the M7.1
update, remove/reuse, growth and three-frame-overlap cases for lights.

### 2. Lossless lists

- **Missed-light oracle (gate).** Zero red pixels in every captured frame of: LightLab at n = 64,
  1,024 and 4,096 over the 12-second rail with lights orbiting, at all five reconstruction cells
  (`off`, `taa` 1.0/0.5, `metalfx` 1.0/0.5), one run with dynamic resolution changing the active
  extent; and Sponza with the rig on at the five cells. Yellow pixels must be zero in these
  overflow-free runs. The count is an integer property of each frame's own depth, lists and rows.
- **List parity (gate).** `--light-check` reports exact GPU/mirror equality on every frame of the
  same runs and in fixtures with probes one guard inside and outside a froxel face, a slice
  boundary, the tile edge of an odd active extent and the open last slice.
- **Independent conservativeness.** A CPU property test, in double precision and sharing no code
  with the mirror, samples points inside froxels and requires every reaching light to be listed.

### 3. Image agreement

- **Scoped exact gate.** `Direct` versus `Clustered` in the same binary requires exact BMP
  SHA-256 equality with `--temporal off` at render scale 1.0: LightLab at the three n (frame 32
  and a 16-frame moving sequence) and Sponza with the rig. A `Direct`/`Direct` repeat of each case
  is captured beside it as the null control and reported; it does not rescue a failed case.
- **Reported, not gated.** The four temporal cells of the same cases report differing pixels,
  pixels over 8/255, maximum delta, mean absolute delta and LDR-FLIP mean/p95, each beside its
  same-path null control. No threshold applies; M7.2's calibrated envelope is not revived.

### 4. Bounded overflow

Capacity-override fixtures and `--lab-light-pile` runs require: counters reconcile exactly; the
kept set is the lowest row indices and the truncated froxels are those the policy names, equal to
the mirror; repeated runs agree; the `overflow` view marks exactly the truncated froxels; no
Metal validation message appears; and lights moving through a saturated froxel never crash,
write out of range or lose a non-truncated froxel's light (missed oracle red = 0).

### 5. Zero-light preservation

Default goldens are unchanged. Parent M7.4 versus candidate on the fifteen-image matrix uses the
M7.1 criteria as recorded, including the scoped `vendor-quantization-v1` profile, with same-binary
null controls captured for every cell. `--local-lights` values must not change a zero-light image
in the same binary (exact, fifteen cells).

### 6. Cost

One paired collection on the frozen device: `Direct` versus `Clustered` in the same frozen release
binary on LightLab at n = 64, 256, 1,024 and 4,096 and Sponza with the rig, 12 alternating AB/BA
process pairs, W32/N256, 10,000-resample bootstrap 95% intervals with the established seed; plus
parent versus candidate on the frozen six workloads to disclose zero-light overhead. Cells report
`lightingGpuMs`, scene-pass and full-frame GPU time, CPU work, counters and list memory. Every
cell is reported; the numbers are diagnostics and select nothing.

### Rules fixed before measurement

- A failing gate is recorded as a failure with its numbers. Constants, guards and thresholds in
  this document are not changed after measurement; any exception is the owner's explicit decision,
  and a broader pass never relabels a narrower failure.
- **Default rule.** If families 2 and 3's gates all pass, `Clustered` is the default for scenes
  with local lights; otherwise the default is `Direct` and the record says why. The rule is
  correctness-based; no timing enters it.
- The inherited Sponza Native-TAA 0.5 divergence and the recorded same-path variability are
  neither an excuse nor an explanation for a failure here. GPU capturability is a separate gate:
  a labelled `lmx.pass.light.*` capture is requested and a tool limitation is recorded as such.
- **Evidence.** Raw evidence lives in `../Luminex-evidence/m7.5-<date>/` with the parent/candidate
  layout and shared comparator schema; every attempt is retained. Shaded sequences save at most
  64 frames per run; missed-oracle sequences save every frame as three-colour PNGs of kilobytes.
  The live bundle is budgeted at 15 GB, and exceeding it stops collection for an owner decision
  rather than deleting attempts. An independent auditor with self-tests re-derives every gate
  from raw JSON and images, and harness failures are recorded apart from renderer failures.

### Regression inventory

Build, `xmake test`, the GPU suite under `MTL_DEBUG_LAYER=1`, format, `xmake policy` with the
module, header, comment and shader-import checks, and the unchanged `[checkpoint-a]` filter pass.
`CaptureSchemaTests` pins schema 4. New goldens pin the `Direct` and `Clustered` LightLab frames'

## Known limits and design boundaries

- Local lights cast no shadows and light only opaque and masked surfaces; shadows and
  transparency are M8. Area lights, stochastic direct lighting and glTF light import are deferred.
- `Direct` is an unbounded O(pixels × lights) reference, not a production path. Assignment is
  O(froxels × lights) per frame with no light BVH, tile prepass, depth-bounds refinement or
  temporal reuse; these wait for measured need. No depth prepass is added.
- Capacities, the grid shape and the 0.3 m and 100 m slice bounds are fixed constants; overflow
  darkens the affected froxels by design. The unit scale is relative, not photometric.
- The missed-light view reconstructs position from depth, while shading interpolates it; the
  oracle proves list coverage, and the scoped exact gate separately proves shaded equality.
- Existing image-parity exceptions, failed gates and capture follow-ups from M6.4 through M7.4
  carry forward unchanged; this slice neither closes nor broadens them.
