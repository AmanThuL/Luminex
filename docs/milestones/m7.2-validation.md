# M7.2 — Implementation and Validation Record

**Status**: Implemented — owner review pending; exact-image gate failed

The [design](m7.2.md) was frozen at `598d9ec` over accepted M7.1 `acf82ed`.
The [implementation plan](../plans/2026-09-15-m7.2-cpu-visibility-indirect.md) preceded source edits.
Work remains on `codex/cpu-visibility-indirect`; neither main integration nor M7.3 is authorized
by this record. In particular, the original cull/off exact-image gate has two failures below.

## Implemented behavior and clarifications

- Mesh-local bounds and world bounds are canonical shared rows: MeshRow 48 B, InstanceRow 240 B.
  Selection and classification share the eight-corner Render helper; static rows still converge
  to zero writes. CPU classification retains every candidate, including rejected diagnostics.
- The scene uses five jittered reversed-infinite planes with the frozen 1e-3 world-unit guard.
  Shadows remain ViewUnculled. Default submission is indirect; direct and stable batched controls
  share the same b4 row-list shader contract. No RHI API or ICB was added.
- Renderer owns three paced row/argument buffer pairs. Combined scene and shadow capacity is twice
  the table instance capacity; old allocations survive through last prepared frame + 3. GPU tests
  exercise active old buffers across growth and four overlapping frames without waitIdle.
- VisibilityLab N includes its five boundary probes. Two meshes and four materials cover opaque,
  mask and two-sided variants; two materials are masked. The deterministic 12-second rail and
  N1024/16384/65536 workloads use the same scene and renderer as ordinary editor execution.
- Hierarchy prefixes [V]/[R]/[B] remain visible with long names. Selection diagnostics retain full
  generational identity and frame. A rejected selection uses an exact display passthrough, because
  the editor has already chosen its selection target before declaration; skipping all passes
  would leave the previous image in that target. No selected geometry is drawn in this case.
- MeasurementRun joins every CPU record to the same retired frame and expected pass inventory.
  Missing/duplicate frames, malformed provenance and incomplete reports fail explicitly. The
  paired collector also checks actual extents/reconstruction, instrumentation and command/byte
  fields, rejects duplicate selectors, and preserves every failed attempt.
- Measurement alone serializes retirement with waitIdle after submission, outside encoding time.
  The Device API exposes only its newest retired timing. This pre-collection decision prevents
  lost joins without adding an RHI API; it measures isolated frame costs, not overlapped throughput.
  Ordinary editor and capture scheduling retain their established behavior.

and identical count/byte sequences across repetitions; no attempt was retried or discarded.

`measurement-summary.md`. The frozen set has six workloads times cull/off,
indirect/direct and batched/direct. Every cell uses twelve fresh AB/BA pairs, W32/N256, 1280x720,

## Remaining review boundaries

- Owner manual review and exact-image failure disposition remain pending. M7.3 stays inactive.
- The indirect default is a transition contract, not a claimed speedup. Shadow culling, GPU
  classification, compaction, ICB, bindless textures and occlusion remain future work.
- Interactive exports are always unscored. Their plan is not a full snapshot of edited scene, exposure,
  bloom or temporal diagnostic settings; the frozen headless collector uses the declared defaults.
- Allocation failure returned by DrawSubmission is fatal at Renderer declaration, consistent with
  the existing declaration API; it does not silently switch submission modes.
- Earlier milestone exceptions and evidence limitations remain unchanged. This record grants no
  new image tolerance, no hardware portability conclusion and no performance adoption.
