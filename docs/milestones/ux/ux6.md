# UX6 — Scene Authoring

**Status**: Proposed

Drafted on 2026-10-02 from the owner's review of the editor after [UX5](ux5.md). Three requests
started it: lab content that the Hierarchy marks "not saved" should be saved; the colored axis
geometry beside the helmet should become a real transform gizmo; and each object should say whether
it may be moved, so an operator cannot rearrange a scene by accident. UX6 turns lab content into
saved scene content, gives every object an authored mobility, and adds a viewport transform gizmo.
[Part IV](../../roadmap/editor-experience.md#ux6--scene-authoring) owns the outcome and gates once
the owner accepts them; this record holds the proposed contract and the decisions still open.

**Placement (proposed):** [UX5](ux5.md) → **UX6** → N1. The accepted order has N1 next, so this
placement needs the owner's decision; UX6 has no step until then.

## Observed state before UX6

- A scene document holds no meshes. A node either references a fetched asset by `uri` and hash, or
  names a lab `generator` with integer parameters. Generators are C++ functions that append objects,
  materials, procedural textures, lights and tracks on every load.
- The Hierarchy labels every generated row "not saved". Edits to those rows last for the session,
  never mark the document dirty and are not exported. Imported source nodes save their pose and
  enabled state through `overrides`.
- The Inspector edits position, rotation and scale for every object, generated or imported, whenever
  no measurement runs. Nothing distinguishes an object meant to move from one that is scenery.
- MaterialLab's document sets `axisStation: 1`, which adds six cubes forming red, green and blue
  axis shafts and tips beside the helmet. They are ordinary scene objects: they take lighting, cast
  shadows, appear in captures and occupy six Hierarchy rows.
- Transform gizmos and viewport picking have been deferred since UX1; Undo/Redo is deferred too.
- `MotionClass` (`Rigid`, `Invalid`) says how a draw produces motion vectors. It carries no
  authoring meaning and no notion of "this object never moves".

| Lab | Generated content today | Count |
|---|---|---|
| MaterialLab | Sphere grid, color patches, gradient ramp, normal probe, depth probes, mip probe, axis station; three procedural textures | 25 spheres plus about 15 fixtures |
| TemporalLab | Floor, reference cube, rotating cube, orbit sphere, poles (baked 60 Hz rigid tracks); an emissive sign driven by an emissive step track; an invalid-motion cube; one checker texture | About a dozen |
| LightLab | Floor, eight pillars, eight spheres; `lights` point/spot lights with closed-form orbits and a `pile` | 17 objects; 256 lights by default, up to 4,096 |

## Proposed decisions

| Topic | Proposal |
|---|---|
| Saved form | Static lab content becomes a checked-in content asset, `Assets/Scenes/Content/<lab>.gltf` with its buffer and textures, referenced through the existing `asset` node. The scene document still holds no meshes |
| What stays generated | Populations sized by a parameter (VisibilityLab instances and occluders, LightLab lights and pile) and behavior with no glTF form (emissive step track, invalid-motion class, closed-form light orbits). The generator's parameters are the saved state |
| Generated rows | Relabeled "Generated by `<lab>`", grouped and collapsed, with a tooltip saying the population comes from the saved parameters. Generated objects stop being editable; generated lights keep today's session-only edits |
| Mobility | One authored value per object node, `static` or `movable`, saved in `LMX_scene`; absent means `static` |
| Static meaning | The pose is read-only in the Inspector, the gizmo and session commands. Enabled state stays editable |
| Changing mobility | An Inspector header control; the change is a document edit and marks the document dirty |
| Renderer meaning | None in UX6. The instance row ABI, `MotionClass` and every pass are unchanged |
| Gizmo | ImGuizmo, vendored and pinned like imgui-node-editor, drawn in the editor's UI layer over the viewport for the selected movable object |
| Axis station | Removed. The gizmo's axes show the helmet's orientation; the `axisStation` parameter retires |
| Delivery | One executor plan and one squash-merged pull request for all three slices, with one owned re-baseline |

Rejected for the saved form:

- **Meshes inside the scene document.** It reverses the UX3 contract that a document holds no
  meshes and puts geometry in the file that Save rewrites.
- **A named built-in shape per node** (`"shape": "sphere"` with inline material values). It adds a
  second mesh and material vocabulary that only Luminex reads, and generic glTF tools would show an
  empty scene.
- **Saving a per-object override list on the generator node.** It keeps the objects in C++ and
  stores edits keyed by generation order, which breaks when a generator changes.

## UX6.1 — Saved lab content

**Outcome:** opening MaterialLab shows named spheres and fixtures that are ordinary saved scene
content. No row in a catalog scene says "not saved" unless it is a generated light.

**Deliver:**

- A one-time exporter that writes each lab's static objects, materials and procedural textures to a
  content asset. Every generated object becomes one named asset node, so the Hierarchy shows one row
  per object and `overrides` saves its pose and enabled state. Vertex data, tangents and mip chains
  are written exactly as the generator produced them. The exporter is tagged and then deleted with
  the generator code it replaces, as UX3's exporter was.
- MaterialLab moves entirely to content and its generator retires. The axis station is not exported.
- LightLab's floor, pillars and spheres move to content; its lights, pile and orbits stay generated.
- TemporalLab's floor, cubes, orbit sphere and poles move to content with their rigid tracks as an
  asset clip, if the exporter reproduces every key; the emissive sign and the invalid-motion cube
  stay generated. If keys do not reproduce, TemporalLab stays generated and the record says so.
- VisibilityLab stays generated.
- Each document groups its Key, Fill and Rim directional lights under one `Lights` node, as local
  lights already sit under `Local Lights`. Roles, the shadow caster and light order are unchanged.
- Generated rows take the new label, grouping and tooltip. `--lab-instances`, `--lab-occluders`,
  `--lab-lights` and `--lab-light-pile` keep working.
- `Tools/Scenes/validate_documents.py` also validates the content assets and checks their buffers
  and textures against recorded hashes, since setup's pinned tree hash does not cover checked-in
  files.

**Exit gate:** the standing matrix (Sponza, MaterialLab, TemporalLab × five modes) is compared with
the parent and reported as measured, with no tolerance approved in advance; Sponza is expected to be
byte-identical; MaterialLab changes by the removed axis station and is re-baselined once with the
owner's acceptance; a pose edit on a former generated object survives save, relaunch and reload;
content assets pass the pinned glTF validator; lab CLI parameters produce the same populations and
counters as the parent.

## UX6.2 — Mobility

**Outcome:** a scene says which objects may move. An operator cannot change a static object's pose
through any editor route, and sees why.

**Deliver:**

- `mobility` on asset nodes and on per-source-node `overrides`, with `schemaVersion` 2. A schema 1
  document loads with every object static and keeps its saved poses. Animated source nodes take no
  mobility, as they take no pose override; setting one fails preflight with the JSON path.
- The six catalog documents author the Damaged Helmet as `movable` and nothing else.
- Inspector: a static object's Position, Rotation and Scale are read-only with the reason shown, and
  the header carries the mobility control. Hierarchy rows mark movable objects, the exception,
  instead of marking thousands of static ones.
- A Hierarchy row whose saved values differ from the document shows the operator mark, so an
  edited object can be found without opening each one; today only the root and the fields show it.
- `SceneSession` refuses a pose edit on a static object at the model level, so the Inspector, the
  gizmo and the session bridge share one rule. A session proposal that changes a static object's
  pose is refused with a named reason, as generated and animated transforms are today.
- A proposed ADR for the mobility value and the content-asset form, amending the still-Proposed
  [ADR 0028](../../decisions/0028-scene-document-contract.md).

**Exit gate:** unit tests cover the reader, writer, export and the model-level refusal; a schema 1
document loads, saves as schema 2 and reloads identically; changing mobility marks the document
dirty and survives relaunch; scene-only screenshots are byte-identical to UX6.1.

## UX6.3 — Transform gizmo

**Outcome:** an operator selects the helmet, drags a handle in the viewport and sees it move,
rotate or scale; the same drag on a static object is not offered.

**Deliver:**

- ImGuizmo fetched by `xmake setup` at a pinned commit with its license and provenance, compiled as
  its own static target and linked by App only, with its header confined to one translation unit. A
  maintained patch is added only if the pin does not build against the pinned Dear ImGui commit. A
  proposed ADR records the choice, following
  [ADR 0011](../../decisions/0011-vendored-imgui-node-editor.md).
- The gizmo appears for a selected, enabled, movable object when playback is stopped and no
  measurement runs. It edits through the same `SceneSession` call as the Inspector, so dirty state,
  save and reset behave identically.
- Move, Rotate and Scale modes and a World/Local toggle, in View > Gizmo and on the toolbar, with
  shortcuts that do nothing during text entry, popups or right-mouse look. Mode and space are
  session state; the workspace schema does not change.
- Escape during a drag restores the pose from the drag's start. The Inspector's reset to the
  authored pose stays the recovery after a drag, since Undo remains deferred.
- The gizmo is drawn with the unjittered editor camera in the UI layer. It never enters the scene
  target, temporal history, screenshots, sequences or scene-only GPU captures.
- An object with several material primitives moves as one, as it does in the Inspector.
- The scene-document and GPU-debugging guides, the App architecture page and `AGENTS.md`.

**Exit gate:** a gizmo drag and the equivalent Inspector edit export the same document bytes; with
the gizmo visible, a scene-only screenshot is byte-identical to one without it; the gizmo is absent
for static, generated, disabled and animation-owned objects and during playback and measurement;
the [completion gate](../../roadmap/editor-experience.md#completion-gate) tasks still pass; native
gestures that are not exercised are recorded as unverified.

## Boundaries and deferrals

Create, duplicate, delete and reparent; viewport picking; Undo/Redo; snapping and numeric drag
entry; multi-selection; gizmos for lights and cameras; importing an asset into an open scene. No
renderer feature consumes mobility. Mobility for lights is not introduced; lights stay editable as
they are. The workspace schema, capture manifest and measurement schema do not change. Showing
Sponza's 25 material primitives as child rows of their source node is a separate, smaller change
outside UX6.

## Risks and open points

- **Exactness through the loader.** Content now passes through the glTF loader instead of direct
  scene calls. Procedural textures, explicit mip chains, samplers and tangent handling may not
  round-trip bit for bit, and instance order changes. The exit gate reports the comparison as
  measured; a difference becomes part of the one re-baseline or fails the slice.
- **Projection convention.** ImGuizmo expects a conventional projection matrix, while the renderer
  uses reversed infinite Z. The gizmo needs its own finite projection built from the same camera;
  misalignment between handles and geometry is the failure to watch for.
- **Dependency risk.** ImGuizmo may not build against the pinned docking-branch commit without a
  patch. If it proves unusable, the fallback is a small `ImDrawList` gizmo limited to translation
  and one-axis rotation, and the record says so.
- **Protection is one click deep.** With the mobility control in the Inspector, an operator can
  unlock an object deliberately. The dirty marker and the save confirmation are the guard.
- **Hashes for checked-in content.** A document's asset hash covers the content `.gltf` only; the
  validation script closes the gap for buffers and textures.

Decisions for the owner before acceptance:

1. Placement: UX6 before N1, or after it.
2. Saved form: content assets as proposed, or meshes inside the scene document.
3. TemporalLab: move its rigid content as proposed, or leave the whole lab generated.
4. Whether a static object's enabled state stays editable.
5. Whether mobility changes in the Inspector, or only by editing the file.
6. Whether local lights also take mobility and a translate gizmo in this milestone.
7. Gizmo shortcuts: W/E/R as other editors use, given W and E already move the camera during
   right-mouse look.
