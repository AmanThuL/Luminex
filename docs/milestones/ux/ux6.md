# UX6 — Scene Authoring

**Status**: Implemented

Drafted on 2026-10-02 from the owner's review of the editor after [UX5](ux5.md), and revised on
2026-10-03 with the owner's answers to the seven decisions the draft left open. Three requests
started it: lab content that the Hierarchy marks "not saved" should be saved; the colored axis
geometry beside the helmet should become a real transform gizmo; and each object should say whether
it may be moved, so an operator cannot rearrange a scene by accident. UX6 saves lab objects in the
scene document, gives every object and light an authored mobility, and adds a viewport transform
gizmo. [Part IV](../../roadmap/editor-experience.md#ux6--scene-authoring) owns the outcome and gates
with execution authorized by the owner on 2026-10-03. Implementation is recorded in
[validation](ux6-validation.md); original parent parity is 10/15, accepted-reference parity 15/15
and LightLab 5/5. Native completion remains incomplete; separate milestone review and owner
acceptance are pending.

**Placement:** [UX5](ux5.md) → **UX6** → N1, by the owner's decision on 2026-10-03.

## Observed state before UX6

- A scene document holds no meshes. A node either references a fetched asset by `uri` and hash, or
  names a lab `generator` with integer parameters. Generators are C++ functions that append objects,
  materials, procedural textures, lights and tracks on every load; nothing else about that content
  is on disk.
- The Hierarchy labels every generated row "not saved". Edits to those rows last for the session,
  never mark the document dirty and are not exported. Imported source nodes save their pose and
  enabled state through `overrides`.
- The Inspector edits position, rotation and scale for every object, generated or imported, whenever
  no measurement runs. Nothing distinguishes an object meant to move from one that is scenery.
- MaterialLab's document sets `axisStation: 1`, which adds six cubes forming red, green and blue
  axis shafts and tips beside the helmet. They are ordinary scene objects: they take lighting, cast
  shadows, appear in captures and occupy six Hierarchy rows.
- Transform gizmos and viewport picking have been deferred since UX1; Undo/Redo is deferred too.
- `MotionClass` (`Rigid`, `Invalid`) says how a draw produces motion vectors. It carries no
  authoring meaning and no notion of "this object never moves".
- A document already has a companion `<id>.scene.bin` holding animation keys, which Save rewrites.

| Lab | Generated content today | Count |
|---|---|---|
| MaterialLab | Sphere grid, color patches, gradient ramp, normal probe, depth probes, mip probe, axis station; three procedural textures | 25 spheres plus about 15 fixtures |
| TemporalLab | Floor, reference cube, rotating cube, orbit sphere, poles (baked 60 Hz rigid tracks); an emissive sign driven by an emissive step track; an invalid-motion cube; one checker texture | About a dozen |
| LightLab | Floor, eight pillars, eight spheres; `lights` point/spot lights with closed-form orbits and a `pile` | 17 objects; 256 lights by default, up to 4,096 |
| VisibilityLab | `instances` icospheres and `occluders`, one mask texture | 4,096 by default, up to 1,048,576 |

## Decisions

The owner answered these on 2026-10-03. They bind the accepted implementation plan.

| Topic | Decision |
|---|---|
| Saved form | The scene document owns its objects: each lab object is its own node with a transform, a mesh reference and a material. Vertex and index bytes sit in a read-only geometry buffer beside the document, textures in image files. This reverses the UX3 rule that a document holds no meshes |
| Model for the form | A Unity scene: the scene file owns the object list and component values; geometry, textures and imported models are referenced. Imported assets (Damaged Helmet, Sponza, San Miguel, the truck) stay `asset` references with `overrides` |
| TemporalLab | Saved entirely, including the emissive sign and the invalid-motion cube; its generator retires |
| What stays generated | Populations sized by a parameter: VisibilityLab's instances and occluders, LightLab's lights, pile and closed-form orbits. A generator node is the equivalent of a spawner component, and its parameters are the saved state |
| Generated rows | Relabeled "Generated by `<lab>`", grouped and collapsed, with a tooltip saying the population comes from the saved parameters. Generated objects stop being editable; generated lights keep today's session-only edits |
| Mobility | One authored value per object node, asset override and light: `static` or `movable`; absent means `static` |
| Changing mobility | Only by editing the scene file. The Inspector shows the value as a disabled Static checkbox |
| Static meaning | The pose is read-only in the Inspector, the gizmo and session commands. Enabled state stays editable |
| Lights | Lights take mobility too. Every authored light is `movable` and gets the gizmo |
| Renderer meaning | None in UX6. The instance row ABI, `MotionClass` and every pass are unchanged |
| Gizmo | ImGuizmo, vendored and pinned like imgui-node-editor, drawn in the editor's UI layer for any selected object or authored light: live when the subject is movable, gray and inert when it is not |
| Shortcuts | Unity's: Q view tool, W move, E rotate, R scale, Y combined, X world/local |
| Axis station | Removed. The gizmo shows any selected object's axes; the `axisStation` parameter retires |
| Delivery | One executor plan and one squash-merged pull request for all three slices, with one owned re-baseline |

Rejected for the saved form:

- **Content assets** (`Assets/Scenes/Content/<lab>.gltf` referenced through an `asset` node), the
  draft's proposal. The objects would sit in a second file and be reached through `overrides`, so
  the scene still would not own them.
- **Everything embedded in one file** as base64 data URIs. Files grow by about a third over the raw
  bytes, diffs become unreadable and Save rewrites geometry on every change.
- **A named built-in shape per node** (`"shape": "sphere"` with inline material values). It adds a
  second mesh and material vocabulary that only Luminex reads, and generic glTF tools would show an
  empty scene.
- **Saving a per-object override list on the generator node.** It keeps the objects in C++ and
  stores edits keyed by generation order, which breaks when a generator changes.

## UX6.1 — Saved lab content

**Outcome:** opening MaterialLab, TemporalLab or LightLab shows named objects that are ordinary
saved scene content, and a glTF viewer opens the same file and shows the same objects. No row in a
catalog scene says "not saved"; rows that come from a generator say which one.

**Deliver:**

- Document form, `schemaVersion` 2. Object nodes carry `mesh` and their `LMX_scene` fields; the
  document's `meshes`, `materials`, `textures`, `images` and `samplers` arrays hold what they
  reference. Objects that share geometry share one mesh, so MaterialLab's 25 spheres reference one
  mesh with 25 materials. Materials are saved but the Inspector does not edit them in UX6.
- A geometry buffer, `<id>.scene.geometry.bin`, separate from the animation buffer `<id>.scene.bin`.
  Save and Save As never rewrite the geometry buffer or the images; Save As copies them beside the
  new document. Vertex data and tangents are written exactly as the generator produced them.
- The document's root `LMX_scene` records a SHA-256 for the geometry buffer and for each image.
  Preflight checks them and fails with the JSON path on a mismatch. The loaded-document hash in
  capture manifests and measurements keeps its definition (JSON bytes, then animation buffer bytes)
  and covers geometry and images through those recorded hashes, so neither schema changes.
- Dirty state compares canonical JSON and animation bytes as today; the geometry buffer and images
  cannot change in the editor and are excluded.
- MaterialLab moves entirely to the document and its generator retires. The axis station is not
  exported.
- TemporalLab moves entirely to the document and its generator retires. The floor, cubes, orbit
  sphere and poles keep their baked 60 Hz rigid tracks as document animations. The emissive sign
  uses `KHR_materials_emissive_strength` animated through `KHR_animation_pointer` with `STEP`
  interpolation; the pinned cgltf does not parse that extension, so the reader parses the channel
  through `JsonTokens`. The invalid-motion cube takes `"motion": "invalid"` in its node's
  `LMX_scene`, the saved form of `MotionClass::Invalid`; absent means `Rigid`.
- LightLab's floor, pillars and spheres move to the document; its lights, pile and orbits stay on
  the generator node. VisibilityLab stays generated.
- A one-time exporter writes the documents, buffers and images from the generators' output. It is
  tagged and then deleted with the generator code it replaces, as UX3's exporter was.
- Each document groups its Key, Fill and Rim directional lights under one `Lights` node, as local
  lights already sit under `Local Lights`. Roles, the shadow caster and light order are unchanged.
- Generated rows take the new label, grouping and tooltip. `--lab-instances`, `--lab-occluders`,
  `--lab-lights` and `--lab-light-pile` keep working.
- `Tools/Scenes/validate_documents.py` validates all six documents with their meshes against the
  pinned glTF validator and rechecks the recorded buffer and image hashes.
- A proposed ADR for the document form, amending the still-Proposed
  [ADR 0028](../../decisions/0028-scene-document-contract.md).

**Exit gate:** the standing matrix (Sponza, MaterialLab, TemporalLab × five modes) and LightLab are
compared with the parent and reported as measured, with no tolerance approved in advance. Sponza is
expected to be byte-identical. MaterialLab changes by the removed axis station and is re-baselined
once with the owner's acceptance. TemporalLab and LightLab are expected to be identical; a
difference from the loader path or from instance order is reported, and either joins the one
re-baseline with the owner's acceptance or fails the slice. A pose edit on a former generated
object survives save, relaunch and reload; a schema 1 document loads and saves as schema 2; the six
documents pass the pinned glTF validator; lab CLI parameters produce the same populations and
counters as the parent.

## UX6.2 — Mobility

**Outcome:** a scene says which objects and lights may move. An operator cannot change a static
subject's pose through any editor route, and sees why.

**Deliver:**

- `mobility` in `LMX_scene` on object nodes, on per-source-node `overrides` and on light nodes. A
  schema 1 document loads with every object static, every authored light movable, and its saved
  poses kept, so lights remain editable as they are today. Animated source nodes take no mobility,
  as they take no pose override; setting one fails preflight with the JSON path.
- The six catalog documents author the Damaged Helmet and every authored light as `movable`, and
  nothing else.
- Inspector: the header shows a disabled Static checkbox whose tooltip says the value is authored
  in the scene file. A static subject's Position, Rotation and Scale are read-only with the reason
  shown. Enabled stays editable for static and movable subjects alike.
- Hierarchy rows mark movable objects, the exception, instead of marking thousands of static ones.
- A Hierarchy row whose saved values differ from the document shows the operator mark, so an
  edited object can be found without opening each one; today only the root and the fields show it.
- `SceneSession` refuses a pose edit on a static subject at the model level, so the Inspector, the
  gizmo and the session bridge share one rule. A session proposal or command that changes a static
  subject's pose, or that changes mobility, is refused with a named reason, as generated and
  animated transforms are today.
- The mobility value joins the proposed ADR from UX6.1.

**Exit gate:** unit tests cover the reader, writer, export and the model-level refusal for objects
and lights; a schema 1 document loads, saves as schema 2 and reloads identically; no editor route
changes mobility or a static pose; scene-only screenshots are byte-identical to UX6.1.

## UX6.3 — Transform gizmo

**Outcome:** an operator selects the helmet or a light, drags a handle in the viewport and sees it
move while the Inspector's numbers follow. Selecting a static object shows a gray gizmo at its pivot
that cannot be dragged.

**Deliver:**

- ImGuizmo fetched by `xmake setup` at a pinned commit with its license and provenance, compiled as
  its own static target and linked by App only, with its header confined to one translation unit. A
  maintained patch is added only if the pin does not build against the pinned Dear ImGui commit. A
  proposed ADR records the choice, following
  [ADR 0011](../../decisions/0011-vendored-imgui-node-editor.md).
- The gizmo is drawn for the selected object or authored light. It is live when the subject is
  movable and enabled, playback is stopped and no measurement runs. Otherwise it is gray and inert:
  static, disabled, generated and animation-owned subjects, and any subject during playback or
  measurement. LightLab's generated lights follow the Inspector's existing session-only rule.
- Objects offer Move, Rotate, Scale and the combined tool. A point light offers Move. A spot light
  offers Move and Rotate, where Rotate edits its direction. Scale is not offered for lights.
- One source of truth. The gizmo edits through the same `SceneSession` calls as the Inspector's
  drag fields, and both read the pose back from the scene every frame: a gizmo drag updates the
  fields as it happens, a field drag moves the gizmo, and dirty state, save and reset are identical
  by either route.
- Tools follow Unity: Q view (no gizmo), W move, E rotate, R scale, Y combined, X toggles World and
  Local. The same choices sit in View > Gizmo and on the toolbar. The keys do nothing during text
  entry, popups or right-mouse look, where W, A, S, D, Q and E keep flying the camera. Unity's rect
  tool (T) and pivot toggle (Z) are not offered. Tool and space are session state; the workspace
  schema does not change.
- Escape during a drag restores the pose from the drag's start. The Inspector's reset to the
  authored pose stays the recovery after a drag, since Undo remains deferred.
- The gizmo is drawn with the unjittered editor camera in the UI layer. It never enters the scene
  target, temporal history, screenshots, sequences or scene-only GPU captures.
- An object with several material primitives moves as one, as it does in the Inspector.
- The scene-document and GPU-debugging guides, the App architecture page and `AGENTS.md`.

**Exit gate:** a gizmo drag and the equivalent Inspector edit export the same document bytes, for
an object and for a light; during a gizmo drag the Inspector fields show the live pose, and during
a field drag the gizmo follows; with the gizmo visible, a scene-only screenshot is byte-identical to
one without it; the gizmo is inert for static, generated, disabled and animation-owned subjects and
during playback and measurement; the
[completion gate](../../roadmap/editor-experience.md#completion-gate) tasks still pass; native
gestures that are not exercised are recorded as unverified.

## Boundaries and deferrals

Create, duplicate, delete and reparent; viewport picking; Undo/Redo; snapping and numeric drag
entry; multi-selection; gizmos for cameras and directional lights; material editing in the
Inspector; importing an asset into an open scene; changing mobility inside the editor. No renderer
feature consumes mobility. The workspace schema, capture manifest and measurement schema do not
change. Showing Sponza's 25 material primitives as child rows of their source node is a separate,
smaller change outside UX6.

## Risks and open points

- **Exactness through the loader.** Lab content now passes through the document reader instead of
  direct scene calls. Tangent handling, samplers and instance order may not reproduce bit for bit.
  The exit gate reports the comparison as measured; a difference joins the one re-baseline or fails
  the slice.
- **Textures with authored mip levels.** PNG holds one level. If a procedural texture, such as the
  mip probe, authors its levels individually, it needs a DDS image, which glTF carries only through
  an extension. The plan settles the image format per texture after reading each generator.
- **Baked keys.** TemporalLab's rigid tracks must reproduce every 60 Hz key through the animation
  buffer. If they do not, the record states the measured difference before any re-baseline.
- **Animation pointer parsing.** `KHR_animation_pointer` is read outside cgltf's own animation
  parse. If that proves unsound, the fallback is the same step track under `LMX_scene`, and the
  record says so.
- **Projection convention.** ImGuizmo expects a conventional projection matrix, while the renderer
  uses reversed infinite Z. The gizmo needs its own finite projection built from the same camera;
  misalignment between handles and geometry is the failure to watch for.
- **Dependency risk.** ImGuizmo may not build against the pinned docking-branch commit without a
  patch. If it proves unusable, the fallback is a small `ImDrawList` gizmo limited to translation
  and one-axis rotation, and the record says so.
- **Static is an editor lock, unlike Unity's.** Unity's Static flag is a runtime promise and leaves
  the object draggable in its editor. Here it locks the pose in the editor, and unlocking means
  editing the file. The name leaves room for a renderer meaning later.
- **Reader and writer growth.** Meshes, materials, textures and the second buffer enlarge the
  document reader, writer, exporter and Save As. This is the largest part of UX6.
