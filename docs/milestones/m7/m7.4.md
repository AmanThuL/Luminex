# M7.4 — Conservative Occlusion

**Status**: Implemented — owner-accepted for integration 2026-09-18

This design specification precedes implementation. The
[roadmap](../../roadmap/gpu-driven-hybrid-rendering.md#m74--conservative-occlusion) owns the outcome,
deliverables, exit gate and deferrals; [ADR 0021](../../decisions/0021-gpu-scene-handoff-contract.md)
owns the identity, update and graph-participation semantics; [ADR 0016](../../decisions/0016-active-render-extent-and-resolution-control.md)
owns the active render extent; and [ADR 0012](../../decisions/0012-gpu-submission-defer.md) owns the
adoption bar. Where wording differs, those win. The owner accepted the scope adjustment recorded
below on 2026-09-18 and authorized implementation the same day.

## Objective and baseline

The baseline is [M7.3](m7.3.md) with its [validation record](m7.3-validation.md): opt-in GPU
frustum classification writes state words, compacted rows and indirect arguments for a scene view
and an unculled shadow view, with the CPU five-plane oracle as the maintained reference and the
default. Scene depth is `D32Float` reversed infinite-far Z (near 1, infinity 0, cleared to 0, sky
not written), rasterized with the jittered view-projection into a ping-pong pair allocated at the
output extent and confined to the active render rectangle.

This slice adds a hierarchical depth pyramid (HZB) built from each frame's scene depth and a
previous-view occlusion test inside GPU classification. It separates two claims:

- **Spatially conservative.** The reduction and the box test never report a box hidden that was
  not hidden in the source frame's depth samples. This is exact and gated per level and per test.
- **Temporally approximate.** The evidence is the previous declared frame's depth under that
  frame's view. It is strict when view and coverage are unchanged, invalidated on the events
  below, and bounded by a recovery deadline under continuous camera motion. Disocclusion latency
  during motion is accepted, measured and disclosed. Two-phase occlusion, the mechanism that
  recovers newly visible geometry within the current frame, stays deferred beyond M7.

Occlusion is opt-in and off by default, requires GPU classification, and adopts no default.
Wireframe retains every candidate because filled depth cannot prove wireframe visibility.
Materials, pre-exposure, masked coverage (ADR 0018), the motion convention, the display boundary,
the M7.1 identity rules and the M7.2/M7.3 row, slot and ordering contracts are unchanged. With
occlusion off, no HZB pass is declared and the default goldens do not change.

## Intended implementation

### RHI format

`rhi::Format::R32Float` joins the format set as sampled, storage-writable and CPU-readable, not
colour-renderable. `R16Float` was rejected: it needs directed rounding to stay conservative and
cannot satisfy an exact per-level oracle. The checkpoint-A subset is unchanged.

### Pyramid

`Source/Render/HzbStage.h` owns two `R32Float` pyramids imported as `lmx.render.hzb0` and
`lmx.render.hzb1` with recorded terminal uses, the reduction pipelines, and one `HzbSource` record
per pyramid: declared frame number, the jittered view-projection that rasterized the source depth,
the source active render extent, level count and a built flag. Pyramids alternate by the stage's
own declared-frame parity, independent of temporal mode.

- **Coverage rule.** Texel (x, y) of level L covers source depth texels
  `[x << (L+1), (x+1) << (L+1)) × [y << (L+1), (y+1) << (L+1))` intersected with the source active
  rectangle. Level 0 is the 2×2 reduction of scene depth; scene depth itself is the implicit finer
  level for later consumers such as M8.3.
- **Reduction rule.** A texel stores the minimum of the depth values it covers, the farthest under
  reversed-Z. Level L ≥ 1 takes the minimum of its up-to-four children that lie inside level L−1's
  active size `ceil(active / 2^L)`. All access is integer `Load`; no sampler, UV or filter exists
  in the path. Texels outside a level's active size are never written or read.
- **Allocation.** The base is `ceil(outputExtent / 2)` rounded up to a multiple of `2^(K−1)`, so
  Metal's floor-sized mips hold every ceil-sized active level; K is the first level count whose
  top active size is at most 16 texels at the output extent (640×384, K = 7 at 1280×720).
  Allocation follows the output extent only, so a render-scale change never reallocates (ADR 0016).
- **Passes.** `lmx.pass.hzb.level0` reads the frame's scene depth as a shader read. Native depth ends
  in `ShaderRead`; vendor depth retains the broader `ExternalRead` stage set; `lmx.pass.hzb.level<k>` reads mip k−1 and
  writes mip k through disjoint subresource uses, one compute pass per level as in `BloomStage`.
  They run after the scene pass of every frame with occlusion enabled, including frames whose
  history is invalid, so the next frame has a source. A final `lmx.pass.hzb.publish` pass reads
  every mip, roots the exported pyramid and establishes its recorded `ShaderRead` terminal use.

Frame N builds its pyramid from depth D<sub>N</sub>; frame N+1's classify pass reads it as the
previous pyramid on the GPU timeline. Rejection never depends on CPU readback, so the three-frame
diagnostic latency does not enter it.

### Occlusion test

`Shaders/Modules/Occlusion.slang` and its CPU mirror `Source/Render/Occlusion.h` hold one ordered
fp32 sequence, written with explicit operations, compiled with safe math on the GPU and with
contraction disabled on the CPU, as the M7.3 plane test is. The test runs in `classifyBounds`
after the five-plane loop, for the scene view only; the shadow view stays unculled because
geometry hidden from the camera still casts shadows.

1. Project the eight corners of the candidate's current world box with the source record's
   jittered view-projection. If any corner has `w ≤ kOcclusionNearGuard`, retain (`NearCrossing`).
2. Map the corners to source depth texels with the source active render extent. The rectangle is
   `floor(min) − 1` to `ceil(max) + 1`: outward rounding plus a one-texel guard. If it is not fully
   inside the source active rectangle, retain (`OutsideSource`): no evidence covers the rest.
3. Choose the smallest level at which the rectangle spans at most 2×2 texels. If that exceeds the
   top level, retain (`RectTooLarge`).
4. Let `zBox` be the largest corner `z / w`, the nearest box depth. Reject only if
   `zBox + kOcclusionDepthGuard < min(covered texels)`; otherwise retain (`Retained`).

An occlusion-rejected candidate is `Rejected` with the new `VisibilityReason::Occluded = 5`;
frustum rejection keeps reason `None`. Bits 8–11 of the state word carry
`OcclusionOutcome { NotTested, Retained, HistoryInvalid, NearCrossing, OutsideSource,
RectTooLarge }` for retained candidates. `OcclusionParams` (source matrix, source active extent,
level count, guards, flags) travels as frame data in buffer slot 13 and the previous pyramid binds
as a texture; `VisibilityTables.h` and the shader module mirror the record with size and offset
asserts. Counters grow from 12 to 20 words per view (160 bytes for both views): the M7.3 words plus occluded,
tested, history-invalid and the three retain outcomes. Reconciliation extends to rejected =
frustum-rejected + occluded and tested = occluded + retained outcomes.

### History validity

`Source/Render/OcclusionHistory.h` is a pure function from the previous and current frame facts to
a validity flag and an `OcclusionInvalidReason`. Invalid history retains every candidate with
outcome `HistoryInvalid`; it is global. History is invalid when:

- no built source exists, the source is not declared frame N−1, or occlusion was off in frame N−1;
- the scene generation or the output extent changed (the pyramid reallocates);
- the camera-cut latch is set: scene switch, Reset camera, Frame selected, camera-rail restart and
  Stop restoration request it through `TemporalEditorState`, and the capture loop sets it on
  the same events;
- the automatic discontinuity rule fires: forward directions differ by more than
  `kOcclusionCutAngle = 10°` or positions by more than `kOcclusionCutDistance = 1 m` between
  consecutive frames; a smaller jump is continuous motion under the recovery deadline;
- `SceneView::coverageEpoch` changed. The scene advances this 64-bit counter when an instance is
  added or removed, when any instance's `model`, mesh or material assignment changes, and when a
  material's alpha mode, cutoff, sidedness, base alpha, diffuse texture or UV transform changes. `previousModel` refreshes and emissive
  changes do not advance it.

Moving, removing or reshaping any occluder therefore invalidates all historical evidence for that
frame, not only the changed object; per-region invalidation is not attempted. The disclosed
consequence: a scene that animates every frame rejects nothing by occlusion while it animates.
A projection or render-scale change needs no reset, because the test uses the source frame's own
matrix and active extent.

### Recovery bound

Claim: with valid history, an instance that has at least one reference-visible sample in frames k
and k+1 is drawn in frame k+1, so consecutive missing frames never exceed one. Frame k+1 tests
against D<sub>k</sub> under frame k's jittered view. If the instance was rejected in frame k, then
D<sub>k</sub> holds strictly farther geometry at its visible sample p, so
`min(covered texels) ≤ D_k(p) < z(p) ≤ zBox` and the test retains it; if it was drawn in frame k,
`D_k(p) = z(p) ≤ zBox` retains it as well. The bound holds only when:

- (a) the consumed pyramid's source is exactly declared frame k and history is valid;
- (b) the test uses the matrix, jitter and active render extent that rasterized D<sub>k</sub>,
  including across dynamic-resolution changes;
- (c) the projected rectangle contains p, which the outward rounding and guard provide;
- (d) every level is conservative, which the per-level gate proves;
- (e) both guards bias only toward retention.

Each condition has a fixture. The bound covers geometry submission only. A recovered instance
enters temporal reconstruction with rejected or absent history at its pixels, so the reconstructed
image converges over later frames; that is measured separately and never inferred from this bound.

Under jitter with a static camera the evidence is sampled at frame N−1's subpixel positions and
consumed at frame N's. The one-texel guard is the design response; an occluder gap narrower than
one source texel remains a theoretical limit, exercised empirically across all jitter phases.

### Independent ID reference

`Source/Render/OcclusionReference.h` declares, only under `--occlusion-check`, a raster pass that
draws every scene-view candidate directly: no visibility kernels, pyramid, row list or indirect
arguments. It uses the frame's jittered view-projection, active render extent and the shared
masked-coverage function, tests depth with `Greater` into its own transient depth, and writes
instance row + 1 into an `RGBA8Unorm` target as four exact bytes. The target and the state words
are read at slot retirement. Per retired frame it reports falsely rejected visible instances
(state `Occluded` with at least one reference pixel), their pixel total, and per-instance
consecutive-missing streaks keyed by generational `InstanceId`, so a recycled row never inherits a
streak. The mode is unscored, requires GPU classification, fails a capture sequence on a strict
violation or a streak of two, and appears in the Inspector and console.

`--classify-check` with occlusion on requires every `Occluded` candidate to be `Visible` in the
CPU frustum oracle and every other state to match it; rows and arguments are compared against the
CPU ordering applied to the GPU states, and counters reconcile.

### Lab, CLI, editor and measurement

- **Lab.** `--lab-occluders <n>` (default 0, VisibilityLab only) adds n deterministic opaque slabs
  with window gaps between the rail and the grid, one of them masked with cutouts many texels
  wide. With 0 the scene bytes, and so the frozen six workloads, are unchanged. The lab stays
  static; moving occluders are exercised by fixtures and the TemporalLab catalog run.
- **CLI.** `--occlusion <on|off>` (default `off`) requires `--classify gpu` and `--visibility
  cull`. `--occlusion-check` requires occlusion on and `--unscored` for a measurement.
  `--hzb-level <k>` shows level k of the frame's pyramid, nearest-expanded over the active
  rectangle, through a `Shaders/HzbDebugView.slang` diagnostic like the temporal views.
- **Editor.** The Visibility block gains the Occlusion toggle, history validity with its reason,
  the source frame, the new counters, check results and `lmx.pass.hzb.*` times. The selected
  object shows its outcome plus the rectangle, level and `zBox` recomputed by the CPU mirror for
  the retired frame. Hierarchy dims occluded objects with the tip "Occluded (previous-frame HZB)".
  A viewport overlay draws the selected object's bounds and source rectangle, and optionally the
  occlusion-rejected bounds up to a disclosed cap. Formatting stays CPU-testable AppModel logic.
- **Measurement.** The report moves to schema version 3: occlusion mode, check mode, history
  validity and reason per sample, the new counters, pyramid bytes, and HZB time reported apart
  from `visibilityGpuMs`. `Tools/Bench/visibility_paired.py` adds occluded-lab workloads at the
  three lab scales and `occlusion-on-off` controls under GPU indirect and GPU batched; the frozen
  six workloads and the 12/32/256 protocol are unchanged and no decision rule is applied.

## Verification plan

The four families below are reported separately; none substitutes for another. Pyramid validation
is the first implementation stage and completes before any kernel consumes a level.

### 1. Per-level correctness

GPU fixtures under `[gpu][hzb]` with Metal validation read back scene depth and every level and
require exact equality with a CPU minimum computed directly from depth by the coverage rule, not
from the level below: at render scales 1.0 and 0.5, an odd output extent, a sky-only frame, a
masked occluder, and after a render-scale change without reallocation. CPU tests pin level sizes,
the allocation rule and K. A golden pins the occlusion-on frame's passes and derived barriers.

### 2. Strict visibility

- **Test parity.** GPU outcomes, rectangles and levels equal the CPU mirror evaluated on the
  read-back pyramid exactly, with probes one guard inside and outside the depth threshold, the
  near guard, the source rectangle edge and the top-level limit.
- **Zero false occlusion.** Against the ID reference, no reference-visible instance is `Occluded`
  with a static camera over a full jitter period, with temporal off, and at both render scales,
  in the occluded lab, Sponza and San Miguel.
- **Invalidation.** Fixtures apply a camera cut, a jump above each discontinuity threshold, an
  added instance, and an occluder that is moved, removed, rescaled and switched to masked, plus a
  scene switch, an output-extent change and an occlusion toggle. Each frame reports the expected
  invalid reason, rejects nothing by occlusion, and loses nothing; the following frame is valid.
- **Attachments and images.** The M7.2 contribution fixture extended to occlusion on versus off
  requires exact HDR, depth, motion and reactive equality with a static camera. The fifteen-image
  matrix, occlusion on versus off in the same binary, requires exact SHA-256 equality. Parent
  M7.3 versus candidate defaults uses the M7.1 criteria as recorded, including the scoped
  `vendor-quantization-v1` profile, the motion readback and the three-frame sequence.

### 3. Motion latency and recovery

`--occlusion-check` runs over the occluded VisibilityLab rail at the three lab scales and the San
Miguel rail, for the full 12-second track at both render scales and with dynamic resolution
changing the active extent mid-run. Reported per run: frames with any false rejection, falsely
rejected instances and affected pixels per frame, and the streak histogram. Gate: no streak
reaches two and no instance is omitted persistently; any violation fails. A fixture per recovery
condition (a)–(e) proves the condition is enforced, including a deliberately skipped source frame
that must invalidate rather than reject. Image recovery is reported as per-frame differing pixels
and LDR-FLIP against the occlusion-disabled run of the same sequence (frustum culling unchanged), with no threshold and no conclusion
drawn from the geometry bound.

### 4. Performance

One paired collection on the frozen device with parent and candidate release binaries frozen
before and after the change, raw evidence outside the source tree, every attempt retained. Cells
report HZB build, classification, scene and shadow GPU time, full-frame cost, CPU work, rejected
counts and pyramid memory with intervals. The numbers are diagnostics; ADR 0012's bar and the
roadmap's production-evidence rule govern any later default, which is a separate owner decision.

### Rules fixed before measurement

A failing gate is recorded as a failure with its numbers; thresholds and guards are not changed
after measurement, and any exception is the owner's explicit decision. The inherited Sponza
Native-TAA 0.5 divergence from M7.2 and M7.3 is neither an excuse nor an explanation for a failure
here. Correct execution and GPU capturability are separate gates: a labelled capture of the HZB
and classify passes is requested, and a capture-tool limitation is recorded as such without
blocking the runtime gates. Harness failures are recorded apart from renderer failures.

### Regression inventory

Build, `xmake test`, the GPU suite under `MTL_DEBUG_LAYER=1`, format, `xmake policy` with the
module, header, comment and shader-import checks, and the unchanged `[checkpoint-a]` filter pass.
Default-path goldens are unchanged. `CaptureSchemaTests` pins the new counter/occlusion layouts
in RHI capture sidecar version 1; `AppOcclusionTests` pins measurement schema 3, while
`AppCaptureMetadataTests` retains sequence manifest version 2. A validation-clean editor session
enables occlusion on every catalog scene, inspects an occluded
object's reason, rectangle and overlay from a retired frame, shows each pyramid level, triggers
each invalidation from the UI, and completes one unscored check run.

## Known limits and design boundaries

- Disocclusion under continuous camera motion can omit an instance for one frame; two-phase
  occlusion is the deferred remedy. Image convergence after recovery takes longer than one frame.
- Invalidation is global. Continuously animated scenes gain nothing from occlusion, and one
  moving object disables rejection everywhere for that frame.
- Boxes that cross the near plane, leave the source view or exceed the top level are never
  rejected. Occluder gaps narrower than one source texel are a theoretical jitter limit.
- The CPU classification path has no occlusion; the CPU mirror exists for parity and diagnostics.
- The shadow view stays unculled. The pyramid starts at half resolution; a full-resolution level,
  other reductions or formats are added only by a real consumer such as M8.3.
- No cluster LOD, per-region invalidation, reprojection, visible-last-frame list or default
  adoption. Fixed-slot CPU encoding is unchanged from M7.3 and stays disclosed.
- Existing image-parity exceptions, failed gates and capture follow-ups from M6.4 through M7.3
  carry forward unchanged; this slice neither closes nor broadens them.
