# M6.5 — Display boundary and EDR evaluation

**Status**: Proposed

The SDR implementation is verified on the feature branch. Closure and the EDR decision are
pending; the shipped baseline remains M6.4. [ADR 0019](../decisions/0019-display-domains-and-edr.md)
records the proposed domain and future reference-white/headroom policy.

## Implemented behavior

The Renderer exposes one opaque eight-bit SDR BT.709/sRGB/PBR Neutral display domain. Inspector
shows it with the encoded SDR UI rule, backing scale and settled 1:1 viewport mapping. Scene,
exposure, temporal and display shaders are unchanged, and the production RHI remains SDR-only.

Screenshots accept PNG or BMP by extension. PNG adds standard SDR color chunks and display/frame
text metadata without a pixel transform. Sequences default to PNG with an explicit BMP override;
manifest v2 records display, container and UI absence. The comparison tool accepts legacy v1 and
both containers, rejecting reused frame filenames. Capture serialization is CPU-testable App logic.

## UI evidence

A production executable copy runs in an isolated `/tmp` bundle with built-in TemporalLab, Metal
validation, and independent workspace state. Inspector shows framebuffer scale 2.00 × 2.00,
display target 1388 × 944 and 1:1 backing pixels; Performance independently reports 694 × 472
logical points. The run presents 4,309 frames, zero skipped, and settles after resize transitions.
CUA window screenshots in the execution conversation show legible text and the read-only block.

A CPU harness linked against the same vendored ImGui library renders the same 13-point text at
framebuffer scales one and two: actual baked rasterizer densities are one and two, respectively.
The two atlas images and harness are retained. No production font-density change was needed.
This establishes raster density, not absolute luminance or a photographed physical-white match.

## EDR evaluation

An isolated `exp/m6.5-edr` worktree provides extended-linear float presentation, current-headroom
policy, linear UI bounded at white one, direct calibration patches, float readbacks, SDL/NSScreen
crosschecks and paired windows. The final 360-frame SDR/EDR runs are validation-clean; current
headroom settles near 11.8033 and the chosen peak approaches four. The owner reports clearly
brighter EDR highlights and similar UI white brightness. After the requested brightness/preset
exercise, the owner reports distinguishable patches and brighter UI; clarification of global
versus EDR-specific UI change and the final decision remain pending. No per-preset numerical
record or photograph is claimed. A stable float readback reaches 3.998046875; forcing headroom
to one yields maximum 1.0 and zero channels above one, then restores peak four. This verifies
range fallback only, without recreating the float layer or changing the EDR metadata domain. The proposed peak-scaled Neutral curve darkens midtones by 63.84%
at input 0.18 and 26.09% at 0.5 (peak four, display-linear oracle output), supporting a defer
recommendation until a future view has an intentional appearance and production comparison. See ADR 0019 for startup-reporting, curve, capture and cost limits.
