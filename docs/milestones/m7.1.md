## Implemented behavior

- `Scene` owns distinct 8-byte instance/mesh/material/texture handles. Store identity rejects
  foreign scenes; slot generations reject stale handles, and exhausted generations never wrap.
  Dense editor object order remains independent of stable GPU row slots. Removal repairs playback
  track indices; slot reuse seeds the new instance's own previous transform.
- `finalize` creates one immutable vertex/index pool, including sky geometry, with rebased indices
  and zero base vertex. `MeshData`/`Vertex` remain CPU vocabulary; GPU `Mesh` ownership and
  `createMesh` are retired. Materials own optional texture handles; frame views resolve ordinary
  texture pointers and retain renderer fallbacks.
- Shared CPU/Slang mirrors define 208-byte `InstanceRow`, 112-byte `MaterialRow` and 16-byte
  `MeshRow`. Size/offset assertions and registered capture layouts pin the ABI. A 16-byte
  `DrawUniforms` selector replaces the 368-byte object block; scene/shadow/selection entries read
  transforms/motion from b5 and factors/cutoff/flags from b6. Shared geometry binds at b0; CPU
  indexed commands and per-draw texture binding remain. Mesh rows have an ABI-reader-only shader.
- `BufferDesc::cpuWrite` and checked `Buffer::write(offset, data, size)` provide explicit
  host-visible uploads. Permission, non-null source and nonempty in-bounds range are validated.
  The caller proves GPU use retired. Metal4 copies into Shared storage; private placed buffers
  reject host upload permission. No new capability, synchronization or general upload API exists.
- Each table kind owns three buffers. `SceneSession::prepareFrame` follows `Device::beginFrame`
  and precedes declaration in editor and capture loops. CPU shadow comparisons dirty all slots;
  only the retired slot receives writes. Static rows converge to zero writes after three uses.
  Growth doubles capacity and retains replaced buffers until the last prepared frame + 3.
  Accepted frames promote previous transforms; skipped frames do not commit them.
- Renderer imports `lmx.scene.vertices`, `.indices`, `.meshes`, `.instances` and `.materials` as
  read-only graph resources. Scene/shadow and editor selection read those bindings without GPU
  writers or new hazards. Opaque/masked/exposure permutations remain separate; AlphaMask consumes
  the material cutoff directly and its former private uniform block is removed.
- Inspector Display & Details exposes counts/capacities, geometry bytes, row/byte writes, active
  slot, growth and pending buffer release through CPU-testable `SceneTableDisplay`. Growth and
  retirement log at INFO. These counters are diagnostics, not a performance measurement.

Current code ownership and frame flow are in the [architecture](../architecture/overview.md) and
[frame walkthrough](../frame-pipeline.md).

## Design clarifications and retained semantics

Texture removal adds safe deferred ownership: it rejects references from any live material and
invalidates the handle immediately, but retains the allocation through `lastFrame + 3` for
submitted bindings. This strengthens the proposed removal contract without introducing a
residency system. Scene destruction still requires the owner to retire all GPU use.

`Tests/SceneTableTestSupport.h` retains test-only `FixtureSceneView`/material/mesh input records so
legacy oracle inputs can preserve their authored transforms, motion classes and texture probes.
The helper creates a production `Scene`, prepares its real paced tables and passes the production
`SceneView` to Renderer; it is not a second rendering path. Scene-owned marker textures preserve
normal-map flags while tests retain the original externally owned texture samples.

MaterialLab's first-frame motion changes because its parent loader left transformed objects'
`previousModel` at identity. `addObject` now seeds each instance from its own authored pose, as the
design requires. The old invalid first-frame seed was not restored to chase image parity.
Row updates, alpha coverage and existing motion-class assertions remain covered by regression tests.
The existing MASK contract still requires a finite, nonnegative cutoff.

## Image comparison criteria

The [original design](../specs/2026-09-15-m7.1-gpu-scene-foundation-design.md) and original strict
criterion remain frozen: each image has at most **1.0%** differing pixels and at most **0.05%** of
pixels whose largest RGB channel delta exceeds **8/255**. Bounds are inclusive and decided using
integer counts. `reference.json`, its strict hash runner and existing golden tolerances remain
unchanged. Exact reference hashes and the paired image gate are reported separately.

The owner authorized an additional, explicitly selected `vendor-quantization-v1` profile in
`Tools/Screenshots/compare.py`. It applies only to MetalFX images; Off and Native TAA keep the
original strict criterion. For MetalFX it requires all of:

- At most **1.0%** of pixels with largest RGB channel delta **greater than 1/255**.
- At most **0.05%** of pixels with largest RGB channel delta **greater than 8/255**.
- Mean absolute RGB channel delta at most **0.1 encoded level** on the 0–255 scale, over every
  pixel and all three channels.

The default remains `strict`. Reports retain the raw differing-pixel count, maximum delta, mean,
strict result and applied-profile result; one-level differences are counted in the raw metrics.
The owner accepted this optional profile for the recorded M7.1 comparison on 2026-09-15.
Acceptance does not turn the original failures into passes, set later milestones' criteria,
or make encoded differences a measure of linear-radiance error or image quality.

The final matrix passes **11/15** under the original criterion and **15/15** under the optional
profile. Earlier reviewed results were 10/15 and 15/15 respectively; those five original failures
remain in the [historical matrix](m7.1-validation-history.md#frozen-image-gate).
Sponza Native and MetalFX half-scale images are exact in this final freeze. That does not erase
prior non-exact runs or establish a new causal explanation. The four remaining strict failures:

| MetalFX case | Raw changed % | Delta >1 % | Delta >8 % | Max /255 | RGB mean /255 |
|---|---:|---:|---:|---:|---:|
| Helmet 1.0 | 7.285916 | 0.003038 | 0 | 3 | 0.024667 |
| Helmet 0.5 | 6.924154 | 0.001302 | 0 | 3 | 0.023919 |

Over 99.95% of changed pixels in these four cases differ by one encoded level. The profile
allows that quantization step, with the mean bound guarding against global brightness drift.
Synthetic full-image +1/+4, one-pixel shift and a high-contrast 32×32 block still fail.
[The comparison guide](../guides/screenshot-comparison.md) explains the engineering limits and
Apple's temporal-history/motion/jitter/exposure contract. Earlier exact parent-to-parent controls
do not support calling the differences random. Sparse prior input changes and MaterialLab's
corrected first-frame motion seed are retained in the input diagnosis; their contributions are
not fully separated. The accepted tolerance is an engineering judgment for this comparison,
not an Apple-certified quality threshold.

The final motion probe retains 1,843,200 components, 3,016 numeric differences and no nonfinite
mismatch, within the unchanged 1/4096 UV bound. Its bytes equal the reviewed candidate probe.
The Native TAA sequence retains four warmup and three saved frames; changed-pixel percentages
are 0.033854 / 0.033095 / 0.033420, with maximum deltas 3 / 2 / 2 and no delta >8 pixels.

## Xcode Replay correction and inspection

RHI render/compute passes now clear their texture-binding slots before attaching the shared
argument table. Previously, a recycled table could retain the resource ID of a retired transient
texture in an unused slot. Xcode Replay attempted to resolve such a binding and crashed; the
parent capture also reproduced the failure. Draws and dispatches snapshot argument-table state,
so clearing before a new pass preserves previously encoded work. Each pass already binds every
slot it uses; buffer/sampler behavior, shader inputs and resource lifetimes are unchanged.

With that correction, Xcode successfully replayed the TemporalLab frame-120 capture
`xcode-fix/texture-reset.gputrace`: **39 draws, 11 dispatches, four render encoders and 11 compute
encoders**. GUI inspection of Scene draw 120 and Shadow draw 75 showed shared vertex/index
buffers, b1 Draw/b2 Pass bindings, b5 `instances.0` and b6 `materials.0`. The inspected `gDraw`
structure contains four uints and occupies 16 bytes. A second full-size Sponza capture,
`xcode-fix/fixed-editor.gputrace`, also replays successfully: frame 3168, 97 draws, 11 dispatches,
seven render encoders and 11 compute encoders, output 3348×2104 and scene 2106×1062.
Selection coverage draw 394 uses shared geometry, b5 instances and b6 materials with the selected
`fabric_g` object's texture. Its capture and schema are archived. Bound resources were inspected;
Xcode marks Accessed mode unavailable for Metal4. Reflection's Read/Write column is not proof of
GPU writes. Unused-resource insights remain distinguishable from runtime validation errors.

Earlier agent attempts to download MetalToolchain received HTTP 401. On 2026-09-15 the owner
successfully downloaded build 17F109; a subsequent local check reports `installed` and
`Apple metal version 32023.883`. `owner-acceptance/toolchain.json` retains the check. The recorded
Replay/binding verification used runtime MSL before this installation; shader-source debugging
was not rerun, and no new offline-compiled rendering result is claimed. Prior crash reports,
failed dump diagnostics and attribution limits are preserved in the
[validation history](m7.1-validation-history.md#editor-capture-and-structural-review).

Existing compute-to-compute, compute-to-render and successive render-pass pixel oracles exercise

bindings across many compute passes. Ordinary pixel tests do not assert Xcode's handling of
unused bindings; the real Replay and GUI inspection supply that evidence.
