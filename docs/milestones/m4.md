# M4 — Correct Image Formation

**Status**: Implemented (2026-08-10)

M4 replaced the hand-sequenced M3 frame with a validating render graph and replaced Blinn-Phong
with physically based image formation. Every frame declares its shadow, scene+sky, display, and UI
passes as reads, attachments, and writes over versioned logical handles; `compile()` proves the
declarations form a DAG and answers a serial schedule before any of it reaches the GPU, and
`execute()` derives its own render-target-to-sampled barriers from those declarations. Scene and
sky render into scene-linear FP16 color with manual exposure; a dedicated display-transform pass
applies the Khronos PBR Neutral tone map and the frame's one sRGB encode. Materials shade full
glTF metallic-roughness inputs with a GGX BRDF for analytic lights and split-sum image-based
lighting with Fdez-Agüera multi-scatter compensation, sourced from a deterministic CPU-generated
IBL set attached to every scene. Depth is reversed and infinite-far throughout. Sponza and Damaged
Helmet's material images bake to a deterministic offline mip chain at setup time; a new
code-generated `material-lab` scene gives every one of these properties a deterministic, asset-free
check. Every render-graph pass reports a GPU timestamp, visible in the editor's Stats panel.

## Evidence

- CPU unit suite: 167 test cases, 75,473 assertions, all passed (`xmake test Tests/unit`).
- GPU suite on an Apple M3 Max with Metal validation: 50 test cases, 1,067 assertions, all passed
  (`MTL_DEBUG_LAYER=1 xmake test Tests/gpu`); zero skipped once `xmake setup` had baked both
  fetched scenes' material images.
- A windowed run of 240 frames (`LMX_MAX_FRAMES=240 xmake run App`) presented all 240 with zero
  skipped frames; the Stats panel's per-pass listing is backed by the same `passTimings()` GPU
  tests below.
- Exit-gate items, each proven by a named case in the suite above:
  - Helmet and Sponza authored material inputs: the glTF loader tests reading metallic-roughness,
    occlusion, and emissive images, plus the fetched-asset loader cases, and confirmed visually in
    the regenerated gallery captures below.
  - Mip filtering: "loadMaterialLabScene's mip probe converges to mid-gray under strong
    minification, proving its mips are filtered rather than point-picked" — a point-picked mip of
    the 1-texel checkerboard probe would read solid black or solid white instead.
  - Furnace and dielectric/conductor: "MaterialLab's sphere grid conserves energy in a white
    furnace" and "dielectric and conductor probes match a CPU BRDF reference at pinned angles".
    The furnace tolerance is derived, not chosen: four `RGBA16Float` roundings at 1.0
    (4 × 2⁻¹⁰ ≈ 0.0039), about an eighth of the roadmap's ±0.03 gate window.
  - Depth reconstruction: "view depth reconstructs from the scene depth buffer at MaterialLab's
    probes" checks `viewZ = -nearZ / d` against a CPU reference at near, mid, and far distances.
  - Gradient and known-color: "loadMaterialLabScene's known-colour patches round-trip the display
    transform and its gradient ramp reads back monotonic".
  - No scene-shader sRGB: `grep -n "linearToSrgb\|Encode" Shaders/ScenePass.slang Shaders/Sky.slang`
    returns nothing; only `Shaders/DisplayTransform.slang` imports `Encode`.
  - Undeclared graph use fails validation: "a pass resolving an undeclared texture is refused
    while the frame runs" (GPU) and "PassResources resolves a declared buffer and refuses an
    undeclared one" (CPU).
  - Unchanged passes matched the M3 reference: while the graph and the hand-sequenced path
    existed side by side, a GPU test rendered one frame through each and asserted byte-identical
    readbacks on a two-cube scene and a shadowed scene under a sky. The hand-sequenced path and
    that equivalence test were removed together once the comparison passed, per the obsolete-path
    rule; the renderer's remaining image tests are the pins that carry the same coverage forward.
  - Every pass reports a visible GPU timestamp: "pass timings stay empty until a frame retirement
    is observed", "pass timings name every pass the graph ran", and "pass timings report every
    pass of the retired frame", backing the Stats panel's per-pass listing.

## Deliberate limits

MaterialLab's roughness×metallic sweep is visually near-invisible under its constant environment —
the furnace property that makes the diagnostic exact also makes a white sphere vanish into a
uniform sky regardless of roughness; correct, but diagnostically weak until a captured
non-uniform environment arrives. PCSS's blocker search still mixes a view-space near-plane
constant with NDC-space receiver depth, a unit-parameterization quirk preserved through the
reversed-Z migration and deferred rather than fixed. The default editor clear renders darker
through the PBR Neutral display transform's black offset; the authored constant has not been
re-tuned for it. IBL regenerates per scene load for what is currently always a constant sky —
cheap today, worth caching once environments grow. Direct lighting is single-scatter; only the
image-based term carries multi-scatter compensation. Baked-DDS selection keys on image index
alone, so a glTF file that reused one image in both a color and a data role would need the offline
bake to distinguish them, which it does not yet do — a latent hazard rather than an observed one
in the two shipped scenes. Sponza's startup is still synchronous, blocking the window until decode
and upload finish.
