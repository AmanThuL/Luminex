# M4.1 — RHI Foundation and Reference Lookdev

**Status**: Implemented (2026-08-10)

M4.1 preserved the M4 renderer while strengthening both its component boundary and its reference
lookdev scene. The RHI is now a repository-root component, and MaterialLab opens on a readable
roughness/metallic matrix under a neutral studio environment rather than a distant grid against a
flat blue sky.

The RHI public surface lives under `RHI/Include/RHI/`, its shared implementation under
`RHI/Source/`, and its Metal 4 backend under `RHI/Backends/Metal4/Source/`. `RHI/xmake.lua` owns the
component build, keeps metal-cpp and backend headers private, and exposes Dear ImGui integration
through the separate `RHIMetal4ImGui` target and its own integration include tree. Existing
`RHI/...` includes, namespaces, signatures, and runtime failure behavior remain unchanged.

RHI failures remain domain-owned. `RHI/Result.h` now carries `ErrorCode`, `Error`, and `Result<T>` as
a self-contained public contract; Engine assets, Render Graph declarations, and App options retain
their more specific error types instead of collapsing into a shared cross-domain error.

Every project-owned C++ source and header under `Source/` and `RHI/` now begins with a checked
120-character file envelope. Public and protected header APIs use Doxygen contracts, while private
implementation comments retain the existing sparse function-boundary style. Policy uses Clang's AST
and parsed comments to distinguish public API from private declarations, and independently compiles
each core RHI header to prevent accidental transitive, Metal, or ImGui dependencies.

MaterialLab now uses Poly Haven's CC0 Studio Small 09 1K HDRI, pinned and verified by `xmake setup`
with provenance and license metadata. Radiance HDR pixels decode to finite scene-linear values and
resample deterministically into the project's cubemap convention. One exposure-scaled 32px CPU
cubemap feeds both the visible RGBA16Float sky and the generated irradiance/specular IBL set, so
background and reflections cannot drift in orientation or radiance. If the fetched environment is
missing or invalid, the scene logs the reason and remains available with a neutral constant
environment and analytic light rig.

The default camera moved from `(0, 0, 80)` to `(0, 0, 12)`, making all 25 spheres prominent. The
scene is a horizontal strip: material spheres at X=0, color/texture/normal diagnostics at X=14, and
depth diagnostics at X=28. Translating the camera along X visits each complete group without a yaw,
pitch, FOV, or Z change. The minification oracle remains behind the normal view.

## Evidence

- `xmake format --check`, `xmake policy`, and `xmake` passed. Policy checked all 64 owned C++ files,
  parsed public API documentation through the compilation database, and compiled all five core RHI
  headers independently. The optional ImGui extension compiled with its owning adapter target.
- `xmake test Tests/unit` and the complete `xmake test` suite passed.
- `MTL_DEBUG_LAYER=1 xmake test Tests/gpu` passed on an Apple M3 Max with Metal API validation.
- HDR decode/conversion coverage passed 242 assertions across five cases, including scene-linear
  values, seams, yaw, bilinear reconstruction, malformed inputs, and missing files. MaterialLab's
  focused GPU coverage passed 227 assertions across ten cases, including forced studio fallback,
  no analytic double-lighting, default framing, X-only lane framing, and the retained image oracles.
- MaterialLab produced a 1280x720 offscreen capture with all 25 spheres visible against a neutral
  studio cyc and readable softbox highlights. A second run with the fetched directory temporarily
  hidden logged the fallback and produced a valid neutral frame. Sponza and Damaged Helmet remained
  green in the complete scene and GPU coverage.
- The core `RHI` target built without ImGui, while App built through the explicit
  `RHIMetal4ImGui` dependency. Normal RHI consumers inherited only `RHI/Include`.
- Three forced RHI rebuilds measured 4.05, 4.10, and 4.07 seconds. That scale did not justify a
  target-private precompiled header, so explicit self-contained includes remain the maintained path.

## Deliberate limits

The root component is extraction-ready, not standalone: its implementation still uses Luminex Core
logging and assertions, and capture/debug tooling remains integrated with the host repository. The
Metal 4 capture and ImGui headers are explicit backend extensions rather than part of the neutral
surface. Publishing a separate repository would still need a diagnostics integration contract,
package metadata, and ownership decisions for conformance tests. Caller-facing interface experiments
remain reserved for M5.1; this maintenance boundary did not pre-empt them.

MaterialLab's studio environment is intentionally fixed: there is no environment browser, arbitrary
HDR import, automatic exposure, GPU IBL generation, or cache. The 32px cubemap is sized for the
existing deterministic CPU convolution and the soft studio source, not general high-frequency
environments. Horizontal movement uses the existing fly camera rather than a new bookmark or label
system.
