# R1.1 — Module Contract and Enforcement

**Status**: Implemented (2026-09-13)

R1.1 turned the layering convention into a machine-readable contract. `Tools/module_contract.json`
names thirteen units, each with an explicit path/target mapping, allowed unit and third-party
dependency set, and (for `asset`) a header allowance; `docs/conventions/modules.md` is its prose
twin. `Tools/check_module_deps.py` reconciles source ownership with xmake target membership from
`xmake lua Tools/xmake_targets.lua` (never by parsing `xmake show` output), resolves quoted and
angle includes through each target's real compilation context, follows project includes
transitively, and checks target dependency closures; `--link` additionally checks linked
frameworks and archive symbols on a release build. `Tools/check_source_headers.py` compiles every
`Source/` header standalone with its owning target's own flags (no added `-Werror`, unlike the
stricter dependency-free RHI public-header check). `Tools/module_allowlist.json` records every
current contract violation with a reason and an `until` slice; an entry that stops matching a
violation, or that nothing violates, fails the check. Both checkers run by default in `xmake
policy` and in CI's `build-test` job after `compile_commands`; `--link` runs separately in CI
after `Build`, since it needs a built archive. ADR 0020 (module layering and units) is Accepted.

The ImGui adapter's two sources, `Metal4ImGui.cpp` and `ImGuiBackendContract.cpp`, moved from
`RHI/Backends/Metal4/Source/` to `RHI/Backends/Metal4/ImGui/Source/`, alongside the adapter's
existing public header directory — the only source motion in this slice. `RHI/xmake.lua`'s
`RHIMetal4ImGui` target now names the new paths and keeps its own `add_includedirs` for the
sources' unrooted includes. This closed the `imgui-adapter` unit's ownership map/target agreement
and removed both the ownership and the transitional include violations the unit carried before the
move.

directory or package. All 32 entries carry `until` values of `R1.2` or `R1.3`, matching the roadmap
contract's exit gate:

- **`until: R1.3`** (14 `shared-source` entries) — the fourteen `app-model`-designate sources

  - 10 `include` entries: `DdsLoader.{h,cpp}`, `Ibl.{h,cpp}`, `TextureBake.{h,cpp}` and
    `HdrEnvironment.{h,cpp}` reaching `rhi-public` through `RHI/RHI.h` (directly, or through

## Deliberate limits

- The archive-symbol check under `--link` sees only non-virtual `lmx::rhi` symbols in a static
  library's own object files; a caller that reaches RHI purely through virtual dispatch leaves no
  undefined symbol, so this layer is a backstop under the include and link-dependency layers, never
  a substitute for them. It also passes vacuously for a static-library target with no matching
  symbols regardless of whether the target actually needs the framework checked.
- `--link` needs a release build (`xmake -y`) to inspect linked frameworks and archived object
  files; it cannot run against source alone, which is why the default `xmake policy` run and CI's
  post-`compile_commands` step run only the include/ownership/closure checks, and `--link` runs as
  a separate CI step after `Build`.
- Target membership for ownership reconciliation comes from `xmake lua Tools/xmake_targets.lua`,
  a dedicated dump script, rather than from parsing `xmake show` output column-by-column, so a
  future xmake output format change cannot silently desynchronize the checker from the build.
- This slice moved no source other than the ImGui adapter; the 32-entry allowlist is R1.2's and
  R1.3's remaining work, not new debt introduced here.
