# R1.1 — Module Contract and Enforcement

**Status**: Implemented (2026-09-13)

R1.1 turned the layering convention into a machine-readable contract. `Tools/module_contract.json`
names thirteen units, each with an explicit path/target mapping, allowed unit and third-party
dependency set, and (for `asset`) a header allowance; `docs/conventions/modules.md` is its prose
twin. `Tools/check_module_deps.py` reconciles source ownership with xmake target membership from
`xmake lua Tools/xmake_targets.lua` (never by parsing `xmake show` output), resolves quoted and
angle includes through each target's real compilation context, follows project includes
transitively, and checks target dependency closures; `--link` additionally checks linked
frameworks and archive symbols on a release build. `Tools/check_source_headers.py` compiles every
`Source/` header standalone with its owning target's own flags (no added `-Werror`, unlike the
stricter dependency-free RHI public-header check). `Tools/module_allowlist.json` records every
current contract violation with a reason and an `until` slice; an entry that stops matching a
violation, or that nothing violates, fails the check. Both checkers run by default in `xmake
policy` and in CI's `build-test` job after `compile_commands`; `--link` runs separately in CI
after `Build`, since it needs a built archive. ADR 0020 (module layering and units) is Accepted.

The ImGui adapter's two sources, `Metal4ImGui.cpp` and `ImGuiBackendContract.cpp`, moved from
`RHI/Backends/Metal4/Source/` to `RHI/Backends/Metal4/ImGui/Source/`, alongside the adapter's
existing public header directory — the only source motion in this slice. `RHI/xmake.lua`'s
`RHIMetal4ImGui` target now names the new paths and keeps its own `add_includedirs` for the
sources' unrooted includes. This closed the `imgui-adapter` unit's ownership map/target agreement
and removed both the ownership and the transitional include violations the unit carried before the
move.

Every entry in `Tools/module_allowlist.json` names one forbidden edge; none names a whole unit,
directory or package. All 34 entries carry `until` values of `R1.2` or `R1.3`, matching the roadmap
contract's exit gate (counts taken from the JSON, not recalled from memory):

- **`until: R1.3`** (14 `shared-source` entries) — the fourteen `app-model`-designate sources
  (`AppOptions`, `CaptureMetadata`, `DynamicResolution`, `EditorActions`, `EditorSelection`,
  `ExposureReset`, `FrameRecordRing`, `GraphInspectorModel`, `GraphLayout`, `GraphNodeModel`,
  `PassTimingHistory`, `PerformanceModel`, `TemporalEditorState`, `WorkspaceModel`) that both `App`
  and `Tests` compile directly, since neither target yet links a separate `AppModel` library. R1.3
  gives `app-model` its own target and removes all fourteen at once.
- **`until: R1.2`** (20 entries) — everything asset- and `TextureBake`-shaped, all removed when
  R1.2 splits `Source/Engine`'s asset files into `Source/Asset`/`Asset` and gives `TextureBake` a
  direct `Asset` dependency instead of the whole `Engine` chain:
  - 13 `include` entries: `DdsLoader.{h,cpp}`, `Ibl.{h,cpp}`, `TextureBake.{h,cpp}` and
    `HdrEnvironment.{h,cpp}` reaching `rhi-public` through `RHI/RHI.h` (directly, or through
    `Ibl.h`) — 8 entries; `GltfLoader.{h,cpp}` reaching `render` through `Render/AlphaMode.h` — 2
    entries; `GltfLoader.cpp` additionally reaching `scene` and, through `Scene.h`, `rhi-public` —
    2 entries; `Tools/TextureBake/main.cpp` reaching `rhi-public` through `Engine/TextureBake.h`
    — 1 entry.
  - 3 `target-dep` entries: `TextureBake` depending on `Engine`, and transitively on `RHI` and
    `Render`, outside its allowed `core`/`asset` set.
  - 4 `framework` entries (checked only under `--link`): `TextureBake` linking `Metal`, `MetalFX`,
    `QuartzCore` and `Foundation` transitively through `RHI`.

Before the adapter move, the default checker run (which does not check frameworks) reported 35
errors: the 30 above that are checked by default (14 `shared-source` + 13 `include` + 3
`target-dep`) plus 5 errors from the ImGui adapter's ownership mismatch and transitional includes
(its two sources still under `RHI/Backends/Metal4/Source`), all foreseen by the contract's own
transitional note and removed by the source move rather than by an allowlist entry. The remaining
4 `framework` entries are checked only under `--link`. After the move and this allowlist, both the
default run and `--link` report zero errors.

## Deliberate limits

- `--link`'s framework check (`otool -L`) is vacuous for a static-library target: a static archive
  links nothing at build time, so it names no framework regardless of what its sources reference.
  It proves something only for an executable or shared target — today, `TextureBake`.
- `--link`'s undefined-symbol check (`nm -u`, driven by a contract target's `forbidUndefined`
  prefix) is the layer a static library needs instead, but no contract target declares
  `forbidUndefined` yet, so it runs on nothing today; R1.2 adds `Asset`'s entry once that target
  exists. Even then it would see only non-virtual `lmx::rhi` symbols — a caller that reaches RHI
  purely through virtual dispatch leaves no undefined symbol — so it is a backstop under the
  include and framework layers, never a substitute for them.
- `--link` needs a release build (`xmake -y`) to inspect linked frameworks and archived object
  files; it cannot run against source alone, which is why the default `xmake policy` run and CI's
  post-`compile_commands` step run only the include/ownership/closure checks, and `--link` runs as
  a separate CI step after `Build`.
- Target membership for ownership reconciliation comes from `xmake lua Tools/xmake_targets.lua`,
  a dedicated dump script, rather than from parsing `xmake show` output column-by-column, so a
  future xmake output format change cannot silently desynchronize the checker from the build.
- This slice moved no source other than the ImGui adapter; the 34-entry allowlist is R1.2's and
  R1.3's remaining work, not new debt introduced here.
