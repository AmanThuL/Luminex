# M5.5 — Render Graph Legibility and Detached Window

**Status**: Implemented (2026-09-05)

M5.5 made the Render Graph node view readable for real frames, without changing render-graph
execution, image formation, RHI semantics, or the `GraphNodeModel` M5.4 shapes from a
`CompiledFrameRecord`. `GraphLayout` (`Source/App/GraphLayout.h/.cpp`) is a pure, ImGui-free
function of that model, an expansion set, and a column count: it keys every pass whose label clears
a four-segment threshold — a label with fewer segments, such as `lmx.pass.scene`, is already the
whole name with no step to fold away and never groups — by its dotted prefix, wherever that prefix
occurs in declaration order (grouping is never conditioned on adjacency), into one stage; splits
that set into a scheduled group and a `#culled` group where members disagree on cull status; forms
a group only where it reaches at least two members after that split; draws a collapsed group as one
node whose only pins are the boundary versions its visible edges cross, deduplicated per `(item,
item, resource, version)`; and restores the per-node picture when a group expands. Every item's
layer is its longest visible-edge path from a producer-less item. `columnsPerRow` controls
wrapping: zero leaves the whole chain in one unwrapped row, and a positive value sits each layer at
row `layer / columnsPerRow`, column `layer % columnsPerRow`, with the culled band kept below the
wrapped rows either way. A `signature` covering the drawn shape, the expansion set, and the column
count — never timing — tells the panel when positions must reapply.

Dear ImGui platform viewports are enabled, and the Render Graph window is submitted with a
dedicated `ImGuiWindowClass` (docking with unclassed windows disallowed, auto-merge overridden
off), so it always opens as its own OS window beside the main one on first use and never docks;
Scene, Viewport, Inspector, and Performance keep the M5.3 docked layout unchanged. The frame loop
calls `ImGui::UpdatePlatformWindows()`/`RenderPlatformWindowsDefault()` after each presented frame,
and the vendored Metal 4 ImGui backend renders the detached window with its own command buffer and
per-slot pacing event — a fix to a real defect the vendored library shipped with: `NewFrame` waited
on a single monotonic counter for a slot that had never signalled it, deadlocking the second frame
after any extra window rendered. The fix is one more hunk in Luminex's maintained patch
(`Tools/Patches/imgui-metal4-remove-texture.patch`, applied by `xmake setup`): one pending value per
frame slot, so a slot waits only on its own last signal.

The panel (`Source/App/Panels/RenderGraphPanel.cpp`) draws a `GraphLayout` on the same vendored
node-editor canvas as M5.4: node items carry compact pins (a dot plus `sceneColorHdr v1`), with the
full `r3 "lmx.render.sceneColorHdr" v1` label shown for a hovered pin (via `ed::Suspend`/`Resume`
and `SetTooltip`) and for the selected item and its visible-edge neighbours; a collapsed group node
carries a `<stage> — N passes — X.XXX ms (k measured)` header and its boundary pins. Double-clicking
a group's body or header toggles it open; a header `columns` control (1–32) edits the wrap width
directly, and Reset Layout reseeds it from `max(2, floor(canvasWidth / kGraphLayoutColumnSpacing))`
alongside restoring dragged positions. The details pane is item-based: a group shows its key,
member count, summed and measured GPU time, a per-member table, and an Expand/Collapse button.

## Evidence

**Automated**, on Metal 4 Apple Silicon (Apple M3 Max, macOS 26.5.2):

- `xmake test Tests/unit` and `MTL_DEBUG_LAYER=1 xmake test Tests/gpu` both 100% pass; the same
  binary run directly (`./Tests "~[gpu]"` and `MTL_DEBUG_LAYER=1 ./Tests "[gpu]"`, from the Tests
  build directory) reports 77,377 assertions in 398 test cases and 11,395 assertions in 97 test
  cases respectively. `AppGraphLayoutTests.cpp` carries the grouping, collapsing, layering,
  wrapping, and signature cases the spec requires, including the M5.4 layout cases rewritten over
  `layoutGraph`; the existing `[gpu]` inspector-agreement case is extended to lay out the retained
  frame both collapsed and with every group expanded — item counts match the model's
  node-minus-grouped-members-plus-groups arithmetic in both directions, the one formed group
  (`lmx.test.inspector`, the two scheduled passes) is asserted by key and member count, the
  always-culled `orphanFill` pass is asserted to stay ungrouped under the two-member minimum, and
  every edge's endpoints index a real drawn item.
- The frozen `[checkpoint-a]` filter passed unchanged under `MTL_DEBUG_LAYER=1`: 1,856 assertions in
  19 test cases — identical to the M5.3 and M5.4 baseline, confirming no added portability surface.
- `xmake format --check`, `xmake policy`, and `python3 Tools/check_project_policy.py --commits
  origin/main..HEAD` (covering M5.4's and M5.5's commits together) all clean.
- `LMX_MAX_FRAMES=120 MTL_DEBUG_LAYER=1 xmake run App`, with the panel's detached window open,
  presented 120 frames, skipped 0, with no Metal validation diagnostics.
- Fixed-camera 1280×720 offscreen screenshots of Sponza, Damaged Helmet, and MaterialLab at the tip
  are byte-identical (SHA-256) to the M5.4-tip baseline: renderer output is unchanged.
- The detached-window spike (Task 2) found the backend deadlock above by first reproducing a hang
  at 120 frames with zero validation output, isolated it to the per-slot/global-counter mismatch,
  and confirmed the fix clean over a 120-frame run, a 140-frame headless run driving an SDL resize,
  move, close, and reopen of the platform window (viewport count toggling 2 → 1 → 2 exactly on
  close/reopen), and a GPU capture whose blob inventory carried two `CAMetalLayer` drawables where
  the pre-fix control (backend renderer suppressed) carried one.
- A throwaway headless smoke (Task 3), reverted before commit, injected a synthetic double-click on
  the collapsed bloom group and confirmed the drawn item count grew from 7 to 15 (the group's nine
  members replacing the one group node); a second variant aimed the mouse at a pin inside that group
  and confirmed the hovered-tooltip path fired with the full label. A third throwaway smoke toggled
  bloom with the group already expanded and confirmed exactly one clean relayout back to 7 items,
  with a stale expansion key left in the set, no crash, and no validation output.

**Manual visual QA** is left for the operator: the detached window opens and reads clearly at its
default size; a stage group expands and collapses on double-click; hovering a compact pin shows its
full label; a long chain wraps across rows as `columns` changes; and dragged positions survive
unrelated frames and reset visibly on Reset Layout.

## Deliberate limits and deviations

- **The vendored ImGui Metal 4 backend shipped a real defect** (single global pacing counter
  compared against a per-slot pending value), independent of anything Luminex's App code could
  configure around. The fix lives in Luminex's maintained patch, which is a rebase obligation on the
  next `imgui_pin` update and worth reporting upstream.
- **Multiple simultaneously detached windows are untested.** Only the Render Graph panel opens its
  own OS window; the spike's open/resize/move/close/reopen matrix covers exactly one.
- **Collapsing can make the item graph cyclic.** A stage that feeds a pass that feeds the same stage
  becomes one box pointing at itself once collapsed; an edge arriving from an item not yet settled
  in schedule order does not push a layer. Unreachable for any shipped scene's stages and untested.
- **The two-member group minimum is checked after the culled split**, not before: a key naming two
  passes where one was culled forms no group at all, since each side of the split has only one
  member.
- **The hover tooltip fires even on a pin already showing its full label** (the selected item and
  its visible-edge neighbours), duplicating information already on screen rather than suppressing
  itself.
- **A double-click landing on a pin is reported by the node editor as a pin double-click**, not a
  node double-click, so a group only expands via its header, its body, or the details pane's Expand
  button — never by double-clicking one of its own pins.
- **Reset Layout re-seeds the column count from the canvas width**, discarding any value the user
  set through the `columns` control.
- **Alias links still have no runtime evidence**, carried from M5.4: every shipped scene's graph
  transients have lifetime-overlapping spans, so the compiler never emits an `aliasedFrom`
  transition and `GraphNodeModel::aliasLinks` stays empty in every observed frame. The alias-link
  derivation and its dashed-line drawing are unit-tested against a synthetic fixture but unseen on
  screen.
- **Drag, double-click, hover, and relayout were verified by headless ImGui-event-injected smokes,
  not by a human** (see Evidence). The interaction code itself is unmodified upstream node-editor
  and platform-viewport logic.
- **Visual sign-off is entirely left to the operator's manual QA pass** (see above); every automated
  check above is log-, count-, or hash-based, not a human look at the canvas.
- **A pre-existing double-shutdown in `EditorShell::create`'s initial-scene-failure path**, recorded
  in the M5.3 milestone, still stands. It predates M5.3 through M5.5 alike and remains outside any
  of their scope.
