# M5.5 — Render Graph Legibility and Detached Window

**Status**: Implemented (2026-09-05)

M5.5 made the Render Graph node view readable for real frames, without changing render-graph
execution, image formation, RHI semantics, or the `GraphNodeModel` M5.4 shapes from a
`CompiledFrameRecord`. `GraphLayout` (`Source/App/GraphLayout.h/.cpp`) is a pure, ImGui-free
function of that model, an expansion set, and a column count: it keys every pass whose label clears
a four-segment threshold — a label with fewer segments, such as `lmx.pass.scene`, is already the
whole name with no step to fold away and never groups — by its dotted prefix, wherever that prefix
occurs in declaration order (grouping is never conditioned on adjacency), into one stage; splits
that set into a scheduled group and a `#culled` group where members disagree on cull status; forms
a group only where it reaches at least two members after that split; draws a collapsed group as one
node whose only pins are the boundary versions its visible edges cross, deduplicated per `(item,
item, resource, version)`; and restores the per-node picture when a group expands. Every item's
layer is its longest visible-edge path from a producer-less item. `columnsPerRow` controls
wrapping: zero, the default, leaves the whole chain in one unwrapped row, and a positive value sits
each layer at row `layer / columnsPerRow`, column `layer % columnsPerRow`, with the culled band kept
one row past the last either way. Layers, ranks, rows, and columns are all `GraphLayout` decides:
it declares no spacing constants and carries no coordinates, because a card's width is the width of
the text in it and only the panel can measure that. A `signature` covering the drawn shape, the
expansion set, and the column count — never timing — tells the panel when placement must reapply.

Dear ImGui platform viewports are enabled, and the Render Graph window is submitted with a
dedicated `ImGuiWindowClass` (docking with unclassed windows disallowed, auto-merge overridden
off) plus `ImGuiWindowFlags_NoDocking` -- the class refuses drop targets, the flag refuses a
`DockId` a pre-M5.5 `imgui.ini` persisted -- so it always opens as its own OS window beside the
main one on first use and never docks; Scene, Viewport, Inspector, and Performance keep the M5.3
docked layout unchanged. The workspace schema is 2 for that reason: a `Schema=1` ini's dock data
still holds a node for the panel, so such an ini is legacy and rebuilds the default layout once.
The frame loop calls `ImGui::UpdatePlatformWindows()`/`RenderPlatformWindowsDefault()` after each
presented frame, and the vendored Metal 4 ImGui backend renders the detached window with its own
command buffer and per-slot pacing event — a fix to a real defect the vendored library shipped
with: `NewFrame` waited on a single monotonic counter for a slot that had never signalled it,
deadlocking the second frame after any extra window rendered. The fix is one more hunk in
Luminex's maintained patch (`Tools/Patches/imgui-metal4-remove-texture.patch`, applied by `xmake
setup`): one pending value per frame slot, so a slot waits only on its own last signal. The same
patch also drains an autorelease pool around that render path and releases the backend's owned
command buffer: compiled without ARC under a frame loop that drains no pool, upstream's code
otherwise leaked one drawable -- and its IOSurface -- per frame of the detached window.

The panel (`Source/App/Panels/RenderGraphPanel.cpp`) draws a `GraphLayout` on the same vendored
node-editor canvas as M5.4, as Falcor-style cards: a filled title band in the kind's colour across
the full card width (`#order name` left, `kind X.XXX ms` right; `culled <reason>` for a dead pass,
`> stage` against `N passes X.XXX ms` for a collapsed group), then a body with inputs down the left
and outputs down the right and every pin dot centred exactly on the card's edge. The editor's node
padding is zero so a band reaches the rounded corner and a dot can sit on the silhouette; the dots
are drawn into the node's content channel rather than as ImGui items, since an item past the edge
would grow the card around it. `ed::PinPivotRect` anchors each link at its dot, and with the link
directions stated and `LinkStrength` at 180 a link leaves and arrives horizontally on a round curve
2.5 thick, coloured from eight hues by `resource % 8` so one resource always reads in one colour.
Pins keep the compact `sceneColorHdr v1` label, with the full `r3 "lmx.render.sceneColorHdr" v1`
shown for a hovered pin (via `ed::Suspend`/`Resume` and `SetTooltip`) and for the selected item and
its visible-edge neighbours.

Placement is measured rather than pitched: a column is as wide as its widest card, a row as tall as
its rank count times its tallest card, and the gaps (`kColumnGap = 120`, `kRankGap = 40`,
`kRowGap = 100`, `kCulledBandGap = 140`) are the panel's. A card reports no size until the editor
has laid it out once, so a changed picture is drawn one frame at a coarse provisional grid purely to
be measured, placed from those measurements on the next, and then left alone —
`RenderGraphPanelState::layoutPhase` is that `Provisional`/`Measured`/`Settled` sequence, and the
view fits to content as it settles. Double-clicking a group's body or header toggles it open; the
header `columns` control (0–32) defaults to 0, labelled `no wrap`, and Reset Layout re-measures and
re-places without seeding a column count. The details pane is item-based: a group shows its key,
member count, summed and measured GPU time, a per-member table, and an Expand/Collapse button.

## Evidence

**Automated**, on Metal 4 Apple Silicon (Apple M3 Max, macOS 26.5.2):

- `xmake test Tests/unit` and `MTL_DEBUG_LAYER=1 xmake test Tests/gpu` both 100% pass; the same
  binary run directly (`./Tests "~[gpu]"` and `MTL_DEBUG_LAYER=1 ./Tests "[gpu]"`, from the Tests
  build directory) reports 77,377 assertions in 398 test cases and 11,395 assertions in 97 test
  cases respectively. `AppGraphLayoutTests.cpp` carries the grouping, collapsing, layering,
  wrapping, and signature cases the spec requires, including the M5.4 layout cases rewritten over
  `layoutGraph`; the existing `[gpu]` inspector-agreement case is extended to lay out the retained
  frame both collapsed and with every group expanded — item counts match the model's
  node-minus-grouped-members-plus-groups arithmetic in both directions, the one formed group
  (`lmx.test.inspector`, the two scheduled passes) is asserted by key and member count, the
  always-culled `orphanFill` pass is asserted to stay ungrouped under the two-member minimum, and
  every edge's endpoints index a real drawn item.
- The frozen `[checkpoint-a]` filter passed unchanged under `MTL_DEBUG_LAYER=1`: 1,856 assertions in
  19 test cases — identical to the M5.3 and M5.4 baseline, confirming no added portability surface.
- `xmake format --check`, `xmake policy`, and `python3 Tools/check_project_policy.py --commits
  origin/main..HEAD` (covering M5.4's and M5.5's commits together) all clean.
- `LMX_MAX_FRAMES=120 MTL_DEBUG_LAYER=1 xmake run App`, with the panel's detached window open,
  presented 120 frames, skipped 0, with no Metal validation diagnostics.
- Fixed-camera 1280×720 offscreen screenshots of Sponza, Damaged Helmet, and MaterialLab at the tip
  are byte-identical (SHA-256) to the M5.4-tip baseline: renderer output is unchanged.
- The detached-window spike (Task 2) found the backend deadlock above by first reproducing a hang
  at 120 frames with zero validation output, isolated it to the per-slot/global-counter mismatch,
  and confirmed the fix clean over a 120-frame run, a 140-frame headless run driving an SDL resize,
  move, close, and reopen of the platform window (viewport count toggling 2 → 1 → 2 exactly on
  close/reopen), and a GPU capture whose blob inventory carried two `CAMetalLayer` drawables where
  the pre-fix control (backend renderer suppressed) carried one.
- The drawable leak was found by the operator's manual QA (a 62 GB footprint, 61 GB of it 3,204
  IOSurface regions of the detached window's size) and reproduced with the runtime's own probe:
  `OBJC_DEBUG_MISSING_POOLS=YES LMX_MAX_FRAMES=240` reported 239 `CAMetalDrawable` and 239 render
  context objects autoreleased with no pool in place before the fix and none after, with the
  remaining per-frame reports identical to a run with the panel hidden; a 900-frame
  `MTL_DEBUG_LAYER=1` run with the window open stayed validation-clean.
- The main-thread autorelease leak was pinned with the same probe and closed by the destructor
  fix. `OBJC_DEBUG_MISSING_POOLS=YES ./App` grouped by class: before, 3,035 `AGXG15CDevice` at
  `LMX_MAX_FRAMES=240` and 10,295 at 900 — 11 per frame, all of them on the main thread's stack.
  After, 2 at 240 and 2 at 900: flat in frame count, and both on Apple's worker threads, with the
  main thread reporting nothing at all at either length. The `CAMetalLayer`/`__NSCFNumber`/
  `__NSArrayI_Transfer` lines still scale with frames (1,786 / 3,570 / 3,596 at 900, unchanged by
  the fix) and stay on the secondary thread stacks that produce them.
- A throwaway headless smoke, reverted before commit, injected a synthetic double-click on
  the collapsed bloom group and confirmed the drawn item count grew from 7 to 15 (the group's nine
  members replacing the one group node); a second variant aimed the mouse at a pin inside that group
  and confirmed the hovered-tooltip path fired with the full label. A third throwaway smoke toggled
  bloom with the group already expanded and confirmed exactly one clean relayout back to 7 items,
  with a stale expansion key left in the set, no crash, and no validation output.

**Manual visual QA** is left for the operator: the detached window opens and reads clearly at its
default size; a stage group expands and collapses on double-click; hovering a compact pin shows its
full label; links leave and arrive at the pin dots; a long chain wraps across rows as `columns`
leaves 0; and dragged positions survive unrelated frames and reset visibly on Reset Layout.

## Deliberate limits and deviations

- **The vendored ImGui Metal 4 backend shipped a real defect** (single global pacing counter
  compared against a per-slot pending value), independent of anything Luminex's App code could
  configure around. The fix lives in Luminex's maintained patch, which is a rebase obligation on the
  next `imgui_pin` update and worth reporting upstream.
- **The main-window path autoreleased without a pool too, and that is now fixed.** The follow-up
  this bullet once deferred was traced to a gap in the RHI's own pool contract rather than to the
  App frame loop: the backend opens a pool in every function that touches Metal, but a destructor's
  pool dies with its body, and the wrapper's `NS::SharedPtr` members were released *after* that.
  Since `-[IOGPUMetalResource dealloc]` autoreleases internally, every wrapper destroyed this way
  leaked its Metal object — about eleven per frame from the transient pool's textures and their
  cached views, and 280 at shutdown from the device. Every Metal 4 wrapper now releases its Metal
  objects explicitly, inside its destructor's pool, in the order its invariants require
  (`ResidencyRegistration::reset()` before the allocation it registered); the rule is stated once
  in `Metal4Common.h`. The runtime's own probe is the regression check. What remains per frame is
  Apple's: `CAMetalLayer`, `__NSCFNumber`, and `__NSArrayI_Transfer` reports on the FramePacing and
  CoreAnimation worker threads, which no Luminex pool can enclose.
- **Multiple simultaneously detached windows are untested.** Only the Render Graph panel opens its
  own OS window; the spike's open/resize/move/close/reopen matrix covers exactly one.
- **Collapsing can make the item graph cyclic.** A stage that feeds a pass that feeds the same stage
  becomes one box pointing at itself once collapsed; an edge arriving from an item not yet settled
  in schedule order does not push a layer. Unreachable for any shipped scene's stages and untested.
- **The two-member group minimum is checked after the culled split**, not before: a key naming two
  passes where one was culled forms no group at all, since each side of the split has only one
  member.
- **The hover tooltip fires even on a pin already showing its full label** (the selected item and
  its visible-edge neighbours), duplicating information already on screen rather than suppressing
  itself.
- **A double-click landing on a pin is reported by the node editor as a pin double-click**, not a
  node double-click, so a group only expands via its header, its body, or the details pane's Expand
  button — never by double-clicking one of its own pins.
- **A selection widens the cards it expands after they were measured.** Placement is measured with
  every pin at its compact label; selecting an item spells its neighbourhood's labels out in full,
  which can widen those cards past the column they were measured into. Reset Layout re-measures.
- **Fitting to content on settle can leave a long chain small.** The node editor's zoom levels are
  discrete, so a thirteen-layer frame fits at a step where the card text is not readable until the
  user zooms in; that is the trade the no-wrap default makes deliberately.
- **The card titles are ASCII.** The editor ships Dear ImGui's default font, so the `>` marking an
  openable group and the plain spaces separating a title's fields stand in for the typographic
  marks the design named.
- **Alias links still have no runtime evidence**, carried from M5.4: every shipped scene's graph
  transients have lifetime-overlapping spans, so the compiler never emits an `aliasedFrom`
  transition and `GraphNodeModel::aliasLinks` stays empty in every observed frame. The alias-link
  derivation and its dashed-line drawing are unit-tested against a synthetic fixture but unseen on
  screen.
- **Drag, double-click, hover, and relayout were verified by headless ImGui-event-injected smokes,
  not by a human** (see Evidence). The interaction code itself is unmodified upstream node-editor
  and platform-viewport logic.
- **Visual sign-off is entirely left to the operator's manual QA pass** (see above); every automated
  check above is log-, count-, or hash-based, not a human look at the canvas.
- **A pre-existing double-shutdown in `EditorShell::create`'s initial-scene-failure path**, recorded
  in the M5.3 milestone, still stands. It predates M5.3 through M5.5 alike and remains outside any
  of their scope.
