# M7.2 — Visibility Gate Reassessment

**Status**: Implemented — owner-accepted for integration 2026-09-15; revised image gate failed

The owner requested a first-principles reassessment of the original cull/off result, 13/15 exact
images, and authorized writing the method into AGENTS.md only if the revised gate passed.
This follow-up ran 180 new captures and an exact pre-temporal GPU fixture. The proposed replacement
gate did **not** pass. AGENTS.md therefore does not adopt it; the original exact failure remains.
The [owner acceptance](m7.2-validation.md#owner-acceptance-and-integration) on 2026-09-15 authorizes integration with these failures retained; it does not adopt a new tolerance or gate. M7.3 stays inactive.

## What the principles require

Removing a conservatively rejected object must preserve its zero contribution to camera raster
attachments. This remains an exact requirement. A world-space guard cannot be converted into an
8-bit SDR tolerance without accounting for every subsequent transform, filter and history step.
Nor does an observed three-code difference justify a universal allowance of three codes.

The [experimental procedure](../guides/visibility-image-validation.md) separates exact geometry
from same-setting output repeatability. It derives a per-pixel/channel min/max interval exclusively
from unculled controls, freezes it, then requires every fresh off/cull sample to remain inside it
with zero extra slack. Independent engineering ceilings limit the interval's total drift.
Those ceiling constants are inherited policy, not mathematically derived error bounds.

## Exact geometry evidence

The new [GPU fixture](../../Tests/GpuVisibilityContributionTests.cpp) renders 15 rejected quads
(five planes, opaque/masked/two-sided variants) with real scene shaders. It compares culled and
forced-submitted geometry against explicit empty-scene controls, then adds retained boundary and
mask/motion controls so a renderer that draws nothing cannot pass.

- Both render scales, 1.0 and 0.5, run all 16 jitter phases: 64 frames / 192 declarations.
- HDR, depth, motion and reactive attachments agree exactly between cull/off. Rejected-only
  attachments equal empty controls; retained masks check transparent/solid texels, front/back
  faces, invalid motion and nonzero rigid motion. Direct clip inequalities independently check
  the rejected vertices, and the renderer's jitter index is checked for every phase.
- Depth uses a test-only texture Load/asuint readback shader because the neutral RHI does not
  expose direct private-depth readback or D32 buffer copies. Production rendering is unchanged.
- Metal validation: **1 case / 253193 assertions PASS**. This is finite fixture coverage, not a
  proof for every scene or floating-point magnitude. Shadow rejection stays zero; this fixture
  does not claim a new shadow-depth oracle.

### First calibration: visibility-null-envelope-v1

Each case has nine controls: one original unculled anchor plus eight fresh unculled processes.
All fifteen anchors enter uniformly; original cull images and selected-case diagnostics do not
train the interval. This is 135 training images, including 120 newly captured images.

The whole min/max span had to satisfy M7.1 strict for every reconstruction mode. Eleven cases
passed calibration; four MetalFX spans failed. No holdout ran under that policy. These four
fresh-eight spans are identical to the corresponding nine-input spans, so the legacy anchors
did not widen them. Most varying samples differ by one stored code value, with small larger tails.

### Second policy: visibility-null-envelope-v2

A separately frozen revision reused exactly the same 135 training inputs and identical min/max
images. It applied existing `vendor-quantization-v1` constants uniformly to all six MetalFX
calibration spans and mixed pairs. The other nine cases retained strict; Temporal Off also
required zero interval width and byte-exact paired BMPs. No numeric constant or sample interval
was enlarged. This revision was informed by control data; it was not a blind original protocol.

The revised calibration passed 15/15. Then 60 **new** holdouts ran: four fresh processes per case,
ABBA or BAAB in alternating case order, A=off/B=cull. Frozen hashes precede every holdout capture.

## Result and retained investigation limits

The retained records are `preregistered.json`, `holdout-start.json`, `envelope/envelope.json`,
`verified.json`, `custody-audit.json`, `negative-controls.json` and the raw image/log directories.
All original implementation evidence and the original 13/15 exact result remain unchanged.
No holdout sample was used to widen the interval or start another threshold revision.
The original 1777-file manifest was rechecked with zero changes. Frozen GPU/verification tool
archives retain their runtime inputs; the GPU archive replays successfully. The first archived
Python check selected an interpreter without Pillow; its log remains, and Python 3.12 with
Pillow 10.4 runs all eight selftests successfully.

The exact fixture gives useful correctness evidence, and the original two differences also occur
within observed control variability. Neither makes the failed end-to-end gate pass. Declaring
only the looser engineering ceilings sufficient now would change the decision after seeing the
holdout. A future investigation needs an independently justified model or the first divergent
rendering input/pass; this follow-up makes no claim to have found that cause.
