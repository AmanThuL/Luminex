does not replace the isolated paired performance collection.

The Summary retains one API usage insight: `occlusionReferenceIds` is reported as lacking
ShaderRead/ShaderWrite usage. The inspected operation is a native `copyFromTexture` readback,
not a shader binding (`26-xcode-readback-copy.jpg`, `xcode-readback-ax.txt`). Source declares a
render target followed by graph CopySource use; the Metal copy encoder uses no argument table,
and the SDK copy contract requires non-framebuffer-only storage rather than shader usage.
This suggests an analyzer limitation, but does not prove an Xcode defect. The insight remains
open and this capture is not described as warning-free. No artificial usage flag was added.

Metal 4 Access Mode reports unsupported. Some API receiver labels show the following pass's
name despite the selected parent encoder and actual kernel/resource bindings; retained AX text
preserves that discrepancy. Disabled resource-image warnings and transient loading markers are
not treated as validated runtime errors or as proof that every analyzer is clean. Summary also
reports unused temporal history allocations around the resize; no performance conclusion follows.
The old extractor's unsupported R32Float/format, attachment-name and uniform-join limitations
remain unchanged. Native inspection supplies the replay evidence independently.
