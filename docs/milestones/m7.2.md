## Objective and baseline

A maintained CPU frustum-visibility oracle and a competent indirect-draw production baseline over
the shared tables give M7.3 a measured reference. The baseline is [M7.1](m7.1.md): `Scene::view`
emits one `DrawItem` per object in object order with no camera in sight, and `ShadowStage` and
`SceneStage` issue one `drawIndexed` per item with a 16-byte `DrawUniforms` row selector and five
per-draw texture bindings. No frustum, plane or bounds test exists on either processor; the only
bounds are the scene-wide sphere the shadow fit consumes and an optional editor-only mesh-local
box. The RHI already exposes `drawIndexedIndirect` over the 20-byte `DrawIndexedIndirectArgs`
layout, and the render graph already declares `indirectBufferReads`. Metal 4 has no multi-draw
indirect without indirect command buffers, so an indirect baseline is still one CPU-issued command
per visible object; this slice discloses that remaining per-object encoding rather than hiding it.

This slice changes which objects reach the GPU and how their commands are expressed, not what they
mean: scene-linear materials, pre-exposure, masked coverage (ADR 0018), the motion convention
(ADRs 0013–0017), the display boundary (ADR 0019) and the M7.1 identity/update rules are unchanged.
Culling never touches table rows, so an object culled last frame keeps its previous transform and
motion class when it returns.

After this slice the editor and offscreen paths cull by default and submit through the indirect
argument path by default, with an unculled bypass and direct per-object drawing retained as
selectable production fallbacks. The indirect default is a transition choice: M7.3 replaces only
the producer of the argument buffer with GPU work, so the stages, shaders and graph declarations
it consumes are settled here. It is not a measured win, and this slice claims none.

## Intended implementation

### Bounds in the shared tables

`Scene::addMesh` computes a mesh-local axis-aligned box from the vertices it receives, so every
mesh row carries reliable bounds without a per-object field. `SceneObject::localBounds` retires;
`Scene::meshBounds(MeshId)` is the single source, and `SelectionBounds` frames selection through
it with the same corner-transform helper `prepareFrame` uses. The helper moves to
`Source/Render/Bounds.h` as `render::Aabb`, `transformAabb(mat4, Aabb)` and finiteness checks, so
Scene, Render and AppModel share one definition under the module rules.

| Row | Added fields (byte offset) | New size |
|---|---|---|
| `MeshRow` | boundsMin as float3 (16), boundsMax as float3 (32), padding | 48 |
| `InstanceRow` | worldBoundsMin as float3 (208), worldBoundsMax as float3 (224), padding | 240 |

`prepareFrame` recomputes each instance's world box from the eight transformed corners of its mesh
box under the existing dirty-row comparison, so a static scene still converges to zero writes. A
mesh whose vertices give an empty, inverted or nonfinite box, or an instance whose model matrix
is nonfinite, sets `kInstanceBoundsUnreliable` in the instance flags instead of a box. The CPU
oracle and M7.3's GPU kernel classify from the same rows, so their inputs cannot disagree. Size
and offset asserts, `Shaders/Modules/SceneTables.slang` and the registered capture schema change
together, and the M7.1 ABI oracle copies the new fields.

### CPU visibility reference

`Source/Render/Visibility.h` owns the reference. `extractFrustumPlanes(viewProjection)` returns
the near plane and four side planes of the reversed infinite-far projection; there is no far
plane, and `Camera::farZ` stays scene data. Planes are normalized and offset outward by
`kVisibilityGuardWorldUnits = 1e-3`, the M5.6 scored-boundary margin. `classifyInstance` tests the
instance's world box with the p-vertex rule: for each plane it takes the box corner farthest
toward the plane's inside half-space, and rejects the instance only when that corner still lies
outside some plane. The test is conservative by construction: it may accept an object that
rasterizes nothing and never rejects one that rasterizes a fragment, which is what makes the
culled-versus-unculled image gate below exact.

`classifyView(planes, items, tables, options)` fills a `VisibilityResult`: one
`VisibilityState` per candidate in candidate order, `Visible`, `Rejected` or
`Bypassed{Disabled, ViewUnculled, UnreliableBounds, NonFiniteTransform}`, the visible index list
in candidate order, and per-reason counts. The camera view classifies against the frame's jittered
view-projection, the matrix rasterization uses, so the guard band is the only difference between
the test and the raster. The shadow view is bypassed as a whole in M7.2 with reason
`ViewUnculled`, because the fit ortho volume contains the scene sphere and per-cascade culling is
M8.1 scope; the result still records every shadow candidate so the counts stay comparable between
views, and `Disabled` is reserved for the user's culling toggle.

### Submission and shaders

`Source/Render/DrawSubmission.h` turns visibility results into GPU-consumable commands. The
Renderer owns one `DrawSubmission`; it holds three paced slot buffers for a `uint32_t` visible-row
list and three for `DrawIndexedIndirectArgs`, created with `cpuWrite`, sized to the instance
capacity and grown with the tables under the M7.1 retirement rule (old buffers release at the
last prepared frame + 3). `prepare(frameNumber, sceneResult, shadowResult, mode)` runs inside
`Renderer::declarePasses`, after `Device::beginFrame` proves the slot retired and before any pass
is declared. It writes two ranges into both buffers, scene draws then shadow draws, and returns a
`DrawList` per pass: entry offset, entry count and, for batched mode, the runs.

One shader contract serves all modes. `DrawUniforms` keeps its 16 bytes but its field becomes
`firstEntry`; every scene and shadow vertex shader reads
`row = gVisibleRows[gDraw.firstEntry + instanceIndex]` and then `gInstances[row]` exactly as
today. The editor-only `SelectionMask` keeps a direct row selector, because it draws one
editor-chosen object that need not be in the visible list; a rejected selection draws no outline.
The visible-row list binds at buffer slot 4 as `kVisibleRowsSlot`, the slot the retired
alpha-mask block freed, so the eight-slot binding limit is unchanged. The observable
`instanceIndex` is defined as the local instance index plus the draw's `firstInstance`; HLSL and
Metal define `SV_InstanceID` differently, so this is a checked contract, not an assumption, and
the first GPU fixture below pins it. A backend whose lowering differs adjusts its shader
declaration, never the CPU side.

| Mode | Per visible entry | `DrawUniforms` | Command |
|---|---|---|---|
| `direct` | bind `{firstEntry = entry}` per draw | per draw | `drawIndexed(indices, indexCount, firstIndex)` |
| `indirect` (default) | args `{indexCount, 1, firstIndex, 0, firstInstance = entry}` | `{0}` once per pass | `drawIndexedIndirect(indices, args, entry * 20)` |
| `batched` | list sorted by (pipeline, material, mesh); one args entry per run `{indexCount, runLength, firstIndex, 0, runStart}` | `{0}` once per pass | one `drawIndexedIndirect` per run |

Direct mode is the retained CPU fallback and the closest descendant of the M7.1 path; the extra
list load is its only shader difference. Batched mode is the competent repeated-geometry control
from the M5.6 contract: runs share one pipeline and one material, so the stages' per-draw texture
bindings and pipeline selection happen once per run, and every instance of a run reads its own row
through the list. Culled entries are absent from the list, so the CPU command count falls with
visibility in every mode; M7.3 will instead fill fixed argument slots on the GPU and measure that
difference against these baselines. Pipeline permutations, texture fallbacks, the sky draw and the
editor selection passes are otherwise unchanged.

The Renderer imports the slot buffers in use as `lmx.draw.rows` and `lmx.draw.args`. Shadow and
scene passes declare the list under `bufferReads` and the arguments under `indirectBufferReads`,
so the compiled record, graph dumps and Render Graph window show them. Nothing on the GPU writes
either buffer in M7.2, so no barrier is derived; M7.3's GPU writer records terminal uses. No ICB,
no new capability query and no RHI addition is required; `drawIndexed` keeps its signature.

### VisibilityLab

`Source/Scene/VisibilityLab.cpp` builds the `visibility-lab` catalog entry (role Diagnostic,
always available). A seeded deterministic layout places N instances on a three-dimensional grid
with distinct depths, alternating two generated meshes (cube and icosphere) and four materials, one
of them masked and one double-sided, so batching keys and every pipeline axis appear in the visible
list. A boundary lane places a row of instances straddling the left, right, top, bottom and near
planes of the initial camera, at least the guard margin from any classification boundary on the
straddling side. A 12-second looping camera rail, baked at the shared 60 Hz rate like San Miguel's,
starts inside the grid looking along it, dollies out and turns until the whole grid is in view, then
returns, so the visible fraction sweeps from roughly one tenth to one. `--lab-instances <N>` sets
N for VisibilityLab only (default 4,096; 1,024, 16,384 and 65,536 are the measurement points) and
is rejected with any other scene. Rows and bytes scale with N under the existing growth rule.

### Editor and CLI surface

The Rendering Inspector gains a Visibility block: a culling toggle (default on), a submission mode
selector (default indirect) and read-only candidates, visible, rejected and bypassed-by-reason
counts for the scene and shadow views, draws issued per pass, instanced runs, list and argument
bytes, and last-frame CPU classify and prepare times. Hierarchy rows carry a visibility badge for
the displayed frame, and the selected object's Inspector section shows its state, reason and world
box; both come from the retained `VisibilityResult`, so rejected instances and bypass reasons are
inspectable per object. Performance's existing draw count becomes the issued command count. All
formatting is CPU-testable AppModel logic with the UX1 field helpers.

`--visibility <cull|off>` and `--submission <direct|indirect|batched>` apply to windowed,
screenshot, capture-sequence and measurement runs, with the same defaults as the editor, so the
frozen fifteen-image matrix can be rendered under any mode. `Tools/Screenshots/reference.json`
and its runner are unchanged.

### Measurement harness

`Source/App/Model/MeasurementRun.h` owns the run: a state machine (idle, warmup, measuring,
draining, complete, cancelled), the frame plan (warmup W then N measured frames along the scene's
camera track at the 60 Hz deterministic step the capture-sequence loop already uses), per-frame
samples and the JSON report, schema version 1. Each measured frame records CPU classify time,
CPU submission preparation time, CPU declare-and-encode time from the slot wait through commit
(slot wait recorded separately), retired per-pass GPU timings joined by frame id after
retirement, the timed-pass sum with its documented exclusions, candidate/visible/rejected counts,
issued commands, and table, list, argument and transient bytes. The report also records device,
OS, build mode, shader hashes, extents, temporal mode, scene, N, visibility and submission mode,
and the actual validation and capture environment flags.

Two front ends share the model. The editor's Performance panel gains a Measure section with the
sequence length, Start and Cancel; a run plays the camera track in the live viewport with UI and
presentation included, then shows the report summary with Export. Editor reports are labelled
interactive and unscored. The headless `--measure <out.json>` run mode renders offscreen without
UI, accepts `--warmup`, `--frames`, `--scene`, `--lab-instances`, `--visibility`, `--submission`,
`--temporal` and `--render-scale`, conflicts with `--screenshot` and `--capture-sequence`, and
refuses scored output when validation or capture is enabled unless `--unscored` is given.

`Tools/Bench/visibility_paired.py` reuses `frame_data_paired.py`'s fresh-process protocol: each
repetition launches two headless processes in alternating AB/BA order, 12 repetitions, 32 warmup
and 256 measured frames, medians per run, paired relative deltas and a two-sided 95% bootstrap
interval over the repetitions (10,000 resamples, seed `0x4C4D5836`), with a `--selftest`. A
missing frame or mismatched plan invalidates the repetition, and every failed attempt is retained.
The frozen comparison set is culled versus unculled and indirect and batched versus direct, on
VisibilityLab at the three N points, Sponza and San Miguel at their initial cameras, and
TemporalLab on its track, all at 1280×720 with Native TAA at scale 1.0. Output stays outside the
source tree. The driver reports every cell with its uncertainty and applies no decision rule;
M7.3 owns adoption decisions under the roadmap's production-evidence rules.

## Verification plan

### Fixtures

CPU tests under `[render][visibility]`, `[render][submission]`, `[scene]` and `[app]`:

- **Planes:** extraction from a known reversed infinite-far matrix yields five normalized planes
  with the expected normals and the guard offset; no far plane exists.
- **Classification:** boxes fully inside, fully outside each plane, straddling each plane, behind
  the near plane and enclosing the camera classify as the conservative rule requires; unreliable
  bounds and nonfinite transforms bypass with their reasons; disabled culling bypasses everything.
- **Mesh bounds:** `addMesh` computes boxes for loader and generated geometry; degenerate input
  sets the unreliable flag; `SelectionBounds` frames the same box as before.
- **Submission:** the visible-row list and argument bytes for each mode match hand-built
  expectations, batched runs are contiguous and keyed correctly, the shadow range follows the
  scene range, and growth releases old buffers at last frame + 3.
- **Options and model:** the new options parse, conflict and default as specified; the
  measurement state machine, frame plan and report schema are pinned; scored refusal under
  validation is tested.
- **Display:** the Visibility block, badge and per-object formatting are pinned.

GPU fixtures under `[gpu][visibility]`, rendering through the real stages into readback targets:

- **Instance-index ABI:** an indirect draw with `firstInstance = 5` and an instanced draw of four
  instances write their observed indices to a readback buffer; the values equal entry plus local
  index, pinning the contract for this backend.
- **Mode parity:** a two-cube scene renders byte-identical images in direct and indirect modes; a
  scene of shared-mesh, shared-material instances renders byte-identical images in direct and
  batched modes with the expected run count.
- **Culling parity:** a scene with one object outside every plane, one straddling an edge and one
  behind the camera renders byte-identical images culled and unculled, and the result reports the
  expected states.
- **Three-frame overlap:** four consecutive frames each change which objects are visible without
  `waitIdle`; each frame's image reflects its own list, and per-slot readback shows each slot
  holding the entries of the last frame that used it.
- **Row ABI:** the M7.1 full-field oracle copies the new bounds fields byte for byte.
- **VisibilityLab:** the lab loads at the default N, its boundary-lane states match the authored
  expectation at the initial camera, and the visible count at three rail times matches the CPU
  oracle run on the same rows.

### Output preservation and comparison rule

Parent and candidate release binaries are frozen on the same device before and after the change,
with raw evidence outside the source tree. Three comparisons are gated, and their rules are fixed
here before any measurement:

- **Same binary, culled versus unculled** on the fifteen-image matrix: exact SHA-256 equality in
  every image, because the classifier is conservative and draw order is preserved.
- **Same binary, indirect versus direct**: exact equality on the fifteen images. **Batched versus
  direct**: the frozen M7.1 strict criterion (at most 1.0% differing pixels and at most 0.05%
  over 8/255 per image), declared here because run sorting changes draw order and depth ties may
  resolve differently; exact agreement is expected and recorded either way.
- **Parent M7.1 versus candidate defaults** (culled, indirect): the M7.1 criteria as recorded in
  its record, including the accepted `vendor-quantization-v1` profile for MetalFX images only.
  The frame-32 TemporalLab motion readback must agree within 1/4096 UV, and the three-frame Native
  TAA sequence is compared frame by frame under the strict criterion.

A failing image is recorded as a failure with its numbers; thresholds are never loosened after
measurement, and any exception is the owner's explicit decision.

### Regression inventory

Build, `xmake test`, the GPU suite under `MTL_DEBUG_LAYER=1`, format, `xmake policy` with the
module, header, comment and shader-import checks, and the unchanged `[checkpoint-a]` filter all
pass. Renderer-driven `Tests/Golden/frame-*.txt` change only by the two added imports and their
reads, with pass order unchanged; the diff is reviewed and recorded. `CaptureSchemaTests` pins the
grown rows. A validation-clean editor session switches every catalog scene including VisibilityLab,
toggles culling and each submission mode with the image unchanged to the eye, inspects a rejected
object's badge and reason, and completes one interactive measurement. One headless paired
collection over the frozen set is completed on the frozen device with variation reported; its
numbers are diagnostics for M7.3, not a performance conclusion.

## Known limits and design boundaries

- No GPU classification, compaction, work generation, occlusion, HZB, ICB, bindless textures or
  descriptor indexing; M7.3 and M7.4 own those, and ICB stays optional.
- The shadow view is unculled; per-cascade culling is M8.1 scope. Sponza and Helmet keep their
  fixed initial cameras for measurement; only VisibilityLab, TemporalLab and San Miguel have rails.
- Indirect and batched modes still encode one command per visible entry or run on the CPU and
  bind textures per run; that remaining per-object encoding is reported, not removed.
- Editor measurements include UI and presentation and are never scored; scored numbers come only
  from fresh headless processes on the frozen device. Native-host timings never establish
  production speedups, and the indirect default is not a measured adoption.
- Frozen M5.6 artifacts stay untouched; the M5.6 workload/oracle contract is reused through
  VisibilityLab's grid, guard margin, seed and paired protocol, not by restoring experiment code.
- Existing image-parity exceptions and manual/capture follow-ups from M6.4, M6.5, R1.3, R1.5 and
  M7.1 carry forward unchanged; this slice neither closes nor broadens them.
