## Implemented behavior and clarifications

- CPU remains the default classifier; culling and indirect submission retain their defaults.
  `--classify gpu` selects fixed argument slots with indirect or batched submission.
  GPU/direct is rejected. `--classify-check` requires GPU and an explicitly unscored measurement.
- CPU-owned candidate/run/chunk tables cover the scene view and an unculled shadow view.
  Sparse indirect uses one slot per candidate; dense batched uses one slot per canonical run.
  CPU encoding still issues every candidate-slot or run command, including zero-instance work.
  A separate sky command is included in scene command counts but has no indirect argument row.
- The visibility graph declares reset, classify, dense-only scan and emit under
  `lmx.pass.visibility`. Sparse emit needs no chunk-offset scan. Retained rows are deterministic
  within runs; per-run scans establish chunk offsets, while atomics update counters only.
- All indices are absolute in combined scene-then-shadow tables. A rejected sparse argument is
  zeroed; an empty dense run retains its geometry fields and reserved firstInstance with zero
  instances. CPU-omitted runs are compared as zero-count logical runs for oracle checks.
- State, row and argument capacities are explicit. Retained work that cannot fit is dropped and
  counted, including rows belonging to an absent argument slot. Overflow invalidates capture and
  measurement evidence. Diagnostic exports keep empty-view passes live as graph sinks.
- The CPU box oracle uses ordered fp32 operations with contraction disabled. Visibility Slang
  entries use safe math in both offline and runtime-MSL compilation. Other shader compilation
  keeps its existing behavior. MaterialRow remains 112 B; per-run texture bindings are retained.
- Three paced slots retain declaration-time bounds, candidate order and scene generation.
  App additionally retains complete generational InstanceIds, so old readback cannot attach to a
  replacement row occupant. Retirement joins exact frame IDs; a post-waitIdle drain delivers final
  results without submitting artificial frames. CPU declaration costs and retired counts remain
  separate until the matching result is available.
- Schema 2 reports requested/effective classifier and submission, GPU visibility preparation,
  counters, diagnostics and storage. `reservedListBytes` is the declaration row span;
  `listBytes` is valid emitted row payload, resolved from retired scene/shadow counts for GPU.
  Allocated list/argument storage remains separate. Interactive reports are always unscored.
- Paired analysis retains absolute CPU/GPU medians and paired millisecond confidence intervals
  when the CPU visibility GPU time is zero. Relative percentage remains explicitly unavailable
  for a zero baseline. Measurements serialize retirement and describe isolated frame cost.
- Selected-object diagnostics show the matching Declared frame or Retired frame beside the
  identity-checked visibility result. Rendering settings, global visibility status and selection
  diagnostics therefore expose which frame each observation describes.
