# R2 — RHI Becomes RojoRHI

**Status**: Proposed

First draft for owner revision. R2 moves the root `RHI/` component into the private
`rojo-rhi` repository and mounts it back as a git submodule, so Luminex stays the primary project
while every RHI edit becomes a commit to RojoRHI. The
refactoring roadmap named RHI extraction as a candidate "once a second backend exists"; the owner
opened it earlier on 2026-09-19.
[Part III](../roadmap/codebase-restructuring.md#r2--rhi-becomes-rojorhi) owns the
outcome and gates; this record keeps design, evidence and limits.

**Placement:** M7.5 → **R2** → R3 (tree and documentation restructure) → R4 (shader source
deduplication) → UX2 (scene documents and hierarchy) → N1. No other milestone plan opens before R2 is accepted.

## Observed coupling before R2

`RHI/` is 49 files and about 7,000 lines: 22 public headers, 3 shared implementation sources, and
the Metal 4 backend with its optional ImGui adapter. Public headers depend on nothing. The
implementation includes four Core headers — `Assert.h` (9 sites), `Log.h` (6), `Align.h` (2) and
`Json.h` (1) — and no glm, spdlog, Render, Asset, Scene or App header. It reads no environment
variable. The Slang-to-metallib rule lives in `xmake/shaders.lua` and RHI never opts into it; RHI
only loads compiled libraries at run time. The ImGui adapter compiles against the backend's
private `Source/` headers, so it cannot stay behind in Luminex.

What is entangled is everything around the code: `Core` as a link dependency, `metal-cpp` fetched
by Luminex's setup task, RHI tests and smoke shaders inside the flat `Tests/` and `Shaders/Tests/`
trees with a support header shared by all 32 GPU test files, four `rhi-*` units in
`Tools/module_contract.json`, `Tools/check_rhi_headers.py`, the maintained ImGui patch and
`Tools/ImGuiBufferProbe/`, the `[checkpoint-a]` filter spanning RHI and render-graph cases
([ADR 0009](../decisions/0009-checkpoint-a-conformance.md)), and about 270 `lmx`/`LMX_` identifiers.
The destination repository holds a 2024 stub: a `CMakeLists.txt`, an `External/NRI` submodule and
empty directories.

## Decisions taken with the owner

| Topic | Decision |
|---|---|
| Identity | Namespace `rojoRHI` and `rojoRHI::metal4`; includes `<rojoRHI/Device.h>`. This is the one owner-approved exception to lowercase namespace and include-root naming: RHI is an initialism the project already writes in capitals, and the mixed case keeps the word boundary. Macros `ROJORHI_ASSERT`, `ROJORHI_LOG_*`; default GPU label prefix stays lowercase `rojorhi.`, matching the `lmx.*` label style; targets `RojoRHI` and `RojoRHIMetal4ImGui`. The repository keeps the name `rojo-rhi`; prose calls the library RojoRHI |
| Include spelling | macOS file systems are case-insensitive and neither repository compiles on a case-sensitive host, so RojoRHI's public-header check rejects any include whose root is not spelled exactly `rojoRHI/` |
| Mount | Submodule at root `RojoRHI/`, as Donut mounts `nvrhi/`. The `RHI/` path disappears so stale references fail loudly |
| History | Tag the 2024 stub as an archive, then replace `main` with the extracted Luminex history. No CMake remains on `main` |
| Build | xmake in both repositories. RojoRHI owns a minimal setup task (metal-cpp and Slang pins) and a test-only copy of the shader rule, so it builds and tests alone; mounted, an option points it at Luminex's fetched `ThirdParty/` |
| Core dependency | RojoRHI gets a private base (assert, alignment, JSON escaping, `std::format` logging) and one public message callback. Luminex installs a sink that forwards to spdlog and the Console. No third repository for Core |
| ImGui adapter | Moves with the backend as an optional target, with its patch and `ImGuiBufferProbe` |
| R2.1 document home | After the archive tag, the documents are authored on an orphan `foundations` branch in `rojo-rhi` holding none of the stub's files. `main` is untouched until R2.4, which rebases those commits onto the imported history, so the destructive step still happens once |
| Founding ADRs | One per source: 0001 identity, 0002 Metal 4 first (Luminex 0002), 0003 thin RHI (0004), 0004 second-backend target (0007), 0005 conformance checkpoint (0009, RHI half), 0006 execution model (0010). Each names the ADR it restates |
| Substitution record | `docs/guides/luminex-extraction.md` explains order and exclusions; the ordered `Tools/Rename/substitution.tsv` beside it is the data R2.3 consumes verbatim |
| Review | One pull request per repository; documents stay `Proposed` until the owner accepts, then become `Accepted` before merge |

Alternatives rejected: an all-lowercase `rojorhi` (loses the word boundary) and `rjrhi` (loses the
name); a `rojo::rhi` family namespace (longer at every call site for a family
that does not exist); keeping the `RHI/` path (hides that an edit is a foreign commit); RojoRHI
owning the production shader rule ([ADR 0004](../decisions/0004-thin-rhi.md) gives the RHI no
shader-toolchain duty); precompiled test shaders (oracles could not be regenerated standalone).

## Target shape

```
rojo-rhi/
  AGENTS.md  CLAUDE.md  README.md  xmake.lua        root project settings only
  xmake/targets.lua  setup.lua  shaders.lua         targets are includable by a host project
  Include/rojoRHI/                                  public, dependency-free
  Source/  Source/Base/                             shared implementation; private base
  Backends/Metal4/Source/  Backends/Metal4/ImGui/
  Tests/  Shaders/Tests/                            contract, validation and GPU conformance
  Tools/                                            public-header check, Patches/, ImGuiBufferProbe/
  docs/conventions/  docs/decisions/  docs/architecture/
```

Luminex includes `RojoRHI/xmake/targets.lua`, never the submodule's root `xmake.lua`, so project
settings, requires and language level are declared once per root. xmake resolves a project root to
the outermost ancestor holding an `xmake.lua`; standalone work inside the mounted checkout
therefore uses `xmake -P .`, the same rule nested worktrees already need.

## R2.1 — RojoRHI foundations

**Outcome:** RojoRHI has its own rules before it has any code, as Luminex did.

**Deliver (documents and the substitution data file only, in `rojo-rhi`):** `AGENTS.md` with `CLAUDE.md` importing it; conventions
for naming, C++ style, commits, documentation and testing, derived from Luminex's and stating every
deliberate difference, including the `rojoRHI` case exception and its include-spelling check;
founding ADRs restating, for RojoRHI, the decisions Luminex ADRs
[0002](../decisions/0002-metal4-first.md), [0004](../decisions/0004-thin-rhi.md),
[0007](../decisions/0007-d3d12-backend-target.md), 0009 (RHI half) and
[0010](../decisions/0010-execution-model-partial-reshape.md) made; the identity table above with
call-site examples; the recorded substitution list R2.3 executes. In Luminex: a new ADR recording
the relocation, the consumer workflow below, the checkpoint A split, and that later RHI decisions
are RojoRHI ADRs. Accepted Luminex ADRs stay immutable.

**Exit gate:** the owner accepts the conventions, the founding ADRs and the Luminex ADR before any
source changes. The archive tag exists on the 2024 stub.

**Accepted 2026-09-19.** `rojo-rhi` carries the tag `archive/2024-cmake-nri-stub` on its stub and,
on the `foundations` line, six founding ADRs, five conventions, the extraction guide with
`Tools/Rename/substitution.tsv`, and its agent instructions, all `Accepted`; Luminex accepted
[ADR 0024](../decisions/0024-rhi-relocation-to-rojorhi.md). Recording the substitution found that
about 1,900 namespace-relative `rhi::` references need their own row, that build files and policy
tools name the component directory, and that RojoRHI's checkpoint A half is 16 cases, one of which
reads a Metal-scoped counter. No source changed.

**Defer:** any code; a license choice beyond "private, all rights reserved"; a public release.

## R2.2 — Decouple in place

**Outcome:** `RHI/` builds and tests as if it were already alone, while still inside Luminex where
parent/candidate comparison is possible.

**Deliver:**

- A private base inside `RHI/Source/Base/` replaces the four Core includes; `RHI` drops its `Core`
  dependency. Assertion text, abort behaviour and alignment contracts are unchanged. The one public
  addition of R2 is the message callback (severity, message); unset, messages go to stderr. Luminex
  registers a forwarding sink at startup so the Console and log files read as before.
- Test split by a checkable rule: a test translation unit moves iff it includes no project header
  outside RHI and test support. The plan lists each file; expected movers are `RHIResult`,
  `RHIFrameData`, the six `RHIValidate*` files and their support header, and the RHI-only GPU files
  (`GpuRhi`, `GpuCompute`, `GpuCopy`, `GpuIndirect`, `GpuMrt` and peers the rule admits). They build
  as a second test target from `RHI/Tests/` with `RHI/Shaders/Tests/`; smoke shaders used by both
  sides are copied, not shared, and the basename-collision rule is scoped per test target.
  `GpuTestSupport.h` splits into an RHI bootstrap and a Luminex header that builds on it.
- Checkpoint A becomes two filters whose union equals the frozen inventory by case name: RHI cases
  move with the RHI tests; `GpuTransientTests` and `RenderGraphTransientTests` cases stay.
- `RHI/xmake/` gains the targets file, setup task and shader-rule copy; `xmake -P RHI` configures,
  builds and runs the RHI tests without the rest of the tree. `check_rhi_headers.py`, the ImGui
  patch and the buffer probe move under `RHI/Tools/`; Luminex's setup calls the patch step there.
- `Tools/module_contract.json` replaces the four `rhi-*` units with one external entry: allowed
  headers per consumer (Asset still only `Format.h` and `TextureDesc.h`), and the archive symbol
  check still proves Asset links nothing from the RHI.

**Owner decisions, 2026-09-19:** the callback
is `RHI/Message.h` — `enum class MessageSeverity { Info, Warning, Error }`, a function pointer
`void (*)(MessageSeverity, std::string_view, void* user)` and process-wide
`setMessageCallback(callback, user)`, where `nullptr` restores stderr. Luminex's forwarding sink
lives in `Render/RhiLog` and is installed by App and the Luminex tests; `FrameDataBench` and the RHI
test target keep the stderr default. A test moves only if it also includes at least one `RHI/`
header. glm and Catch2 are test-only packages of the standalone root. Evidence is tiered: every
commit meets the gates and a case-name inventory comparison; image, artifact and capture
comparison run when the `App` binary or its shader outputs differ from the parent.

**Exit gate:** the [R1 comparison protocol](../roadmap/codebase-module-boundaries.md#r1--module-boundaries-and-shared-foundations)
holds commit by commit; every pre-existing test case is present under its name in one of the two
targets and passes; `MTL_DEBUG_LAYER=1` GPU runs are validation-clean; the standalone build links
no Luminex target.

**Defer:** renames; any RHI capability or semantic change; deduplicating the two shader rules.

**Accepted 2026-09-19.** `RHI/Source/Base` replaces the four Core
includes; `RHI` links nothing. `RHI/Include/RHI/Message.h` is the one public addition; `Render/RhiLog`
installs the forwarding sink in App and the Luminex `Tests` binary, and `FrameDataBench`/`RHITests`
keep the stderr default. `RHITests` holds 201 cases against `Tests`' 849, disjoint and together equal
to the pre-slice inventory plus exactly the three `[rhi][message]` cases. Checkpoint A splits 16/3
across the two binaries by name, checked by `Tools/check_checkpoint_a.py`. `RHI/xmake.lua` plus
`RHI/xmake/targets.lua`, `setup.lua` and `shaders.lua` let the component configure, build and test
from its own root (`xmake -P RHI`, after `xmake setup -P RHI` or a `ThirdParty` copy); the repository
root includes `RHI/xmake/targets.lua` alone. `check_rhi_headers.py`, the ImGui patch and
`ImGuiBufferProbe` moved under `RHI/Tools/`. `Tools/module_contract.json` replaced the four `rhi-*`
units with one `externals` entry; the target-closure check still proves nothing under `RHI/` links a
Luminex target and `Asset`'s `forbidUndefined: lmx::rhi::` still runs under `--link`.

Deliberately copied rather than shared: six smoke shaders (`BufferHazardSmoke`, `ComputeImageSmoke`,
`FullscreenSample`, `MrtSmoke`, `SamplerSmoke`, `ShadowSmoke`), the `Shadow.slang` module, and the
Slang-to-metallib rule as `RHI/xmake/shaders.lua`; `RHI/xmake/setup.lua` carries its own metal-cpp and
Slang pins, verified against the same hashes as Luminex's copy.

**Evidence** (bundle `../Luminex-evidence/r2.2/`, outside the repository): built base `a2787b5`
against head `142c4ba` in separate worktrees, release, `--ccache=n`, matching `imgui.ini`. Tier 1:
`Tests` (849) and `RHITests` (201) case-name inventories are disjoint and their union is the parent's
1,047 plus exactly the three additive `[rhi][message]` cases; all four unit/GPU groups, both
checkpoint-A checks, `xmake policy`, `xmake format --check` and the Python test suite pass. Tier 2:
Sponza `LMX_GRAPH_DUMP`, tagged PNG bytes and metadata, a three-frame capture sequence and manifest,
and the capture-schema JSON are byte-identical between base and head; `gputrace_dump.py`'s decoded
manifest and uniforms differ only in the two recorded path strings, matching a base-vs-base capture
control taken in the same session; a five-frame stdout run is identical once timestamps are
stripped, including every RHI-originated log line. `Tools/Screenshots/parity.py` ran eight alternating
rounds (four base, four candidate) over all fifteen reference cases, including `sponza-taa-0.5`
(the case that showed one candidate-only hash earlier in this work); every candidate
hash this run was also produced by base in the same session, so zero cases were unresolved and the
flake-probe procedure was not needed. `allMatched` is `false` on both builds, the documented
pre-existing historical-reference failure; `reference.json` was not touched. The standalone gate
(`RHI/` copied out with `ThirdParty` seeded, `xmake setup -P .`, `xmake f -m release -P .`,
`xmake build -P . RHITests`, `MTL_DEBUG_LAYER=1 xmake test -P .`) passed, including a completed
Slang download and checksum verification; the link line names only `RHI`, Catch2 and system
frameworks.

**Limits.** The `App` link is not bit-reproducible: two builds of identical inputs can differ by a
`LC_UUID`/signature/GOT-slot-order artifact of link-input ordering (recorded during this slice), so
equality is judged on objects, symbols, MSL and rendered/graph/capture output, not the raw binary
hash. One earlier parity round produced a candidate-only hash on `sponza-taa-0.5` that base did not
produce in that session although both `App` binaries were byte-identical; it was left unattributed,
not retried and not re-baselined, and did not recur in this closing run. The standalone `setup`
task's Slang download path is exercised end to end only in this closing run; earlier in this work
it was seeded by copy after a slow-network timeout. Luminex's `Tests` still reaches one header inside the
component, `RHI/Tests/RhiGpuTestSupport.h`, which R2.4 replaces with a Luminex-owned copy. The host
passes `rhi_thirdparty`/`rhi_imgui_target` as plain Lua globals rather than an xmake option, because
`get_config` returns `nil` on early description passes. `FrameDataBench` and `RHITests` write RHI
messages to stderr by decision, not omission. Inside the component, Luminex's module checker no
longer proves what the retired internal units proved — that `RHI/Source` is free of metal-cpp, the
backend's private-header rule, the adapter's unit allowances — nor does it review RHI files against
line budgets; the public-header, comment, layout, process-policy and shader-import checks still
cover `RHI/`, and RojoRHI's own policy arrives with the extraction. No automated job configures the
standalone root, so `RHI/xmake.lua` is proven by the recorded manual run only until the extraction
adds the component's own workflow; `Source/Asset/xmake.lua`'s include directory `../../RHI/Include`
and the format task's `RHI/**` globs are host-side paths the rename must carry.

## R2.3 — Mechanical rename

**Outcome:** the component carries its own name everywhere before it leaves.

**Deliver:** one mechanical commit reproducible from the recorded substitution: namespace, macros,
include root `RHI/` → `rojoRHI/`, targets, default label strings and the directory `RHI/` →
`RojoRHI/`; Luminex call sites follow in the same commit. Formatting is a separate commit.

**Exit gate:** the protocol holds with one declared difference: default GPU labels and log text
containing the old prefix change exactly as the substitution predicts, and capture-dump comparison
applies the substitution before comparing. Rendered images, graph dumps, manifests and schemas are
byte-identical. Renderer-owned `lmx.*` labels, `LMX_*` environment variables and the `lmx`
namespace outside the component are untouched.

**Defer:** any hand edit the substitution cannot express; those wait for the pull request's own,
separately reviewed hand-edit commit.

**Owner decisions, 2026-09-19** ([design](../specs/2026-09-19-r2.3-mechanical-rename-design.md)):
identity-bearing build names follow the identity — `RHITests` becomes `RojoRHITests` (build
directory `rojorhi-test`, groups `RojoRHITests/unit` and `RojoRHITests/gpu`), the Lua names
`rhi_slang2metallib`, `rhi_thirdparty` and `rhi_imgui_target` take the `rojorhi_` prefix, and
`LMX_IMGUI_BACKEND_SOURCE` becomes `ROJORHI_IMGUI_BACKEND_SOURCE` — while file names, Catch2 tags,
test case names and Luminex's `Render/RhiLog` keep their spelling. The amended substitution table,
its applying script and the extraction guide's second dry run live on `rojo-rhi`'s `foundations`
line and are accepted there before any Luminex source moves; Luminex holds no copy. The pull
request carries the mechanical commit, a formatting commit and a third, separately reviewed commit
of hand edits.

**Implemented 2026-09-20.** The record was re-derived against the tree R2.2 reshaped and made
executable as `rojo-rhi`'s `Tools/Rename/apply.py` over a 24-row `Tools/Rename/substitution.tsv`,
accepted on `rojo-rhi`'s `foundations` branch on 2026-09-19 before any Luminex source moved. The
branch carries four source commits where the design specified three — the unedited mechanical
output; a `Source/Render/SceneTables.h` comment reword, because the rename pushed a documented
declaration past the column limit into a wrap the public-API comment check cannot read; formatter
output only; and one hand-edit commit for comments naming the old identity — plus one
documentation-only commit whose scope was widened during review to current convention and pipeline
documents. Tier 1 passed on every commit; at the head, Tier 2 is byte-identical or equal after the
declared substitution and documented build-path normalization, with one unattributed capture
difference (see the validation record); `Tools/Screenshots/parity.py` left zero of fifteen cases
unresolved. See the [validation record](r2.3-validation.md) for full evidence and limits.

**Accepted 2026-09-20.** The owner accepted R2.3 and its integration on 2026-09-20, retaining the
unattributed capture difference and the other recorded limits; the executor plan is closed.

## R2.4 — Extract, mount and wire

**Outcome:** `RojoRHI/` is a submodule, both repositories are green, and the workflow is written.

**Deliver:**

- Tag Luminex's last in-tree commit as immutable evidence. Extract with `git filter-repo`, keeping
  history for every path that ever held a file RojoRHI receives (the plan records the path list
  and renames); force `rojo-rhi` `main` to the result after the owner confirms; tag the import.
- Replace the directory with the submodule at the imported commit. Root `xmake.lua` includes
  `RojoRHI/xmake/targets.lua` and passes the `ThirdParty/` option.
- CI: Luminex checks out the private submodule with a read-only credential stored as a repository
  secret; `rojo-rhi` gets its own workflow — policy, build, CPU contract tests and GPU case
  inventory. Hosted runners lack Metal 4 in both repositories, so GPU conformance runs on Metal 4
  Apple Silicon before merge, as today.
- A policy check that the pinned submodule commit is reachable from `rojo-rhi` `main`.
- Documents: `AGENTS.md`, the module convention, architecture overview, README directory table and
  the worktree guidance (`git submodule update --init` per worktree) describe the new layout.

**Exit gate:** a fresh recursive clone builds with `xmake setup && xmake`; Luminex at the mount
commit matches the pre-extraction tag under the comparison protocol; `rojo-rhi` builds and passes
from a clean clone with no Luminex checkout present; `xmake policy` is green in both.

**Defer:** a second backend (still governed by ADR 0007); versioned releases or a package
registry entry; a public repository; samples beyond the conformance tests.

**R2.4a (complete in place) implemented, awaiting owner review, 2026-09-20.** Before extraction, `RojoRHI/` gained its own `.clang-format`, `.gitignore`, and standalone `format`/`policy` tasks plus copies of the four source-policy checkers (`check_project_policy.py`, `check_shader_imports.py`, `check_cpp_comments.py`, `check_cpp_layout.py`) with their own tests; Luminex's checkers stopped walking `RojoRHI/`, and the root build fails with a clear message when `RojoRHI/` is empty; `docs/plans/2026-09-20-r2.4a-complete-in-place.md` records the six implementation tasks and this record's standalone-gate, object-file and shader-output evidence. R2.4b (tag, `git filter-repo` extraction, submodule mount, CI) follows separately once this pull request merges and the owner tags the merged head.

## Working across the two repositories

An RHI change is a `rojo-rhi` branch and pull request, driven by a Luminex consumer as the roadmap
already requires. During development the Luminex branch may pin the RojoRHI branch commit; before
the Luminex pull request merges, the RojoRHI change is merged and the pin is a commit on its
`main`. RojoRHI changes meet RojoRHI's conventions and conformance tests; the Luminex bump meets
Luminex's GPU suite. A Luminex commit never edits files under `RojoRHI/`.

## Risks and open points

- **Force-replacing `main`** on `rojo-rhi` is destructive and needs explicit owner confirmation at
  execution time; the archive tag is created and verified first.
- **Private submodule in CI** adds a secret and a failure mode hosted runs did not have.
- **Two shader rules** can drift. The accepted cost is about 150 lines; RojoRHI's copy serves
  tests only.
- **Copied smoke shaders and bootstrap code** trade duplication for independence; the plan lists
  each copy so later divergence is deliberate.
- **Agent sessions** need both instruction files: work inside `RojoRHI/` follows its `AGENTS.md`.
- Open: whether `CaptureSchema` (capture evidence JSON, RHI-owned today) stays in RojoRHI or is
  reconsidered in R3; whether `Benchmarks/FrameData`, which depends only on Core and the RHI,
  stays in Luminex (proposed: stays); license text.
