# M6.3 — TAAU and Dynamic Resolution

**Status**: Implemented (2026-09-09)

M6.3 lets the scene rasterise into a render rectangle smaller than the output extent and
reconstructs the full-extent image from jittered lower-resolution samples, then adds a pure,
GPU-time-driven controller that picks the render scale automatically. Every renderer-owned temporal
target allocates at the output extent regardless of scale, so a scale change reallocates nothing;
at scale 1 the frame declaration, the native TAA kernel and fixed-camera output stay byte-identical
to M6.2, and with temporal off they stay byte-identical to M5.5.

**RHI** grows an origin-anchored render area on `RenderPassDesc` (`renderAreaWidth`/`Height`,
default 0/0 meaning the whole attachment): a non-zero pair becomes an explicit Metal 4 viewport and
scissor rect; the zero path is untouched, so every pre-M6.3 pass keeps encoding exactly what it did
before. `validateRenderArea` rejects a half-set pair or an area exceeding any attachment.

**Render** grows the same additive pair on the graph's `PassDesc`/`DebugPass`/`CompiledFrameRecord`,
printed by the dump only when declared, so every M6.2 golden is unchanged. `Temporal.h` adds
`renderExtentsForScale` (each axis rounds `output * scale`, clamped to `[1, output]`),
`jitterTexelOffset` and `renderSamplePosition`; the camera's projection aspect now follows the
*output* extent while jitter stays render-relative. `TemporalHistory`'s `ExtentChanged` narrows to
the output extent alone (ADR 0016 supersedes ADR 0013's clause): a render-scale change alone derives
`None` and reuses history: a real resize still resets it. `Renderer::declarePasses` derives
`extents = renderExtentsForScale(...)` from `SceneView::temporal.renderScale`, declares the scene
pass's render area only when upscaled (so scale-1 stays byte-identical), and tracks
`TemporalStatus::{extents, renderScale, upscaled, lastRenderExtentChangeFrame}` (the last advancing
only on temporal-on frames under `None`). `TemporalResolve` adds `Shaders/TemporalUpscale.slang`
(the reconstruction kernel: dilated motion/disocclusion over the active rectangle, a five-tap
Catmull-Rom history fetch corrected for exposure, a five-tap Catmull-Rom *current* fetch shared with
`Shaders/SpatialUpscale.slang`, neighbourhood clipping, and a proximity-weighted inverse-luminance
blend) and a kernel-selection rule: the native `lmx.pass.temporal.resolve` runs only when render
equals output extent and history was not just accumulated at another extent; every other `NativeTaa`
frame runs `lmx.pass.temporal.upscale`. `Raw` gets the matching split between a plain commit copy and
`lmx.pass.temporal.commitUpscaled`. Shared reason codes, constants and colour-space helpers moved
into `Shaders/TemporalCommon.slang`, confirmed to leave `TemporalResolve.slang`'s compiled MSL
unchanged. New goldens: `frame-render-area.txt`, `frame-temporal-upscaled.txt`,
`frame-temporal-raw-upscaled.txt`.

**Render** also adds `Source/Render/ResolutionController` (`ResolutionControllerSettings`: budget,
headroom, hysteresis window and step bound; `minScale`/`maxScale` default to `Temporal.h`'s
`kMinRenderScale`/`kMaxRenderScale`): a pure class with no device, graph or App dependency that
attributes a retired frame's summed GPU pass time to the scale it was declared at (an 8-entry ring
keyed by frame number and a monotonic sequence) and proposes the next scale with a deadband,
consecutive-sample requirements before stepping, and a settle window after any change.

**App** adds `EditorRenderSettings::{renderScale, dynamicResolutionEnabled, gpuBudgetMilliseconds}`
and `Source/App/DynamicResolution.h/.cpp` (`applyDynamicResolution`, a pure per-frame policy
`EditorShell` calls after ticking the performance model), a "Render scale" slider, "Dynamic
resolution" checkbox and "GPU budget (ms)" slider in the Inspector's Temporal block alongside three
new status rows (render extent and scale, frame GPU time, the last render-extent-change frame), the
`--render-scale <0.5..1.0>` flag (conflicts with `--temporal off` below 1.0, since the temporal path
is what reconstructs a sub-output render), and `LMX_DYNAMIC_RESOLUTION_BUDGET_MS` — an automation
hook that seeds dynamic resolution on with a chosen budget before the frame loop starts and logs
every controller scale change at INFO, for a scripted long run to show the controller settle.

## Known limits and deviations

- **Screenshot hashes depend on the build environment.** A nested-worktree build of the same commit
  (and independently, of `main`'s tip) rendered MaterialLab's 32-frame default with 29 bytes
  differing (≤ 8/255) from the baseline while every other screenshot matched; three consecutive runs
  of the main checkout's build reproduce the baseline hash exactly. The image is deterministic per
  build, so the difference is a build-environment effect (no Metal toolchain installed; MSL compiles
  at runtime in both builds) rather than a rendering regression. Parity evidence above is taken from
  the main checkout's build, the build that produced the baselines.
- **No texture mip bias under upscaling.** The scene shaders' `Sample` calls are shared with the
  parity-locked non-temporal pipelines, so textures read softer below scale 1; a mip bias is left
  for a future slice (spec §13).
- **The controller drives on GPU pass-time sum, not wall time**; a frame's CPU cost is invisible to
  it, by design (spec §8).
- **The kernel splits at scale 1** (ADR 0016): a scale-1 frame following a different render extent
  still runs the upscale kernel for that one frame rather than the native kernel, to read the
  correct history rectangle.
- **The upscaled ghosting tolerances are widened** (spec §10's 2026-09-09 amendment; ADR 0016):
  "Motion and ghosting" to 0.125× contrast and the "Scale oscillation" ghosting clause to 0.15×,
  both structural consequences of dilating motion/depth over render texels rather than output
  pixels at a reduced scale; the native scale-1 tolerance (0.1) is unchanged. Narrowing the dilation
  footprint at reduced scale is a candidate follow-up; it changes the kernel and is not taken here.
- **`ResolutionControllerSettings` bounds come from `kMinRenderScale`/`kMaxRenderScale`.** A `float3
  pad` in a Slang parameter block is 16-byte aligned in the generated MSL; the upscale kernels'
  trailing pad is spelled `float pad[3]` (4-byte aligned) for this reason, while
  `TemporalResolveParams` keeps its original `float3 pad` since nothing is appended after it —
  recorded as a trap for any future field appended there.
- **`Tests/*.cpp` and `Shaders/*.slang` carry no `@file` header**, by existing convention.
- Deferred review minors, none blocking: the controller has no assert on a negative
  `gpuMilliseconds` sample; `--render-scale nan` passes the range check (`nan` compares false
  against both bounds); `TemporalResolve.cpp`'s `declareUpscale` duplicates `declareResolve`'s
  binding lambda, and the file is about 935 lines; `GpuTemporalTests.cpp` is about 3,076 lines;
  `TemporalUpscale.slang`'s reset-path comment numbering does not match its step count exactly; the
  render graph's `compile()` does not reject a render area declared with no attachment (`execute()`
  does).
