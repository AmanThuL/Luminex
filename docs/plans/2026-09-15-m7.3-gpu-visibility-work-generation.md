## 2. GPU classify, scan and emit

- `GpuVisibility` owns pipelines, paced candidates/runs/chunks, states/counters and readback
  context. Draw rows/arguments permit GPU storage writes. CPU uploads tables only when bytes
  change in that slot. Grow by the scene-table rule; retain replaced resources through last use + 3.
- Declare reset copy, classify, dense-only scan and emit under `lmx.pass.visibility`.
  Classify preserves bypass precedence and computes chunk counts. Scan loops with carry over
  arbitrarily many chunks per run. Emit uses deterministic exclusive prefixes, never atomic
  allocation; counters alone use atomics. Arguments are five raw words with defined rejected slots.
- Bounds-check every state/row/argument write. Capacity fixtures verify drop-and-count,
  reconciliation, truncated run instanceCount, guard bytes and empty ranges. Production capacity
  prevents overflow; any observed overflow is surfaced and invalidates scored/capture output.
- Integrate graph imports and terminal-state tracking for GPU writers, shader readers and
  indirect readers. Preserve CPU default graph goldens; add GPU goldens including transients
  and derived barriers. Scene/Shadow retain fixed command encoding and existing material semantics.
- Retire results at paced slot reuse, preserving frame number, scene generation, candidate
  ordering and diagnostics. Check mode snapshots CPU expectations at declaration, compares states,
  valid sequences, per-run counts and defined argument words on retirement, and is unscored.

### Clarifications pinned before implementation

All record indices are absolute within combined scene-then-shadow tables; view ranges select
those indices. Compare CPU/GPU by canonical run identity, treating omitted CPU runs as zero-count
logical runs; compare retained row sequences and defined geometry fields exactly. GPU physical
firstInstance stays layout-specific. Preserve zeroed rejected sparse arguments; an empty dense
run keeps its geometry fields and reserved firstInstance with instanceCount zero.
Argument-capacity failure drops that command's retained rows too; state-capacity failure drops
retained candidates without an emit read of absent state. Count these drops in reconciliation;
CPU command lists never reference physically absent arguments. Export diagnostics as graph sinks
so empty-view passes remain live. Track terminal uses per physical allocation across mode changes.
Retained readback context owns declaration-time bounds/order. App captures full generational
InstanceIds at declaration, never reconstructing old identities from current row occupants.
Keep declaration metrics and retired GPU counters separate, join by exact frame ID, and expose
an explicit post-waitIdle drain for final frames without fabricating three new rendered frames.
