# M5.5 — Render Graph Legibility and Detached Window

**Status**: Implemented (2026-09-05)

This plan executes the accepted design in `docs/specs/2026-09-05-m5.5-graph-legibility-design.md`.
`docs/roadmap.md` owns the M5.5 outcome, deliverables, exit gate, and deferrals; this plan
decomposes that boundary without expanding it. The spec fixes the layout model, the window
mechanism, the panel behavior, and the testing obligations; tasks reference those definitions and
may not change them.

## Outcome

The Render Graph opens in its own OS window, and its canvas draws a compact, grouped, wrapped
layout of the exact newest retired frame: stage groups collapse the bloom and exposure chains,
pins are short labels with full labels on hover and selection, and long chains wrap into rows under
a columns-per-row control. Positions stay deterministic; renderer output stays byte-identical.

## Integration

All work lands on `feat/m5.5-graph-legibility`, forked from `feat/m5.4-graph-node-view`, and
reaches `main` in one squash pull request after M5.4's. Tasks run sequentially on the branch. Every
task passes `xmake format --check`, `xmake policy`, and `xmake test`; GPU checks run on Metal 4
Apple Silicon under `MTL_DEBUG_LAYER=1`. Parity baselines are the M5.4 tip's fixed-camera
1280×720 screenshots (SHA-256), kept outside the source tree.

## Global constraints

- C++23; the Tests target links no ImGui, SDL, or node-editor code.
- `ax::NodeEditor` and `imgui_internal.h` stay confined to `RenderGraphPanel.cpp` and
  `EditorShell.cpp` respectively; no Luminex header exposes either.
- Nothing under `Source/Render`, `RHI/`, `Shaders/`, or `ThirdParty/` changes.
- Workspace schema stays 1; no new persisted file.
- Layout is a pure function of record, expansion set, and column count; timing and frame ID never
  influence it.
- Commit subjects ≤ 72 characters; no AI trailer.

## Task 1 — GraphLayout model

**Model**: Opus 5 (review: Fable, main thread). **Files**: create `Source/App/GraphLayout.h/.cpp`
and `Tests/AppGraphLayoutTests.cpp`; modify `Source/App/GraphNodeModel.h/.cpp`,
`Tests/AppGraphNodeModelTests.cpp`, `xmake.lua` (Tests `add_files`).

Public surface (spec section 4):

```cpp
namespace lmx::app {
inline constexpr float kGraphLayoutColumnSpacing = 260.0f;
inline constexpr float kGraphLayoutRowSpacing = 110.0f;
inline constexpr float kGraphLayoutRowGap = 80.0f;
inline constexpr float kGraphLayoutCulledBandGap = 120.0f;
struct GraphLayoutOptions { uint32_t columnsPerRow = 0; std::vector<std::string> expandedGroups; };
struct GraphLayoutGroup {
    std::string key, stage;               // "lmx.pass.bloom" / "bloom"; culled split appends "#culled"
    std::vector<uint32_t> members;        // node indices, declaration order
    bool culled; bool expanded;
    std::optional<double> gpuMillisecondsSum; uint32_t measuredMembers;
};
enum class GraphLayoutItemKind { Node, Group };
struct GraphLayoutPin { uint32_t resource; std::string resourceName, shortLabel, label; uint32_t version; };
struct GraphLayoutItem {
    GraphLayoutItemKind kind; uint32_t index;   // node index or group index
    std::vector<GraphLayoutPin> inputs, outputs; // node items: copied from the node; groups: boundary pins
    uint32_t layer, rank, row, column; float x, y; bool culled;
};
struct GraphLayoutEdge { uint32_t fromItem, fromPin, toItem, toPin, resource, version; std::string resourceName; };
struct GraphLayoutAliasLink { uint32_t fromItem, toItem; uint32_t sourceLink; }; // index into model.aliasLinks
struct GraphLayout {
    std::vector<GraphLayoutGroup> groups; std::vector<GraphLayoutItem> items;
    std::vector<uint32_t> itemOfNode;     // node index -> item index (its group's item when collapsed)
    std::vector<GraphLayoutEdge> edges; std::vector<GraphLayoutAliasLink> aliasLinks;
    std::string signature;
};
GraphLayout layoutGraph(const GraphNodeModel& model, const GraphLayoutOptions& options);
std::string graphPinShortLabel(std::string_view resourceName, uint32_t version); // "sceneColorHdr v1"
}
```

Steps: (1) leave `GraphNodeModel`'s M5.4 layout fields and constants in place for now — the panel
still reads them until Task 3 switches it over and deletes them, so the App keeps building after
this task; (2) add `AppGraphLayoutTests.cpp` with the M5.4 layout cases ("a culled pass … sits in
the culled band" position assertions and "layout is identical for two compiles…") rewritten over
`layoutGraph` with `columnsPerRow = 0` and every group expanded, leaving the originals in place
until Task 3 removes them; (3) implement grouping, items, visible edges, layering, wrapping, culled band, and the
signature exactly per spec section 4; (4) tests per spec section 6, including: a frame with
`lmx.pass.bloom.threshold/downsample0/upsample0` collapses to one group whose pins are only the
boundary versions and whose internal edges are hidden; expanding it yields the same items and edges
as the model; a two-segment-suffix label such as `lmx.pass.scene` never groups; a single-member key
never groups; a mixed scheduled/culled key splits; `columnsPerRow = 2` over a five-layer chain puts
layers 0–1 in row 0, 2–3 in row 1, 4 in row 2, with row heights from rank counts; signature
changes with expansion set and column count, not with timings. Commit:
`app: add GraphLayout with stage groups, wrapping, and compact pins`.

## Task 3 — Panel

**Model**: Opus 5 (review: Fable, main thread). Depends on Tasks 1–2. **Files**:
`Source/App/Panels/RenderGraphPanel.h/.cpp`, `Source/App/EditorShell.cpp` (state init only).

1. `RenderGraphPanelState` gains `GraphLayoutOptions layoutOptions` and `std::optional<uint32_t>
   selectedItem` (replacing `selectedNode`); `appliedSignature` now stores `GraphLayout::signature`.
   Remove `layer`, `rank`, `x`, `y`, and the three spacing constants from `GraphNodeModel.h/.cpp`
   and delete the two M5.4 layout cases from `AppGraphNodeModelTests.cpp` (their replacements
   landed in Task 1); the layout constants in `docs/plans/2026-09-04-…` are historical and stay.
2. Draw items from `layoutGraph(model, state.layoutOptions)`: node items as in M5.4 but with
   compact pins (dot plus `shortLabel`; tooltip with `label` on hover via `ed::Suspend`/`Resume`;
   full label drawn in place for the selected item and its visible-edge neighbours); group items
   with the distinct header (`<stage> -- N passes -- X.XXX ms (k measured)`) and boundary pins.
   Ids per spec section 5. Alias links and culled overlays map through `itemOfNode`.
3. Interaction: `ed::GetDoubleClickedNode()` toggles the group (or the member's group) in
   `layoutOptions.expandedGroups`; the header `columns` `ImGui::InputInt` (1–32) edits
   `columnsPerRow`; first draw with a frame and Reset Layout set it from
   `max(2, floor(canvasWidth / kGraphLayoutColumnSpacing))`; relayout and selection clear when the
   layout signature changes.
4. Details pane: item-based; a group shows key, count, sum and measured count, member table
   (schedule position, label, GPU ms), Expand/Collapse button.
5. Verify: `xmake`, `xmake test`, a 120-frame validation-clean run with the detached window and a
   headless injected double-click on a group, bloom toggle with a group expanded. Commit:
   `app: draw grouped, compact, wrapped nodes on the Render Graph canvas`.
