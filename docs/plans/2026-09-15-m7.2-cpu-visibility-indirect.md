### Retirement scheduling decision (before collection)

The existing Device API publishes only the newest retired timing, so a continuous loop can skip
measured frames. To retain every exact GPU join without an RHI addition, measurement front ends
waitIdle after each submitted measurement/warmup frame, outside the CPU encoding interval, then
join on the next beginFrame. Reports explicitly label serialized-retirement pacing. The live editor
still renders UI and presents every frame; ordinary execution retains three frames in flight.
These samples characterize isolated frame costs, not steady-state overlapped throughput. Missing
joins still invalidate a report; no interpolation or fabricated GPU time is permitted.
