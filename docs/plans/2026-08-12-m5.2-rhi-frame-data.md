# M5.2 — RHI Frame-Data Path and Public Surface

**Status**: In progress

This plan executes the accepted design in
`docs/specs/2026-08-12-m5.2-rhi-frame-data-design.md`. `docs/roadmap.md` owns the M5.2 outcome,
deliverables, exit gate, and deferrals; this plan decomposes that boundary without expanding it.
The spec fixes the public contract, arena policy, workload set, measurement protocol, and
acceptance thresholds; stages below reference those definitions and may not change them. The
spec's stage order (section 13) is preserved; the two stage-1 tracks are mutually independent and
may proceed in parallel.

## Outcome

The production RHI absorbs M5.1's proven per-frame data-delivery win through one typed,
GPU-address-visible `bindFrameData` path over retirement-safe growable per-slot pages, while the
monolithic public `RHI.h` splits into self-contained concept headers behind an umbrella. All
callers migrate in this milestone; `setUniforms` is removed with no compatibility alias. The
frozen `Experiments/NoApi/` artifact is not modified.

## Integration

All work accumulates on the outcome branch `feat/m5.2-frame-data` (the milestone docs branch
renamed to satisfy `docs/conventions/commits.md`), which reaches protected `main` in a single pull
request. The spec, this plan, and the `AGENTS.md` active-plan pointer are committed on this branch
when the milestone starts. Every stage passes `xmake format --check`, `xmake policy`, and the
relevant suites before it is considered done; GPU coverage runs under `MTL_DEBUG_LAYER=1` on
Metal 4 Apple Silicon; scored performance runs use release builds with validation and capture off
per the spec's protocol.

## Stage 1 — Baseline and header boundary

Track A and Track B touch disjoint files and may run concurrently.

### Track A — Public header split

1. Split `RHI/Include/RHI/RHI.h` into the spec's leaf set, moving each declaration with its `///`
   contract unchanged: `Format.h`; `Buffer.h` (with `BufferDesc`, `BufferRange`, `BufferUse`);
   `Texture.h` (with `TextureDesc`, `TextureKind`, subresource/view/copy/layout/mip types,
   `TextureUse`); `Heap.h` (with `HeapDesc`, `SizeAlign`); `Sampler.h` (with `SamplerDesc` and its
   enums); `ShaderLibrary.h`; `GraphicsPipeline.h` and `ComputePipeline.h` (each with its
   descriptor and coupled enums, `StorageAccess` with the pipeline that declares it);
   `Indirect.h` (the three indirect-argument structs and alignment constant); `RenderPass.h`
   (`RenderPassDesc` and load/store vocabulary); `CommandList.h` (recording interface,
   `BarrierOptions`); `Swapchain.h` (`SwapchainDesc`); `Device.h` (`DeviceDesc`, `PassTiming`,
   creation surface). `Result.h`, `Validate.h`, `CaptureSchema.h`, and the Metal extension
   headers remain as they are.
2. Reduce `RHI.h` to an umbrella containing includes only. Leaf headers include only what their
   own declarations require and use forward declarations where ownership permits.
3. Point backend and RHI-internal sources at the narrowest practical leaf set; component and test
   code adopt narrow includes where doing so proves the boundary. External callers may keep the
   umbrella.
4. Keep the split behavior-neutral: no declaration, contract, or runtime change. The existing
   suites must pass unmodified.

Exit: `python3 Tools/check_rhi_headers.py` compiles every leaf and the umbrella in isolation; no
public header exposes a Metal, D3D12, or ImGui type; `xmake test` and `xmake policy` pass with no
production behavior change.

### Track B — Production benchmark and frozen baseline

1. Add a non-default `FrameDataBench` target under `Benchmarks/FrameData/` linking the production
   RHI only — no `Experiments/NoApi/` include or import. It renders the spec's disjoint
   deterministic quads offscreen and verifies readback.
2. Implement the five frozen workloads exactly as specified in spec section 11: `F-FIT-512`,
   `F-DYNAMIC-1024`, `F-DYNAMIC-4096`, `F-STATIC-1024`, `F-STATIC-4096`. Dynamic block contents
   are a deterministic function of frame and draw index; static resources are prebuilt before
   timing. Per-frame data delivery goes through one small seam function so the baseline and
   candidate builds differ only there. The baseline seam reproduces the incumbent's measured
   allocation path (ADR 0010, evidence 7.1): the fixed uniform ring while a frame's blocks fit,
   and per-draw buffer creation beyond its capacity, so overflow workloads measure the
   allocation cliff instead of fatally exhausting the ring.
3. Implement the timed region per the spec (starts after the pacing wait; includes arena reset,
   allocation, copy, binding, encoding, submit) and a deterministic readback oracle usable for
   baseline/candidate byte comparison.
4. Add the paired driver `Tools/Bench/frame_data_paired.py`: fresh baseline and candidate
   processes back to back, AB/BA alternation, 12 paired repetitions, 16 warm-up plus 256 measured
   frames per side, per-side median frame time, and a two-sided 95% paired bootstrap over
   percentage deltas using M5.1's fixed-resample method.

Exit: all five workloads run clean under `MTL_DEBUG_LAYER=1` on the incumbent delivery path —
ring within capacity, the measured per-draw allocation fallback beyond it — with deterministic
readback across repeated runs; the driver executes a full paired collection against two copies
of the incumbent build and reports a null result.

### Stage close

Tag the stage-1 tip `m5.2-baseline`. Its RHI runtime semantics are those of the branch's fork
from `main` — stage 1 changes header organization and adds the harness only — so stage 4 builds
the baseline executable from this tag.

## Stage 2 — Frame-data primitive

1. Add `GpuAddress.h`: standard-layout, trivially copyable value; zero is null; equality and an
   explicit validity test; no arithmetic.
2. Add to `CommandList.h`: the pure-virtual `bindFrameData(slot, data, size, alignment)`, the
   non-virtual default-alignment overload, the typed trivially-copyable template requesting
   `max(kFrameDataAlignment, alignof(T))`, and `kFrameDataAlignment = 256`, each with its `///`
   contract per spec sections 3 and 8. `setUniforms` remains until stage 3.
3. Implement the Metal 4 per-slot arena per spec section 4: 256 KiB normal pages as persistently
   mapped shared `MTL::Buffer`s with cached CPU/GPU bases, one page per slot at device creation
   reported through `Result`, bump allocation, lazy page growth with oversized requests rounded to
   the page quantum, cursor reset only after shared-event retirement with the spec's diagnostic,
   stable per-page labels, one-time residency registration, and the fatal exhaustion diagnostic.
4. Add validation asserts before native calls: pass scope (render and compute only; copy passes
   reject), slot bounds, null or empty input, non-power-of-two or sub-256 alignment, and
   frame-slot reuse.
5. Record capture metadata (page label, slot, offset, size, alignment, returned address) per spec
   section 10, and expose test counters — page creations, pages and bytes per slot, frame-data
   calls and bytes, native address binds — through a Metal extension header, not the public API.
6. Tests: CPU coverage for typed and untyped validation, alignment arithmetic across page
   boundaries, oversized pages, exact cursor reset, and deterministic page reuse; capture-schema
   coverage for the new range metadata and stable labels; GPU coverage uploading distinguishable
   blocks across multiple pages and at least twelve overlapping frames, verifying exact results
   and that no slot resets before retirement.

Exit: new CPU and GPU tests pass under `MTL_DEBUG_LAYER=1`; the frozen `[checkpoint-a]` filter
passes unchanged; existing suites remain green with `setUniforms` still in place.

## Stage 3 — Atomic migration

1. Migrate `Source/Render/Renderer.cpp` per-frame blocks to the typed `bindFrameData`; data that
   is static per spec section 6 stays on `bindBuffer` untouched.
2. Migrate every remaining caller — the GPU test suites, render-graph and validation tests, test
   support, and the benchmark's delivery seam — typed where a concrete block type exists, untyped
   for raw byte spans.
3. Remove `setUniforms` from `CommandList`, the Metal backend, mocks, and every remaining
   reference including comments and docs. No wrapper or alias remains.

Exit: `grep` finds no `setUniforms` outside `Experiments/NoApi/` and frozen research/milestone
records; checkpoint A passes unchanged; `xmake test` is green; Sponza, Damaged Helmet, and
MaterialLab run under Metal validation with manual/automatic exposure and bloom on/off exercised.

## Stage 4 — Evidence and conformance

1. Build the baseline executable from the `m5.2-baseline` tag in a separate worktree (regenerate
   its `compile_commands.json` with `-P .` and copy `ThirdParty/` subdirectories per the known
   worktree procedure) and the candidate from the branch tip; both release, validation and
   capture off, same compiler configuration.
2. Run the frozen paired protocol via `Tools/Bench/frame_data_paired.py` for all five workloads;
   verify byte-identical baseline/candidate readback per workload before accepting its timing.
3. Judge against spec section 11 verbatim: ≥25% CPU encoding win with CI excluding zero on both
   dynamic cases; candidate upper 95% bound ≤ +5% on `F-FIT-512` and both static cases; zero new
   arena pages or per-draw GPU buffers in measured frames after high water; one call, one copy,
   at most one native bind per `bindFrameData`; zero frame-data calls and bytes in static cases.
   Inconclusive results are rerun or investigated, never called a pass.
4. Verify capture quality: an Xcode capture retains M5.1's pass and resource readability and
   every uploaded address traces to one labeled page range.
5. Re-run checkpoint A under `MTL_DEBUG_LAYER=1`, the full `xmake test` suite, `xmake format
   --check`, and `xmake policy` at the collection tip.

Exit: every threshold holds with recorded environment, exact paired results, confidence bounds,
and allocation/binding counts; any deviation is recorded, not rationalized.

## Non-goals

Per the roadmap's M5.2 deferrals and spec section 14: bindless-resource migration;
shader-pointer, root-signature, resource, barrier, residency, or pipeline redesign; a general
mapped-buffer or allocation API; per-mip raster attachments; generation-checked handles;
resident-size queries; a D3D12 backend; later rendering features. Also out of scope: modifying
`Experiments/NoApi/`, re-running M5.1 evidence, multi-threaded recording, arena shrinking,
cross-frame frame-data reuse, content deduplication, and any public performance-query API.

## Validation

- `xmake format --check` and `xmake policy` at every stage
- `xmake test` (full suites) at every stage; GPU suites under `MTL_DEBUG_LAYER=1`
- The frozen `[checkpoint-a]` filter at milestone start, after stage 2, after stage 3, and at
  the tip
- Byte-identical baseline/candidate readback per workload before any timing is accepted
- The spec's frozen paired measurement protocol for every performance claim
- Scene validation runs (Sponza, Damaged Helmet, MaterialLab) after migration

## Exit gate

The roadmap's M5.2 exit gate applies verbatim: checkpoint A passes unchanged; every public header
compiles alone and leaks no native types; all production callers use the new path; frame-data
growth creates no backing allocations after the three slots reach high water; static bindings
write no frame-data bytes; overflow workloads materially improve while fitting and static
workloads regress by no more than 5%; captures identify uploaded ranges; and three-frame reuse is
validation-clean.
