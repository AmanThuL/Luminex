# M4.1 — MaterialLab Lookdev

**Status**: Implemented (2026-08-10)

## Outcome

MaterialLab opens as a useful material-reference scene: its complete roughness/metallic sphere grid
fills the default camera, a neutral studio environment reveals highlight shape without a distracting
blue background, and the remaining diagnostics form horizontal lanes reachable by translating the
camera without changing its orientation. The existing deterministic GPU oracles remain intact.

## Decisions

- Use Poly Haven's `Studio Small 09` 1K HDR environment. Poly Haven publishes the asset as CC0; the
  setup task pins its source URL and hash and writes provenance/license metadata beside the fetched
  file under `Assets/Fetched/MaterialLab/`.
- Decode Radiance HDR data as scene-linear float, resample the equirectangular image into the
  existing cubemap convention deterministically, and feed the same exposure-scaled, fixed-rotation
  cubemap to both the visible sky and IBL generation.
- Preserve MaterialLab's asset-free availability. A missing fetched HDRI emits an explicit warning
  and uses a neutral constant environment; tests that need analytic furnace or known-colour inputs
  continue to provide those environments directly.
- Keep the 5x5 sphere matrix. Arrange diagnostic groups, rather than individual spheres, along the
  world X axis so camera yaw, pitch, FOV, and Z remain fixed while A/D translation visits each lane.
- Treat high-frequency/minification-only content as a test oracle rather than forcing it into the
  default lookdev composition.

## Work

1. Add pinned setup acquisition and provenance for `studio_small_09_1k.hdr`.
2. Add a small Engine HDR/equirectangular environment loader with deterministic bilinear sampling,
   cubemap orientation tests, finite-value validation, fixed exposure, and fixed yaw rotation.
3. Upload the environment cubemap as linear `RGBA16Float`; generate irradiance, prefiltered
   radiance, and DFG assets from the exact same CPU cubemap.
4. Rebuild MaterialLab into three horizontal lanes: the sphere matrix at the origin, colour/
   gradient/normal diagnostics to its right, and depth diagnostics farther right. Pull the initial
   camera forward so every sphere is prominent and visible at both 16:9 and 4:3.
5. Keep the mip oracle outside the normal lookdev view and retain dedicated GPU coverage for it.
6. Add projection tests for the default sphere framing and translated lane cameras, plus HDR decode,
   equirectangular mapping, fallback, scene construction, and maintained image-oracle coverage.
7. Regenerate and visually review MaterialLab's offscreen capture, then close this plan into a
   renamed M4.1 milestone record covering both the RHI foundation and reference-scene polish.

## Non-goals

- Environment selection UI, arbitrary user HDRI import, automatic exposure, or background/IBL
  intensity decoupling.
- New RHI formats, compute IBL generation, general asset streaming, or an environment cache system.
- World-space text labels, camera animation, or a generic scene-bookmark framework.
- Changing furnace, BRDF, depth-reconstruction, known-colour, normal-map, or mip-filtering math.

## Validation

- `xmake format --check`
- `xmake policy`
- Focused Engine/Ibl/scene tests and `xmake test Tests/unit`
- `xmake test`
- `MTL_DEBUG_LAYER=1 xmake test Tests/gpu`
- MaterialLab offscreen capture with and without the fetched HDRI
- Visual confirmation that the 25 spheres fill the default frame and remain individually readable

## Exit gate

The default MaterialLab frame contains every roughness/metallic sphere at a useful screen size; the
other visible diagnostics are reachable by horizontal camera translation alone; the Studio Small 09
sky and its IBL share orientation, exposure, and source radiance; missing assets fail over explicitly
to a neutral deterministic environment; all prior M4/M4.1 validation remains green; and the final
M4.1 milestone record truthfully covers both component-boundary and reference-scene outcomes.
