# M5.6 — GPU Work-Submission Experiment — Implementation Plan

**Status**: In progress

This plan implements the accepted
[design spec](../specs/2026-09-06-m5.6-gpu-work-submission-design.md).
[Roadmap M5.6](../roadmap.md) owns the boundary. The spec owns workload definitions, variant
semantics, measurement protocol and judgment; stages below implement those definitions without
expanding them. Implementation is active; scored collection starts only after the freeze gate.

## Execution state — 2026-09-06

Stages 1–4 are implemented for direct, CPU-indirect, GPU-args and batched modes. The pinned ICB
route, GPU-span/stage instrumentation and complete trace-replay inspection remain unavailable.
Pre-collection production/experiment tests, 160 × 256-frame correctness replay and all-mode
900-frame stress passed. This verifies those runs, not uninterrupted measurement scheduling.

Stage 5 is blocked: the frozen no-verify collection encountered GPU global restarts and retirement
assertions, then was stopped for safety. There are 1,043 structurally valid pairs, two failed
processes and one interrupted pair; the full 1,920-pair supported matrix is not complete. The
[attempt record](../research/2026-09-06-gpu-submission-evidence.md) retains failures, missing rows
and the observation limits. No performance conclusion is accepted; verification readback changes
overlap and cannot dismiss the failure. The original pair's faulting mode remains unresolved.

The user authorized a bounded follow-up on the same Mac. A single-mode, pipelined diagnostic
without readback reproduced gpu-args/S timeout during warmup, submission 2/slot 1/frame 1, with
validation off; API+shader-validation-on retired. The session stopped after another global reset.
See the [diagnostic record](../research/2026-09-06-gpu-submission-diagnostic.md). This narrows a
reproducible path but does not establish root cause or a fix; the requests also differed in replay
length. No full collection was resumed and no diagnostic timing is scored.

A [fixed-length dependency follow-up](../research/2026-09-06-gpu-submission-dependency-diagnostic.md)
ran all/declared/declared/all masks with the same binary and 32+900 requested frames. The first
three retired; the fourth timed out during warmup and reset the GPU. Expanding the consumer mask
is not a sufficient correction. GPU testing stopped after that reset; root cause remains open.

Do not mark stage 5 or 6 complete, remove this plan, merge the experiment into main, or create the
final `m5.6-gpu-submission-evidence` tag. The current Mac is authorized for bounded test sessions.
Next, localize producer/consumer sensitivity while preserving submission telemetry, then verify any proven
fix and recollect all compared modes under a new freeze. Never overwrite the failed collection.

## Outcome

A repeatable Metal 4 submission/culling report, CPU and image oracles, an explicit ICB capability
result, and an ADR choosing adopt/retain/defer. Native-host measurements concern execution
mechanisms; a later M7 production benchmark must establish any production improvement.

## Integration and constraints

- Start from the merged M5.4/M5.5 main baseline plus these documents. Implementation lives on
  `exp/gpu-work-submission`; document preparation does not start that experiment branch.
- On starting implementation, mark the spec `Accepted` and this plan `In progress`; ensure it is
  the only active plan. Record baseline build, compiler/dependency pins and checkpoint results.
- Keep C++23, Metal 4, Slang and three frames in flight. Do not modify production source/public
  headers or fetched dependencies. Root `xmake.lua` may only include non-default experiment targets.
- All new source, shaders, tests and analysis tooling live under `Experiments/GpuSubmission/`.
  The native executor and production reference own separate resources; no native downcasts or
  public buffer-mapping/ICB API are introduced. All scored modes use one native executor.
- Every stage builds its affected targets and passes the applicable format/policy checks;
  maintain production build and tests at integration boundaries. GPU evidence runs on Metal 4
  Apple Silicon with validation; scored performance uses separate validation-free executions.
- Keep evidence bundles outside the source tree. End with an immutable experiment tag and a
  separate conclusions-only integration to main; never merge experiment source into main.

## Stage 1 — Manifest, targets and independent oracle

**Files:** `Experiments/GpuSubmission/xmake.lua`, `Model/Manifest.h/.cpp`, `Model/Workload.h/.cpp`,
`Model/Oracle.h/.cpp`, `Tests/ModelTests.cpp`; root `xmake.lua` include only.

1. Register the five spec section 3 targets with `set_default(false)` and disjoint shader output
   directories. The model exposes no Metal/RHI types. Production target source globs stay unchanged.
2. Define schema-versioned `Case`, `FrameInput`, `ExpectedVisibility`, `Variant`, and `Suite`
   records. Implement the exact core/bin matrices, deterministic 256-frame replay and generator
   from spec section 5. Serialize resolved matrices, IDs, geometry, bounds and hashes.
3. Implement CPU visibility independently of GPU shader code; add degenerate, boundary,
   bin-order, vertex-range overflow and stable-hash tests. Freeze explicit sphere/plane epsilon
   and coordinate conventions in the manifest. Include non-multiple-of-threadgroup counts.
4. Define the result schema with run/case/mode/frame IDs, nullable unsupported measurements,
   validation status, environment and capabilities. Make schema validation reject missing IDs,
   NaNs, duplicate frames and incomplete pairs rather than silently averaging them.
5. Run CPU selftests without creating a Metal device. Produce the first manifest for review;
   no timings at this stage are scored.

**Exit:** deterministic model/oracle tests pass; a plain build does not build experiments; the
manifest enumerates exactly the selected cases and is usable by both adapters.

## Stage 2 — Native host and bounded ICB probe

**Files:** `Metal/Host.h/.cpp`, `Metal/FrameSlot.h/.cpp`, `Metal/Capabilities.h/.cpp`,
`Shaders/Probe.slang`, `Tests/MetalProbeTests.cpp`, experiment build description.

1. Implement the minimal offscreen Metal 4 device/queue, pipeline, argument bindings, attachments,
   counter heaps, readback and slot completion events. Follow existing autorelease/destructor
   rules. Use experiment-local domain errors for creation and assertions for misuse.
2. Give each of three slots independent mutable resources and exact last-completion values.
   Validate basic direct rendering and alternating slot data before adding GPU command generation.
3. Implement `--capabilities` and the spec section 4 Slang-to-MSL ICB probe. Verify both the
   native host entry points and the compiled shader route; preserve diagnostics and emitted-MSL
   identity in the external evidence bundle. Test reset, inherited/explicit binding and residency.
4. End the probe within its two-day budget. If unavailable, mark ICB unsupported/unresolved with
   the reproducer and continue stages 3–6 for the supported modes. Do not begin compiler work,
   change pins or substitute handwritten MSL to manufacture a successful capability result.

**Exit:** the host can render/read back validation-clean with three slots; ICB is either verified
or truthfully unavailable. Production checkpoint A still passes unchanged.

## Stage 3 — Submission variants and production reference

**Files:** `Metal/Submission.h/.cpp`, `Shaders/Scene.slang`, `Shaders/Prepare.slang`,
`Reference/RhiReference.h/.cpp`, `Tests/ParityTests.cpp`, `Tests/GraphContractTests.cpp`.

1. Implement `direct`, `cpu-indirect`, `gpu-args`, and `batched` exactly as spec section 6 defines.
   Share native storage, state and compiled shader artifacts. Do not add per-draw frame uploads
   to direct mode when other modes use persistent instance tables.
2. Add `gpu-icb` only after stage 2 passes. Reset fixed per-bin ranges before every generation;
   encode visible candidates and execute the ranges without CPU count readback. Charge empty
   traversal. Keep optional optimization/compaction experiments outside the scored configuration.
3. Implement S's shared precomputed bitmap and E's CPU/GPU frustum paths. Include per-frame
   transfers and packing; GPU E receives no oracle output. Stable IDs and exact command counts
   must explain why CPU indirect and GPU-argument modes submit different numbers of calls.
4. Build the production reference with unchanged public APIs and the same diagnostic shaders.
   Compile the ordinary semantic graph with production RenderGraph; compare indirect resource
   uses, barriers and sinks, then execute it and compare retired readback with native direct.
   Use untimed public buffer creation/import for updates and retain resources until retirement;
   do not model native CPU writes as GPU copy passes. ICB native hazards remain a separate report.
5. Add independent visibility bookkeeping/readback in correctness builds, image comparisons,
   empty/full/tail cases and stale-command tests. Keep all validation-only writes out of scored
   shader variants. Record the parity relationships among their shared math and bindings.
   Replay the exact scored artifacts untimed with post-retirement readback and image/argument
   checks; instrumented visibility alone is not proof that the scored binaries are correct.

**Exit:** supported variants pass the 256-frame oracle and image contract. Captures explain
preparation and execution. The production RHI serves as a correctness anchor, not a timing baseline.

## Stage 4 — Runner, statistics and report contract

**Files:** `Bench/Main.cpp`, `Bench/Runner.h/.cpp`, `Model/Results.h/.cpp`,
`Tools/paired.py`, `Tools/test_paired.py`, `Tests/RunnerTests.cpp`.

1. Implement the proposed CLI in spec section 11, safe output-directory handling and paths
   resolved independently of caller CWD. Reject invalid case/mode combinations and active
   validation/capture in measurement mode. Capability absence is not a zero-duration success.
2. Implement spec section 9's separate headline, GPU-span and stage-diagnostic lanes. Prove GPU
   boundary ordering, measure observer overhead, and keep marker-free CPU/throughput evidence
   separate. Preserve raw frames and retirement IDs with explicit warmup/drain boundaries;
   pass-time sums are not workload spans, and unproven spans are unavailable metrics.
3. Implement paired AB/BA execution, 12 repetitions, 32 warmup/256 measured inputs, fixed-seed
   bootstrap intervals and the section 10 rubric. Make the driver collect the whole matrix for
   S/E and both scored lanes, including GPU-args/ICB-versus-batched pairs; preserve failures and
   unsupported rows. Stage-diagnostic runs are separate unscored observations.
4. Test the driver using synthetic known deltas, reversed AB/BA, incomplete/duplicate frame sets,
   unavailable counters, zero denominators, failed processes, mismatched manifests/shader hashes,
   lane mismatches, output collisions and an uncertain >15% loss that must block adoption.
   Tests must detect biased or incomplete reports, not just file creation.
5. Produce an unscored smoke report, audit timed boundaries and stage/frame counts, and freeze
   the resolved manifest, shaders, schemas, counter placement and protocol for scored collection.

**Exit:** one command produces an auditable report; statistics and failure-path tests pass. Any
later workload/shader/instrumentation change invalidates collection for all compared modes.

## Stage 5 — Validation and scored evidence

1. Build production App/Tests and all supported experiment targets in release configuration.
   Run production unit/GPU suites, frozen checkpoint A and experiment CPU/GPU suites separately.
2. Run the 900-frame lifetime stress and capture representative empty/sparse/dense cases with
   validation enabled. Verify complete generated work, labels, resource reachability, retirement,
   no stale slot data, no post-warmup capacity growth, and clean teardown.
3. Collect scored runs with validation and capture off, per spec section 9; record actual flags,
   environment, power/thermal observations and every run failure. Preserve all matrix cells and
   confidence intervals. Do not alter thresholds or remove outliers after viewing results.
4. Check requested/allocated/resident memory labels, reset/preparation costs, and counter
   availability. Report native execution conclusions separately from production RHI coverage.
5. Repeat the report generation from retained raw results and verify the same summary. Re-running
   GPU collection should reproduce the stated effect within its uncertainty, not byte-identical
   timings. Record any unstable finding as inconclusive.

**Exit:** every claimed supported path passes gates; the report is complete even if ICB is
unavailable or no performance hypothesis succeeds. No scored evidence predates the freeze.

## Stage 6 — Decision, evidence tag and production handoff

1. Apply correctness/lifetime/capture gates before the frozen material-change rules. State
   adopt/retain/defer, break-even regions, failing cells and limits in a dated research record.
   If native ICB wins, identify the bounded M7 contract needed rather than promoting this host.
2. Write the deciding ADR and `docs/milestones/m5.6.md` only after evidence exists. Link the
   artifact manifest and last verified environment; state which ICB and production graph claims
   were actually validated. Do not imply that native timings measure the production renderer.
3. Freeze the experiment source, workload/oracle, analysis tools and reproducibility instructions
   at `m5.6-gpu-submission-evidence`. Keep raw bundles outside the published tree with checksums
   and accessible artifact references. Never move an existing evidence tag.
4. Integrate only conclusions/ADR/milestone into main. No experiment directory or root build
   include survives there. M7 builds a maintained production benchmark from the frozen workload
   contract after interface gate B, leaving the original experiment untouched.
5. Update roadmap baseline and operational documentation where facts changed; close/remove this
   plan per convention. Verify the clean production tree still builds, tests and passes policy.

**Exit:** roadmap M5.6 is satisfied with truthful evidence and an immutable reproduction route.
M6 can proceed without waiting for another vendor/API or an unavailable ICB capability.
