# R1.3 — App Model Library and Shared Scene Session

**Status**: Implemented (2026-09-13)

This plan executes [R1.3](../roadmap/codebase-module-boundaries.md#r13--app-model-library-and-shared-scene-session)
without expanding its boundary. The milestone record is written first, this plan second, and
implementation follows. R1.1 and R1.2 are implemented; R1.4 remains deferred.

## Integration and constraints

Work uses `codex/r1.3-app-session` from local main and lands as one commit, fast-forwarded into
local main without a PR, as explicitly requested by the owner. This overrides the roadmap's
multiple move commits and normal PR integration convention for this slice. Existing main history
is preserved. No shader, uniform, SceneView field, pass label, rendering behaviour or RHI change
is permitted. Independent evidence, mechanical model extraction and session work may use
subagents after this plan exists; source changes wait until parent runtime artifacts are frozen.

## Task 1 — Freeze parent evidence

Build parent App, Tests and TextureBake in this session on this device. Save binaries, runtime
shaders, hashes, test inventories and commands outside the source tree under
`/tmp/luminex-r1.3-evidence`. Preserve the exact pre-existing case names/tags and checkpoint-A
selection. Reuse evidence procedures from R1.2 with newly generated parent artifacts.

## Task 2 — Link the App model

Mechanically move the 14 shared C++ sources, their headers, DirectionalLightRole.h and
EditorRenderSettings.h into Source/App/Model; update includes without namespace or behaviour
changes. Add the AppModel static target linked by App and Tests. Tests lists Tests C++ sources
only (its existing shader build inputs remain). Replace transitional ownership entries with the
Model directory and remove all 14 shared-source allowances. Include and target-dependency checks
continue rejecting shell, ImGui, SDL and Metal dependencies from Model.

## Task 3 — Share scene preparation and frame declaration

Add a model-layer SceneSession composed by EditorShell and the offscreen loop. It borrows the
active Scene, carries its camera, and shares activation/reset, playback advancement and sampling,
camera-track follow, view production into caller-owned items, and accepted-frame motion commit.
Keep screenshot frame zero at authored time, sequence absolute frame/bake-rate sampling, editor
fixed-step playback and fly-camera override exactly as before. Settings and one-shot exposure
and temporal latches keep their current owners. EditorShell composes the session and retains its
ImGui settings handler, panel coordination and input. The shared clear constant leaves the shell
header so headless capture does not include EditorShell.

Inspection found an existing activation difference: the editor resets object motion, while
headless preserves the loader's previous transforms (MaterialLab can retain identity there).
Activation takes an explicit initial-motion policy to preserve both contracts; a unit test pins
the distinction. Making headless reset as well would be a behaviour change outside this slice.

Add shared frame declaration/retention used by main and Screenshot: begin the transient pool
after Device::beginFrame retires its slot, construct a graph with the caller's pooling flag,
declare passes, permit the editor to append its UI/present sink or headless to export the output,
execute and retain the compiled record. Timing joins and Device begin/end/wait stay in each loop.
Preserve headless pooling/export semantics from Renderer::render. Do not change Renderer itself.

The session header documents that SceneView borrows caller item storage and scene resources
through declaration and execution; per-frame graphs die before the pool, and that pool rotates
only on the slot beginFrame retired; destruction is shell, renderer, pool, device, SDL layer;
motion commits only after execute accepted a frame and resets on editor activation/discontinuity;
headless activation explicitly preserves loaded motion as described above.
Add session tests for activation/camera, editor pause/fly override, screenshot/sequence time,
borrowed view and motion reset/commit. Add shared-frame integration coverage where useful.

Run the unchanged fifteen-case strict screenshot matrix in alternating parent/candidate rounds.
The total maximum is eight paired rounds, fixed before measurement, including all extensions.
Stop only when every candidate hash has occurred for its case in this session's parent runs.
Keep every output and strict-runner failure; do not edit reference.json, widen the M6.5 exception,

until a cause is identified and fixed. No performance claim.

Exercise the editor with LMX_MAX_FRAMES through its down/up resize hook and LMX_CAPTURE_AT_FRAME
under Metal validation. Record scene switching, playback, camera cut and dynamic-resolution
behaviour in the editor; UI evidence supplements unit tests of the extracted policy and session.
