# R1.2 — Asset and Scene Replace Engine

**Status**: Implemented (2026-09-13)

This plan executes [R1.2](../roadmap/codebase-module-boundaries.md#r12--asset-and-scene-replace-engine)
without expanding its boundary. The milestone record is written first, this plan second, and
implementation follows. ADR 0020 is accepted. R1.3 and R1.4 remain deferred.

## Integration and constraints

Work uses `codex/r1.2-asset-scene` from local main and lands as one commit, fast-forwarded into
local main without a PR, as explicitly requested by the owner. This overrides the roadmap's
multiple move/rename commits and the normal PR integration convention for this slice. Existing
main commits are preserved. No shader, uniform, SceneView field, pass label, rendering behaviour,
RHI signature or umbrella change is permitted. Namespace migration is mechanical: identify the
owning declaration, replace Engine include paths with Asset/Scene paths and `engine::Symbol`
with its owning `asset::Symbol` or `scene::Symbol`; namespace declarations follow file ownership.
Do not keep an Engine compatibility namespace or add Asset dependencies on GPU interfaces.

## Task 1 — Freeze parent evidence

Build parent App, Tests and TextureBake in this session; preserve binaries, runtime shaders,
case inventory and hashes outside the source tree under `/tmp/luminex-r1.2-evidence`. Record
parent commit and all commands. The checkpoint-A selection keeps its exact names and tags.

## Task 2 — Shared leaf contracts

Extract Core/Color.h with scalar and glm overloads and public glm; remove duplicate colour
headers. Extract RHI/TextureDesc.h from Texture.h, keeping Texture.h's include compatibility and
RHI/RHI.h unchanged. Extract the existing frame input declarations into Render/SceneView.h;
Renderer.h includes it and retains the orchestrator and pass constants. AlphaMode retains its
leaf declaration through the frame input header. RHI public header and standalone Source header
checks remain required.

## Task 3 — CPU content and scene ownership

Move CPU decoders, bake/SHA-256, geometry and clip sampling into Asset; split DDS/IBL upload into
Scene. Move scenes, catalog, labs, environment and playback into Scene. Give the glTF loader its
own alpha enum and translate explicitly at scene upload, preserving BLEND rejection. Consolidate
repository asset discovery while preserving each caller's candidate order and failure contract.
Move the BMP writer to Asset with its bool result and byte format unchanged. Move cameraFromScene
to Scene. Subagents may implement independent file groups after this plan exists.

## Task 4 — Consumers, targets and contract

Replace Engine with Asset and Scene static targets. TextureBake depends on Core and Asset only;
Asset receives the RHI public include directory without linking RHI. Update consumers and
namespace qualifiers mechanically. Change only test grouping tags `[engine]` to `[asset]`, `[scene]` or `[core]` for
colour tests, based on ownership; preserve case names and all other tags. Record mixed cases by
case rather than treating a whole file as CPU-only. Update the contract map and remove all R1.2
allowlist entries; enable Asset's undefined-RHI-symbol check. Keep R1.3 exceptions only. The transitive include checker also grants TextureBake the same two
descriptor headers as Asset, because the unchanged BakedMipChain exposes TextureMip views;
this grants no RHI target dependency or GPU interface.

## Task 5 — Verification and parity

Run build, format check, policy including module link and standalone headers, Python tooling
tests, CPU and Metal-validation GPU tests, and the unchanged checkpoint-A filter. Compare parent
and candidate case names; any new tests are additive. Compare graph dumps byte-for-byte, capture
sequence manifests/PNG metadata and capture schema JSON byte-for-byte, deterministic bake DDS/PNG
and manifests byte-for-byte. Compare GPU capture dumps semantically: pass/encoder/resource labels,
pass order and uniform layouts, excluding timings. Preserve commands, logs and binary/shader hashes.

Run the existing fifteen-case strict screenshot matrix in alternating parent/candidate rounds.
The total maximum is eight paired rounds, fixed before measurement, including any extensions.
Stop early only when each candidate image hash has appeared for that case in this session's
parent runs. Preserve every output and strict-runner failure; never change reference.json,
rebaseline, widen the M6.5 exception, or retry beyond the cap. A candidate-only hash at the cap
blocks acceptance and merge until a cause is identified and fixed. No performance claim.

## Task 6 — Record and integrate

Update architecture overview, frame walkthrough, README directory table, AGENTS.md, module
convention and roadmap baseline for the implemented ownership. Fill the milestone with measured
results and limitations; close this plan when accepted, following R1.1's retained-plan precedent.
Review the final diff and confirm the index contains only this slice; commit once with the
conventional subject `scene: separate CPU assets from GPU scenes`, then fast-forward main.
