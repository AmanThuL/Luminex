# R3.4 Core Implementation Plan

**Status**: In progress

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development to
> execute this plan task by task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Core owns the domain-free math and data structures under
`Source/Core/{Math,Containers,Util,IO,Diagnostics}/`, Engine keeps only scene meaning, and the
catalog is its own unit `Source/Scenes`, with no rendered or behavioural change against `52945a6`.

**Architecture:** the contract first admits both layouts; Core's fourteen files move into folders;
each new Core header lands with tests that pin it to constants captured from the code it replaces;
owners of disjoint files adopt Core in parallel; two Engine files are decomposed; three cuts and a
scripted move and rename take the catalog out. A cheap gate runs at every commit, a heavy gate at
every adoption, the full protocol once at the head.

**Spec:** [R3.4 record](../milestones/r/r3.4.md) — its interface table is every Core task's
contract and its commit sequence numbers (S1–S32) are used below — with the
[R3 design](../milestones/r/r3.md#r34--core) and
[ADR 0026](../decisions/0026-core-charter-and-placement.md). Executors read all three.

## Global constraints

- Branch `r3.4-core`, which already carries the roadmap change; one pull request holds both. The
  chain is built in a worktree. No commit edits a file under `RojoRHI/`. No AI trailer or
  attribution in commit or pull-request text. Subjects follow `docs/conventions/commits.md`:
  `<scope>: <imperative outcome>`, at most 72 characters, scopes `core`, `engine`, `asset`,
  `scene`, `render`, `app`, `tool`, `build`, `docs`, `test`; no mention of plans, tasks, agents or
  models, in commits or in source comments.
- No pass label, shader basename, CLI option, schema, file format, test tag or existing test case
  name changes; `Scene::sponzaLightIds` → `rigLightIds` is the one public rename; no
  using-directive; glm stays the vector vocabulary; Core includes no Engine, Asset, Render, App or
  RojoRHI header.
- Arithmetic moves expression for expression, operand order included. Never simplify, reassociate,
  or swap a glm call for an equivalent. `-ffp-contract=off` stays on `LocalLightMath.cpp` only.
- `xmake format --check`, every checker, `check_module_deps.py --link` with an **empty** allowlist
  and the cheap gate pass at **every** commit; the heavy gate at S16–S26.
- Model tiers: the main thread is Opus 5 and no subagent runs above it. **[Opus]** tasks are
  design-sensitive, **[Sonnet]** standard, **[Haiku]** trivial. An Opus subagent reviews Sonnet
  work; the main thread reviews Opus work. Every task in a wave is dispatched in one message so
  the wave runs concurrently; an agent that finishes early is not a reason to wait on its wave.
- Worktree recipe (every agent that builds): its own worktree of the stated base; every xmake
  command takes `-P .`; `git submodule update --init`; copy each subdirectory of the main
  checkout's `ThirdParty/` into the worktree's `ThirdParty/`; symlink the main checkout's
  `Assets/Fetched`; `xmake f -P . -m release -y`. Never run `xmake policy` in a worktree; run the
  checkers listed in `AGENTS.md` directly. An agent returns one commit hash; the main thread
  cherry-picks in S order into `$EV/wt-chain` and appends to `$EV/chain.txt`.
- Evidence lives in `/tmp/luminex-r3.4-evidence/` (`$EV`), never in the tree; `$EV/seed/` holds
  R3.3's `gate.sh`, `move.py`, `namespace.py`, `namespace-tests.py`, `chain-step.sh` and
  `gen_comments.py` to adapt. Failed runs are kept. GPU work is serialized with `mkdir
  $EV/gpu.lock` (remove on exit). Three failed attempts on one problem: stop and report.
