## Roles, models and parallelism

Main thread: Opus 5.5 — worktrees, commits, builds, measurement runs, reviews of Opus work and
the decision. Implementers: Opus 5 for shader candidates (Tasks 4, 5), Sonnet 5 for harness and
scripts (Tasks 1–3) and the validation draft (Task 9); each Sonnet task gets an Opus 5 reviewer.
No subagent runs above Opus. Waves: **W1** Tasks 1, 2, 3, 4 in parallel → **W2** H commit, Task 5,
builds → **W3** Tasks 6–7 (static in parallel with CPU suites; GPU serialized) → **W4** Task 8
session in the background with Task 9 in parallel → **W5** Task 10.

## Review focus

1. A capture that crashes, times out or exits nonzero is a recorded failure (hash `null`, not
   unchanged), never skipped; an interrupted session resumes from `session.jsonl`.
2. `LMX_EXPERIMENT_AUTO_EXPOSURE` is set only for Auto cases: each capture's environment starts
   from a clean copy (selftest pins it).
3. Every capture runs with CWD = that build's App directory and loads that build's own metallibs;
   the static step checks each build's `.metal`/`.metallib` inventory.
4. A test binary run directly is rebuilt first (`xmake build -P . Tests`) so a stale pass is
   impossible.
5. Normalization never hides a layout change: selftests prove a changed binding index, type or
   uniform offset compares unequal.

### Task 4 (Opus): candidate A — worktree `a`

**Files:** create `Shaders/Passes/Scene/ScenePassShared.slang` (`module ScenePassShared;`, no
entry point); rewrite the four `ScenePass*.slang` as thin entry files.

The module carries, in today's order and with today's comments: the file header (slot map), the
imports, `kSpecularMipCount`, `Vertex`, every global except `gExposureOverride`, `PassUniforms`,
`applyNormalMap`, `VSOutput`, `shadeVertex`, the reactive constants and `reactiveFromEmissive`,
`SurfaceShading`, `MotionVSOutput`, `MotionFSOutput`, and three helpers holding today's entry
bodies verbatim: `VSOutput sceneVertex(uint vid, uint instanceIndex)`, `MotionVSOutput
sceneMotionVertex(uint vid, uint instanceIndex)`, `MotionFSOutput sceneMotionOutput(MotionVSOutput
input, SurfaceShading shaded)`. The shading body becomes:

```slang
interface ISceneExposure { static float preExposure(); }
struct ManualExposure : ISceneExposure { static float preExposure() { return gPass.preExposure; } }
interface ISceneCoverage
{
    static void clip(float alpha, float cutoff);          // Masked: applyAlphaMask
    static float3 orient(float3 normalW, bool frontFace); // Masked: frontFace ? n : -n
    static float outputAlpha(float baseColorAlpha);       // Masked: 1.0
}
struct OpaqueCoverage : ISceneCoverage { /* no-op, identity, baseColorAlpha */ }
struct MaskedCoverage : ISceneCoverage { /* as commented */ }
SurfaceShading shadeSurfaceDetailed<E : ISceneExposure, C : ISceneCoverage>(VSOutput input,
                                                                            bool frontFace)
```

The calls sit exactly where `ScenePassMask.slang` has its differences today (`clip` after the base
colour sample, `orient` after normal mapping, `outputAlpha` in the colour write), and `E.preExposure()`
replaces both exposure reads. Each Auto file declares `gExposureOverride` (binding and comment as
today) and `struct AutoExposure : ISceneExposure` reading `gExposureOverride[0]`. Entry files keep
the four entry names and signatures; opaque fragments pass `frontFace = true`. Each entry file
keeps a short header naming its variant and the module.
