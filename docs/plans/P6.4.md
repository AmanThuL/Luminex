## Findings that shape the plan (verified against v0.1.0 and the worktree)

1. **v1 is unchanged except formatting and a split unit.** Between `8da2a79` and `v0.1.0` the v1 tree was reformatted (`856bc775 build: adopt the No Graphics API C++ format`), moved under `Legacy/` (`d308feff`), and its metal-cpp implementation unit moved into a new shared target `RojoRHIMetalCpp` that `RojoRHILegacy` now `add_deps` (`52a34f57`). `Legacy/Tests/checkpoint-a.inventory` equals the old `Tests/checkpoint-a.inventory` byte for byte; `Tools/Patches/imgui-metal4-remove-texture.patch` and `xmake/shaders.lua` are unchanged. Hence byte-identical images are the expectation.
2. **v0.1.0's `targets.lua` declares, on macOS:** `RojoRHILegacy` (default), `RojoRHILegacyMetal4ImGui` (default, because Luminex sets `rojorhi_imgui_target`), `RojoRHILegacyTests` (non-default, dir `rojorhi-legacy-test`, groups `unit`, `gpu`), `RojoRHIMetalCpp` (non-default), v2 `RojoRHI` (**default**), v2 `RojoRHITests` (non-default, dir `rojorhi-test`, groups `contract`, `death`, `abi`, + `conformance` on metal4), `RojoRHILtoProbe` (non-default), `RojoRHIBench` (non-default, groups `null`, `native`, + `metal4`). The option `rojorhi_backend` defaults to `metal4` on a macOS host. No `add_requires` and no rule/option/task name collides with Luminex's (`slang2metallib`, `setup`, `format`, `policy`). Setup pins (metal-cpp `c595afef…`, Slang `v2026.14.1`) match Luminex's `xmake/setup.lua`.

## Decisions

- **P1 — keep v2 `RojoRHI` building as a default target.** Luminex does not override the component's `set_default`. Hosted CI builds it on Null (no Metal toolchain needed); the local metal4 configure builds the v2 Metal 4 backend and its kernels (`xcrun metal` present: 32023.883). This is the build-interface de-risking D2.1 asks for. Tradeoff: some extra build time.
- **P2 — contract entries for all eight component targets**, deps: `RojoRHILegacy` → `RojoRHIMetalCpp`; `RojoRHILegacyMetal4ImGui` → `RojoRHILegacy`, `RojoRHIMetalCpp`, `ImGui`; `RojoRHILegacyTests` → `RojoRHILegacy`, `RojoRHIMetalCpp`; `RojoRHIMetalCpp` → none; `RojoRHI` → `RojoRHIMetalCpp` (metal4 only; absent on Null, which the closure check tolerates); `RojoRHITests`, `RojoRHILtoProbe` → `RojoRHI`, `RojoRHIMetalCpp`; `RojoRHIBench` → `RojoRHI`, `RojoRHIMetalCpp`. Luminex targets that listed `RojoRHI` list `RojoRHILegacy`, `RojoRHIMetalCpp` instead (Render, Engine, Scenes, AppModel, Tests, FrameDataBench); App also replaces `RojoRHIMetal4ImGui` with `RojoRHILegacyMetal4ImGui`. Contract deps, not allowlist entries, because the edge is permanent until P6.7. `externals.rhi.targets` lists all eight; `includeRoots` = `["RojoRHI/Legacy/Include"]`; consumer allowances unchanged (header spellings still match by tail).
- **P3 — checkpoint A stays in force** (Luminex ADR 0009 still governs until ADR 0033): the checker reads `RojoRHI/Legacy/Tests/checkpoint-a.inventory` and `build/macosx/arm64/release/rojorhi-legacy-test/RojoRHILegacyTests`; its CLI flag `--rhi-tests` is kept.
- **P4 — CI runs only the Legacy suite of the component** (`RojoRHILegacyTests/unit`, the `[gpu]` inventory of `RojoRHILegacyTests`); v2's suites are rojo-rhi CI's job. `--rojorhi_backend=null` in both configures.
- **P5 — docs:** correct only sentences that become false (AGENTS.md command/architecture lines, `docs/architecture/rojorhi.md`, `frame-pipeline.md`, `shaders.md`, `docs/conventions/modules.md`); state that plain `xmake test` also runs the component's v2 groups and name the four explicit Luminex groups instead. No ADR; no roadmap edit (P6.0 owns the R5 records).
- **P6 — local evidence adds the 600-frame windowed smoke** (7 s) beyond the §11 exit, because App now links the renamed ImGui target, which `parity.py` does not exercise.
- **P7 — three development commits, one squash.** Squash subject: `build: pin RojoRHI to v0.1.0 on the Legacy targets`.
