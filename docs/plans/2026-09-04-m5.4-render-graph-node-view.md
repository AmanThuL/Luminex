# M5.4 — Render Graph Node View

**Status**: Implemented (2026-09-04)

This plan executes the accepted design in
`docs/specs/2026-09-04-m5.4-render-graph-node-view-design.md`. `docs/roadmap.md` owns the M5.4
outcome, deliverables, exit gate, and deferrals; this plan decomposes that boundary without
expanding it. The spec fixes the dependency containment, the node model, the layout and stability
rules, the panel contracts, and the testing obligations; tasks below reference those definitions
and may not change them.

## Outcome

The Render Graph panel becomes a canvas-first node view of the exact newest retired compiled frame
over a vendored, patched imgui-node-editor: passes are nodes, version dependencies are edges,
sinks are endpoints, culled passes sit in their own edgeless band, alias links are drawn apart from
execution edges, and a details pane shows the selected node's uses, barriers, timing, lifetimes,
and reuse. Layout is deterministic; drags are session state. Fixed-camera renderer output stays
byte-identical and no graph, renderer, scheduling, or RHI behavior changes.

## Integration

All work lands on the outcome branch `feat/m5.4-graph-node-view`, which reaches protected `main`
in a single squash pull request. Tasks 1 and 2 touch disjoint files and run in parallel in isolated
worktrees (per-worktree checker procedure per `AGENTS.md`; a worktree needs its own
`ThirdParty/` copy and `-P .`), integrating by rebase onto the outcome branch. Every task passes
`xmake format --check`, `xmake policy` (or the per-worktree checkers), and `xmake test` before it
is done; GPU and visual checks run on Metal 4 Apple Silicon under `MTL_DEBUG_LAYER=1`. Parity
baselines (fixed camera, 1280×720, Sponza / Damaged Helmet / MaterialLab, SHA-256) were captured at
the branch fork from `main` and are kept outside the source tree.

## Global constraints

- C++23; the Tests target links no ImGui, SDL, or node-editor code.
- No `ax::NodeEditor` type in any Luminex header; the library header is included only by
  `Source/App/Panels/RenderGraphPanel.cpp`.
- No new field in `CompiledFrameDebug`; nothing under `Source/Render`, `RHI/`, or `Shaders/`
  changes.
- Workspace schema stays 1; the library writes no settings file.
- Every commit compiles, passes the relevant tests, and passes `xmake policy`; commit subjects are
  at most 72 characters (CI checks the PR range).

## Task 2 — GraphNodeModel

**Model**: Opus 5 (review: Fable, main thread). **Files**: `Source/App/GraphNodeModel.h/.cpp`,
`Tests/AppGraphNodeModelTests.cpp`, `xmake.lua` (`Tests` `add_files` list). Independent of Task 1.

Public surface (ImGui-free; built on `buildGraphInspectorModel` so use, transition, and transient
rows and the timing join are not re-implemented):

```cpp
namespace lmx::app {
inline constexpr float kGraphNodeColumnSpacing = 280.0f;
inline constexpr float kGraphNodeRowSpacing = 140.0f;
inline constexpr float kGraphCulledBandGap = 120.0f;
enum class GraphNodeKind { Pass, Sink };
struct GraphNodePin { uint32_t resource; std::string resourceName; uint32_t version; std::string label; };
struct GraphNodeTransientSpan { uint32_t resource; std::string resourceName; uint64_t offset, size, alignment; bool aliases; };
struct GraphNode {
    GraphNodeKind kind; uint32_t index;            // pass declaration index or sink index
    render::PassKind passKind; std::string label;  // sinks: label "export|present|readback"
    std::optional<uint32_t> scheduleOrder; std::optional<render::CullReason> cullReason;
    std::optional<double> gpuMilliseconds;
    std::vector<GraphNodePin> inputs, outputs;     // sinks: one input, no outputs
    std::vector<GraphInspectorUseRow> uses; std::vector<GraphInspectorTransitionRow> barriersBefore;
    std::vector<GraphNodeTransientSpan> transientsAlive;
    render::SinkKind sinkKind; std::optional<uint32_t> producerPass; // sinks only
    uint32_t layer, rank; float x, y;              // layout, in canvas units
};
struct GraphNodeEdge { uint32_t fromNode, fromPin, toNode, toPin; uint32_t resource, version; std::string resourceName; };
struct GraphAliasLink { uint32_t fromNode, toNode; uint32_t freedResource, resource; std::string freedResourceName, resourceName; uint64_t offset, size; };
struct GraphNodeModel {
    uint64_t frameId; bool poolingEnabled; render::TransientMemory memory;
    std::vector<GraphNode> nodes;          // passes in declaration order, then sinks in declaration order
    std::vector<GraphNodeEdge> edges;      // execution edges only
    std::vector<GraphAliasLink> aliasLinks;
    std::string shapeSignature;
};
GraphNodeModel buildGraphNodeModel(const render::CompiledFrameRecord&, std::span<const rhi::PassTiming>);
}
```

Rules (spec sections 4–5): producer of `(r, v+1)` is the scheduled pass whose use of `(r, v)` has
role `Write`, `ColorAttachment`, `DepthAttachment`, or `CopyDestination`; an edge exists for every
scheduled-pass use with `v > 0` and for every sink; a missing producer or a producer scheduled
after its consumer is `LMX_ASSERT`ed. Culled nodes have no pins, no edges, `layer`/`rank` in the
culled band (`y = (maxRank + 1) × row spacing + gap`, `x` by culled ordinal). Alias links: one per
transition with `aliasedFrom`, from the last scheduled pass of the freed transient (its
`DebugTransient.lastPass`) to `transition.beforePass`. Layer = longest path over edges from
producer-less scheduled passes; sink layer = producer layer + 1; rank orders by schedule position
then sink index. `shapeSignature` is newline-joined lines over nodes (`n<index> pass|sink <kind>
<label> [culled]`), pins, edges, and alias links, excluding timing, frame ID, offsets, and totals.

Tests, Catch2 `[app]`, prose names, using `FakeTexture`/`FakeBuffer` from the existing
`GraphInspectorModelTests.cpp` pattern (copy the fakes; do not export them):
- edges match producers and every edge's producer precedes its consumer in the schedule
- a version-0 import is an unconnected input pin with no edge
- a sink node has one edge from its producer and the producing pass recorded
- a culled pass has no pins, no edges, and sits in the culled band below every scheduled rank
- alias links come only from `aliasedFrom` transitions (use `TransientPool` with pooling on, two
  lifetime-disjoint transients, as `GraphInspectorModelTests` does for transient rows)
- layout is identical for two compiles of the same declarations and unchanged by timings/frame ID
- the signature is unchanged by timings, frame ID, and offsets, and changes when a pass, edge,
  sink, or alias link changes
- node facts (uses, barriers, timing) equal the `GraphInspectorModel` rows for the same pass

Commit: `app: add the ImGui-free GraphNodeModel behind the node view`.

## Task 3 — Canvas-first Render Graph panel

**Model**: Opus 5 (review: Fable, main thread). Depends on Tasks 1 and 2. **Files**:
`Source/App/Panels/RenderGraphPanel.h/.cpp`, `Source/App/EditorShell.h/.cpp`.

1. Header: declare `struct RenderGraphPanelState` with an opaque
   `std::unique_ptr<NodeEditorHandle, NodeEditorHandleDeleter> editor` (both names forward-declared
   in the header, defined in the .cpp), `std::string appliedSignature`, `std::optional<uint32_t>
   selectedNode`, and `void releaseRenderGraphPanelState(RenderGraphPanelState&)`. Change the entry
   point to `drawRenderGraphPanel(bool& open, RenderGraphPanelState& state, const FrameRecordRing&)`.
2. `EditorShell` owns one `RenderGraphPanelState m_renderGraphPanel` and calls
   `releaseRenderGraphPanelState` in `~EditorShell` **before** `ImGui::DestroyContext()`, and in
   both early-return paths of `create()` that destroy the context.
3. Panel body, per spec section 6: header row (`frame N -- pooling on|off`, Dump frame, Reset
   Layout, transient totals); a left child (65% width) hosting `ed::Begin("lmx.renderGraph")`; a
   right scrolling child with the details pane. Editor context created lazily with
   `Config.SettingsFile = nullptr` on the first draw that has a retired frame. Node ids:
   `nodeIndex + 1`; pin ids: `(nodeIndex + 1) * 1000 + pinOrdinal + 1` (inputs first, then
   outputs); link ids: `edgeIndex + 1`. When `model.shapeSignature != state.appliedSignature` or
   Reset Layout was pressed: `ed::SetNodePosition` for every node from `(x, y)`, `ed::ClearSelection`,
   `ed::NavigateToContent(0)`, store the signature. Selection read back each frame via
   `ed::GetSelectedNodes` into `state.selectedNode`.
4. Styling: node header colour by `PassKind` (raster / compute / copy), sink nodes with a distinct
   header colour and shape hint, culled nodes desaturated grey with no pins and a `culled: <reason>`
   line, execution links solid. Alias links and culled-node borders are drawn dashed with
   `ImDrawList::AddLine` segments on `ed::GetHintForegroundDrawList()` between
   `ed::GetNodePosition`/`GetNodeSize`-derived body anchors, in a separate colour, never through
   `ed::Link`.
5. Details pane table per spec section 6 (nothing / scheduled pass / culled pass / sink). Remove
   the M5.3 list sections (`Resources`, `Schedule`, `Culled passes`, `Transitions`, `Transients`)
   and the now-unused `drawPassRow`.
6. Verify: `xmake`, `xmake test`, `LMX_MAX_FRAMES=120 MTL_DEBUG_LAYER=1 xmake run App` with the
   panel open, toggling bloom and automatic exposure through the Viewport toolbar to force a shape
   change and relayout; panel close/reopen; Reset Default Layout with the panel open. Commit:
   `app: draw the Render Graph panel as a node canvas with selection details`.

## Exit gate

The amended roadmap M5.4 gate: unchanged frames produce stable positions; dependencies agree with
resource versions and schedule; culled passes and aliases cannot resemble scheduled edges; details
agree with the selected pass, version, and transient assignment; node view and dump identify the
same frame; fixed-camera renderer output is unchanged.
