## Validation and evidence

Build App and Tests explicitly; run CPU and GPU suites with Metal API validation for GPU work,
format check and policy including compilation-database-backed direct checkers. Test PNG CRC,
metadata, deterministic encoding and decoded BMP parity. Generate both real-display goldens and
compare against the existing oracle. Run the fifteen-image parity matrix and preserve every
mismatch rather than weakening hashes or tolerances. The accepted M6.4 record already documents
unexplained run-to-run drift; distinguish that limit from a proven new regression.

Record viewport backing density and settled 1:1 mapping, capture the UI, inspect font density.
EDR evidence includes platform headroom, float readback, timings, fallback and validation;
physical visible-range/white and photographs require an observer and cannot be inferred from
an SDR screenshot. Unavailable measurements remain explicitly pending, never fabricated.

## Current evidence

App and Tests build. All 580 CPU cases and 170 GPU cases pass (252,365 GPU assertions), with
Metal validation on. Formatting and policy pass. Both GPU fixtures match their oracle and golden
exactly on the reference machine; no tolerance or shader changed. UI reports 2× and settled 1:1;
the vendored font harness confirms actual 2× rasterization at the same logical font size.
The initial strict screenshot matrix matches 14/15: Sponza MetalFX scale 1 differs from the
historical hash. Four isolated baseline/current alternated reruns match the historical hash,
showing drift within the unchanged current executable. Keep the initial failure. PNG/BMP twins
match 13/15 independently rendered screenshots (the two Sponza vendor runs drift); all nine
paired tiny-sequence frames match. Both v2 formats and a rebuilt 360-frame v1 report pass.
The EDR probe is frozen at `m6.5-edr-evidence`, with validation-clean final smoke, ten samples
per pass/mode, stable float readback and a forced range-one check. The owner sees brighter EDR
highlights and on 2026-09-13 explicitly confirms equally bright white UI text at the same system
brightness. Record the bounded visual check as a subjective match, superseding the earlier
brighter-text impression and uncertainty; no photometric measurement is claimed. No further
informal user comparison is pending. [ADR 0019](../decisions/0019-display-domains-and-edr.md)
retains the defer recommendation for measured midtone darkening and incomplete production
fallback/cost evidence, independently of this positive UI-white observation.
The final full parity batch is 13/15, so literal hash-gate closure needs explicit disposition.
Raw results are under `~/Documents/Luminex-evidence/m6.5/` and the separate probe bundle.

The continuing `exp/m6.5-hash` investigation leaves production rendering unchanged. Per-frame
readback suppresses drift in bounded samples; last-frame-only diagnostics still yield 13/15,
including a native half-scale failure, and broad barriers do not establish a repair. GPU stage
checksums and a direct HDR snapshot locate differing scene-color input before temporal history
propagation. Diffuse-only shading varies, while shadow-only and world-position-only outputs each
agree across three 32-frame repeats. Anisotropy one, disabled GPU-optimized uploaded or target
texture contents, tile size 32, and explicit `SampleGrad` still vary. Full FP32 U/V byte outputs each agree across all
frames in three repeats; `ddx(U)`, `ddy(U)` and `ddx(V)` byte outputs vary, while this `ddy(V)`
group remains stable. These observations localize the existing diffuse/gradient path without
proving engine API misuse, benign platform behavior or a common cause for all historical drift.
Stable GPU checksums are bounded observations, not cryptographic proof. Shader-validation bloom
usage warnings remain a separate unresolved issue; default-zero-fill output cannot serve as
parity evidence. The strict gate remains unmet, with no waiver or readiness claim.

Explicit fragment depth output stabilizes three diffuse-only and three `ddx(U)` diagnostic runs,
but changes depth/HDR/history in all 32 frames against prior diffuse-only rendering. It is not a
compatible repair. Explicit early depth testing without the depth write still varies. Keep both
findings bounded; no production shader change follows from them. Eight alternating rounds of
unmodified baseline/current App rendering produce 32 successful processes. Native-half hashes
fail in 2/8 baseline runs and 5/8 current runs, with both baseline variants also occurring exactly
in current output; vendor-scale-one fails in 1/8 baseline and 0/8 current runs. This demonstrates
pre-existing native variants and baseline vendor drift without instrumentation; it neither
estimates failure rates nor proves a shared root cause or satisfies the strict gate.
