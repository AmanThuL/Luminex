# M5.3 — Editor Workspace and Selection

**Status**: Implemented (2026-08-13)

This plan executes the accepted design in
`docs/specs/2026-08-13-m5.3-editor-workspace-selection-design.md`. `docs/roadmap.md` owns the M5.3
outcome, deliverables, exit gate, and deferrals; this plan decomposes that boundary without
expanding it. The spec fixes the workspace model, selection identity, panel contracts, action
boundary, time-domain separation, and testing obligations; stages below reference those definitions
and may not change them. The spec's stage order (section 14) is preserved; tracks marked
independent touch disjoint files and may proceed in parallel.

## Outcome

The docked editor becomes a five-panel selection-driven workspace — Scene, Viewport, Inspector,
Performance, Render Graph — with a main menu, versioned workspace persistence and migration,
editor-local single selection resolved safely across scene changes, coherent Performance
observation, and an independently dockable exact-frame Render Graph, while fixed-camera renderer
output stays byte-identical and no graph, renderer, scheduling, or RHI behavior changes.

## Integration

All work accumulates on the outcome branch `feat/m5.3-editor-workspace`, which reaches protected
`main` in a single pull request. The spec, this plan, and the `AGENTS.md` active-plan pointer are
committed on this branch when the milestone starts. Parallel tracks develop on short-lived
`feat/m5.3-<track>` branches in isolated worktrees (per-worktree checker procedure per `AGENTS.md`)
and integrate by rebase onto the outcome branch; each track's commits carry their own code, tests,
and build registration together. Every stage passes `xmake format --check`, `xmake policy`, and
`xmake test` before it is considered done; GPU and visual checks run on Metal 4 Apple Silicon under
`MTL_DEBUG_LAYER=1`. Baseline parity screenshots are captured at the branch fork from `main`
(fixed camera, 1280×720, Sponza / Damaged Helmet / MaterialLab) and kept outside the source tree.

## Stage 1 — Pure workspace models

Four mutually independent tracks. Each adds ImGui-free, SDL-free sources under `Source/App`,
registers them in both the `App` and `Tests` targets, and lands Catch2 `[app]` tests in the
existing style (prose case names, banner comments, file-local fakes).

### Track A — Selection model

`Source/App/EditorSelection.h/.cpp`: `EditorSubject`, `EditorSelection` (spec section 5 verbatim),
and a resolver that takes the selection, the active `engine::SceneId`, and the active
`engine::Scene`, returning a resolved subject or a healed `None`; plus the fixed transition
functions for startup, successful switch (select `Camera`, clear filter), failed switch (retain
everything), same-scene reselect, and index healing. Tests cover every subject kind, all three
light indices, object indices, duplicate display names, invalid-index healing, filtered selection
retention, and repeated switching without stale selection.

### Track B — Workspace and schema model

`Source/App/WorkspaceModel.h/.cpp`: the five-panel visibility set with defaults, the workspace
schema constant, and the decision function mapping stored settings text (absent / legacy without
schema / matching schema / unknown schema) to build-default-versus-restore plus recorded schema.
Includes the encode/decode for the Luminex settings-handler section so tests run over in-memory
settings text. Tests cover clean, representative M5.2 legacy, matching custom, unknown schema,
repeated reset idempotence, and close-button/menu-toggle sharing one visibility value.

### Track C — Action intents

`Source/App/EditorActions.h/.cpp`: quit, capture-next-frame, and reset-layout intents with the
spec's coalescing and consumption rules — duplicate capture gestures coalesce into one pending
request, a skipped drawable retains it, one attempt (success or failure) consumes it. Tests prove
intent emission only, coalescing, retention, and single consumption.

### Track D — Performance model

`Source/App/PerformanceModel.h/.cpp`: one coherent display snapshot over `PassTimingHistory`
summaries, frame-interval history (App wall-clock delta), object/draw counts, resolution, and
retained-frame transient-memory values; the 0.25-second republish policy; timed-pass sum; and
pause/resume/clear transitions that freeze and release the whole snapshot together. Tests preserve
the existing rolling-window, duplicate-label, schedule-change, and repeated-frame rules, then cover
coherent pause, resume, clear-to-waiting-state, timed-pass sum, and retained-frame memory joins.

Exit: all four tracks integrated on the outcome branch; `xmake test`, `xmake format --check`, and
`xmake policy` green; no new model includes an ImGui, SDL, Metal, or RHI backend header.

## Stage 2 — Workspace shell

Sequential; restructures `EditorShell` and `main.cpp` against the stage-1 models with behavior
otherwise unchanged.

1. Register the ImGui settings handler that persists schema and panel visibility in `imgui.ini`;
   apply the stage-1 schema decision on startup: clean and legacy settings build the M5.3 default
   topology once, a matching schema restores without rebuilding, unknown schemas are legacy.
2. Submit the main menu (File / Window / Layout / Debug per spec section 9) before the dockspace;
   menu items read and write the stage-1 visibility and intent models only. The frame loop consumes
   quit through the normal window-close path and capture through the existing
   acquired-drawable boundary, replacing the loop-local request flag.
3. Replace the two-window default layout with the five-panel deterministic topology and clamps of
   spec section 3, built at current work-area size and display scale; implement Reset Default
   Layout as an intent consumed at a safe frame boundary, idempotent, preserving unrelated
   settings, and leaving relative-mouse look.
4. Extract panel drawing into `Source/App/Panels/` — `ScenePanel`, `ViewportPanel`,
   `InspectorPanel`, `PerformancePanel`, `RenderGraphPanel` — as mechanical moves of existing
   drawing code behind panel visibility, keeping `EditorShell` as coordinator; Performance content
   moves out of the Inspector's Stats header, and the scene selector moves to the Scene panel
   unchanged (same `selectScene` boundary).

Exit: menu, migration, default and reset topology, and all five panels work in-app; clean, legacy,
matching, and unknown settings behave per spec section 4; existing suites and policy stay green;
screenshot parity holds.

## Stage 3 — Selection and properties

Two tracks, parallel after stage 2, touching disjoint panel files and meeting only at the stage-1
selection model plus small `EditorShell` glue integrated by rebase.

### Track A — Scene panel

Catalog selector with existing availability hints and failure behavior; case-insensitive filter
with no-matches state; Workspace, Directional Lights, and Objects groups in the spec's fixed
order; mouse selection and Up/Down keyboard navigation over visible rows; selection transitions
wired through the stage-1 resolver on every scene switch, including failed switches.

### Track B — Context Inspector, Viewport toolbar, and input edges

Subject-scoped Inspector sections (Camera, Rendering, Directional light, Object) with the spec's
fields, units, clamps, and `Select an item in Scene` empty state; the compact Viewport toolbar
editing the same state as the Rendering section on the same UI frame; relative-mouse-look exits on
right-button release, Viewport close or collapse, focus loss, reset begin, and shutdown; viewport
sizing from the content region below the toolbar with the existing ten-stable-frame debounce
producing one resize and one exposure reset per stable extent.

Exit: spec sections 6–8 behaviors verified in-app, including scene-switch edge cases and input
exits; unit suites extended where a model rule changed; screenshot parity holds.

## Stage 4 — Observability migration

Parallel with stage 3 (disjoint panel files). The Performance panel renders the stage-1 snapshot
with honest labels — `Frame interval`, separate logical size and pixel extent, the
Pass/Average/Latest/Min–Max/Samples table in schedule order, `Timed pass sum` with its explicit
non-total caveat, frame ID and memory context, coherent Pause, and Clear History with a waiting
state. The Render Graph panel keeps `GraphInspectorModel`, the newest-timed-frame join, frame-ID
display, no-retired-frame state, and Dump Frame over the displayed record, gaining only menu-driven
visibility, default lower-dock tab placement, and independent close/float. Neither panel retargets
the other's time domain.

Exit: spec sections 10–11 behaviors verified in-app; Performance pause freezes one snapshot;
Render Graph frame identity unchanged; suites and policy green.

## Stage 5 — Evidence and record

1. Layout matrix QA: clean, legacy, restored-custom, and reset workspaces at 1280×720, 1440×900,
   and 2560×1440 including Retina scale; Viewport unobscured; every hidden panel recoverable.
2. Renderer parity: fixed-camera 1280×720 screenshots of all three scenes byte-identical to the
   fork-point baseline; editor session under `MTL_DEBUG_LAYER=1` across scene switches, panel
   toggles, resets, and capture.
3. Full `xmake test`, `xmake format --check`, `xmake policy` at the tip; `[checkpoint-a]` filter
   unchanged as a regression tripwire.
4. Update `docs/architecture/overview.md` and `AGENTS.md` (editor description, controls, any
   command changes); write `docs/milestones/m5.3.md` distinguishing automated from manual
   evidence and recording accepted deviations; update the roadmap baseline pointer.
5. Mark the spec `Implemented`, clear the `AGENTS.md` active-plan pointer, and close this plan per
   `docs/conventions/documentation.md`.

Exit: the roadmap's M5.3 exit gate holds with recorded evidence.

## Non-goals

Per the roadmap's M5.3 deferrals and spec section 15: viewport picking, outlines, gizmos,
multi-selection, hierarchy or ECS work, persistent identity, rename or serialization, undo/redo,
asset browsing, graph visualization or mutation, multiple platform windows, new profiling
instrumentation, and any graph, renderer, scheduling, or RHI change.

## Validation

- `xmake format --check` and `xmake policy` at every stage
- `xmake test` at every stage; GPU suites under `MTL_DEBUG_LAYER=1` on Metal 4 Apple Silicon
- Fork-point baseline screenshots compared after stages 2, 3, 4, and at the tip
- The `[checkpoint-a]` filter at milestone start and at the tip
- Manual in-app checks recorded per stage; the milestone record separates them from automated
  evidence

## Exit gate

The roadmap's M5.3 exit gate applies verbatim: clean, legacy, restored, and reset layouts keep a
usable Viewport; every panel and menu action works; selection, filtering, scene changes, resize,
and hidden-Viewport input are safe; Performance pause is coherent; Render Graph remains
frame-correct; fixed-camera renderer output is unchanged.
