# R2.3 — Mechanical Rename Implementation Plan

**Status**: Proposed

> Executors: use superpowers:subagent-driven-development. Steps use checkbox syntax for tracking.
> Task 1 sets this plan to `In progress`.

**Goal:** the component carries the RojoRHI identity everywhere — namespace, macros, include root,
targets, default labels and the directory `RojoRHI/` — through one commit reproducible from a
recorded table, before it leaves the repository in R2.4.

**Architecture:** `rojo-rhi` gains `Tools/Rename/apply.py`, which applies the amended
`Tools/Rename/substitution.tsv` to a Luminex checkout in memory, then writes (`git mv` for `path`
rows, Python `re` for `regex` rows, per-row path-glob scope). Luminex receives three commits:
mechanical, format, hand edits.

**Spec:** [design](../specs/2026-09-19-r2.3-mechanical-rename-design.md), under the
[R2 record](../milestones/r2.md#r23--mechanical-rename) and
[ADR 0024](../decisions/0024-rhi-relocation-to-rojorhi.md). Executors read all three, plus
`docs/guides/luminex-extraction.md` and `docs/conventions/` in the sibling checkout `../rojo-rhi`
(branch `foundations`).

## Global constraints

- Identity is fixed: namespace `rojoRHI`/`rojoRHI::metal4`, includes `<rojoRHI/...>`, macros
  `ROJORHI_ASSERT`/`ROJORHI_LOG_*`, label prefix `rojorhi.`, targets `RojoRHI`,
  `RojoRHIMetal4ImGui`, `RojoRHITests` (build directory `rojorhi-test`, groups
  `RojoRHITests/unit|gpu`), Lua names `rojorhi_slang2metallib`/`rojorhi_thirdparty`/
  `rojorhi_imgui_target`, define `ROJORHI_IMGUI_BACKEND_SOURCE`, directory `RojoRHI/`.
- Unchanged: file names, Catch2 tags and case names, `Render/RhiLog`, the contract unit id
  `"rhi"`, the stderr prefix `[RHI]`, renderer-owned `lmx.*` labels, every `LMX_*` environment
  variable, the `lmx` namespace outside the component, the `LMX_CAPTURE_PATH` message wording.
- No RHI capability or semantic change; no shader, uniform, schedule or `SceneView` change.
- Commit 1 of the Luminex pull request is exactly `apply.py`'s output. A failing gate is fixed by
  changing a row in `rojo-rhi` and re-running, never by touching the Luminex tree by hand.
  Three failed attempts at one gate: stop, record what failed, report to the owner.
- In a Luminex worktree pass `-P .` to every xmake command, copy the `ThirdParty` subdirectories
  (`imgui`, `metal-cpp`, `slang`, …) rather than the directory, link `Assets/Fetched`, and run the
  checkers directly (`AGENTS.md`, Commands).
- Agents touching `../rojo-rhi` run one at a time (shared index). Tell every subagent: no commit
  trailers, no AI attribution, no helper agents, no lingering monitors.
- Commit subjects follow each repository's `docs/conventions/commits.md`: ≤ 72 characters, no
  trailer. Repository-relative paths only; no commit hashes in documents.
- Review runs one tier above the implementer: Haiku → Sonnet, Sonnet → Opus, Opus → a Fable
  subagent (`model: "fable"`), since the executing main thread is Opus.

## Evidence protocol

Bundle root `../Luminex-evidence/r2.3/<task>/`. Parent = `main` at the branch point, built in a
second worktree in the same session, release, `--ccache=n`, the same `imgui.ini` copied into both
build directories.

Case inventory (tier 1): in each test binary's build directory run `<binary> --list-tests
--reporter xml`, reduce to the sorted `<Name>` values, and require `Tests` and the RHI binary
(`rhi-test/RHITests` on the parent, `rojorhi-test/RojoRHITests` on the candidate) to each give a
list byte-identical to the parent's.

Gate set G (every Luminex commit, from the worktree root):

```bash
xmake f -m release -y -P . --ccache=n && xmake build -P . \
  && xmake build -P . Tests && xmake build -P . RojoRHITests
MTL_DEBUG_LAYER=1 xmake test -P . && python3 Tools/check_checkpoint_a.py
xmake project -k compile_commands -P .
for c in Tools/check_project_policy.py Tools/check_module_deps.py Tools/check_source_headers.py \
  RojoRHI/Tools/check_rhi_headers.py Tools/check_cpp_layout.py Tools/check_shader_imports.py
do python3 "$c" || exit 1; done
python3 Tools/check_cpp_comments.py --public-api-docs error && python3 Tools/check_module_deps.py --link
python3 -m unittest discover -s Tools/tests && python3 -m unittest discover -s Tools/GpuDebug/tests
```

`xmake format --check -P .` joins G from commit 2 onward.

## Task 2 — `apply.py` with its self-test (`rojo-rhi`)

**Model**: Opus 5 (review: Fable). **Repository**: `../rojo-rhi`, new branch
`rename-record` from `foundations`. **Files**: create `Tools/Rename/apply.py`; rewrite
`Tools/Rename/substitution.tsv`.

**Produces:** `python3 Tools/Rename/apply.py <luminex-root> [--dry-run | --check]` and
`python3 Tools/Rename/apply.py --selftest`; exit 0 success, 1 check failure, 2 usage or table error.

- [ ] **Step 1: start from the planning drafts.** `../Luminex-evidence/r2.3/planning/` holds
      `apply.py`, `substitution.tsv` and `dry-run-starting-table.md`, written and run during
      planning (self-test passing, 20 rows; the dry run is read-only). Copy the two files to
      `Tools/Rename/`, read them whole, and make them meet `rojo-rhi`'s conventions (file header,
      comments, naming). They are a starting point under review, not accepted work.
- [ ] **Step 2: the table's contract.** Eight tab-separated columns, no quoting:
      `order kind include exclude pattern replacement strict note`. `include`/`exclude` are
      space-separated globs (`**/` spans zero or more directories, `**` anything, `*` anything but
      a slash) spelled in **post-rename** paths, because `path` rows run first. `strict` is `yes`
      when the pattern must match nowhere outside `docs/**` and `**/*.md` after a run. Rows:
      10/11/20 `path` (public include root, the ImGui adapter's include root, the directory);
      30 `\blmx::rhi\b`; 31 namespace-relative `rhi::` in consumer C++; 40 quoted include →
      angle form; 41 a quoted string that is exactly `RHI/<Name>.h` or `RHI/Metal4/<Name>.h` →
      `rojoRHI/...`; 42 the header-check glob; 43 `Include/RHI/` → `Include/rojoRHI/` in tool
      files; 45 `(?<![a-z])RHI/` → `RojoRHI/` in build, CI, ignore and tool files and
      `Tests/GpuTestSupport.h` (after 40–43, whose outputs the lookbehind protects); 50/60 macros;
      61 the probe define; 70 component `"lmx.` labels; 80 consumers of component-owned labels;
      85 `RHITests`; 86 `rhi-test`; 87 the three `rhi_*` Lua names; 90/100 quoted target tokens.
- [ ] **Step 3: the script's contract.** `read_table` (tab split, header and field-count checks,
      strictly increasing orders, exit 2 on error); `load` (tracked files via `git ls-files -z`,
      non-UTF-8 files skipped); `transform` (all rows in memory, per-row counts inside the
      component, outside it, and out of scope but not prose); `write` (`git mv` per `path` row in
      order, then changed texts; refuses a dirty checkout); `check` (no `path` source still
      tracked, no in-scope residue, strict rows clean outside prose); `--dry-run` prints the
      Markdown table the guide embeds. The self-test builds a throwaway git repository, applies
      the **real** table and compares every file. It pins: path-row order and the ImGui include
      root; angle includes; the `"../RHI/Tests/..."` directory include; `sprhi::x` and
      `std::rhi::y` untouched by row 31; `"-IRHI/Include"` reached by row 45; one contract JSON
      line carrying both meanings of `RHI/`, all three target tokens and the `forbidUndefined`
      prefix; a renderer label and `LMX_ASSERT` outside the component untouched; prose untouched;
      a `"` kept as field content; idempotence; `check` passing.
- [ ] **Step 4:** `python3 Tools/Rename/apply.py --selftest` prints `selftest passed (20 rows)`.
      A failure names the file and both strings; fix the row or the code, not the expectation,
      unless the expectation contradicts the Global constraints.
- [ ] **Step 5:** commit in `rojo-rhi`: `tool: apply the recorded rename from its table`
