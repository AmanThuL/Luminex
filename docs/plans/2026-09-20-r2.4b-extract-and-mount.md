# R2.4b — Extract, Publish and Mount RojoRHI Implementation Plan

**Status**: Proposed

> Executors: use superpowers:subagent-driven-development. Steps use checkbox syntax for tracking.
> Starts only after [plan R2.4a](2026-09-20-r2.4a-complete-in-place.md) has merged and the tag
> `r2.4-pre-extraction-evidence` exists on the remote. Task 1 sets this plan to `In progress`.

**Goal:** `RojoRHI/` is a submodule of the public `rojo-rhi` repository at a commit on its `main`,
both repositories are green, and the two-repository workflow is documented and checked.

**Architecture:** a recorded, verifiable `git filter-repo` run in a scratch clone produces the
import; `foundations` is rebased onto it and replaces `rojo-rhi` `main` once. A `rojo-rhi` pull
request adds the licence, CI and current documents without touching source. A Luminex pull
request swaps the directory for the submodule, wires CI and adds the pin check.

**Tech stack:** git, git-filter-repo, Python 3 `unittest`, xmake, GitHub Actions, `gh`.

**Spec:** [design](../specs/2026-09-20-r2.4-extract-mount-wire-design.md), stages 2–4. Executors
also read `AGENTS.md` and `docs/conventions/` in both repositories; the sibling checkout is
`../rojo-rhi`.

## Global constraints

- **Owner stops — the executor never proceeds past these alone:** installing `git-filter-repo`;
  any push to `rojo-rhi` `main`; changing repository visibility; merging any pull request.
- No file under `Include/`, `Source/`, `Backends/`, `Tests/` or `Shaders/` of the component
  changes after the import. A Luminex commit never edits a file under `RojoRHI/`.
- The extraction runs in a scratch clone outside both checkouts. The Luminex checkout, its remote
  and its tags are never rewritten.
- Agents touching `../rojo-rhi` run one at a time. Tell every subagent: no helper agents, no
  lingering monitors, no pushes, no AI attribution, no commit trailers.
- Worktree rules, commit rules and gate set G are those of plan R2.4a, with
  `git submodule update --init` added after creating any worktree from Task 6 onward.
- Models: Opus for Tasks 2, 3 and 6; Sonnet for Tasks 4 and 7, reviewed by the main thread.
  **Owner checkpoints** close Tasks 3 and 7. Three failed attempts at one gate: stop and report.

- [ ] Pin check, tests first (`test_submodule_pin.py` builds a temporary superproject and

```python
"""Fails unless RojoRHI's pinned commit is reachable from the component's origin/main."""
from __future__ import annotations
import argparse, configparser, subprocess, sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]
MOUNT = "RojoRHI"
URL = "https://github.com/AmanThuL/rojo-rhi.git"

def git(root: Path, *args: str) -> subprocess.CompletedProcess[str]:
    return subprocess.run(["git", "-C", str(root), *args], capture_output=True, text=True)

def check(root: Path, url: str = URL, fetch: bool = False) -> list[str]:
    modules = configparser.ConfigParser()
    modules.read(root / ".gitmodules", encoding="utf-8")
    section = f'submodule "{MOUNT}"'
    if not modules.has_section(section) or modules[section].get("url") != url:
        return [f".gitmodules must name {url} for {MOUNT}"]
    entry = git(root, "ls-tree", "HEAD", MOUNT).stdout.split()
    if len(entry) < 3 or entry[1] != "commit":
        return [f"{MOUNT} is not a submodule entry in HEAD"]
    mount = root / MOUNT
    if not (mount / ".git").exists():
        return [f"{MOUNT}/ is empty: run `git submodule update --init`"]
    if fetch and git(mount, "fetch", "-q", "origin", "main").returncode != 0:
        return [f"cannot fetch origin main in {MOUNT}"]
    if git(mount, "merge-base", "--is-ancestor", entry[2], "origin/main").returncode != 0:
        return [f"{MOUNT} pin {entry[2][:12]} is not reachable from rojo-rhi main"]
    return []

if __name__ == "__main__":
    parser = argparse.ArgumentParser()
    parser.add_argument("--fetch", action="store_true")
    errors = check(ROOT, fetch=parser.parse_args().fetch)
    print("\n".join(errors) if errors else "submodule pin passed")
    sys.exit(1 if errors else 0)
```
