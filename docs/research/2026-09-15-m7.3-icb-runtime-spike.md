# M7.3 indexed ICB runtime spike — 2026-09-15

**Status**: Frozen — non-normative

## Result and boundary

The bounded spike did **not** clear the complete adapter gate. Native GPU-written indexed ICB
execution, texture sampling and 900-frame retirement passed on the tested device, but the required
labelled ICB GPU capture did not. The [M7.3 design](../milestones/m7/m7.3.md) therefore does not unlock
an ICB production adapter from this evidence. Fixed-slot GPU classification remains independent.
This is an unresolved capture/interop integration result, not evidence that Metal 4 cannot execute
ICBs, and not a performance adoption result.

| Gate | Observed result |
|---|---|
| Compiler reproduction | Native prelude and texture arrays compiled through pinned Slang and Metal; two historical naive mappings reproduced their Metal compiler failures |
| P1 runtime execution | PASS: GPU emitted indexed commands; a native Metal 4 render encoder executed them and produced the expected pixels |
| P1 labelled GPU capture | FAIL / unresolved: after two retired warmup frames, capture refused with the diagnostic below |
| P2 textures and exactness | PASS: two meshes, two materials, five separately indexed textures each; every output byte equalled fixed argument slots |
| P3 reliability | PASS: 900 frames over three paced slots, reset/re-encode each frame, 900 feedback callbacks, zero feedback/validation errors, exact pixels every frame |
| Complete spike gate | NOT PASSED; no production adapter is authorized by these results |

The explicit capture failure was:

```text
Capturing Metal 4 Compute Command Encoder is not supported.
```

## What the runtime verifies

A Slang native prelude defines an MSL argument structure containing `command_buffer` and an index
pointer. The host populates it through `MTL::ArgumentEncoder`, including
`setIndirectCommandBuffer`; it does not invent the opaque command-buffer representation.
A GPU classify fixture writes the five indexed-draw words for each of two candidates. A later GPU
pass reads those words and uses `render_command::draw_indexed_primitives`. Buffer bindings and
the pipeline are inherited from the Metal 4 encoder; execution uses `executeCommandsInBuffer`.

Both paths consume the same GPU-written argument words. The ICB shader dynamically indexes ten
textures through a Slang `ParameterBlock`; the reference binds five textures individually for
each fixed indirect draw. Both sum the same five samples in the same order. Two distinct triangle
meshes use different index ranges and materials. The 128 × 96 RGBA8 outputs match in all
49,152 bytes. Independent expected-value checks require 1,950 pixels of `(57,176,66,255)` and,
when the second candidate is retained, 1,680 pixels of `(162,91,131,255)`.

Every fourth frame rejects the second candidate. All 900 frames check the expected coverage,
argument fields and exact image comparison after the owning slot's shared event retires. Three
allocators, ICBs, argument buffers and output pairs rotate; reuse waits only for that slot, with no
per-frame `waitIdle`. A fresh commit-feedback handler per frame establishes 900 callbacks and zero
reported errors. An earlier run reused one `CommitOptions` and received only one callback; its
log is retained, and the final run fixes this evidence-collection gap.

This fixture is deliberately small and synthetic. Its classification is a controlled visibility
pattern, not production frustum classification. It does not establish scene/material-table ABI,
multiple render pipelines per ICB, scene-scale performance, production fallback behavior or
production 900-frame reliability. Those remain adapter work only after a complete spike pass.

## Capture debugging and remaining uncertainty

Early one-frame captures returned success and `isCapturing=true`, but produced no document.
Starting before queue/resource creation, using the backend's exact file-URL construction, pumping
the main runloop after stop, and adding a CAMetalLayer clear/present did not produce an ICB trace.
An explicit Metal 4 capture scope threw an Objective-C exception:
`-[MTLCaptureScope traceStream]: unrecognized selector`. That framework failure is retained.

A task-owned Time Profiler session was running during the earliest attempts. A fresh capture
still failed after that process exited, so its presence alone does not explain the result.
The root task independently captured the frozen parent fullscreen editor successfully at frame 3,
with its existing compute/temporal pipeline; evidence is the sibling
`m7.3/parent-capture-control.gputrace` and its log/schema.

Matching that two-frame retired warmup exposed the explicit Metal 4 compute-encoder refusal.
A final paired host control retained the same libraries, pipelines, ICB allocations, texture
bindings, warmup and drawable presentation, but skipped ICB reset, the ICB emit dispatch and ICB
execution. It passed exact output checks and generated `warmup-fixed-control.gputrace`
(21 files, 854,681 bytes). Thus the generic minimal host can capture under those conditions;
the gap follows the exercised ICB route. These controls do not identify which ICB operation causes
it and do not establish an API-wide impossibility.

Reopening requires isolating reset, native emit and execution individually, obtaining a labelled
ICB capture and verifying its replay, then repeating the complete P1/P2/P3 gate under the pinned
compiler. The successful runtime observations stay valid within their measured scope; the failed
capture gate remains failed. No tolerance, renderer default or adoption bar changes.
